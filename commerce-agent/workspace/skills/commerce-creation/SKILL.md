# 工作方法

1. 理解用户要交付的结果，区分生成、剪辑、局部修改和多版。使用已经给出的信息，不重新要求填完整表单。
2. 用 `commerce_capabilities` 检查工具与配置。用 `commerce_media` 探测附件，并查看工具返回的真实图像/抽帧；只读任务资料，按需检索，不预建知识库。
3. 保存简短制作单：目标、素材、已知事实、禁止变化、输出和预算。图片任务先保证主体一致；教程先验证源片实际存在所需动作；促销/问答不补造事实。
4. 生成任务使用 `commerce_generate`，从核对过的能力目录选择模型或 AI 应用。业务默认由你选择，用户无需回答模型选择题。需要明确风格决定时先交付少量候选。
5. 已有素材剪辑与声音组合使用 `commerce_media`；提供明确源时间和文字，不让工具重新策划。按需调用外部声音能力，普通字幕修改不触发配音。
6. 长任务保存真实 taskId，使用 `commerce_task` 查看进度、结果或恢复。先告知开始，不能用 queued 当完成。遇到提交结果不确定，不盲目重试。
7. 对实际结果做技术检查和视觉核对。看不到或听不到的维度明确待审。缺陷在预算内有针对性地修正，不能无限重做。
8. 交付原生媒体附件及简短结果说明。用户继续修改时绑定原结果，只执行请求变化，保留旧版供撤销或比较。

交付时将工具返回的每个 `media` 字段原样放在最终回复的独立行，例如 `MEDIA:/absolute/path/result.mp4`，由 OpenClaw 渠道转为附件。不能只说“已保存”，不能自行构造网页链接。`ready_for_review` 先用 `commerce_media.inspect` 观察实际产物；无听音能力时不得声称听感通过。

RunningHub 目录按 `image-to-image`、`image-to-video`、`text-to-image`、`text-to-speech`、`music-generation` 检索，然后查询具体 `capabilityId` 参数。缺少配置或核对过的价格上限时不得把 `estimatedCostCny` 当执行授权。工具一次返回至多 45 秒进度，继续查询同一个 `runId`，不得因等待超时重新生成。

## 场景选择

| 目的 | 制作重点 |
|---|---|
| 商品场景图 | 主体身份、包装、颜色和细节不漂移，场景服务用途 |
| 上新/亮相 | 尽早展示商品，突出有依据的重点，清楚收尾 |
| 详情/卖点 | 每条主张有相应画面或资料，标注指向正确 |
| 操作教程 | 源片包含必要动作，删等待不删关键步骤，不生成虚假功能证据 |
| 系列/组合 | 每款商品分别保持名称、外观和事实 |
| 促销/预告 | 活动条件、时间和 CTA 一致，缺价格不编价格 |
| 问答/选购 | 先回答问题，再给证据和限制 |
| 精剪/多版 | 保留明确保持集；时长、画幅、开头变化只影响必要对象 |

## 输入不足与修改

- 不确定商品背面/细节时不要虚构，改用已有视角或明确请求补图。
- “只改第二张背景”保留第一、第三张文件；对第二张以指定原图/版本作为参考。
- “只改字幕”保持源镜头和音轨，不调用图像/视频生成或 TTS。
- “保留原声”在剪辑后核对源时间映射，不能将整条原声音轨错铺。
- 外部能力不可用时仍完成不依赖它的工作，但不把替代结果冒充原要求。

## 完成判据

原始要求与输出一致；真实文件存在且可打开；商品事实与保持集通过核对；当前结果可以从同一会话继续修改。评估记录必须说明哪些来自技术检查、哪些来自实际视觉/听音、哪些仍待用户判断。
