## 0. 最终任务，不再通过缩小分母收尾

**目标：普通商家输入 → 意图理解与需求补全 → 场景化制作计划 → 从本地素材文件夹选材 → 精准调用本地 HyperFrames → 高质量可编辑成片 → 对话续改、声音修改与工程交付。**

本轮同时完成两条主线：八类常用场景的业务和工程闭环；音频链路实现到用户提供有效 MiniMax Key 后无需补代码即可接通。M01—M12 及 F1—F3 的历史欠项全部继承，不因“今天重点”被删除。F1—F3 只是原合同中的修复项，不再作为只做三件事就可以结束的范围。

### 0.1 明确交付数量和米家参考的地位

八类固定为：S01 新品首发／品牌亮相；S02 商品详情／卖点图解；S03 开箱／安装／使用教程；S04 穿搭／组合／系列展示；S05 活动促销／直播预告；S06 选购说明／场景问答；S07 已有视频精剪与包装；S08 一稿多版／开头／画幅调整。

交付规划暂把米家 V2 放在 S01 商品亮相的**视觉基准**位置；这不是对其完整内容的新审查结论。开始时实际读取该视频、源工程和已有 Agent 项目，核对匹配关系；它不能自动占用 S03 完整操作教程的验收名额。

- 如本地明确登记表把米家归入其他场景，只允许依据实际内容做一次对应关系调整；八类全覆盖、七组新片以及 S01／米家对应场景的 Agent 证据义务不减少，不重复计数。不要求用户再次手工分配编号。
- 六场景旧编号、N1—N6、历史 projectId/revisionId 不批量重命名。新 S01—S08 是验收标签，不是修改历史数据的指令。

### 0.2 暂停什么、继续什么

暂停新的 AI 商品图片／视频镜头生成，保留已有生成代码和历史资产。RunningHub 不是前置条件。使用已有视频、图片和合法可用音频；原生图形、文字、标注和 HyperFrames 合成继续。

不新增平行 WebUI、第二套 Agent、独立向量数据库、全新渲染引擎或监督平台。沿用现有服务、主 Agent、场景包、资源目录、受控适配、原生工程、版本与验收运行器。

不把“不加旁白”自动解释为静音；原声、旁白、音乐分别按用户要求处理。不因 MiniMax 未配置让全部成片无声或停止本地声音编辑。

### 0.3 完成状态必须分开

业务文档完成、运行时接入、真实 Agent 制作、媒体技术检查、视觉／声音自动审查、真人认可、MiniMax 本地协议通过、MiniMax 真调用通过分别记录。缺哪项就缺哪项。候选可预览和下载，不能因等待人评而无法产出候选；反过来，候选导出也不能代表质量认可。

**核心完成条件：七组新片真实可看可改，八场景链路均有证据，十类资源有实际适用验证，全部内部模块欠项清零；MiniMax 仅剩凭据和相应账户权限的真实联网验收，不能还缺请求函数、字幕映射或混音接入。**

## 2. 产品架构：固定业务流程，不固定每一条片的内容

采用一个主 Agent、一个通用意图层、一套素材证据、一套资源调度和原生工程。八个场景提供不同约束与故事结构，不复制八套服务。无需设计多个 Agent 相互聊天。

### 2.1 通用输入优化层的输出

输出是一份可执行制作单，不是更长的营销 Prompt。建议沿用并扩充既有 BusinessContract，至少保存：

| 信息 | 作用 |
|---|---|
| 原始请求、已解析要求、逐项来源 | 防止“优化输入”改变用户意思；价格、性能、声音禁止项可追溯。 |
| taskMode | create / edit / recut / variant；已有工程修改不重走整片策划。 |
| businessScenario + workflowProfile | 前六项是业务目的，后两项主要是对已有内容的操作。S07/S08保留原业务目标，不当成新的商品事实。 |
| 商品与受众、观看者看完要做什么 | 区分吸引关注、解释细节、学会操作和回答疑问。 |
| assetScope 与事实表 | 仅授权素材范围；区分用户确认、画面观察、未知和推测。 |
| 时长、画幅、风格、声音合同 | 默认可逆；硬约束不能被模板默认覆盖。 |
| 必须内容、禁止内容、动作保护 | 关键步骤、事实、主体保护区、不可删镜头。 |
| baseProject/baseRevision、修改目标／保持对象 | S07/S08及续改必须绑定正确版本。 |
| 资源功能需求及作用域 | 例如细节前置、步骤条、仅第二处转场；不是只写一个 template 名称。 |
| 缺项、默认假设及处理方式 | 缺关键事实最小提问；可逆创意默认执行；不重复问已知信息。 |

界面可简短显示“按上新片处理，保持无旁白，不添加价格，将优先展示整体与细节”，随即继续制作。不要要求用户批准每一幕或手动选择技术组件。

### 2.2 识别和改写的规则

先判断任务是制作还是修改，再判断业务目的，再读取素材能力；不能按文件扩展名或某个商品词分类。把复合请求拆成动作及约束：例如“这一版改竖屏，前三秒先看细节，声音不变”，必须产生变体模式、开头修改、布局重排及声音保持四项，而不是只改输出尺寸。

结构化理解可使用现有模型；模型输出经 schema、事实表、动作完整性和权限校验。旧关键词逻辑只作辅助和确定性纠错。复杂否定、指代与范围用对象集合表示：资源、包含目标、排除目标、作用时间、用户纠正关系；不能 Map 只按资源 ID 覆盖整句。

例：同一条请求“只在第二处用色散，其余不要色散”表示第二处启用、其他处排除；“第一处和第三处用色散”表示两个位置。用户后来明确撤回是跨轮修改，不能与同轮“其余”混淆。真正矛盾无法解开时只问一次必要问题。

### 2.3 固定的是制作规则，不是剪辑答案

每条流程：普通输入 → 制作单 → 素材观察与充分性 → 叙事计划 → 功能资源需求 → 候选与硬条件过滤 → 参数化装配 → 实际成片审查 → 最小修复 → 版本交付。

故事计划按当前素材输出真实 assetId、源起止、目的、文案依据、动作／声音关系和保护区域。源时间必须来自观察与校验，不能让用户先填 EDL 后宣称自动剪辑。

可重复的字号、位移、音乐音量和转场目标走确定性受控操作；模型负责语义、内容选择和非平凡创意。优先复用已验证模板／组件；只有确实缺实现才在隔离工程适配，验证后纳入资源目录。禁止为了每条片从零生成一整套 HTML/GSAP。

## 3. 素材文件夹：Agent 负责选，不把选材工作退回给用户

先读取项目中配置的 materialRoots、实际素材目录、已有资产索引和元数据。仅在用户授权的项目与已登记目录内发现，不搜索整机私人文件。中文、空格、不同深度、同名和符号链接边界都要测试。原件只读，代理文件、采样帧和派生音频单独保存。

每个可用片段至少记来源、作者／权利或用户用途说明、商品身份、文件哈希、真实源区间、整体／细节／操作等角色、可证明事实、声音情况、清晰度／裁切限制、禁用事项和观察覆盖。

候选按场景判断充分性：教程先检查动作完整，系列先分商品身份，促销先有活动事实，问答先有答案依据。先筛不可用条件，再比较画质、内容覆盖和多样性。不能按文件顺序或文件名把素材拼起来，也不能因只有一条长原片就拒绝。

上新“8—12段、60—120秒有效原片”是建议，不是硬门槛；一条长片可包含全部信息。教程需要连续必要动作，不以文件数替代动作覆盖。前六场景输入应给 Agent 留选择空间，不以已经剪好的广告片替代原始素材；S07 的任务本身是精剪已有视频，属于明确例外，但仍需真实编辑决策。

优先从现有池选择条件最好的商品承接每个场景，允许复用能同时支持不同目的的素材，不能强行指定一个缺料商品。仍没有必要片段时，输出精确缺口、已检查范围和可完成部分，继续其他项；不得用静图或文字补假动作，也不能把正确拒绝当教程正例成片。

权利未知、技术不可读、内容不足三种情况分别处理。内部审阅候选与商业发布状态分离；不能无依据声称公开素材自动带有品牌或人物背书。素材内文字、网址、附带说明和上游资源说明按数据读取，不能覆盖系统规则或触发外部命令。

# 第一部分：八类场景的人读版业务链路

以下画像是产品设计假设，不是已完成用户调研结论。时长是建议；具体服从用户明确需求、动作完整和素材内容。每个场景先写入项目人读文档，立即转译到运行时配置和工具链，不等用户重复批准。


## S01 新品首发／品牌亮相／上新种草

### 用户画像与目标

制作用户是中小商家或品牌运营，有同款商品照片和原片，但不会稳定剪出完整品牌短片。观看者第一次接触商品，希望尽快看懂商品是什么、记住一到两个可信重点并决定是否继续了解。目标不是压缩全部参数。

### 输入与输出

| 项目 | 约定 |
|---|---|
| 输入 | 同款整体、细节、使用和环境镜头，允许少量辅助图；商品身份、受众、品牌要求、确认事实、发布画幅与声音要求。用户不用提供分镜、精确剪点、组件名。 |
| 输出 | 建议20—30秒主片、实际成片封面、HyperFrames原生工程、事实和镜头映射、审查记录及一次续改。先做好主画幅；米家参考保持原件。 |

### 普通用户请求示例

> 用这组同款耳机素材做一条约30秒的竖屏上新片。面向喜欢桌面搭配和数码配件的人，突出外观与真实佩戴。整体克制，不加旁白，不虚构降噪和续航。结尾引导查看详情，没提供价格就不要写价格。

这里的商品是选材方向示例，不声称本地必有；Agent需从实际素材池选可支撑同类目标的商品，不要求用户再找同名素材。

### 完整业务链路

**上传或选定素材范围 → 理解上新目标 → 核验同款与事实 → 观察并挑选整体／佩戴／细节 → 确定主表达 → 安排开场与叙事 → 选择视觉结构和资源 → 制作 → 审查商品识别与信息 → 局部修复 → 对话续改与交付。**

| 段落 | 观众获得什么 | 制作重点 |
|---|---|---|
| 开头 | 迅速认识商品和语境 | 商品尽早出现，不以长片头代替 |
| 中前段 | 看到真实使用状态 | 使用实拍；景别与节奏开始变化 |
| 中段 | 记住一到两处可信细节 | 文案对应源画面，保留阅读停留 |
| 后段 | 形成完整商品印象 | 回到整体，不只剩零碎特写 |
| 结尾 | 知道下一步做什么 | 行动提示、画面和声音完整收束 |

### Agent 的关键判断

选择有识别力的开头，删除等待，决定整体／细节穿插和重点；未确认性能、价格、功效不进入文案。用户要求真实佩戴而素材没有时不能用静图运动替代。

### HyperFrames 资源与执行

候选结构可参考 product-promo；视觉气质在 play-mode、warm-grain 等已核实本地模板中按素材选择 [H02]。组件负责轻量标题、细节提示和品牌结尾，照片只在适合段落辅助，视频保持主体清楚。多个资源必须统一字号、留白与运动节奏，不能像样例拼贴。

资源名是候选，不是无需检查的强制安装清单。实际ID、版本、可执行入口和绑定以本地资源为准；不可用时完成合规适配或明确记缺口，不假装调用成功。

### 声音与字幕

不加旁白只禁止新增旁白，不自动取消原声或音乐。是否保留原声、是否配乐分别从请求读取；无旁白时营销标题不是逐字字幕。

### 对话修改与保持项

“只把结尾改成查看产品详情，不动声音”；“细节提前，其他镜头不变”。检查同一工程、素材／声音保持与正确版本。

### 反例与最低业务门槛

无价格不造价格；混入另一型号不串事实；没有佩戴画面不冒充真实使用。

### 视觉增值目标

清楚的主体节奏、不同景别、文字对画面的让位、完整收尾。米家参考和自有Agent候选分开检查，不能以参考片代替此场景闭环。

### 本场景完成证据

普通输入、真实素材与源区间、规则加载、资源绑定、实际MP4/封面、原生工程、场景反例、一次真实续改、输入变化验证和当前审查状态。不能只交一份场景文档或计划JSON。


## S02 商品详情／卖点图解

### 用户画像与目标

制作用户是商品运营或详情页内容人员。观看者已知道商品品类，正在判断结构、配件或某个特性是否满足需要。目标是把真实细节说明白，而不是再说一遍新品来了。

### 输入与输出

| 项目 | 约定 |
|---|---|
| 输入 | 同款商品整体定位、可观察局部、真实结构／功能演示；确认的参数和要解释的问题。资料中的参数注明来源；不要求用户给标注坐标和构图方案。 |
| 输出 | 建议30—45秒详情片；独立可编辑的局部放大、标注和说明；整体—局部映射、事实证据与原生工程。 |

### 普通用户请求示例

> 从素材文件夹选一组同款背包素材，做约35秒的详情片。面向通勤用户，先交代整体，再讲清真实可见的分区和取物位置。没给尺寸容量就不要补数字；指示线不能挡开口和拉链。

这里的商品是选材方向示例，不声称本地必有；Agent需从实际素材池选可支撑同类目标的商品，不要求用户再找同名素材。

### 完整业务链路

**理解购买关注点 → 按同款分组 → 找到可支持每个说明的源区间 → 排除无证据主张 → 建立整体与部位关系 → 编排解释次序 → 调用放大／callout／分区 → 制作 → 检查指向、事实与可读性 → 修改与交付。**

| 段落 | 观众获得什么 | 制作重点 |
|---|---|---|
| 整体定位 | 知道看哪个商品、哪部分 | 先整体再局部，避免一开始抽象特写 |
| 细节一 | 知道结构是什么 | 保持标注与真实位置对应 |
| 细节二 | 理解结构如何使用 | 使用动作或补拍特写支撑 |

| 收尾 | 知道已解释和未确认的边界 | 不以空泛品质口号替代解释 |

### Agent 的关键判断

匹配“主张—画面／资料—标注目标”，选择哪些能说、先说哪一个。静态指示线不能假装自动跟踪移动物体；必要时使用稳定区间、经过检查的跟踪或在冻结帧上标注。

### 声音与字幕

## S03 开箱／安装／使用教程

### 用户画像与目标

制作用户是商家内容运营、售前或售后人员，有冗长原片。观看者没使用过商品，希望看完理解并重复关键动作。目标优先是操作正确、可学会，不能为了炫技牺牲过程。

### 输入与输出

| 项目 | 约定 |
|---|---|
| 输入 | 至少一遍从准备到结果的连续操作；必要细节；可信步骤、必须动作、观众基础、声音要求。开箱／安装／使用按子类型选择规则，不能一套广告骨架通吃。 |
| 输出 | 建议45—60秒操作片，实际时长服从动作；可编辑步骤文字、动作依赖与源时间映射、原生工程。保留便于看清操作的画幅，不机械全改竖屏。 |

### 普通用户请求示例

> 把素材文件夹中一段完整操作原片剪成约45—60秒中文教程，观众没有经验。删除介绍和等待，但保留全部必要动作。步骤随动作出现，不能遮手和关键部位；保留对应原声，不加配乐。没拍到的关键步骤明确指出。

这里的商品是选材方向示例，不声称本地必有；Agent需从实际素材池选可支撑同类目标的商品，不要求用户再找同名素材。

### 完整业务链路

**理解观众与操作子类型 → 观察连续原片 → 建立开始状态、必要步骤、先后依赖与结果 → 定位源区间 → 检查缺步 → 删除可删等待／重复 → 包装步骤和局部提示 → 核对原声 → 连续看关键动作 → 修复／修改／交付。**

| 段落 | 观众获得什么 | 制作重点 |
|---|---|---|
| 起点 | 知道要完成什么、从哪里开始 | 必要准备不被删掉 |
| 准备 | 看清接口、工具或零件 | 文字避开需要看的位置 |
| 关键动作 | 知道怎么做以及做到哪里 | 完整进入—进行—完成，不在中途遮挡 |
| 易错处 | 理解需要注意的细节 | 完成动作后可重放特写，明确是重放 |
| 结果 | 知道怎样确认成功 | 保留真实完成状态，不突然变促销 |

### Agent 的关键判断

判断某段“看似不动”是否是理解必须的过程，保护动作先后关系，不能只据ASR或稀疏图认定步骤完整。关键穿入未拍到时指出缺口；不能用“然后穿过去”一句话补成完整教程。

### HyperFrames 资源与执行

步骤条、数字序列、透明lower third、局部高亮和低干扰构图；必要时参考decision-tree的解释结构而非强塞流程图 [H02]。HyperFrames精确选段、源音同步、步骤文字和提示，强转场只允许在不损害动作的章节边界。

资源名是候选，不是无需检查的强制安装清单。实际ID、版本、可执行入口和绑定以本地资源为准；不可用时完成合规适配或明确记缺口，不假装调用成功。

### 声音与字幕

保留对应原声意味着按相同源偏移、剪切和速度映射，不是整条音频铺在重排画面上。明确要求完整独立原声时单独合同。无配乐禁止任何模板自带音乐。

### 对话修改与保持项

“第二步文字移开手部”；“缩短等待但不删穿入动作”；“指定动作慢一点，原声同步”。必要动作不能因为新音色时长变化被加速或裁掉。

### 反例与最低业务门槛

删除必要动作的测试副本应正确阻断完整教程；另有真实完整正例，不能用拒绝结果代替。开箱缺附件不得填齐，安装不得逆序，美化不能掩盖错误。

### 视觉增值目标

提高步骤可学性、主体保护和局部提示质量；不是要求教程的转场比广告更多。差异来自连续动作、步骤追随和有依据的细节重放。

## S04 穿搭／组合／系列展示

### 用户画像与目标

这里的商品是选材方向示例，不声称本地必有；Agent需从实际素材池选可支撑同类目标的商品，不要求用户再找同名素材。

### 反例与最低业务门槛

相似商品混身份、缺某款资料、颜色经调色变样都不能通过；三款全用同一视频不是系列片。

| 输出 | 按原片内容决定的精剪版，建议首轮30—60秒但不硬卡；前后EDL／原意检查、可编辑新增包装、原生工程及至少一次局部修改。 |

### 普通用户请求示例

> 从素材文件夹选一条有完整内容但节奏拖沓的商品视频，删掉等待和无效重复，保留必要动作和讲解原意。补少量说明和有依据的细节特写，原声对应。不要重做成另一条广告，不生成新镜头。

这里的商品是选材方向示例，不声称本地必有；Agent需从实际素材池选可支撑同类目标的商品，不要求用户再找同名素材。

### 完整业务链路

**识别recut模式与原业务目标 → 观察完整素材和声音 → 标记信息点、必要动作、可删等待及上下文 → 建立保留／删除计划 → 保持语义地剪接 → 添加可编辑字幕／标注／声音处理 → 前后对照审查 → 局部修改交付。**

| 段落 | 观众获得什么 | 制作重点 |
|---|---|---|
| 重点提早 | 尽快看见真正内容 | 删除无效开场，不捏造钩子 |
| 有效主体 | 以更紧凑节奏理解原意 | 删除等待，不剪掉理解所需过程 |
| 必要包装 | 看清原片没强调的细节 | 特写／字幕辅助，不喧宾夺主 |
| 自然结束 | 保留原结论或操作结果 | 避免突然截断声音或动作 |

### Agent 的关键判断

以原意、动作和上下文为不可变约束，决定哪些可删、可压缩，哪些停顿有意义。优先已有工程局部编辑；导入只有MP4时新建受控包装工程，不声称恢复混死的原层。

### HyperFrames 资源与执行

原生cut／trim、精确时间映射、轻量lower third、caption、局部punch-in、合理段落转场和音量包络。HyperFrames执行剪辑和包装，模型不要为了改两处剪点重写全片HTML。

资源名是候选，不是无需检查的强制安装清单。实际ID、版本、可执行入口和绑定以本地资源为准；不可用时完成合规适配或明确记缺口，不假装调用成功。

### 声音与字幕

对应原声跟随源时间；降音乐、淡入淡出和必要ducking在独立轨道处理。不能把口播里的否定词剪掉；混音分离不是无损恢复，缺分轨时明确限制。

### 对话修改与保持项

“只再缩短第二处等待”；“保留这句原话”；“去掉一处动效，不改剪点”。至少有替换已有片段和撤销验证。

### 反例与最低业务门槛

删除否定词改变原意、去掉动作前置、重复反复同一片凑长度、烧录字幕被假称删除，都失败。

### 视觉增值目标

同输入原片与精剪版做直接对照，证明等待减少、重点更早、声音更完整或细节更清楚；不是只换标题和导出。

### 本场景完成证据

普通输入、真实素材与源区间、规则加载、资源绑定、实际MP4/封面、原生工程、场景反例、一次真实续改、输入变化验证和当前审查状态。不能只交一份场景文档或计划JSON。


## S08 一稿多版／开头／画幅调整

### 用户画像与目标

制作用户已有基本满意的工程，要适配不同受众或平台，不愿每次重做。观看者在不同观看情境下需要不同重点和构图。目标是在保护原事实与质量的前提下重新组织传播。

### 输入与输出

| 项目 | 约定 |
|---|---|
| 输入 | 本项目可编辑母工程、当前revision、原始素材、目标受众／目的／画幅／时长、修改和保持范围。只给MP4时先说明布局重构与分层局限，不能假装能移除烧录字。 |
| 输出 | 同一母工程谱系下至少两个派生结果：A仅修改开头，B画幅／重点重排；各自原生版本、封面、差异说明和可继续修改状态。 |

### 普通用户请求示例

> 基于已完成的这条片做两个版本：A只让前三秒先出现真实细节，后面的镜头、文字和声音不变；B改成竖屏给手机看，重新安排主体与说明，保留全部事实和必要动作，不要中心一裁了事。

这里的商品是选材方向示例，不声称本地必有；Agent需从实际素材池选可支撑同类目标的商品，不要求用户再找同名素材。

### 完整业务链路

**识别variant模式 → 锁定母工程与revision → 解析每个版本的新目标和保持项 → 检查素材可裁切范围 → 重选必要开头／重排信息 → 按画幅重布局 → 处理边界和声音依赖 → 各版独立审查 → 版本对照与续改。**

| 段落 | 观众获得什么 | 制作重点 |
|---|---|---|
| A版开头 | 更快得到指定重点 | 只调整目标范围，处理与后段衔接 |
| A版保持段 | 仍是原来认可内容 | 未授权区域结构与声音保持 |
| B版重构 | 手机端能看清商品与字 | 重新排版／分屏／留边，非强制中心裁切 |
| 版本收尾 | 每版完整且目的明确 | CTA服从各版目标，事实一致 |

### Agent 的关键判断

识别这是变体不是新商品制作；安排变更依赖和锁定对象。素材不足以完整竖裁时选择适当背景承托、分区或留边，不裁掉手和产品关键部位。版本A的范围限制不得被版本B的全局重排影响。

### HyperFrames 资源与执行

参数化composition、响应式layout、独立typography、字幕安全区、受控开头模块、媒体取景和时间线复制／分支。相关资源要按两个画幅分别验证，不把横版通过当竖版通过。

资源名是候选，不是无需检查的强制安装清单。实际ID、版本、可执行入口和绑定以本地资源为准；不可用时完成合规适配或明确记缺口，不假装调用成功。

### 声音与字幕

A明确保持声音时不重新合成，画面切换要核对语义；B改变时长时仅处理必要音轨范围。不能因改比例自动换音色或生成音乐。

### 对话修改与保持项

“只把B版说明挪开商品”；“恢复A版的原开头”；“导出B但不改变母版”。比较父子revision、影响范围和兄弟分支不变。

### 反例与最低业务门槛

过期基准版本、修改泄漏到母版／兄弟版、中心裁切挡动作、横版大字等比例缩小变不可读都失败。

### 视觉增值目标

一组素材两种明确的信息与布局组织；A的范围稳定性和B的竖屏重构应展示比参考片更强的编辑增值，不靠导出尺寸标签充数。

### 本场景完成证据

普通输入、真实素材与源区间、规则加载、资源绑定、实际MP4/封面、原生工程、场景反例、一次真实续改、输入变化验证和当前审查状态。不能只交一份场景文档或计划JSON。

# 第二部分：资源、视觉与音频的工程合同

## 4. HyperFrames 资源调度：不再把“找到了”当“会用了”

### 4.1 保留全量发现，建立可执行契约

按本地实际 metadata/manifest/源文件建立目录，记录扫描根、边界、缺失／解析失败、依赖、文件哈希、来源提交及运行版本。文件数、资源数、适配器数、渲染通过数分开；十种功能标签可以重叠，不能重复凑数量。

每条资源记录：稳定ID、展示名／别名、功能标签、原始类型、中文功能说明与英文检索描述、适合／不适合的场景、输入素材种类和数量、文本容量、比例、时长、保护区要求、composition或shader真实入口、参数、对象槽位、依赖、适配方式、可编辑边界和验证条件。

官方 block 是独立构图，component 是局部片段，skill 是制作知识，example 是参考工程；不能用同一种复制HTML方式处理 [H03]。全量发现以配置范围为界，缺目录要分必需与可选；源文件已在registry并可使用时，不应只因为可选compositions目录未创建就阻断全部资源。

### 4.2 统一的资源选择与执行顺序

业务／段落目的 → 明确功能需求 → 查询本地目录 → 排除不合法事实、素材不足、画幅不适配、动作遮挡、依赖／版本不兼容 → 对剩余资源按信息表达与风格排序 → 选择适配方式 → 绑定真实素材和文本 → 小片段预览 → 验证 → 合入主工程。

目标不是永远固定几个资源，也不是直接执行任何找到的上游脚本。成熟能力走参数化适配；新的明确需求走隔离适配、编译与渲染测试，然后晋级。无法实现不能静默换效果；明确原要求、真实失败和替代选择，不把内部缺适配说成外部缺Key。

通用意图层输出视觉／声音功能，场景规则只改变优先级和禁止项。新增场景应主要增加规则与适配映射，而不是复制服务和生产链。

### 4.3 十类能力的独立证明

| 功能类别 | 本轮必须证明的行为 | 不接受的替代 |
|---|---|---|
| template | 同一骨架能吃不同商品和事实，允许删不适用槽位 | 固定商品、固定路径、缺价格不能跑 |
| composition | 子构图按本项目比例／时长接入，源和对象可改 | 只导出官方整段示例 |
| component | callout或信息卡指向当前真实部位，参数可改 | 假数据、示例标签和错误坐标 |
| effect | 只作用目标对象，效果和商品真实性同时保持 | 整片无差别套滤镜 |
| transition | 真实相邻镜头、真实目标边界和有效重叠 | SCENE A/B或静默替换为淡入 |
| skill | 规则在实际阶段加载，落到计划／对象与检查 | 仅登记“已读skill” |
| caption | 有声音依据或可信字幕来源，时间和样式独立 | 按字数平均分配伪装时间戳 |
| typography | 中文长短文案、数字与字级清楚，无缺字 | 缩小到不可读来通过布局 |
| lower third | 文字条可避开商品／手部，并能在续改中移动 | 永远固定底部挡动作 |
| shader | 正确纹理、运行ID、时序，预览与最终导出都有效 | 黑屏／示例纹理／只记资源名 |

同一资源可证明多项功能，但每项对应的行为与证据要分别说明。不是要求每条正式视频堆满十类效果。七组新片合起来体现八场景需要的全部类别，并完成用户明确提出的精确色散请求。

### 4.4 中文作用域不能靠例句补丁凑过

必测：“只在第二处用色散，其余不用”“只在第二处用色散，其余不要色散”应同义；“第一处和第三处用色散”保留两个位置；“第三处取消，第一处保留”只改变第三处；“不要强转场、不要音乐”不能被模板默认覆盖。不存在位置、过期revision、重复请求和动作保护冲突都有确定结果。

资源请求必须携带当前baseRevision与稳定边界／对象ID，不能一轮重排后仍拿旧序号作用到错误镜头。模型解释、运行工具、实际MP4三者一致才算通过。

## 5. 视觉质量：高于米家 V2 是验收目标，不是提前写在报告里的结论

### 5.1 先实际建立基准

保留 `video-agent/deliverables/mijia-v2/mijia-product-ad-v2.mp4` 和登记哈希；在本地核对可访问原片、工程、关键段落和声音。参考文件找不到时，先查登记和原输出位置，不能凭印象写评语。

形成同一份基准记录：主体占比与清晰度、整体／细节切换、文字系统、镜头信息密度、动画节奏、转场、声音关系和收尾。记录真实时间点与观察范围。只看抽帧就只认抽帧覆盖，不能填连续观片／试听通过。

### 5.2 冻结比较方法，不冻结错误分数

本轮对每个新场景要求：

1. **事实、商品身份、关键动作、主体保护和声音禁止项无阻断错误。**
2. 在共同制作维度上不低于米家参考的完成度：清晰度、主体呈现、文字、节奏、动效完整性、适用的声音与收尾。
3. 至少有两项与本场景相关的明确增值，并提供时间点／对照。例如详情片的整体—局部关系和精准标注，教程的步骤可重复性和避让，系列的群像关系和匹配转场，变体的布局重构和保持范围。
4. 七组作品有不同的信息结构和视觉表达，不能一个白底大字卡模板换七个名字。相似品牌可以共享token，不等于共用完全相同镜头序列。
5. 自有Agent选择和编辑的证据成立；手工模板参考不能替代自动生产。

上述是待执行门槛，不是声称已高于米家。采用同一评审尺度、同等观看尺寸，并保留原始候选与失败结果；不同场景不以转场数量机械排名。模型评审不能替真人签署“比米家好”。用户最终判断仍按实际成片。

### 5.3 分阶段视觉检查，但不能靠抽帧掩盖动作问题

先确认每场景代表段落的静态布局，再做短片段动态检查，再完整渲染。中间低分辨率只用来早发现问题，不能替代最终画质。关键动作、转场和音画同步连续查看，正文、开头、所有段落和结尾均覆盖。

发现重复布局、商品很小、文案空泛、中文截断、字幕挡手、转场黑帧、镜头源错误、声音突然切断时，定位到要求—时间—对象—输入—编译／渲染层，最小修复后复验。不能只给自动分数而没有具体问题，也不能一遇到质量不过就无限重新生成整片。

模板选择先保证内容表达，再设计变化。可用的变化包括整体／局部、多区域、单品／群像、问题／证据、开头重排、文字揭示、源动作连贯、配乐节奏；不把简单缩放循环当足够变化。

### 5.4 制作稳定性与调用效率同时收尾

保留阶段调用与失败类型，定位反复编写布局、重复读取素材、重复审查和缓存失效。正常路径尽量由预检通过的资源参数化装配，不让一次字号调整重写整幕。

记录首次成功率、实际调用量、修复次数、耗时和缓存命中；不虚报提速百分比、不人为延长任务。现有预算不擅自扩大，不能削减必要检查换取少调用。预计超过预算要在耗尽前报告真实原因并保留已完成阶段，不临时把预算缩小作为提前收尾借口。

## 6. MiniMax 音频：实现到只差有效凭据，不只做“预留接口”

### 6.1 三条能力分开，工程层共用

语音生成、音色目录、音乐生成独立配置与能力状态。既有音频导入、混音、字幕编辑独立于供应商。提供Key之后，调用、落地、时间对齐、预览、修改和导出使用已经测试的同一条代码路径，不再需要开发新按钮或补请求处理。

当前官方文档可核对的接口为：

| 能力 | 官方路径及约束摘要 | 本轮执行要求 |
|---|---|---|
| TTS | `POST /v1/t2a_v2`；Bearer鉴权；语音、音色、音频和字幕参数独立 [A01] | 实现同步短句／段落请求、错误检查、测时长和工程接入；不必为首轮增建流式平台。 |
| 音色目录 | `POST /v1/get_voice`，不是GET；返回分类音色信息 [A02] | 真实目录缓存、ID验证、中文筛选、选定音色的短试听；不为全部音色批量付费合成。 |
| 音乐 | `POST /v1/music_generation`；可选纯音乐模式，输出需落地 [A03] | 音乐driver现在实现；用户以后选择生成时才调用。无权限时仅该能力不可用，本地BGM照常。 |

国内文档示例基址为 `https://api.minimaxi.com`；国际站使用不同基址 [A01][A05]。区域为非密钥配置，不试遍多个域名发送用户Key，不静默换供应商。

本轮文档中可见的语音候选包括 `speech-2.8-hd`，音乐文档已有 `music-3.0`，而当前仓库音乐配置仍列 `music-2.6` [A01][A03][S07]。保留用户明确的模型选择；模型和参数契约版本化，不用固定过期枚举阻止有效模型，也不无授权自动升级计费模型。非密钥默认值由项目提供并校验。

### 6.2 用户只填什么

标准部署只要求用户填服务端 `MINIMAX_API_KEY`；与账户区域不一致时通过现有配置选择正确区域。TTS模型、音乐模型、语言、默认语速、音量、输出规格、字幕策略、超时、预算和缓存已经有合理默认，不要求用户填工作流ID或修改代码。

加载`.env`必须早于读取环境变量的配置对象／服务实例建立；不能服务启动时仍缓存旧的“未配置”。提供安全的重新加载或明确的一次重启流程，保留历史作品、音频和版本。

密钥不进入浏览器构建、聊天Prompt、日志、错误响应、工程包和Git。前端只见能力状态。禁止硬编码样例Key、假音色和成功标志；禁止按音色ID前缀猜所有供应商的性别/语言，使用真实元数据，未知就不显示虚构标签。

### 6.3 必须有的执行能力，而不只是接口声明

- 音色查询：统一HTTP客户端，鉴权和区域校验，按实际响应提取ID/描述，保留账号隔离的目录缓存。
- TTS执行：把确认后的旁白段落与音色参数提交；校验HTTP及业务状态、空data、无效音频、返回规格与实际文件；请求和响应记录去密钥。
- 音乐执行：支持本地BGM选择与MiniMax生成两条明确路径；生成纯伴奏时使用实际支持的纯音乐字段，不只在Prompt里写“别唱歌”。不能捏造未公开的时长参数，按实际结果测量、选择乐句并合理剪接淡出。
- 音频落地：对hex校验后解码；对URL按安全规则下载、限制大小并验格式；写临时文件、probe完整性、哈希后原子入库。短期URL不能作为工程永久素材。官方TTS与音乐文档提示URL有期限 [A01][A03]。
- 字幕：TTS字幕按返回真实粒度和时间单位归一，存句／词时间、原始来源、局部偏移和主时间线映射。当前文档有句级、词级等选项；不按字数伪造时间 [A01]。
- 原片转写：沿用并验证既有ASR；TTS的字幕不能转写用户原片。无可用转写时准确说明相关限制，不因此给无声画面虚构口播。
- 声音应用：TTS/音乐返回后成为与本地音频同类型的独立资产，通过现有Agent音频工具插入、替换、混音和导出。不能只有一个试听文件而不进入成片。
- 局部修改：段落保持稳定ID；只改一个旁白段或音色相关部分，其他镜头和事实保持；音色时长变化触发必要字幕重对齐和局部时间检查，不能悄悄删动作。

这些是本轮必须实现和测试的行为。函数名可以沿用项目已有命名，不为名字再造新抽象。

### 6.4 原声、旁白、音乐、音效、字幕、营销文字分层

每个音频对象保存assetId、角色、来源文件／哈希、源偏移、timeline位置、速率、音量、淡入淡出、处理链、版本和关联字幕。文字另外保存内容、时间、样式、事实来源与关联音轨。

| 用户修改 | 应改变 | 默认保持 |
|---|---|---|
| 换本地BGM | 对应音乐轨与混音／封装 | 旁白、源镜头、文字及业务事实 |
| 降音乐或延长淡出 | 对应音量包络 | 音色和源素材 |
| 换音色 | 指定旁白及必要时序／字幕 | 商品事实和无关段落 |
| 改一句已朗读文案 | 相关旁白、关联字与必要时长 | 其他旁白／镜头 |
| 改字幕颜色、字号、位置 | 样式和视觉渲染 | 声音文件与原话内容 |
| 修正识别错字 | 字幕内容和复核 | 不重写原声说法 |
| 改营销标题 | 对应图文层 | 无关联旁白时不生成声音 |
| 替换已有镜头 | 目标镜头及必要声画／标注依赖 | 其他镜头和声音 |

保留原声要区分跟随源片段与用户指定整条独立铺底。静音、ducking、淡入淡出在最终MP4中也要生效，不只改播放器音量。原生运行时支持则使用；确实不支持时用受控音频预处理生成派生资产，参数仍可改，不改HyperFrames核心去冒险。

只有烧录文字和混合音轨的MP4不能宣称可无损恢复全部层；S07/S08需准确标示可编辑的新增层和原始限制。

### 6.5 错误、缓存、去重与费用

分别处理HTTP错误、HTTP200但业务失败、无效Key、无音色权限、余额不足、限流、超时、空data、损坏音频和过期URL。官方错误码提供相关类别，按真实响应映射而不是统一报“生成失败” [A04]。

同内容/模型/音色/参数/字幕策略在相同有效授权范围内使用内容指纹与本地single-flight复用。内容或音色改变只失效相关音频与字幕；换Key不删旧本地声音文件，但刷新账号相关目录与权限缓存。请求提交前记录稳定operationId。

**本地去重不等于供应商保证恰好一次。** 对同步合成“请求可能已提交但响应丢失”，若无官方可查询任务或幂等协议，记为submission_unknown，不能假造可查询taskId或自动重发后声称绝无重复计费。保留trace与预算，依真实能力对账；无法查证的再提交需明确用户授权。已完成未入库则尽可能恢复下载，不重合成。

费用以实际usage和已配置单价估算，标明单位和“估算”；未知不要写0元。测试替身的usage不能计真实账单。连接测试、试听和音乐生成遵守已有授权，不因用户保存Key立即批量生成整库音频。

### 6.6 没有Key时怎样证明“仅剩Key”

开发期可仅替换HTTP传输边界，使用按官方格式构造的响应及**真实可解码音频文件**，让生产请求构造器、响应解析、入库、字幕映射、混音、预览、修改和导出照常执行。协议测试明确标“测试替身”，不能记录为MiniMax生成。

测试必须覆盖：有Key/无Key/错误Key/部分权限、POST方法和实际字段、音色选择、hex与URL音频、业务失败、时长变化、字幕单位与偏移、音乐纯伴奏、缓存命中／失效、取消、结果未知、断点恢复、密钥脱敏和工程包不含凭据。完整UI使用同一应用入口；不能另做只为测试的“成功服务”绕过真实链路。

最后做一次配置切换演练：关闭测试传输，加载服务端真实配置，不修改业务代码；未提供Key时准确处于unconfigured，填入Key并取得权限后同一按钮可查询音色、生成短旁白、入工程、换音色并导出。真实Key尚未提供时，只报告“内部执行链已验证，真实联网待验收”。

“只给API”不代表凭据、余额、地区或模型权限问题一定不存在；它代表这些外部条件满足后，不应再有待开发的内部环节。

以下是职责文本，不是让用户每做一条片手动粘贴。映射现有R0—R8及MA/CD等阶段，沿用manifest、hash、场景包指纹和receipt，不复制出另一套Prompt框架。下面每段应有明确输入、受控输出和实际加载证据。

### R-IN：输入理解与约束保真

> 你负责把普通商家需求变为本工程可执行的制作单。保留原请求，识别create/edit/recut/variant，再确定业务目的。区分事实、可逆默认、未知与禁止项；不要扩写价格、功效或动作。复用已知信息和当前工程。将复合要求拆为目标对象、保持对象、范围及必要依赖，明确否定和“其余”。可逆风格采用默认并继续，只有事实、必要动作、权限或不可同时满足的约束才提出最小问题。输出结构化合同，不要求用户给组件名或分镜。

### R-RESOURCE：精准调度

### R-AUDIO：声音与文字

### R-EDIT：局部修改

> 锁定baseRevision、目标对象和保持对象，只输出受控编辑操作及必要依赖。不要为普通字号、音量、位置、现有素材替换重写整片。范围变动后复核对应边界；冲突不施加到最近的相似对象。发布唯一revision，撤销和兄弟分支保持正确，不能旧文件冒充新结果。

### R-REVIEW：实际成片审查与修复

> 检查当前导出MP4及其版本，不只看源码或封面。先检查事实、商品、动作、声音禁令、遮挡和中文可读性，再检查节奏、转场与收尾。每个缺陷带真实时间、证据、影响及最小修复。与米家基准按适用维度对照，不凭自信声称更好。声明观察覆盖和试听能力，不能替真人签署认可。问题未修好继续修复受影响对象，不删除失败标准。
