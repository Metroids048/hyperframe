**适用项目：Metroids048/hyperframe / video-agent**  
**阅读对象：产品、设计、开发、测试，以及后续将本文转译成运行时配置的实施 Agent。**

> 产品定义：商家提供普通业务需求和有选择空间的商品素材，Agent 完成理解、观察、取舍、策划与资源选择；HyperFrames 将这些决定落实为可编辑的视频工程。用户继续用自然语言修改，系统只改变相关对象和必要依赖。

本文补充的是“每条片应该怎样被正确做出来”，不是再发布一份要求执行者“不要停止”的任务合同。文中的流程、时长分配、文案和验收门槛是**设计建议**，不是已实现能力或已完成测试。八场景、七组新制作与旧模块收口目标保持不变；本文不替代、不删减原交付合同。

用户最新贴出的 S02 显卡进度单独保存在附录。本文没有访问用户本地 3020/3024 服务，没有观看未上传的米家或显卡完整视频，没有运行生产模型，也不对这些作品作新增质量通过判定。公开官方资源只证明存在对应设计起点；本地安装、版本兼容和实际效果需要工程验证。

## 01｜产品目标与八场景边界

### 1.1 核心价值不是“能够导出视频”

一个有价值的电商制作 Agent，应能解释四件事：为什么这个镜头适合表达用户目标；为什么这句话有依据；为什么选择这种构图或动效；为什么后续修改只需要改变这些对象。最终解释必须与真实工程相符，而不是成片之后补写一段制作故事。

HyperFrames 的 HTML、样式、时间线和媒体装配提供可编辑制作底座。[H01] 我们的增量在其上层：将商家的业务语言转成素材选择、信息结构、资源约束和可检验的修改。让编码代理手工写一条漂亮片，可以作为创作参考；只有普通请求实际经过产品的理解、素材与工程链路，才属于产品 Agent 的结果。

当前重点是已有素材的后期增值。暂停新 AI 商品图片和视频镜头生成；允许基于真实素材制作文字、图形、标注、构图、转场与音频。新制作不使用耳机素材。米家 V2 是保留原件的视觉参考，不自动算 S01 已通过，更不能抵作 S03 完整教程。MiniMax 在凭据提供后接入声音供应链，但本地音乐、字幕和工程编辑不以它为前提。

### 1.2 八场景不是八个皮肤

以下画像均是产品设计假设，后续可用用户访谈验证。场景由**观看者要解决的问题**区分，而不是按商品品类或文件格式区分。

| 场景 | 制作方常见表达 | 观看者核心问题 | 内容组织主线 | 区别于其他场景的判断 |
|---|---|---|---|---|
| S01 新品首发／品牌亮相 | “刚上架，做一条让人记住它的介绍。” | 是什么，为什么继续了解？ | 商品识别→可信重点→品牌与行动 | 选择少量记忆点，不塞全部规格 |
| S02 商品详情／卖点图解 | “把这个结构、接口或配件讲清楚。” | 在哪里，怎样对应，有什么依据？ | 整体定位→局部证据→关系回归 | 建立空间和证据关系，不只是列参数 |
| S03 开箱／安装／使用教程 | “第一次看也要会做。” | 从什么状态开始，怎样完成？ | 准备→必要步骤→检查→结果 | 判断哪些等待可删、哪些过程不可删 |
| S04 穿搭／组合／系列展示 | “这些商品要有统一风格和搭配感。” | 如何搭配，各款是什么关系？ | 组合主题→单款作用→组合变化→群像 | 多商品身份、曝光和关系不能混乱 |
| S05 活动促销／直播预告 | “时间、条件、参与方式要看清。” | 为什么关注，何时怎样参与？ | 主题→真实价值→条件→行动 | 事实字段完整、条件可读、不过期误导 |
| S06 选购说明／场景问答 | “回答这个购买前问题。” | 结论是什么，依据和限制是什么？ | 问题→简答→证据→边界 | 回答原问题，不偷换成广告口号 |
| S07 已有视频精剪与包装 | “保留内容，剪紧一点，再包装。” | 如何更快理解原内容？ | 原意分析→删冗余→保逻辑→包装 | 编辑而非重写，能解释每次删留 |
| S08 一稿多版／开头／画幅调整 | “同一稿换开头，再做竖屏。” | 不同触达场景怎样复用内容？ | 母版→变化与保持→派生→对照 | 正确继承、重布局、范围隔离 |

### 1.3 采用两个维度，避免场景路由混乱

**业务目的**描述观众需要获得什么，主要对应 S01—S06。**任务操作**描述对现有内容做什么，包括新建、局部编辑、精剪、多版。S07 和 S08 是用户可见入口，但后端不能丢掉原作品的业务目的。

例如“这条安装教程删掉等待，再出竖屏”应组合成“教程规则＋精剪操作＋竖屏变体”。关键动作仍受教程保护。不能因为进入 S08 就只改分辨率，也不能因为进入 S07 就默认重排所有步骤。

开箱、安装和使用归于 S03 的不同子流程：仅展示盒内物件的开箱不等于安装教程；真实完成开机不等于展示所有功能。街访、UGC、杂志感、技术感是呈现方式，不另外扩成业务场景。模板不能反过来决定商品事实。

### 1.4 每条片最终交付的对象

对商家，交付是当前可播放 MP4、来自实际成片的封面、清楚的版本和修改入口。对工程，交付是可重开的 HyperFrames 原生结构、源素材引用、文字与音轨、资源绑定和版本依赖。对验收，交付是原始需求、证据覆盖、实际检查结果和待人评项。

“精选展示”“技术检查通过”“业务规则通过”“用户认可”是不同状态。参考片、新 Agent 候选、历史预设不能混为一类；一次导出不自动成为首页精选。

## 02｜通用输入理解与意图调度

### 2.1 输入优化的产物是一张制作单

不要让输入优化器把一句需求扩写成一千字广告提示词。它应该生成可核对、可继承、可修改的任务理解。

| 制作单内容 | 必须说明什么 | 不允许做什么 |
|---|---|---|
| 原始需求与要求编号 | 每个目标、否定和保持项来自哪句话 | 改写后丢掉“不要配乐”等约束 |
| 操作与工程上下文 | 新建、修改、精剪或变体；基准项目与版本 | 已有工程修改却新建无关项目 |
| 业务目标与观看者 | 看完需要认识、理解、学会、选择还是参与 | 仅凭“显卡”判断应做哪个场景 |
| 素材范围 | 当前上传、本地已授权文件夹、已有工程 | 遍历用户整机私人文件 |
| 商品事实 | 用户确认、画面可观察、未知、模型推测分开 | 由片名、型号或外观推断性能 |
| 输出要求 | 时长、画幅、语言、渠道、风格 | 静默用 UI 默认值覆盖文字需求 |
| 声音合同 | 原声、旁白、音乐、音效分别保留／新增／禁止 | “不加旁白”被解释为全部静音 |
| 内容保护 | 必要动作、限制条件、必须出现的商品、保留对象 | 为卡节拍删除关键过程 |
| 视觉功能需求 | 放大、标注、分区、步骤提示、指定转场范围 | 直接强行匹配一个完整模板 |
| 缺项与处理 | 哪些可默认，哪些须补事实，哪些素材不支持 | 已有信息重复询问或凭空补齐 |

这里的字段是业务对象设计，不要求另建数据库。优先扩展现有合同和阶段回执。

### 2.2 意图识别的实际顺序

首先识别是否在修改已有作品。存在有效母工程且说“这一版、第二幕、原声别动”，应优先解释对象和保持范围。没有工程但要求精剪时，允许从已有 MP4 创建可编辑的新包装工程，但明确无法恢复原先未提供的层。

其次识别观看目标。用户说“接口在哪里”偏 S02；“怎样连接”偏 S03；“能不能接我的设备”偏 S06。相同名词不能触发同一流程。

然后检查信息和素材可行性。视觉风格等可逆选择可以给简短默认后继续；商品身份冲突、关键动作缺失、活动时间未确认等需要最小澄清。对未知项按影响分级，不把所有未知字段都升级成阻塞。

最后拆成制作动作。例如“更克制、细节提前、原声别动、只在第二处用色散”至少包含叙事排序、低干扰视觉、原声锁定和局部转场四项；不能只解析出“色散”。

### 2.3 同一句话在不同上下文的路由

| 输入 | 上下文 | 正确结果 |
|---|---|---|
| “把接口讲清楚” | 仅有显卡原片 | 进入 S02，定位接口所在整体与局部，不补接口规格 |
| “把接口讲清楚” | 当前是安装教程，用户选择第三步 | 局部加强 S03 第三步说明，保留步骤顺序 |
| “换个开头，后面不要动” | 存在母工程 | S08 开头分支；锁定后续源区间、文字、声音和时间 |
| “更快一点” | 关键穿入动作必须完整 | 缩等待与冗余，不能直接加速全部操作 |
| “字幕短一点” | 营销说明 | 精简文字，保持事实；相关旁白有绑定时再联动 |
| “字幕短一点” | 逐字口播字幕 | 优先断句、显示方式；若意指改写原话，需要说明声音一致性 |
| “不加旁白，原声留着” | 视频存在语音或动作声 | 禁止 TTS；保留与镜头对应的原声，不添加默认音乐 |
| “用 HyperFrames 资源包装” | 普通制作请求 | 识别为能力要求，不寻找名叫“HyperFrames 资源”的条目 |

### 2.4 范围要按对象集合解析

“第一处和第三处使用色散”应表示两个转场目标；“只在第二处用，其余不要色散”表示局部启用与其余排除。“其余”属于同一请求的补充，不应覆盖第二处的启用。

未确认含义的“第二处”需要结合已展示的镜头或转场列表。明确选择了转场对象时不再重复问；既可能指镜头又可能指字幕时，只澄清这一点。跨轮纠正应依据新的请求覆盖相应旧约束，而不是合并成不可理解的矛盾。

### 2.5 用户可见理解摘要

摘要应短到能检查，但不要求每次点击批准。例如：

> 将按显卡详情片制作：先建立整体，再解释正面、连接位置和背面。只使用画面可确认的外观信息；中文旁白，不加背景音乐。关键说明会与对应部位同时出现，工程中的文字、旁白和标注分别可改。

如果图像不足以证明端口类型，摘要应说“介绍可见接口位置”，不能写“解释 HDMI 版本”。确认的是目标，不是让商家承担剪点、坐标或组件名。

## 03｜素材理解：从文件夹到可用证据

### 3.1 先知道有什么，再决定怎么讲

素材库回答“有哪段真实内容可以使用”，资源库回答“如何表达这些内容”。二者不能混用：一个流程图组件不能填补真实操作缺失，一个品牌模板不能提供产品性能证据。

产品使用用户授权的素材目录，原件只读。发现结果须区分目录不存在、读取失败、格式不可解码、内容不适合。中文名称、空格、子目录、同名文件与符号链接需要处理；不能依靠文件名筛选“显卡教程”，也不能将 review、poster 等分析产物再次作为商品原片。

上新建议的 8—12 段、60—120 秒有效素材只是准备建议。文件数不应决定充分性：一个长原片可包含多种内容；大量无关短片仍不足。当前新制作排除耳机，但不修改、删除历史耳机工程。

### 3.2 每条源片产生什么信息

| 信息层 | 应记录的内容 | 作用 |
|---|---|---|
| 技术层 | 文件哈希、时长、尺寸、帧率、音轨、解码状态 | 保证源区间与输出可执行 |
| 身份层 | 商品 ID、同款／同系列关系、确认依据和不确定项 | 防止串商品、串事实 |
| 内容层 | 整体、局部、使用、环境、等待、重复等候选区间 | 提供真实选段空间 |
| 事实层 | 可观察结构、用户资料、禁用主张、证据强度 | 约束营销文字和旁白 |
| 动作层 | 起点、过程、完成状态、前置步骤、不可断区间 | 保护教程与原意 |
| 空间层 | 主体／手／接口保护区，适合的裁切和标注位置 | 决定构图而非盲目 cover |
| 声音层 | 是否有音轨、实际识别内容、动作声、可用区间 | 建立真实音画关系 |
| 权利与用途层 | 来源、作者信息、用户用途说明、可分发限制 | 区分内部候选、对外商用和工程打包 |
| 观察覆盖层 | 实际看过哪些帧／连续区间、未观察部分 | 不让稀疏抽帧冒充完整观片 |

源片的“同款”与“同一次操作”分别判断。两个同款视频中的不同装配状态不能随意接成一个连续操作。几张截图能辅助定位，但不足以证明穿入、锁紧、通电等过程完整。

### 3.3 分层观察与选段

先低成本定位全片结构，得到可能的整体、细节和动作区间；再对准备使用的区间连续观察，验证开始、结束与相邻语境；最后在成片上复查这些区间的裁切、声音和包装。观察缓存绑定源文件版本和观察范围，不因重复制作就对同一原片从零描述。

候选先过硬条件，再比较适用性。硬条件包括同款身份、可读性、真实动作、足够源时长、事实依据和授权用途。通过后才比较清晰度、构图空间、信息量与节奏。漂亮但错误型号的镜头不能用高分抵消身份冲突。

S02 优先选能够建立部位关系的相邻景别；S03 优先动作完整；S04 优先多款区分与群像；S05 优先能支撑活动主题的真实内容；S06 优先直接回答问题的证据。相同素材在不同目标下可以排序不同，但解释必须可回溯。

### 3.4 缺素材的正确处理

无性能资料，可继续做不含性能的外观片；无某一细节，可减少该主张，但不能悄悄删除用户明确要求的重点。缺关键安装动作，不能交付完整教程；可给出准确缺口和已完成的非完整候选。缺某款上身画面，不能套另一款；未确认活动日期，不能自设“今晚八点”。

材料不足不意味着整个工程都停住：任务理解、已知素材索引和可用段落可保存。也不能把一次正确拒绝记为教程正例成片。最终示例选择应优先从当前池中寻找有完整内容的商品，而不是先硬指定商品再用错误素材勉强补齐。

## 04｜共用制作流程与阶段交接

### 4.1 一个主 Agent，分阶段受控执行

下表的“角色”是职责边界，不要求运行十几个独立模型代理。模型承担语义、取舍和创意判断；确定性的计时、路径检查、参数应用、媒体探测与版本写入交给程序。每阶段有明确输入输出，避免后一个阶段重新发明前面的事实。

| 阶段 | 输入 | Agent 作出的决定 | 执行工具／HyperFrames 的工作 | 阶段产物与前进条件 |
|---|---|---|---|---|
| 需求理解 | 用户原话、当前工程、能力状态 | 操作模式、业务目标、保持项与缺项 | 校验项目、版本与配置 | 制作单；硬冲突已处理 |
| 素材观察 | 授权文件及已知资料 | 可用内容、身份、事实、动作覆盖 | 解码、抽样、连续片段读取、声音分析 | 带真实区间的素材证据 |
| 内容策划 | 制作单＋证据 | 主表达、信息段落、选段与删留 | 验证源范围和步骤依赖 | 故事计划；每个段落有信息任务 |
| 视觉定向 | 故事＋品牌与参考 | 视觉层级、主要构图、动效强度 | 生成可复用设计参数 | 单一视觉系统，非随机拼贴 |
| 资源规划 | 每段功能需求与约束 | 选什么、排除什么、怎样适配 | 本地目录检索与兼容检查 | 资源绑定计划；无假 ID |
| 声音与计时 | 旁白草稿、原声、音乐、画面容量 | 旁白取舍、原声优先级、时序策略 | TTS／现有声音、测时、字幕对齐 | 实际音频＋统一时间排程 |
| 静态构图 | 实际文字、媒体、保护区 | 重点是否清楚、哪些元素删减 | 真实字体度量、媒体构图、标注 | 最可见状态可读、无遮挡 |
| 动画与合成 | 已确认布局和排程 | 必要的进入、强调、退出和衔接 | HyperFrames 生成原生时间线 | 可 seek、预览与导出一致 |
| 成片审查 | 实际 MP4＋原需求 | 业务、视觉、声音缺陷 | 完整解码、时段读取、技术检查 | 问题定位到真实版本和时间 |
| 最小修复 | 缺陷＋原工程 | 修哪层、保持哪些内容 | 局部 patch、依赖失效与重渲染 | 新 revision；缺陷位置复验 |
| 交付与续改 | 当前工程和审查状态 | 向用户解释结果与可改范围 | 工作台、封面、视频和原生包 | 用户能看、能改、能重开 |

### 4.2 三类时序策略，不能用一套顺序套全部场景

**动作优先**用于教程：先锁必要动作与原声，再把步骤说明放进动作窗口。说明太长就精简说明，不能先生成长旁白再逼动作加速。

**语义对齐优先**用于详情和问答：先确定哪个证据支撑哪句话，生成或读取真实声音后，反向校验其能否放入对应画面；不把旁白从零秒一路铺到片尾。

**画面节奏优先**用于上新和系列：先编排主体、细节与群像，再根据用户声音要求配合音乐或短旁白。音乐节拍可以影响非必要停留，不改变事实与操作逻辑。

S05 的日期、条件等字段准确性优先于节奏；S07 先保护原意；S08 先锁母版保持项。计时必须允许阶段间有限回调，但不能一处字幕溢出就整片重策划。

### 4.3 计划和最终工程必须能够核对

建议延续项目现有对象，保留六种关系：需求到制作单，事实到证据，段落到源片段，资源到原生对象，旁白到声音文件与字幕，修订到目标与保持对象。它们可以存在现有 JSON 或存储中，不必新建平台。

例如计划写“接口旁白分四段”，最终工程必须真的具有四段声音对象或四个准确裁切区间。检查“计划文件有四行”不足以通过。计划写“第二处色散”，最终时间线不能把全片转场都改成色散。计划写“后文不动”，派生版必须检查后文源区间与对象。

### 4.4 成功复用与失败路由

同一输入、配置与资源版本未变，可复用观察和资源预检。字号和坐标的明确修改应由对象操作完成；复杂叙事改动再由模型规划。保留失败证据，但不要让失败工程重复触发无变化的审查请求。

失败定位顺序是：需求是否被误解、源片是否足够、说明是否有依据、资源是否兼容、实际绑定是否正确、编译是否覆盖参数、预览与导出是否一致。一个模块缺陷在模块内解决，确需修改前置计划时只使相应依赖失效。

## S01｜新品首发／品牌亮相

### S01.1 用户画像、目标与适用边界

制作用户是中小商家、品牌内容运营或负责新品上线的人：有商品图片和拍摄片段，希望在不自行编写分镜的情况下得到完整介绍。观看用户第一次接触商品，首先需要识别商品及使用语境，再判断是否继续了解。

本场景只确立一个主表达、通常一到两个可信重点。它不是参数百科，也不是没有商品的大字片。与 S02 的区别在于建立印象而非解释全部结构；与 S05 的区别在于不以活动条件作为主要信息。米家 V2 仅提供视觉完成度参照，不固定所有新品片必须按它的镜头和时长制作。

### S01.2 输入与输出

| 项目 | 设计定义 |
|---|---|
| 输入素材 | 同款商品整体、细节、真实使用或能建立使用语境的原片，辅以少量图片。优先存在多个可选镜头，而非直接使用一条完整成品广告。 |
| 输入信息 | 商品身份、受众、已确认重点、品牌风格、发布用途、画幅、时长和声音要求。 |
| 用户不必提供 | 开头源时间、镜头顺序、组件名、字号、动画曲线和逐秒分镜。 |
| 建议输出 | 20—30 秒主片、真实成片封面、独立文字与音频层、原生工程、证据与审查摘要。时长随实际需求调整。 |
| 必要边界 | 没有使用镜头时可以明确做外观亮相；不能把图片运动称为真实使用。缺价格就不加价格。 |

**普通需求示例：**

> 从素材文件夹找一组同款桌面相机原片，做一条约 25 秒的新品亮相。给关注桌面设备外观的人看，重点是整体造型与实际摆放。克制，不加旁白；有合适且可用的音乐再配，不写没有证据的画质、续航和价格，最后引导查看详情。

桌面相机是示例选材方向，不表示本轮已经找到或观看了对应原片；新制作不使用耳机。

### S01.3 Agent 怎样形成制作方案

先确定“观众应记住的一句话”，再从素材挑最能识别商品的整体镜头。环境只用于交代语境，不承担本品功能证明。优先把真实动作或形态变化作为开场吸引力，而不是先做数秒品牌片头。

随后为每个重点找到画面依据。若两处细节事实上重复，就合并成一个重点，留出完整商品镜头。结尾使用真实品牌资料和可确认的行动提示；不因 Logo Outro 中有链接槽就编一个网址。

**完整链路：**识别上新意图 → 同款与事实核验 → 观察候选 → 确定主表达 → 整体／细节／使用取舍 → 选择视觉语言 → 资源装配 → 声音与时间 → 成片审查 → 同工程修改。

### S01.4 25 秒的导演示例

以下时间为目标成片设计窗口，不是任何源视频的已观察时码。

| 窗口 | 信息任务与镜头组织 | HyperFrames 表达 | 必须保留的意义 |
|---|---|---|---|
| 0—3 秒 | 商品直接出现，快速建立外形 | 轻量标题进入，主体不缩成角落 | 观众不等长片头就知道看什么 |
| 3—8 秒 | 商品与桌面／真实环境的关系 | 简洁构图切换，短说明不抢主体 | 知道商品出现在哪种语境 |
| 8—15 秒 | 一个或两个有依据的细节 | 从整体定位到局部，短标注 | 细节不是无来源的抽象特写 |
| 15—21 秒 | 回到整体或真实使用状态 | 画面节奏放缓，重点收束 | 不全是碎片或连续大字 |
| 21—25 秒 | 品牌与下一步 | 克制片尾和声音淡出 | 完整结束，不突然截断 |

### S01.5 资源选择与风格

整片结构可参考官方 `product-promo`；温和品牌表达可参考 `warm-grain`，动感社交表达可参考 `play-mode`。这只是选择方向，须先核对本地资源。[H03]

每条片统一主要字体、强调色、留白和动画节奏。某一处可用遮罩揭示，某一处用局部提示，结尾再收回整体；不逐镜头随机换三种字体和不同风格的资源。商品已经在运动时，避免额外大幅“摄像机运动”让观众看不清。

### S01.6 声音、修改和验收

“不加旁白”只控制旁白，原声和音乐分别记录。无讲话时没有必要建立逐字字幕；卖点与片尾属于营销文字。若音乐无合格来源，不擅自使用公开歌曲。

用户说“细节提前”，改变的是选段顺序及关联文字、音频，不重建所有素材；说“片尾改成查看详情”，只更新片尾及其必要依赖；说“动效少一点”，降低非必要运动，不删除关键信息。

合格片应让首次观看者能说出商品是什么、一到两个可信重点及下一步。测试变体应改变商品或同义输入，验证不是品牌专用脚本。负例包括混入另一型号、缺使用画面、模板引入价格、片头过长。相对米家的增值应来自更清楚的视觉焦点和信息推进，不以转场数量衡量。

## S02｜商品详情／卖点图解

### S02.1 用户画像、目标与适用边界

制作方是商品运营、详情页内容人员或售前人员；观看者已认识商品品类，想看清部位、结构、配件或某个特点。目标是把“名字—部位—整体位置—可确认特征”对应起来。

这是解释片，不是性能测试，也不是完整安装教程。显卡风扇可见，不能因此声称散热更好；端部接口可见，不能因此推断接口协议版本。与 S06 的差别是主动介绍结构，而非围绕一个购买疑问给结论。

### S02.2 输入与输出

| 项目 | 设计定义 |
|---|---|
| 输入素材 | 能建立整体方向的画面、各局部清楚的原片、整体与局部间的连接镜头。 |
| 输入信息 | 解释目标、商品事实和术语、受众知识水平、要保留的细节、声音和画幅要求。 |
| 用户不必提供 | 标注坐标、源时间、整体—局部切换方式、版式和旁白段落时长。 |
| 建议输出 | 30—45 秒详情片，实际文字、标注和声音独立可改；部位关系、事实和源区间可追溯。 |
| 核心缺口处理 | 不能判断部位名称时使用中性位置描述；缺对应画面时不能只靠标题强行补齐。 |

**普通需求示例：**

> 用这条显卡原片做 35 秒横屏详情片，让装机用户看清外形和连接位置。先整体，再局部，再回整体；只讲可见外观，不推断性能、噪声和尺寸。中文旁白，不加背景音乐，说明和标注不要早于对应部位出现。

### S02.3 整体—局部关系模型

每个被解释部位保存四种关系：属于哪个商品；位于哪一面／哪一侧；哪段整体画面可定位它；哪段局部画面能看清它。相邻镜头存在旋转、镜像或角度变化时，标注方向不能简单继承。

解释结构可采用“整体定位—局部放大—局部说明—整体回归”。如果原片已经连续靠近部位，优先利用真实镜头完成关系；不强制再加一次数字推近。需要同时展示整体与局部时，整体小窗是定位参照，不是第二份独立证据。

### S02.4 完整业务链路与调度

| 步骤 | Agent 决定什么 | HyperFrames／执行层做什么 |
|---|---|---|
| 解释目标 | 将“讲清楚结构”拆成几个观众问题 | 保存部位与事实列表 |
| 证据定位 | 哪些区间支撑每一句说明，哪些只能中性描述 | 读取源段、核查范围与清晰度 |
| 关系编排 | 哪个整体镜头建立方位，局部怎样接回整体 | 建立组合构图与对象关系 |
| 文案与声音 | 一句只讲一个正在显示的部位 | 实际生成／读取旁白，测量并分段 |
| 视觉表达 | 单画面、画中画、分区、标注哪种最清楚 | 装配资源，绑定真实媒体与文字 |
| 排程 | 画面、旁白、字幕、标注什么时候出现与结束 | 写入统一时间线，而非各自从零累计 |
| 审查 | 观众能否认出部位，指向是否准确 | 检查成片对应时段、修复局部对象 |

### S02.5 镜头和版式变化

一段先让完整商品占据主要视野，再通过低干扰框线指出当前部位；下一段切到可辨识的局部，同一短名称留在相近视觉位置；解释结束时返回整体或用整体小窗保留方位。切到另一面时给明确方向提示，不能让十个近景连成无空间关系的目录。

可采用四种布局：全画幅整体＋轻量标题；整体定位＋局部画中画；较大细节画面＋侧栏说明；多个已解释部位的简短回顾。不会每个镜头都套相同的“上面大标题、下面小视频”。

### S02.6 HyperFrames 资源与失败边界

`mk-placeholder-grid` 可作为整体与细节的分区起点，`mk-specs-list` 可表达已确认信息，`yt-camera-move` 可作局部推近候选。[H04][H05][H06] 资源默认示例内容都必须替换；参数列表没有来源就删槽，不补数字。

移动商品上的标注有三种允许方式：选择足够稳定的源区间；在经过检查的冻结帧上解释；使用已经验证的跟踪并逐段检查。普通静态 callout 不自动拥有跟踪能力。数字推近不生成原片没有的分辨率；放大看不清就换源或减少解释范围。

### S02.7 音频、字幕与修改

旁白按部位解释分段，字幕来自对应声音的准确文本和实测时间。部位标注可以只写“侧边连接位置”，口播字幕则呈现实际说的话，两者不需完全重复。字幕的字形错了但声音正确，可修文本；声音读错专业词，就需要修对应旁白，不能只把正确字盖在错误声音上。

“把接口提前”移动的是接口证据、旁白段、字幕与标注的语义组；“标注挪开”只改变布局；“不要这一句性能判断”删除所有关联表达，但不必替换正确的商品镜头。显卡当前实例的完整设计见第 07 章。

验收要实际指出每条说明对应哪个部位、哪个时间窗口。正例检查关系清楚和声画同步；负例覆盖连接部位看不清、背板源段跨到侧面、旁白提前、同音错字与单字落行；输入变化测试应换解释顺序或另一组结构素材。十幕渲染完成不等于十个解释任务成立。

## S03｜开箱／安装／使用教程

### S03.1 用户画像、目标与三种子流程

制作方为电商运营、售前售后或教育型内容人员；观看者是无经验的新用户。目标不是“感觉操作很顺”，而是能看懂从初始状态到结果的必要过程。

开箱关注包装、清点和取出；安装关注前置条件、顺序、连接与确认；使用关注设置、操作和结果反馈。不能把只拍了取出商品的开箱称为完整安装片，也不能用结果画面替代中间操作。

### S03.2 输入与输出

| 项目 | 设计定义 |
|---|---|
| 输入素材 | 至少一遍连续必要操作，起始与完成状态清楚；必要时有细节补拍。 |
| 输入信息 | 操作目标、观众基础、可信步骤、不可删动作、原声、时长与画幅要求。 |
| 用户不必提供 | 步骤源时码、保护框、等待裁切点、步骤条模板。 |
| 建议输出 | 45—60 秒教程起点，实际时长服从动作；独立步骤文字、动作依赖、同步原声、原生工程。 |
| 必须保护 | 动作的进入、关键接触／连接、完成检查；安全或使用限制不能因精简被删除。 |

**普通需求示例：**

> 从素材文件夹选择一段完整操作视频，整理成第一次看也能照做的中文教程。去掉介绍和无效等待，关键动作全部保留。步骤随动作出现，别挡住手和接口；原声对应，不加配乐。缺哪一步直接指出。

### S03.3 Agent 的判断不止“识别了四个步骤”

每个必要步骤要明确前置状态、关键过程、结果状态和前置步骤。若只有“插好后的结果”，不能把前面的插入动作标为已观察。拍摄中的等待可能是等设备响应或确认状态，不能一律按静止时长删除。

判断是否能剪，需要回答：删除后新手还知道手、零件或线应从哪里进入吗？是否知道动作完成到什么程度？是否丢失必须先松开或必须断电等已经给出的条件？对看不清的过程，保留未知，不靠模型常识补拍摄事实。

### S03.4 完整业务链路

操作目标 → 连续观察 → 建立动作依赖 → 关联源区间 → 检查缺步 → 分离必要动作与可删等待 → 规划步骤说明 → 同步声音 → 包装 → 连续检查 → 修改与交付。

| 内容段落 | 剪辑决策 | 包装决策 | 不得发生 |
|---|---|---|---|
| 起点与准备 | 留下观众确认起始状态的画面 | 简短准备条或物件说明 | 前置条件只存在于原片，被成片删掉 |
| 主要操作 | 保留连续关键过程，等待按语义处理 | 当前步骤、轻量高亮 | 用转场遮住操作最重要时刻 |
| 中间确认 | 保留结果反馈与检查动作 | 必要时指出确认位置 | 剪掉反馈后让动作显得瞬间完成 |
| 易错点 | 在完整动作后重放相关细节 | 明确标注“细节回看” | 倒放或跨商品拼接伪造成功 |
| 结束 | 保留真实完成状态 | 简洁总结，不加无关促销 | 尚未成功就切片尾 |

### S03.5 资源、构图与音频策略

优先低遮挡步骤条、进度提示、局部高亮和必要的重放构图。`lt-mask-reveal` 一类信息条是候选，不意味必须放在画面下方。保护区包括手、工具、接口、动作路径及其即将进入区域，而不仅是当前帧物体轮廓。

跨步骤可轻切，动作内部不使用遮挡或变形 shader。流程图仅辅助解释顺序，不能替代实际动作。原声按与视频相同的源区间和速率处理；语音跨切点时保护句子。慢放需要明确声音处理，不能画面放慢而声音仍按原时序解释下一步。

### S03.6 缺步、续改与验收

正确缺料说明应具体到“第三步从开始穿入到完成的过程未显示”，并说明目前能交付哪部分，而不是泛泛说“素材不够”。图文补充可以做成说明候选，但不能标完整教程通过。

“第二步说明挪到左上”只改对应文字；“等待缩短”只裁允许区间；“动作慢一点”保持关键过程并同步其声音；“缩到 30 秒”若与动作完整性冲突，提出实际可达到的结果及最小协商。

完整正例应有一个从头到尾可理解的操作片。另用保留原件的删步副本测试拒绝能力。验收必须连续看关键过程，不能用几张静帧或“步骤字幕都存在”代替。相对米家的价值应体现在可学性、动作保护和步骤对齐，不以广告片的炫技强度评价教程。

<a id="s04"></a>
## S04｜穿搭／组合／系列展示

### S04.1 用户画像、目标与关系类型

制作方经营多个款式、色系或组合，希望让内容有统一视觉；观看者希望了解如何搭配、区分款式或认识组合。重点是“这些东西为什么放在一起”，不是把多商品剪成同一商品。

需要区分同款多色、同系列不同款和不同单品组合。仅外观相似不能认定同系列；多件珠宝同屏不等于套装出售。珠宝穿搭是用户当前提供的候选方向，实际身份与素材覆盖仍待观察。

### S04.2 输入与输出

| 项目 | 设计定义 |
|---|---|
| 输入素材 | 单品整体、细节、对应上身／使用及组合画面；各项关系可确认。 |
| 输入信息 | 款式和名称、颜色表达、组合主题、是否成套、展示优先级、音乐与画幅。 |
| 用户不必提供 | 曝光分配、网格数量、匹配剪切位置、组内动画。 |
| 建议输出 | 25—45 秒组合片；可独立调整各款素材、标签、顺序和组合收尾的工程。 |
| 缺料处理 | 某款无上身画面，只能呈现已知展示或说明缺口，不能借用另一款。 |

**普通需求示例：**

> 把素材里这组珠宝和对应穿搭画面做成 30 秒组合展示，突出整体搭配与可见细节。先看穿搭，再认识各件，最后回到组合。名称按现有资料，没有材质和套装信息就不要推断。统一杂志感，别用一串无关联的特写。

### S04.3 从素材关系到导演方案

Agent 先建立“商品—款式—对应穿搭镜头—组合镜头”关系表。每个标签绑定商品 ID，而不是字幕出现的位置。换顺序时，标签随商品移动，不留在旧镜头。

选择一条组合叙事：整体造型拆解适合珠宝穿搭；款式轮换适合系列选款；同一搭配的变化适合不同配色。没有足够对照资料，不下优劣排名。各款展示时长可以不等，但必须有可辨识的曝光，不能靠一帧划过声称“都出现了”。

### S04.4 30 秒示例结构

| 窗口 | 内容和观众收获 | 表达方式 |
|---|---|---|
| 0—4 秒 | 看到组合主题与整体穿搭 | 整体主画面，短主题字 |
| 4—12 秒 | 认识组合中的两项主要单品 | 单品与对应上身镜头交替，稳定名称 |
| 12—20 秒 | 看到可观察的形态或色彩呼应 | 匹配剪切或双区关系展示 |
| 20—26 秒 | 看另一种确认存在的组合变化 | 保持视觉系统，改变商品关系而非乱换模板 |
| 26—30 秒 | 回到完整表达，清楚辨认各项 | 群像或完整穿搭，简短收束 |

当没有第二种组合时，不虚构变化；改为更清楚地回顾已有关系。

### S04.5 HyperFrames 融合策略

Rounded Media Grid 可作群像或单品＋整体的组合底座；每格单独绑定媒体、标签和裁切，不把整个网格渲染为不可编辑的一张图。[H04] 运动以成组进入、位置对应和匹配方向为主，节拍为辅。由单品全屏转为群像时保持颜色和形态可辨，让空间变化解释关系。

不同款跨场景保持同一文字系统。不能用形变转场把 A 款“变成”B 款以致误认同款，也不能调色改变真实色号。只有标签多、卡片多不等于搭配感更强。

### S04.6 声音、修改、反例

音乐优先统一情绪而非压满所有镜头；存在实际讲解时保护其可懂性。没有音色 API 仍可用本地可用音乐完成本场景。逐字字幕与名称标签独立。

“删掉第二件”应更新对应镜头、群像与关联旁白；“两款调换顺序”不改变它们的名称和事实；“只改组合主题”不重新抽取全部素材。负例要覆盖相似款误认、缺上身素材、关系不明却写成套装，以及标签交换。验收看组合是否成立、各项可辨、同屏关系清楚，而不是按款式数量均分秒数。

<a id="s05"></a>
## S05｜活动促销／直播预告

### S05.1 用户画像、目标与边界

制作方是店铺运营、活动负责人或直播内容人员；观看者需要知道是否值得关注、何时参与、条件是什么和到哪里参与。准确传达比制造刺激更重要。

活动促销与无报价直播预告是不同子类型。没有确认优惠时可以做内容预告，但不能把它命名为“限时大促”。未知日期可以做无日期介绍候选，却不能声称具体场次预告完整交付。直播原片不是硬前提，但用于预告的画面应与将要展示的内容有关。

### S05.2 输入与输出

| 项目 | 设计定义 |
|---|---|
| 输入素材 | 活动所涉商品和内容的原片、品牌资产；有明确用途的音乐。 |
| 输入事实 | 主题、日期时间及时区、商品范围、价格或优惠条件、适用人群、行动入口。只填实际已提供的信息。 |
| 用户不必提供 | 价格卡版式、日期动画、条件停留时长和 CTA 布局。 |
| 建议输出 | 15—30 秒活动片；商品、日期、条件、价格与 CTA 分别可编辑，字段与旁白联动。 |
| 必须防止 | 虚构原价、到手价、库存、销量、时间和背书；条件被压成不可读小字。 |

**普通需求示例：**

> 用素材文件夹里与本次直播主题相符的商品画面做 20 秒预告。主题、日期和直播间按我给的活动卡，不添加优惠价、限量和倒计时。商品要看清，条件有阅读时间，最后说明怎样进入直播间。

此示例没有编造任何实际活动字段。缺活动卡时记录明确缺项，不能自行补日期。

### S05.3 活动事实的依赖关系

价格不应是一个孤立大数字。凡宣传优惠，必须保留与之相关的条件：适用商品、门槛、时间和例外。字段在标题、信息卡和旁白中可能多处出现，修改一个事实时应从同一来源同步更新所有关联处。

Agent 先区分必要信息与装饰信息，优先删除重复口号，不能删除优惠限制来腾位置。过时版本作为历史保留，但默认分享／精选入口不应继续指向错误活动时间。修改活动后生成新版本，不覆盖旧证据。

### S05.4 完整业务链路与段落

活动目标 → 事实卡校验 → 素材主题核对 → 信息优先级 → 商品与条件编排 → 图文／声音制作 → 最终字段核对 → 局部修订 → 交付。

| 20 秒建议窗口 | 内容 | Agent 取舍 | HyperFrames 执行 |
|---|---|---|---|
| 0—3 秒 | 商品与活动主题 | 不用长倒计时占开头 | 商品主画面＋短标题 |
| 3—9 秒 | 真实内容或已确认权益 | 只保留最能说明参与价值的内容 | 镜头与信息卡交替，重点逐项出现 |
| 9—15 秒 | 时间、范围、条件 | 字段多时延长停留或减少口号 | 清楚层级与足够阅读空间 |
| 15—20 秒 | 行动方式与收束 | 不编链接、不把重要条件挤掉 | CTA 与日期保持清晰，声音完整结束 |

必要条件读不完时，应该调整时长或信息量，而不是让字体无限缩小。内部设计占位必须标“待确认”，不能被正式导出流程悄悄当真。

### S05.5 资源、声音和修改

可以复用清单、数字排版、轻量强调与片尾结构，但只填已确认字段。Specs Checklist 适合分级条目，不是自动优惠引擎。[H05] 数字清晰优先，强 shader 不应用于价格、日期正在被阅读的瞬间。Logo Outro 的品牌与网址槽可删减；没有正式素材就用已确认文字，不假造标识。[H07]

旁白读到的价格、日期和条件必须绑定事实字段。用户说“日期往后一天、其他不动”，要更新屏幕和相关音频；若暂无重新配音能力，可生成明确的待修候选，不能交付声音旧、画面新的矛盾版本。用户只改日期样式，不应重新合成声音。

负例包括条件缺失、日期不完整、相对时间无法确定、未提供价格、旧音频残留。正例要求静音看能读明白、有声看没有矛盾；后续能独立改时间和 CTA。相对米家的增值在可编辑的信息层级与字段一致性，不是更多促销动效。

<a id="s06"></a>
## S06｜选购说明／场景问答

### S06.1 用户画像与目标

制作方是客服、商品内容人员或售前；观看者带着一个具体问题进入，希望尽早得到结论、依据和适用范围。问答不应被做成另一个“值得拥有”的宣传片。

问题可以是外观位置、操作方法、收纳适配或功能边界。是否能接某设备、能放多大物件等，需要相应资料或实际演示。只有外观原片，不足以回答性能或兼容性结论。

### S06.2 输入与输出

| 项目 | 设计定义 |
|---|---|
| 输入素材 | 直接相关的演示、细节、实际测试或用户确认资料。 |
| 输入信息 | 原问题、观看者条件、已确认答案与限制；未确认项显式列出。 |
| 用户不必提供 | 回答结构、证据剪点、问题卡和强调方式。 |
| 建议输出 | 20—40 秒单问题回答片，问题、简答、证据和边界各自可编辑。 |
| 必要判断 | 有条件回答、可直接回答、无法确认分别处理；不能偷换问题。 |

**普通需求示例：**

> 用这组已经提供的显卡素材回答“连接位置从哪个角度看更清楚”。先直接说明，再展示对应整体和局部。不回答性能和接口协议版本；画面不足以确认的地方直接说明。不要写成新品宣传口号。

该例利用外观证据回答观察问题，不假设其能回答设备兼容性。实际资源不足时不应为了交付问答强行编结论。

### S06.3 答案的组织不是“先问一句再放介绍片”

Agent 将问题拆成判断条件：在什么商品、什么条件下、询问什么关系。先形成一句与证据强度相符的简答，再选择最直接的演示。证据只支持个例时，答案保留个例边界；没有尺寸就不承诺所有尺寸适配。

如果问题是“怎么完成这个操作”，应调用 S03 的步骤保护子流程，但仍保留原问题，避免扩写成无关的完整产品手册。如果问题包含多个独立问题，按需求范围分段或提示拆片，不把所有内容塞进几十秒。

### S06.4 完整链路与表达结构

原问题 → 可回答性判定 → 条件与证据匹配 → 简答 → 证据段落 → 限制 → 原问题复核 → 修改与交付。

| 30 秒建议窗口 | 观众获得什么 | 制作重点 |
|---|---|---|
| 0—3 秒 | 明确原问题 | 问题短，商品或证据仍可见 |
| 3—7 秒 | 尽早得到简答 | 不把结论拖到片尾；语气不过度 |
| 7—21 秒 | 理解为什么成立 | 真实演示＋准确局部提示，必要时并列条件 |
| 21—27 秒 | 知道适用条件和未知边界 | 边界是答案一部分，不藏在免责声明小字中 |
| 27—30 秒 | 知道下一步核对什么 | 回到原问题，不用强促销替代限制 |

### S06.5 HyperFrames 融合与修改

问题卡、答案重点、证据画面、条件条使用同一视觉系统。可以采用视频＋问题侧栏、答案高亮、证据区域 callout 或条件比较，但不能全片只有文字卡。自定义 Q&A 结构是应用侧场景配方，不应冒称官方存在一个无需适配的万能 Q&A 模板。

旁白以短句连接证据，字幕如实对应音频；总结式答案卡和逐字字幕分层处理。用户说“回答更短”，先删重复解释，不能删限定条件让结论变绝对。“删掉这条没有依据的说法”需同时移除旁白、字幕和对应答案卡。“证据别动，换平实语气”只改文字／相关声音。

正例检查问题确实被回答、证据可定位、限制可见；负例覆盖偷换问题、无依据性能、个例泛化、删除条件后的误导。迁移测试换一个问题，Agent 应选择不同证据与结构，而不是只换问题标题。相对米家的提升在清晰回答和可核验依据，不是标题动效。

<a id="s07"></a>
## S07｜已有视频精剪与包装

### S07.1 用户画像、目标与输入层级

制作方已有长原片、初剪或已发布视频，希望更清晰紧凑，不希望把原意重写成另一条广告。观看者应更快接近重点，同时不丢失动作、讲话条件和上下文。

需要区分三类输入：原生工程可以直接编辑原对象；原片加独立声音可以重建选段和声音关系；只有混合 MP4 只能剪切现有画面、添加新层和有限处理，不能假称可无损删除烧录字幕或独立替换已经混合的音乐。

### S07.2 输入与输出

| 项目 | 设计定义 |
|---|---|
| 输入素材 | 原片或初剪；优先有原生工程、独立声轨和备选镜头，但不能强制用户重新提供完整工程。 |
| 输入信息 | 原用途、希望保留的意思、必须内容、可删除部分、目标时长、声音与画幅。 |
| 用户不必提供 | 所有冗余时码、剪辑点、字幕样式和补充 B-roll 位置。 |
| 输出 | 原素材到新片的删留对照、精剪版、可编辑新增包装、原生工程和局部修改记录。 |
| 时长 | 可从 30—60 秒候选设计，但必须服从原内容和请求，不能机械折半。 |

**普通需求示例：**

> 把素材里这条商品原片整理得紧凑一些。删掉摆放前等待和重复展示，保留原意、必要操作与对应声音。用少量文字帮助理解，不做成另一条夸张广告。说明哪些内容被删了，不生成新镜头。

### S07.3 信息结构与删留原则

Agent 先建立原片内容图：开场目的、核心信息、必要动作、解释、限定条件、结果。再把区间分成“必须保留”“可缩短”“可删除”“不确定”。同一动作多次出现可能是无效重复，也可能展示不同步骤或条件，不能按画面相似度直接删除。

自然停顿和等设备反馈不是同一类等待。剪掉口播中间的否定词或条件会改变原意；跳过关键接触动作可能让教程不可学。必要 B-roll 来自同款且符合语义的备选素材，不能用更漂亮但无关的镜头掩盖音画不对应。

### S07.4 完整链路

识别精剪与原业务目标 → 观察画面和原声 → 建立内容／动作图 → 形成删留计划 → 选段和声画映射 → 必要包装 → 前后对照审查 → 续改。

| 处理对象 | 可采用的剪辑 | 不应采取的捷径 |
|---|---|---|
| 无效开场 | 从第一个有效信息进入 | 为吸引力拼出未发生的结果 |
| 重复展示 | 保留最好且信息完整的一段 | 删除所有相似镜头而丢掉差异 |
| 等待 | 在允许区间缩短，保留反馈前后状态 | 等待一律加速，关键动作被压缩 |
| 口播 | 保持语义、句子与条件 | 拼接改变结论或省略限制 |
| 说明不足 | 在对应画面加短说明／局部提示 | 全片补密集文字遮住商品 |
| 结尾突兀 | 保留结果并做声音收束 | 统一套一个无关品牌片尾 |

### S07.5 HyperFrames 的具体增值

以真实源区间组成新时间线，添加独立字幕、说明、callout、轻量章节提示与音频处理。需要画面微调时优先参数化，保留原母工程风格。局部效果的作用应有原因，如在完成动作后冻结一小段解释细节，而不是每个切点都放强转场。

交付中保留删留表：源区间、输出区间、删除或保留原因、关联声音。原工程已有字幕时尽量复用其内容和时间；只有烧录字幕时明确不能恢复原始对象，避免新字与旧字重叠。

### S07.6 修改、反例与价值证明

“再紧一点”再次检查可删等待，不默认全片提速；“这一步别剪”恢复相关完整源区间和原声；“只换标题样式”不重新规划剪点；“恢复到上一版”恢复工程对象而不是只展示旧 MP4。

验收应比较原片与精剪片：是否更快进入重点、信息是否保留、必要动作能否理解、讲话是否改变含义、音轨是否平顺。负例覆盖损坏音轨、无声素材、句中切断、只有混合音频却被标独立、原生工程与输入 MP4 版本不一致。完成证明来自真实删留和包装增值，不是压缩文件变小或片长变短。

<a id="s08"></a>
## S08｜一稿多版／开头／画幅调整

### S08.1 用户画像与目标

制作方是多渠道内容运营或希望测试不同开头的人，已有认可的母版，不希望每次从零制作。观看者在不同设备与渠道中看到内容，需要保持可读性与核心意思。

S08 是变体操作，不抛弃原业务目的。详情片变竖屏仍要保护整体—局部关系；教程变竖屏仍要保留双手、工具与动作；活动改开头仍要保留准确条件。

### S08.2 输入与输出

| 项目 | 设计定义 |
|---|---|
| 输入 | 母工程与确定版本；仅 MP4 时注明编辑层限制；可用原始素材和声音。 |
| 请求 | 改什么、保持什么、目标画幅／时长／观看目的、是否保持原声。 |
| 用户不必提供 | 新坐标、裁切窗口、每个元素尺寸、工程复制与版本规则。 |
| 输出 | 至少两个明确不同的派生版本及同源关系：开头分支与画幅／重点分支；母版保持。 |
| 关键原则 | 版本是从同一确定母版派生，不能把几个独立新项目当“一稿多版”。 |

**普通需求示例：**

> 基于当前详情片做两个版本。A 版前三秒先给细节，三秒之后的内容和声音都不动；B 版改成竖屏，整体与局部重新排，文字不要挤小，不能只中心裁切。保留母版，方便比较。

### S08.3 分支 A：开头替换的范围契约

锁定母版、开头区间与后续对象。若用户要求“三秒之后完全不动”，新开头必须在同样窗口内完成，不能因转场重叠把后文整体前移。跨边界的转场、旁白和字幕属于共享依赖，需要明确保留或调整边界，不能只锁画面文件。

如果要更长开头而又要求后文时间不动，应在开头内压缩表达或提出冲突；不能悄悄删后文。A 版可以更换前段素材与短标题，但不可让片头性能主张超出原事实。

### S08.4 分支 B：画幅变化不是缩放画布

先识别主体和关键部位，按目标屏幕重新安排信息顺序。横屏左右布局到竖屏可以转为上方整体／下方局部、整段全屏交替或较大主体配短标签；不是把两栏同时缩小一半。

| 原结构 | 竖屏优先方案 | 需要检查 |
|---|---|---|
| 左整体＋右细节 | 上整体定位＋下细节，或先整体后细节 | 细节是否仍足够大、方位可理解 |
| 宽画幅双手操作 | 保留横画面于合理区域，文字放空白，或另用合格角度 | 不裁掉手、工具或动作路径 |
| 多款并排群像 | 分段单款＋最后适量群像 | 每款仍可识别，标签不串 |
| 旁白字幕一长行 | 按语义分行并增加合理停留 | 不拆产品术语、不出现单字孤行 |
| 片尾长网址／条件 | 重排并保留必要信息 | 不能裁掉、缩到不可读 |

无合格竖屏布局时明确显示问题和替代版式，不谎称自动适配成功。输出尺寸变化后需要重新检查实际字体、标注、遮挡和转场，而不是沿用横屏通过状态。

### S08.5 完整业务链路与 HyperFrames 调度

读取母版 → 解析变化／保持项 → 计算依赖 → 生成分支计划 → 选择目标画幅资源与布局 → 局部装配 → 独立渲染 → 比较保持项与新目标 → 交付版本。

复用媒体、事实、音频与已验证资源，但布局参数和必要时间可以按分支变化。需要可复用 composition、变量绑定、字体重排、媒体取景和独立音轨；缺少适配能力时补应用侧配方，不假设一个模板支持所有比例。[H02]

### S08.6 声音、续改与验收

用户要求声音不变时保留声音源和播放排程；画幅调整一般不需要 TTS。新开头与旧旁白含义冲突时不能机械保留，须在该范围说明并解决。换音色造成时长变化是另一项修改，不能夹带到改画幅操作里。

“B 版标题改短”只影响 B；“A 版恢复原开头”不能回滚母版或 B；“把母版换音乐同步到两个分支”属于明确跨版本修改，应产生各自新 revision 并保留来源。

验收同时检查新目标达成与保持项成立。对照对象、源区间、文字内容和声音，而不是要求重新编码的 MP4 字节完全相同。负例包括错误母版、过期 revision、边界转场牵动后文、中心裁掉接口、一个分支编辑污染另一个。相对米家的增值在可复用、可控且真正适合新画幅的内容，不是机械复制。

## 05｜HyperFrames 资源发现、选择和执行

### 5.1 融合深度如何定义

最浅的接法是最后把 MP4 交给 HyperFrames 导出；再深一层是手动把官方样例插进工程；本项目需要的是**业务需求驱动的资源选择、真实素材绑定、原生对象编辑和成片复验**。

官方 Catalog 区分较完整的 block 与局部 component，也要求替换样例内容、统一设计并放入整片检查。[H02] 我们要补的是“何时用、是否适合当前输入、如何编入产品工程、修改时如何保持”。资源下载到本地只是发现条件，不是执行完成。

### 5.2 三个分类轴，避免数目录冒充能力

一个资源按三个轴记录：**功能**、**来源形式**、**执行方式**。例如一个官方 block 可承担 transition 与 shader 两种功能，但不是两个独立资源；一个 skill 指导标题制作，却不是可以直接播放的片段。

| 功能类 | 在产品中的工作 | 必须绑定／检查的内容 | 常见误用 |
|---|---|---|---|
| template | 整片或段落的可复用信息骨架 | 媒体槽、事实槽、可选段落、目标画幅 | 固定商品名、固定时长、必须填虚假价格 |
| composition | 可组合的场景与子场景 | 实际组合 ID、时间、尺寸、对象层级 | 把演示场景原样插入用户片 |
| component | 局部卡片、标注、列表 | 当前文本、数据、目标对象、布局 | 仅拷贝源码，仍显示示例数据 |
| effect | 对某个对象或层进行视觉处理 | 目标、幅度、时段、保持的商品特征 | 全片随意发光、变色或变形 |
| transition | 两段内容之间的过渡 | 两路输入、相邻边界、重叠时间 | 把演示 A/B 当用户镜头或错作用范围 |
| skill | 制作规则与操作知识 | 加载阶段、适用规则、实际决策／产物 | 只读了一遍就记“已使用所有能力” |
| caption | 与声音或可信字幕相对应的呈现 | 内容、真实时间、样式与关联声轨 | 字数平均分时、错误转写、遮挡动作 |
| typography | 字体、层级、断行与文字运动 | 实际字体、字号、排版框、阅读停留 | 动画好看但中文拆词、缺字、单字落行 |
| lower third | 辅助信息条与局部说明 | 信息优先级、保护区与可移动布局 | 永远固定底部，挡住手与商品 |
| shader | 部分复杂效果的底层图形实现 | 当前纹理、时间参数、运行支持、最终导出 | 只预览可用，离线黑屏或错误纹理 |

来源形式可为官方 example、registry block、component、skill 文本、应用侧配方。执行方式明确标记为直接绑定、受控适配或依据 skill 的原生创作。后两者不冒称“逐字运行官方组件”。

### 5.3 资源说明卡应包含什么

| 说明组 | 要回答的问题 |
|---|---|
| 身份 | 展示名、Catalog ID、本地路径、版本与文件哈希是什么？别名如何映射？ |
| 语义 | 这个资源帮助观众看懂什么？适合哪个段落目的？ |
| 输入 | 需要几段视频、几张图、哪些文字／数字？允许没有某个槽吗？ |
| 运行 | 实际 composition／runtime ID、入口、依赖与参数范围是什么？ |
| 布局 | 支持的比例、最少空间、文本容量、主体保护要求是什么？ |
| 修改 | 哪些对象可分别编辑？哪些属性存在时间线控制，不能直接覆盖？ |
| 质量 | 在哪个环境、输入、画幅和版本下通过过哪些检查？ |
| 缺口 | 未解析、缺依赖、未适配、无本地字体等问题是什么？ |

全量扫描的范围是配置的本地根目录，需报告未读目录和错误文件。同名不同版本保留身份；缓存不能把旧版本渲染通过自动传给新版本。未安装目录返回零项不等于“已扫描所有”。

### 5.4 通用调度算法的人读设计

**第一步：从故事段落生成视觉任务。** S02 需要的是“看清这个部位相对整体的位置”，不是先找一个叫“高级详情”的模板。S03 需要“文字不遮手的步骤提示”，不是先找最炫转场。

**第二步：召回候选。** 用中文意图及规范化的英文功能词查询本地说明；精确指定的资源按真实名称和别名解析。词面查找、规则归一、语义重排分别记录，不能只有字符串包含却声称理解所有中文。

**第三步：硬条件过滤。** 输入数量不足、画幅不支持、保护区冲突、文本装不下、运行时不兼容、用户明确禁止的效果先排除。高相关分数不能抵消硬冲突。

**第四步：比较表达方式。** 比较是否容易看懂、与品牌是否统一、是否重复前段、是否增加不必要运动、能否继续修改。可选结果包括不加特效的普通剪切；不使用资源有时是正确决策。

**第五步：确定执行方法。** 有已验证配方就参数化；新官方资源先在隔离候选适配再晋级；确无适合项时允许受控原生构图，但记录原因。显式指定的效果不可静默替换。

**第六步：绑定、预览和入主工程。** 真实媒体、文字与时间绑定后检查最可见帧和运动过程，确认后进入主工程。资源选择回执必须从实际对象和输入产生，不得由规划文本自己认定“已执行”。

### 5.5 已核对的官方资源与产品侧补充

下表仅说明官方资源起点和本产品拟使用方式；不代表当前本地均已安装或适配。没有列出确切 ID 的能力按功能检索，不编一个名字作为运行调用。

| 官方展示／入口 | 已核对标识 | 适合任务 | 本项目必须补的部分 |
|---|---|---|---|
| 多幕商品展示模板 | `product-promo` | S01，部分 S05 | 真实镜头选择、事实绑定、可选槽与续改 [H03] |
| 温和品牌／生活方式模板 | `warm-grain` | S01、S04 | 不改变商品颜色，兼容中文与真实素材 [H03] |
| 活泼社交／发布模板 | `play-mode` | S01、S04 的明确活泼请求 | 不违背克制要求，不让节拍覆盖信息 [H03] |
| 结构化技术风格模板 | `swiss-grid` | S02、S06 | 整体局部关系、清楚字号与媒体占比 [H03] |

| Chromatic Radial Split | 展示名与运行 ID 分开核对 | 明确指定的适合边界 | 两路真实商品纹理、精确范围、导出一致性 [H02] |

上述是功能选择示例，不规定每条片必须使用所有资源。特别是 `mk-placeholder-grid` 的名字带 placeholder，不代表允许成片保留占位内容。

### 5.6 从资源文件到原生工程

应用侧可编辑文档与 HyperFrames HTML 不能双向各改各的。建议由现有原生文档和编译器维护对象身份，编译为 HyperFrames 所消费的 HTML、CSS 和动画时间线；经批准的手工调整必须回写或登记，不形成隐藏第二份工程。

直接嵌入与局部组件适配分别处理。组合需要核对实际内部 ID、尺寸、时间和素材范围；component 需把标记、样式和必要脚本纳入受控对象，防止样式污染其他场景。skill 是规则来源，不能执行其中未经当前任务授权的升级、登录或外部生成命令。[H08]

源码名称不等于运行 ID。资源编译后记录具体对象 ID、输入 assetId、源区间、输出起止、参数和文件版本。相同资源复用多次时，实例 ID 应不同，避免一个修改影响全部实例。

### 5.7 布局先于动画，但静态通过不代替动态通过

先使用实际字体与真实文案检查最可见状态，再加进入、强调、停留和退出。长中文不能为了不溢出无限缩小；应先语义断行、改框宽、精简无关文案或延长阅读。关键词和型号不按单字动画任意拆散。

动画需要与编辑兼容。位置由布局控制、进出由动画控制时，可通过分层包装或统一参数避免互相覆盖；具体实现按当前 DOM 与运行时验证，不能把某个 CSS 位移属性当万能修复。修改后必须在多个实际时间点 seek，并检查最终 MP4。

`data-start`、媒体源偏移、组合时长和动画时钟必须由编译器统一换算。官方文档和不同版本对组合时长、轨道、层级的描述可能有差异，应以锁定的本地运行时和实际预览／导出为准；不能把最新版网页规则直接写进旧运行时。[H01][H09]

### 5.8 自然语言资源请求的完整例子

用户：“第二处色散，其他不要；细节放大时文字别挡产品。”

意图层输出两个独立任务：第二个有效镜头边界应用指定转场，其余边界排除；细节段落采用低遮挡放大说明。资源层解析出真实转场与放大候选，检查两路媒体、动作保护和清晰度。布局层将文字放在可用区域，不把“别挡商品”仅做一个标签。

执行后检查第二个边界前、中、后画面；检查其他边界仍保持；检查放大部位与指向准确。若第二处在教程关键动作内部，应说明冲突并提供最近可用章节边界，而不是用效果偏好覆盖动作合同。

## 06｜声音、字幕与画面的统一排程

### 6.1 声音与字幕是资产，不是最终 MP4 的附属品

至少分别管理原声、旁白、背景音乐、音效、转写字幕、营销／步骤文字。每个声音对象保存资产、源偏移、实际时长、音量、输出位置、角色和版本；每个字幕对象保存文本、真实时间、样式、关联声音与信息单元。

只有混合音轨的 MP4 不自动存在可独立编辑的旁白和音乐；只有烧录字幕的画面也不能宣称可以直接删除旧字。可采用有限分离或覆盖，但应准确展示损失与限制，优先取得源工程而不是承诺无损恢复。

### 6.2 三套时间必须区分

| 时间 | 含义 | 示例用途 |
|---|---|---|
| 源媒体时间 | 原视频或原声中的起止位置 | 从原片第 18 秒截取一段；本文不为显卡编造真实源时码 |
| 语音局部时间 | 某段旁白文件内的词／句时间 | 某句话在这段音频的第几秒开始 |
| 工程输出时间 | 对象出现在最终片中的时刻 | 将该句话放入对应部位显示窗口 |

恒定速率下，源时间映射到输出时间的基本关系为：**输出时刻＝片段在工程中的起点＋（源时刻－源截取起点）÷播放速率**。字幕先裁到有效源范围，再映射和量化到帧。嵌套场景还要加父级偏移；不能把旁白文件从零开始的时间直接当成全片时间。

变速不是简单修改总时长。原声、字幕和动作需要使用相同映射；复杂变速曲线只有实际支持时才使用，否则生成可追溯的同步派生素材。不能承诺原生引擎具备尚未验证的自动漂移校正。[H10]

### 6.3 建立“信息单元”的共同排程

一项可解释的信息由相关画面、旁白、字幕和标注组成，不一定等于一个镜头。S02 的“端部接口”可能有整体定位与近看两个镜头，却应作为一个完整解释单元。

每个单元记录：能支撑它的可见画面窗口、确认术语、旁白片段、字幕、标注、最低理解停留、前后关系及保持项。声音和文字围绕这个单元排程，不分别生成三份互不关联的顺序。

对于具体指称“这里的接口”，旁白应在相关部位已经可辨识时开始；不能提前在风扇画面上解释接口。章节预告句可以先行，或采用经策划允许的声音先入，但不得造成指向误解。旁白尚未结束时，画面仍应继续支持该说明，或明确过渡到相关证据。

### 6.4 旁白从脚本到工程的完整流程

证据支持的短文案 → 术语和发音检查 → 生成／读取真实声音 → 测量时长 → 取得或对齐真实字幕时间 → 检查画面容量 → 安排声音与画面 → 编入原生工程 → 核验实际导出。

脚本字数只能估算，不能作为最终计时。语音过长时依次考虑去重复、拆分信息、换更充分的源段或延长合理停留。必要动作不可为旁白让路，不能用大幅提速和尾部截断掩盖容量冲突。

已有整条旁白不一定必须全部重生成。可在真实测得的句界拆成源区间并重新排程，保留原音频和切分依据；无法可靠切分才对相关句段重新合成。计划有分段列表但工程只有一条不分区间的长音轨，属于尚未落地。

### 6.5 字幕错字、拆词与单字落行的处理

先判断文本源。自己生成的旁白以已批准脚本为内容基准，识别／对齐用于取得时间和发现读音偏差，不能让 ASR 任意改写已确认型号。用户原声则以实际讲话为准，不能把想宣传的话替代实际台词。

术语表记录商品名、部位名、缩写、中文规范写法和必要读法。改正确显示文字不能掩盖读音错误；音频读错就修音频或准确列待审。事实未确认的专业词不因发音顺口就加入。

排版以词组和语义单位分行。先尽量保持“接口布局”“背板开口”等词组完整，再检查行首行尾标点、最后一行孤字、字幕框宽度与遮挡。超过容量时精简非必要营销字或调整布局，不无条件把逐字字幕改成不同意思。需逐字高亮时更要具备可靠词级时间，只有句级时间就采用句级呈现。

### 6.6 角色化音频合同

“不加旁白”“不加音乐”“原声保留”“全程静音”是四种不同要求。原声保留再区分随选段保留和整条独立保留；后者在画面重排后可能造成语义冲突，必须复查。

背景音乐的任务是支撑节奏与情绪，不是覆盖语音。混音检查实测峰值、空白、时长、语言清晰度及结尾，不硬编码所有视频相同音量。音乐不足时选择合格延展或换已有素材；不能机械循环造成明显断点。原声与旁白同时存在时说明优先级，避免两个讲解互相竞争。

上游音频 skill 区分找／生成声音与已放置音轨的混音处理。项目应优先使用本地实际支持的原生能力；缺少某项处理时可受控生成派生音频，记录处理参数并保证预览和最终文件一致。[H10]

### 6.7 MiniMax 的产品接入边界

MiniMax 的语音合成、音色查询和音乐生成分别作为能力提供方，不能合并成一个“有 Key 就全绿”的状态。[M01][M02][M03] 音色接口的已核对请求为 `POST /v1/get_voice`；语音为 `/v1/t2a_v2`；音乐为单独服务。可用模型、返回格式、字幕支持和权限按当前配置及真实响应判断，本文不冻结一个必定可用的账号模型名。

| 用户动作 | 项目负责 | 供应商负责 | 当前无 Key 时 |
|---|---|---|---|
| 查询音色 | 配置、缓存、列表、选择与状态 | 返回账户可用音色信息 | 明确未配置；本地已有音频仍可选 |
| 生成旁白 | 事实脚本、分段、落地、测时、入工程 | 合成真实语音 | 内部协议可测，真实调用待验 |
| 换音色 | 保持内容、更新相关声音与字幕时序 | 新音色合成 | 可以完成内部流程，不冒称已试听新音色 |
| 换／生成音乐 | 选择与混音、版权状态、长度匹配 | 在支持并授权时生成音乐 | 本地可用音乐不受影响 |
| 改字幕 | 文本、时序、样式、语义保护 | 仅在支持时提供相应时间信息 | 原字幕和现有对齐能力继续工作 |

密钥只由服务端读取，不入前端、模型提示、日志和工程包。临时音频 URL 下载并校验后成为本地持久资产。协议测试替换网络边界即可，后面的音频解码、时间安排、字幕、混音和导出仍走真实路径；不可用“返回成功对象”代替音频处理。

重复点击、缓存命中和重试需区分。对支持查询或幂等的供应商接口使用对应机制；同步请求超时且无法确认是否已执行时，不承诺绝对不会重复计费，更不能自动反复重发。保留未知提交状态，在授权范围内对账或说明需要处理。

### 6.8 音频修改影响矩阵

| 请求 | 必须改变 | 默认保持 | 必须复验 |
|---|---|---|---|
| 字幕上移、字号调整 | 指定文字布局 | 音频文件、镜头、文字含义 | 多时点布局与最终画面 |
| 替换本地音乐 | BGM、相关混音与封装 | 商品镜头、旁白与字幕内容 | 输出真实声轨、结尾与响度关系 |
| 音乐小一些 | 指定声轨参数 | 其他声源与时间 | 实际 MP4，不只播放器 |
| 改一句旁白 | 该句音频及关联字幕和必要窗口 | 无关句段与素材 | 时长、发音、接句和画面对应 |
| 换旁白音色 | 所有指定旁白段及时间复核 | 商品事实、源镜头优先保持 | 长度变化、字幕和必要动作 |
| 接口段前移 | 对应信息单元 | 其他对象在允许范围保持 | 旁白、标注、源范围和边界 |

改文字可能重新渲染画面，换音乐可能只需混音和封装。两者都不等于重新生成商品镜头。供应商调用数来自真实日志；模型只规划过而未提交，不记为真实调用成功。

## 07｜S02 显卡案例：从十幕工程到完整详情片

### 7.1 已知输入、报告问题与未知边界

根据用户本轮粘贴的状态，素材路径为项目根目录下 `素材/ASUS_PROART_RTX_4070_Ti_Unboxing_-_By_INVADERPC.webm`；目标为 35 秒横屏详情片，面向关注外观与接口布局的装机用户；原片无声音，使用本地中文旁白，不加背景音乐。现有 Agent 工程已制作十幕，正在修复并导出审阅版。[U01]

已报告问题包括：旁白分段计划没有实际进入声音排程；部分说明早于画面；字幕同音错字；拆词或单字落行；整体与局部关系弱；部分源段跨入不同角度。它们是用户提供的现状，不是本文重新实测所得。本文不凭文件名确认具体硬件规格，不填写未观察的源时码或标注坐标。

需要核对但目前未知：源片各角度的准确起止；是否每个连接位置都足够清楚；现有旁白的实际波形与句界；当前字幕来源；具体原生对象和资源绑定；十幕是否都有必要信息。不能把这些未知用固定分镜数盖过去。

### 7.2 先改信息结构，不先追加特效

建议主表达改为：**“用整体方位把几个可见部位串起来，帮助用户读懂这张显卡的外观与连接位置。”**

十幕是当前制作单元，不必强制删成六幕，也不必保住十幕数量。建议按六个信息段落组织，已有镜头可分别承担整体定位、过渡和细节。一个段落可以含两幕，一幕也可出现两次合理的信息状态。决定保留与合并的依据是观众是否获得新信息。

所有性能、尺寸、噪声和效率描述继续禁止。部位名从画面和确认资料核验；不能把泛称连接位置未经验证具体化为某种标准或针脚规格。

### 7.3 35 秒目标结构与声音文案草案

下表是**待实测调整的成片蓝图**。所有窗口是输出时间，不是源片时码。旁白须先完成发音与事实检查、生成或裁切真实声音，再验证能否放入窗口；不能直接据表宣布排程成立。

| 信息段落／建议窗口 | 画面与空间关系 | 屏幕短标注 | 旁白草案：仅在画面核验支持后使用 | 资源功能与保持要求 |
|---|---|---|---|---|
| D1 整体建立／0—4秒 | 先展示完整显卡，确定观看方向 | “整体外观” | “先看整体，再沿不同角度看细节。” | 大主体＋短标题；不长片头、不写性能 |
| D2 正面细节／4—10秒 | 整体正面→同区域近看；必要时小窗定位 | “正面布局” | “正面近看风扇与外壳的布局。” | 可用推近或整体＋局部；实际画面支持后才标名 |
| D3 侧边位置／10—16秒 | 用正侧相邻画面建立方位，再看对应位置 | “侧边连接位置” | “转到侧边，先定位这里的连接位置。” | 低遮挡标注；不推断规格；图像不清就改中性侧面说明 |
| D4 端部接口／16—23秒 | 交代与侧边不同的面，再展示端部接口 | “端部接口” | “换到端部，再看接口的排列位置。” | 同一名称只指当前部位；不提前在风扇镜头讲接口 |
| D5 背面关系／23—30秒 | 转至背面，先整体再可辨的背板／开口 | “背面结构” | “背面从整体看，再看这里的开口。” | 源段结束不得跨到别的面；不声称开口改善散热 |
| D6 整体回归／30—35秒 | 回到完整显卡或少量已解释区域的回顾 | “把细节放回整体” | “回到整体，各处细节的位置就更清楚了。” | 简洁回顾和收尾；不新增未经要求的促销 |

这些旁白是候选写法，不要求逐字使用。画面不支持“风扇、连接位置、背板”等名称时应改写或换已验证源段。旁白最后一段不是必须；若它重复且画面足够表达，可留自然停顿，让结尾完整。

### 7.4 两种主布局，解决空间关系而不是堆卡片

**布局 A：大画面＋轻量定位。** 用于整体、方位过渡和回归。商品占主要空间，只有当前段落名称或短定位标签。观察者先看商品，不先读一页文字。

**布局 B：整体参照＋大局部。** 用于需要解释位置的细节。整体参照较小但可辨，局部承担主要阅读，二者用一致名称或简单定位框关联。整体小窗不得当成另一条事实证据，位置变化时根据实际角度更新。

两种布局穿插已足以形成变化，进一步变化来自正面、侧边、端部、背面的真实景别关系。强转场不是本案核心；不应在每个角度变化时色散。显式要求效果时单独做指定候选，并保护接口的可见窗口。

### 7.5 旁白段落必须真的落地

先为 D1—D6 建立旁白片段或真实切分区间，并测得每段长度。后续工程应能回答：D4 用哪个音频文件或源音频区间、从工程第几秒开始、何时结束、哪些字幕从该音频产生、与哪组视频和标注绑定。

若已有一条整音频且句界可准确确定，可保留原文件并以不同源区间入轨，不必重新生成全部声音。若整音频没有可靠停顿，或者词语读错，只修相关段落；避免过细切分导致音色与语气不连续。

对每段检测三种错误：开头词已经读出但对应部位尚未出现；画面已切到另一部位而上一句尚未结束；字幕的局部时间未加工程偏移。检查对象是实际 audioGraph／音轨和输出音频，不是旁白计划文字。

### 7.6 当前四类缺陷的具体修复设计

| 已报告缺陷 | 要核对的证据 | 修复的正确层 | 修复后检查 |
|---|---|---|---|
| 旁白计划分段但没有落地 | 旁白计划、实际声音对象、源偏移、混音输出 | 时间排程／音轨构建，不是另写更长 Prompt | 各段音频实际存在且在对应窗口播放 |
| 说明早于对应画面 | 具体名词的发声时刻、部位可辨窗口、标注时刻 | 信息单元同步；必要时缩句或换足够源段 | 接口说明只在接口或明确定位画面中发生 |
| 同音错字或专业词错误 | 已批准脚本、音频读法、字幕文本与时间 | 字幕内容或局部声音；两者分别判断 | 字正确且声音读法正确，不以字幕掩盖读错 |
| 拆词、单字落行 | 实际字体、文本框宽、布局、动态状态 | 中文断行与布局规则，不全局无限缩字 | 正常播放与关键帧均可读，术语不碎裂 |
| 局部缺整体关系 | 观众首次看到局部前的定位画面 | 故事与布局，添加有依据的整体参照 | 观众能指出这是哪一面／哪一位置 |
| 背板镜头越界到侧面 | 源片连续区间、当前出点、播放速率 | 选段出点与对应声音容量 | 输出最后一帧仍属于该部位，话语不拖尾 |

这些只是设计诊断方向，不能未经读取原生工程就把每一项确定为已定位代码根因。

### 7.7 调度回执应该如何讲清楚

一个合格的 D4 制作记录，可以用人读方式表达：

> 此段解释端部接口的位置。选取已观察且可辨的端部源区间；使用大局部画面与短标签，保留前一镜头建立的方位。对应旁白在部位可辨之后开始，字幕由这段真实声音对齐。没有接口版本资料，因此没有参数数字。未使用强转场，以免掩盖接口。标签位置可单独调整。

其中“源区间、资源和时间”在工程记录里必须有真实值。本文不编造 assetId、坐标和源时码，后续由素材观察与编译器填入。这样的记录证明 Agent 作了选择，胜过一句“已调用高级 HyperFrames 模板”。

### 7.8 本案例的修复顺序与完成定义

先核实事实和源段，再修实际旁白分段及声画关系，然后修术语与断行，再改善整体—局部布局，最后检查动效、声音结尾和封面。错误声画未解决前继续加装饰，通常只会增加修复范围。

保留当前母工程与失败版本；在同一创作链上产出候选。至少验证三次修改：端部段前移且其声音与字幕同行；只移动标签而音频不变；字幕字号更改但文字内容和已确认镜头保持。最终工程要能重开继续修改，不能只给新 MP4。

本案通过必须满足：六类信息任务覆盖符合实际内容；没有借外观推断性能；关键名词与画面可对应；字幕无已识别错词和破坏阅读的断行；实际声音符合无背景音乐要求；整体局部关系清楚。缺少真实观片与听感时状态仍为待审，不以十幕、720帧或成功导出代替。

## 08｜原生工程、局部修改与工作台交付

### 8.1 “可编辑”应具体到对象

应稳定识别商品媒体、文字、标注、声音、字幕、转场和布局容器。每个对象知道属于哪个信息段落、源素材和版本。模型返回修改意图后，由受控工具应用，不任意覆盖整份 HTML。

建议将“修改目标、保持对象、必要依赖、预计失效检查”组成一次编辑事务。对象不存在、版本过期、同名字幕出现多次时不猜一个最相近的目标；先依据当前选择和上下文解析，仍不确定才最小澄清。

### 8.2 典型修改的依赖闭包

| 修改 | 直接对象 | 必要联动 | 不应变动 |
|---|---|---|---|
| 标注向上移 | 对应标签／指示线 | 遮挡与动画范围检查 | 媒体源、旁白、其他标签 |
| 部位段落前移 | 对应视频语义组 | 旁白、字幕、标注与相邻转场 | 无关事实、其他商品身份 |
| 只换某镜头 | 目标媒体对象 | 新源时长、保护区与相关声音匹配 | 其他镜头选段、无关文字 |
| 背景音乐降低 | 音乐轨增益／包络 | 最终混音与音量关系 | 商品画面和字幕内容 |
| 改活动日期 | 事实字段的所有引用 | 已朗读日期的声音、相关字幕 | 商品镜头与其他活动条件 |
| 改竖屏 | 变体布局及媒体取景 | 全部保护区、字体、必要时序 | 母版和兄弟版本 |

“保持对象”用工程结构、源区间和文件哈希判断。重新渲染后 MP4 字节变化正常，不能据此判断全部内容重做。反过来，复用一个旧 MP4 也不能证明当前编辑已生效。

### 8.3 版本、缓存与恢复

每次提交绑定基准 revision 和唯一操作身份，成功后写入唯一新版本。撤销恢复对象状态并保留历史；重复相同请求不应冲突或误拿旧目录。

后台任务状态与浏览器连接分开。刷新后仍能定位同一工程、任务和检查点；恢复时校验素材、规则、资源和编译版本。未变化部分复用，失效部分重做。模型服务暂时不可用时保留计划和工程，界面显示真正的失败或待恢复，不把“0秒停止”当完成，也不让已出的片消失。

### 8.4 作品工作台的信息架构

默认入口展示明确的精选／置顶作品和当前制作，不把所有导出历史铺在同一个下拉。全部作品、预设参考和历史版本分别可达。观看预设只读；用户明确选择编辑副本或基于素材创作时才创建工程，避免浏览一次增加一个同名作品。

作品详情显示来源类型、业务场景、当前版本、时长画幅、审查状态、视频与原生包可用性。视频正常而包缺失，应允许播放并准确禁用包下载，不能隐藏整条作品。单条错误不拖垮所有参考。

本地工作台可从服务端受控解析复制实际视频／工程路径；非本地部署不暴露用户私有绝对目录。入口地址跟随实际端口，不把文档中的 localhost 路由当可跨机器访问的链接。

### 8.5 工程包的真正交付

原生包包含可编辑文档／HyperFrames结构、相对素材引用、必要资源与版本、字幕与声音层、使用说明和当前版本。不得包含 Key、登录状态和无权分发字体。不能分发的依赖明确列出，不能声称完全自包含。

验证在独立目录导入，确保不偷读原目录或缓存。重开后修改一个文字和一个音频设置，再导出并检查。能解压 ZIP、能播放包内旧 MP4，都不等于工程可继续编辑。

<a id="quality"></a>
## 09｜视觉质量、场景有效性与评审方法

### 9.1 不把“效果更多”当成质量更高

米家 V2 的意义是建立当前可接受参考，而不是让八场景都套相同广告风格。教程可以在动作呈现和说明避让上超过参考；系列可以在组合关系与空间编排上更丰富；多版可以在画幅重构和版本保持上体现增值。

每条片先过事实、身份、动作、声音和可读性硬门槛，再比较构图、节奏、运动语言和情绪。一个好看的强转场不能弥补错商品或接口说明早于画面。用户说“克制”，少动效可以正确，但不能用这两个字掩盖全片重复布局、碎片特写和缺少信息推进。

### 9.2 五套可复用的视觉表达方向

这些是应用侧设计方向，不是新增业务场景，也不是声称已经制作好的模板。

| 表达方向 | 适用目标 | 主要画面与运动原则 | 禁止的低质量替代 |
|---|---|---|---|
| 主体揭示 | 上新、品牌亮相 | 主体先出现，景别有对比，文字让位，结尾收束 | 长片头＋全程缓慢推同一张图 |
| 结构解释 | 详情、部分问答 | 整体方位、局部证据、稳定标签、合理回归 | 连续近景无定位、每幕大标题遮主体 |
| 动作跟随 | 教程、操作精剪 | 连续动作、步骤同步、低遮挡提示、结果确认 | 强转场跳步、图卡替代真实动作 |
| 组合陈列 | 系列、穿搭、多版群像 | 单款与整体转换、成组节奏、标签随对象 | 同一模板复制多次、身份和事实混用 |
| 信息响应 | 活动、问答、解释型精剪 | 问题／条件与证据同步，重点清楚，可读停留 | 全片价格牌或空泛口号，条件藏小字 |

统一视觉系统包括主要字体与层级、留白节奏、线条／圆角风格、强调色角色、进入与退出方式、信息密度上限。品牌系统允许每幕不同构图，不允许每幕换一个无关模板气质。字体必须实际具备中文字形，导出环境和预览环境一致。

### 9.3 可复验的质量问题

| 维度 | 应回答的问题 | 检查证据 |
|---|---|---|
| 商品识别 | 开头是否能辨识主体，各款是否清楚？ | 实际开场与切换画面 |
| 场景任务 | 详情解释了吗，教程能学会吗，问答答题了吗？ | 完整信息结构与相应连续段落 |
| 事实与证据 | 每个主张有何依据，是否扩大结论？ | 事实引用与源片／资料 |
| 空间关系 | 局部在哪里，标注是否指对？ | 整体—局部前后画面和坐标 |
| 文字可读 | 真实屏幕上能读清，是否错词、拆词或截断？ | 实际字体、完整动态状态及输出帧 |
| 动作连续 | 必要过程和结果是否完整？ | 连续区间，不是稀疏关键帧 |
| 动效适用 | 它帮助理解还是遮挡？指定范围是否正确？ | 前、中、后三个状态与上下文 |
| 声画字幕 | 说的内容是否正在出现，字幕是否来自真实声音？ | 最终音轨、字幕时码和可见窗口 |
| 节奏与结尾 | 信息有推进，停留足够，声音与画面收尾完整？ | 完整播放与时间安排 |
| 可编辑性 | 变更目标后，保持项是否稳定？ | 原生对象差异和版本链 |

数值门槛应在实际发布尺寸和业务风险下校准，不能为了可自动评分随意写一个“所有字幕 0.2 秒误差都合格”。可先使用项目设定的容差进行回归，但通过技术容差不等于听感、语义与阅读正确。

### 9.4 米家与新片的对照方法

先实际读取参考文件及它的来源说明，明确只观察到哪些片段。比较共同维度时，不因为时长、品类或音乐不同直接得出谁更好。新片须在自身场景达标的前提下，列出至少两项可观察增值，如整体局部关系更清楚、必要动作被保留、竖屏文字和主体更可读、修改无需重做所有声音。

工程机制可进一步用**同素材基础版与精编版**比较。二者使用相同事实、素材池和内容范围，基础版保持正常可读，不故意做差；精编版的变化集中在选段、结构、构图、动效与声音配合。对照说明只写观察到的改善，不把计划当提升。

用户最终确认单独记录，模型评审不能替代。自动播放结束证明播放过程，不证明观众理解或创意满意。没有试听工具时，音轨检测与真实听感的状态必须分开。

### 9.5 场景验收需要正例、反例和迁移

| 场景 | 正例必须证明 | 关键反例 | 迁移／输入变化 |
|---|---|---|---|
| S01 | 普通需求得到商品亮相与可信重点 | 缺价格／混型号不能编造 | 换一组非耳机商品或同义请求 |
| S02 | 整体、部位、文案与声音对应 | 无性能资料、标注错位、说明提前 | 调换解释顺序或更换部位 |
| S03 | 完整动作链可理解 | 缺一步不能假装完整 | 不同等待长度或另一个完整操作 |
| S04 | 多款身份和组合关系成立 | 某款缺使用素材不得套另一款 | 调换两款顺序，标签不串 |
| S05 | 主题、条件、时间和入口一致 | 缺报价不得造优惠、旧音频日期冲突 | 改活动字段并联动检查 |
| S06 | 直接回答原问题并给边界 | 证据不足不绝对化、不偷换问题 | 换问题后证据也应按需变化 |
| S07 | 内容更紧凑但原意与动作保持 | 删除否定／条件或必要动作 | 恢复指定片段，检查声画关系 |
| S08 | 两分支变化明确、母版与保持项稳定 | 改 A 污染 B、改比例裁掉操作 | 另一画幅与开头窗口变化 |

### 9.6 缺陷应该进入哪一层修复

“接口文字出现早”优先查排程；“字上移但导出没动”查动画覆盖与编译绑定；“一切都有但仍看不懂”查信息结构和整体局部关系；“商品用错”查身份和证据；“只有某种说法能调到效果”查意图归一和对象范围。

审查记录至少包含原要求、实际文件版本、具体时段、可观察问题、证据、最小修复与保持项。同类问题反复出现，应沉淀为资源输入契约、布局校验或范围解析规则，而不是每次重新让模型“再高级一点”。

### 10.4 分阶段运行时 Prompt 草案

下面是**人读的指导文本**，不是声称已经接入的系统提示，也不是可执行代码。后续应映射现有阶段并配合结构、事实和工具校验；单靠提示无法保证正确。

#### 输入理解与路由

> 根据本轮原话、当前工程与素材范围，先判定新建、修改、精剪或变体，再识别观众需要获得的结果。保留每个显式要求、否定和保持项的来源。不把“HyperFrames 资源”当成资源名，不从商品品类直接推断场景。可逆风格可采用已记录默认；事实、身份、必要动作和不可同时满足的要求才最小澄清。输出制作单与简短理解，不向用户索取逐秒分镜。

#### 素材观察与充分性

> 只依据实际可读内容建立身份、事实、候选区间、动作与保护区。说明真实观察覆盖；转写不替代动作观察，文件名不替代事实。按当前场景验证输入充分性，保留可用部分和明确缺口。候选素材不得因为画面漂亮就替换成别的商品；新制作排除耳机，不生成新商品镜头。

#### 场景导演

> 围绕当前观看目标组织信息段落，每段给出新增信息、源素材依据、画面、文字、声音和保持项。S02 建立整体与局部关系；S03 保护必要过程；S04 保护多款身份；S05 保护活动条件；S06 回答原问题；S07 保持原意；S08 保持母版与分支范围。资源是实现手段，不能先固定模板再编内容填槽。

#### 资源规划

> 先描述功能，再查询本地资源。将精确名称、同义意图、包含目标和排除目标分别处理。运行版本、输入数量、画幅、保护区、文本容量和用户禁止项是硬过滤，相关性不能抵消。列出实际候选、选择／拒绝原因、绑定和执行方式；未适配不称可用。指定效果不能静默换成其他效果，示例内容不得进入成片。

#### 声音与统一排程

> 为信息段落绑定真实画面窗口、旁白段、字幕和标注。读取或生成声音后按实际时长安排；旁白脚本分段必须落实为真实声音对象或准确源区间。具体部位解释不能在无关画面提前出现。区分原声、旁白、音乐、音效与营销字；字幕样式修改不合成声音。容量不够时先缩重复说明，不能剪掉必要动作或截断话语。

#### 原生装配与局部修改

> 在已有受控工具中实现已验证计划，不自由改写目标。使用稳定对象 ID，修改前说明目标、保持项与必要依赖；修改后比对实际对象。布局与动画参数不得互相覆盖；先检验实际文字和素材，再加入运动。复杂度增加必须服务信息任务，不因为资源多而全用。

#### 实际成片审查

> 读取当前版本实际导出文件，对照原需求、事实与动作证据。先检查真实性、身份、必要动作、文字可读与声画关系，再评价构图、节奏、动效和结束。每个问题给出真实时段、证据、影响和最小修复，声明未观察范围。模型意见不替代真人认可；播放完成和技术解码不是创意验收。

### 10.5 可观察的落地验证

普通需求从新会话进入，不粘开发合同，不在终端补手写分镜；记录实际加载的场景和 Prompt 版本。对同义输入、复合指令、否定、多位置和对象选择做功能验证，再进入真实媒体和工程。不能只测字符串结果，必须测最终时间线和画面。

建立“配置规则→阶段决定→资源绑定→原生对象→最终画面／声音”的可追溯关系。修改了音色配置，只使对应声音与字幕时间失效；修改了字体，复验文本布局，不重选商品；修改了素材，重新检查关联证据、保护区与音频。依赖关系是效率和稳定性的基础。

### 10.6 本文向后续实施移交的内容

八场景正文用于完善场景包；通用制作流程用于串起真实生产；资源说明卡和调度约束用于发现与执行；信息单元排程用于音画字幕同步；显卡案例用于把现有失败转成具体修复；原生工程与质量章节用于检验结果。

本轮文档不把七组新片、MiniMax、十类资源或旧模块标为完成。它为这些工作提供制作逻辑和可检验设计，避免再用短状态表或“导出成功”取代产品定义。
