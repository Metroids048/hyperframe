## 1. 执行排序：先验证共用链，再复制到剩余场景

不是先花整周建框架，再在最后一天开始做视频。用已经完成的真实 Agent 工程作为集成载体，让路由、音频和编辑的每一次修改都回到现有 WebUI 与实际成片。

| 优先级 | 工作 | 进入下一项的门槛 |
|---|---|---|
| P0 基准和依赖 | 冻结已完成片；读取真实服务、数据目录、规则与素材池；核对 MiniMax 配置和授权预算；提前检查教程连续动作及系列多商品素材 | 有准确基准和可执行输入；不把摸底文档当完成，也不重做已完成片。 |
| P1 通用路由和兜底 | 统一新建、编辑、精剪、变体；接通场景内与场景外分流；把规则映射进现有运行时 | 普通需求、同义表达、复合要求、否定范围、未知场景、缺料和容量失败得到正确行为。 |
| P2 MiniMax 与声音字幕 | 真实音色查询、短句试音、分段旁白、字幕映射、音乐、音频入轨、混音和导出 | 同一工程最终 MP4 使用真实返回的音频；字幕与画面关联，不仅是拿到音频 URL。 |
| P3 多轮再编辑 | 改字、换音乐、换音色、移字幕、替换已有镜头、撤销、重开和分支 | 目标变更、保持项和版本可验证；普通编辑不整片重新策划，不新增商品镜头生成。 |
| P4 剩余场景逐个完成 | 使用同一底座完成剩余七类；每类独立正例、反例、输入变化和续改 | 每类有自己的真实成片、原生工程和证据，不能只替换标题。 |
| P5 产品与旧账收口 | 精选入口、只读预设浏览、资源范围、恢复、干净目录导入、平台回归、最终观片 | 所有当前可执行必验项都有证据；外部未完成和真人待审单列，不缩小分母。 |

P1—P3 的开发期间即可推进依赖就绪场景；不等待所有基础能力“完美”后才出片。场景未就绪时先做其依赖，不宣布场景通过。并行只用于独立素材检查或不会争用工程的验证；不让多个执行者同时改同一工程／全局配置。

### 最近几个工作日的目标节奏

- **第一个工作日**：固定基准；统一意图与兜底；实际跑通 MiniMax 音色、短句、音频落地和字幕入轨；从同一工程导出一条有真实配音的候选。所有场景先做素材充分性检查，尽早暴露必要步骤、活动事实和系列身份缺口。
- **第二个工作日**：完成完整声音、字幕和连续编辑验收；将精剪与多版直接作为 S07/S08 的场景交付；优先处理教程的动作风险，并制作依赖已满足的剩余场景。
- **第三个工作日及后续连续任务**：逐个结束剩余场景、资源类别和历史问题；干净目录工程往返、故障恢复、作品入口、最终质量比较集中复验。

以上是依赖顺序和目标窗口，不是尚未实测的工时承诺。到达某一天不自动允许把未完成项改为“后续优化”。每项通过后立即继续下一项，实际平台中断则保存精确恢复点。

## 2. 通用意图识别：先判断用户在做什么，再决定业务场景

### 2.1 双轴模型

业务目的：S01 上新、S02 详情、S03 教程、S04 系列、S05 活动、S06 问答。

操作模式：create 新建、edit 局部编辑、recut 精剪、variant 派生。S07/S08 是用户可见任务入口，后端仍继承原业务目的。

控制请求独立处理：取消、撤销、恢复、查看状态等不进入新建或整片导演规划。

### 2.2 决策顺序

1. 识别控制请求、明确的新建要求，以及对当前澄清问题的回答。存在打开工程不代表任何消息都要编辑；“另做一条”按明确新建处理。
2. 对“这一版、刚才那个、第二幕”等解析当前项目、基准 revision、上轮已改变对象及用户选择。
3. 识别操作模式：局部修改优先保留现有计划；整体精简走 recut；另出比例／多个开头走 variant。
4. 新建或目的变更时，识别观众要获得什么，再匹配业务流程。商品名称或视频扩展名不是场景判定依据。
5. 提取原声、旁白、音乐、字幕、时长、画幅、必须内容、禁止项、事实与目标范围。
6. 用真实素材与能力状态检查可执行性；明确的可执行动作直接进行；业务含糊且不同解释会改变结果时提出最小澄清。
7. 生成统一制作／编辑合同，再调用场景 Skill 或通用受控编辑。规则版本、输入、依赖进入缓存与恢复指纹。

不要用未经校准的模型自报“置信度 0.9”作为安全边界。判定依据应是目标、材料和对象是否明确，候选是否产生实质冲突，所需能力是否具备。资源名、模型输出、素材里的文字都不能绕过服务器校验。

### 2.3 制作单与多轮状态

| 信息组 | 最小内容 |
|---|---|
| 请求来源 | 原消息、要求编号、每条约束的原文、默认项与已澄清答案。 |
| 任务上下文 | 操作模式、业务目的、project/revision、对象焦点、当前分支、上一轮实际变更。 |
| 内容与证据 | 商品身份、受众、确认事实、未知事实、素材范围、步骤／问题／活动条件。 |
| 输出与声音 | 时长和比例；原声、旁白、音乐、音效分别保留／禁止／新增；字幕的内容类型。 |
| 执行范围 | 目标对象集合、排除对象集合、时间范围、保持对象、锁及必要依赖。 |
| 调度 | 主 Skill、辅助 Skills、能力需求、选择资源、执行方法、回退触发条件。 |
| 状态与证据 | 已读取什么、下一动作、需要用户补什么、实际使用资源／供应商和降级原因。 |

跨轮明示修改覆盖对应旧约束，不清空其他约束。用户说“音色换沉稳一点，其他不动”，只更新音色目标及必要时序依赖，不清除“无音乐”“不写性能”等要求。

## 3. 八场景路由、Skill 和场景内兜底

以下 `commerce.*` 为**建议的项目级 Skill 标识**，不是现有官方资源名，也不要求新建八个服务。映射进当前场景包和 Prompt 加载链。原先完整的人读版场景正文继续作为内容依据。[D1]

| 场景／路由触发 | 专用 Skill 及决策职责 | 正常链路与资源功能 | 兜底：允许做什么；何时停 |
|---|---|---|---|
| S01 新品首发／品牌亮相：想让初次接触者认识、记住商品；不是完整教操作 | `commerce.launch`：挑一两个可信重点，选择开头、景别和收尾 | 同款核验→整体／细节选段→记忆点→主视觉、轻标题、克制揭示、CTA | 缺性能资料就不写性能；少量细节可减少表达，不重复填时长。用户必须要真实使用但没有片段时，提出具体补料；不得静图冒充。 |
| S02 详情／卖点图解：要解释某个结构、位置、配件或有依据的特性 | `commerce.detail`：主张—证据—部位绑定，整体与局部关系 | 整体定位→局部证据→联动／分区→回到整体；callout、局部放大、对照构图 | 无可靠跟踪时改用稳定片段或明确冻结帧标注；没有证据的结论删除或请求资料。明确要求连续跟踪时不能静默用静态箭头冒充。 |
| S03 开箱／安装／使用：观众要按步骤完成或理解实际过程 | `commerce.procedure`：区分子类型，必要步骤、依赖和动作保护 | 起始状态→连续必要动作→关键检查→完成状态；步骤条、局部高亮、源声同步 | 时长紧优先删等待而非动作；不足以完成时说明时长冲突。缺必要动作就不能交付完整教程，可以给明确不完整的审阅候选，不能计正例通过。 |
| S04 穿搭／组合／系列：多款、搭配或同款多个明确造型的关系 | `commerce.collection`：身份分组、各款曝光、比较条件、群像 | 关系建立→各款→组合变化→群像；网格、分屏、统一文字、匹配切换 | 缺某款使用镜头可仅作该款真实外观展示，但不能违反用户逐款使用要求；不能借另一款填充。删款或改组合关系需明确许可。 |
| S05 活动促销／直播预告：观众要知道条件、时间、参与方式 | `commerce.campaign`：活动字段、条件完整性、声画一致和过期风险 | 活动核验→主题／价值→条件→行动；独立日期、价格、条件、CTA 对象 | 无价格可作允许的无价格预告；必须的活动日期／入口缺失先澄清，不造数据。模板不适合就去掉价格槽，不能把优惠条件缩得不可读。 |
| S06 选购说明／问答：围绕一个具体问题需要结论与依据 | `commerce.evidence_qa`：解析问题、证据强度、适用条件 | 问题→直接回答→演示／资料→限制；问题卡、证据定位、结论层级 | 没有测试或规格不能编性能答案；能回答的部分与未知项分开。需要操作证明时调用 S03 子流程，不偷换成上新。 |
| S07 已有视频精剪与包装：保持原意、删冗余、增强清楚度 | `commerce.recut`：识别关键内容、可删等待、声音上下文 | 原意分析→删留→受控剪接→字幕／图形／声音包装→前后比较 | 只有 MP4 时仅承诺可编辑新增层与可剪源片，不承诺恢复烧录字幕和混合音轨的原分层。源工程缺失不必阻塞所有剪辑，但相关不可实现要求要说明。 |
| S08 一稿多版／开头／画幅：母版派生、改变局部或发布用途 | `commerce.variant`：目标变化、保持集、母版继承与布局重算 | 读母版→定变化／保持→分支→重排→比较；重框、分支开头、比例布局 | 竖屏中心裁切损害动作时，选合适源片、分区或保全主体版式；不能假装满幅。明确同时要求“仅开头”与改变后文时澄清，不能擅自动母版。 |

### 3.1 每个 Skill 必须是执行合同，不是一段口号

必须登记：用途和不适用情况；输入与前置条件；按顺序调用的现有工具；事实和动作保护；资源需求与输入契约；失败分类和具体下一动作；产物；修改时保持项；正例、等价输入和关键反例；实际加载和执行版本。

Skill 不直接获得任意 shell、网络和写文件权限；调用现有受控工具。上游 Skill 的默认选择不能覆盖用户明确声音和画面要求。

### 3.2 S02 Skill 的落地示例

**触发**：用户希望看懂接口、结构位置和外观关系，不是学安装，也不是判断性能。

**输入**：商品身份、已批准事实、真实可用源区间、部位保护区、当前声音合同、输出条件。文件名可辅助找素材，不是硬件规格证明。

**执行**：先建立整体；给每个局部说明绑定部位及对应源区间；稳定／冻结／实际可用跟踪三选一；确定信息段；生成并测量各段旁白；统一声画时间；绑定标注、版式和轻转场；导出后检查讲到的部位是否出现、标注是否准确、术语和换行是否正确。

**故障分支**：跟踪不可靠→稳定段或标明冻结（明确跟踪要求须说明）；话太长→先去重复，必要时调整对应镜头；术语读错→修读音字典并只重配对应段；字幕显示错→修字幕，不默认重做音频；找不到事实依据→删除自拟主张或澄清。

**输出**：事实—镜头映射、场景方案、资源回执、音频和字幕资产、原生工程、实际视频、问题清单、当前 revision。

## 4. 共用 Skills 与 HyperFrames 资源融合

| 共用能力（设计标识） | 负责什么 | 关键限制 |
|---|---|---|
| `intent.resolve` | 意图、上下文、对象、否定、复合请求和最小澄清 | 不让分类结果改写事实；控制请求不触发制作。 |
| `media.evidence` | 素材发现、同款、可用区间、事实和动作证据 | 没观察到不声称观察到；素材和资源说明按数据处理。 |
| `resources.route` | 全量发现、意图召回、条件过滤、具体执行器绑定 | 发现不等于可用；明确资源和范围不能被静默替代。 |
| `native.compose` | 参数化／受控适配、稳定对象、布局与动画 | 不每轮自由重写整片；验证本地版本与输入槽位。 |
| `audio.schedule` | 原声、旁白、音乐、字幕局部时间到工程时间 | 实际音频长度驱动排程，不用文本字数代替时长。 |
| `edit.scoped` | 局部操作、保持集、失效范围、分支和回滚 | 原工程与旧有效导出不覆盖；新版本验证后发布。 |
| `quality.review` | 实际 MP4 检查、问题定位、受控修复、交付状态 | 技术通过、业务审查和真人认可分开。 |

上述设计应复用现有 R 阶段 Prompt、场景包、资源目录、编辑工具和验收器；不新造多 Agent 讨论系统。

资源功能覆盖 template、composition、component、effect、transition、skill、caption、typography、lower third、shader。功能标签与来源／执行类型分开。官方 registry 的 block 为独立子合成，component 为需要并入宿主的片段；下载完成不代表已绑定工程。[H1]

调度顺序：业务目的和该段功能→候选召回→素材／文字／画幅／动作保护／版本／依赖过滤→已验证执行器优先→当前素材绑定→局部预览→主工程。无合适现成资源时，只对确有需要的部分做受控适配，检查后可登记复用。

对简单改字号、位置、音量、指定切点使用受控操作；对新信息结构才用模型策划。执行器实际做了什么必须与回执一致。显式 Chromatic Radial Split 不能实际用淡入却写色散通过，官方 SCENE A/B 或示例数据不能进入商品成片。

一条片不用十类资源全部出现；十类能力的有效验证分别记录。资源改版本、素材改比例或关键绑定变化时重验受影响条件，不自动沿用横屏历史通过。

## 5. 场景之外的兜底与意图歧义

兜底不是默认套上新模板，也不是把困难需求一律拒绝。先看原目标能否在当前能力下被正确实现。

| 输入类型 | 正确分流 | 例子与结果 |
|---|---|---|
| 属于八类，只是说法不同 | 结构化理解→同场景 Skill | “让第一次看到的人先认出它”可以是上新，不能要求精确说“新品首发”。 |
| 混合目的或复合操作 | 一个主目标＋辅助子流程，保留共同合同 | “做安装教程，再给竖屏版”是 S03＋variant；教程动作约束仍有效。 |
| 没有场景名但操作明确 | 通用受控编辑 | “第5秒加标签，音乐小一点”直接编辑；不要先问营销场景。 |
| 不在八类模板，但能由现有能力组合 | 通用编排合同＋同一资源调度与审查 | 电商展会片加章节、对已有商品视频加多语种说明；标通用工作流，不另建第九套服务。 |
| “帮我优化一下”，多种理解会明显改变结果 | 读取工程与问题记录；仍不明确则最小澄清 | 问“主要想缩短时长还是加强说明”，不让用户提供逐秒脚本。 |
| 要求已经暂停的视觉生成，或尚不支持的跟踪／三维等 | 能力边界与可行部分说明 | 不调用被暂停的视觉生成；不把静图运动冒充新真实动作。 |
| 缺必要素材、商品身份或事实 | needs-input，并保留已有制作单和素材观察 | 只问缺失项，继续不依赖该项的工作；缺动作的拒绝不计完整教程通过。 |
| 项目不存在、对象歧义、旧 revision | 先解析当前真实状态或澄清；禁止误改 | 不把“第二处”自动作用到另一个项目；冲突不覆盖用户的新修改。 |

通用工作流与场景工作流共用素材证据、工具边界、音频、可编辑工程和质量标准；它不是无约束写 HTML 的后门。不能借通用兜底降低原目标或取消事实校验。

## 6. 运行失败的兜底：业务、资源和基础设施分别处理

| 失败类型 | 自动处理 | 不可做的事 |
|---|---|---|
| 场景识别或结构输出格式错 | 依据原输入和 schema 做有限修复；仍歧义就最小澄清 | 将错误结果直接推进渲染，或为过 schema 换业务目标。 |
| 可选装饰资源缺依赖／渲染失败 | 修适配；确实不可用时，在保持业务与用户约束的前提下换已验证等价表达，记为降级候选 | 用户明确指定的效果失败后静默换成别的并记完成。 |
| 主体／步骤／事实无法支持 | 保留候选和缺口，停止对应完整交付判断 | 用漂亮字幕补假动作、用模板填假参数。 |
| MiniMax 音色／权限不可用 | 给准确错误；保留旧音轨，允许用户选择实际可用音色；已授权本地备选另行标注 | 未经许可切换供应商／音色、默认静音后声称已配音。 |
| 字幕对齐粒度不足 | 只有句级时间就用句级呈现；重取可用对齐或实际 ASR | 均分字数假造逐词卡点。 |
| 渲染失败 | 保留最后有效版本；定位资源／布局／媒体／运行环境后重做受影响部分 | 覆盖旧成品或用历史 MP4 当新版本。 |
| 主模型 at capacity | 在已批准且能力兼容的候选模型内恢复；无可用模型则保存同一任务等待恢复 | 把 TTS API 当导演模型，或改用不具备视觉能力的模型却声称完成观察。 |
| 付费生成提交后结果未知 | 持久请求摘要、状态与 trace；查可取得记录，暂停盲目重发 | 虚构供应商查询接口或宣称本地幂等能保证远端绝不重复收费。 |
| 用户取消／过期并发修改 | 保存已产生资源，不发布取消后结果；核对新基准再继续 | 取消后继续批量提交付费任务，或迟到结果覆盖新 revision。 |

建议映射现有状态：正常候选、降级候选、待输入、可恢复、明确不支持、失败、待真人。降级候选可以预览，但不等于“比米家更好”的质量目标已通过。接口或模型失败不能把任务默认为成功。

每条兜底记录触发原因、原要求、允许保持项、实际采取的动作、影响、用户是否需确认、恢复动作和验证方式。既有权限、预算和安全规则优先；不无限重试，不为了早点结束临时缩小预算。

## 7. MiniMax 真实接入方案

### 7.1 先把正确边界接上

MiniMax 本轮承担语音、音色目录和音乐；不替换业务导演模型，也不承担 HyperFrames 混音或原片 ASR。

服务端从用户本地已有配置读取 Key；不让用户把 Key 粘贴进对话，不打印、不推 Git、不打包。确认该 Key 所属区域、类型、可用资源与预算；有 Key 不等于所有音频模型都已成功调用。[M0]

中国站文档使用 `https://api.minimaxi.com`；国际站文档使用 `https://api.minimax.io`。地址按账户配置，不无依据跨区域尝试。[M1][M5]

### 7.2 核对后的接口合同

| 能力 | 方法与路径 | 必要处理 |
|---|---|---|
| 可用音色 | `POST /v1/get_voice` | 使用文档支持的 voice_type；解析实际音色信息，以 provider + voiceId 存储，不从本地 zf_/zm_ 前缀判断所有音色。[M2] |
| 同步旁白 | `POST /v1/t2a_v2` | 配置模型、text、voice_setting、audio_setting；首轮采用非流式，开启需要的字幕；解析 HTTP 与 base_resp、音频和附加信息。[M1] |
| 音乐 | `POST /v1/music_generation` | 按账户选择实际支持模型；背景伴奏在支持的模型设置 `is_instrumental=true`；不把广告文案作为歌词唱出来。[M3] |

TTS 当前字幕字段是 `subtitle_enable` 与 `subtitle_type`。字幕类型支持 sentence、word，以及仅流式使用的 word_streaming；不要把旧稿里的描述词当接口字段名。非流式输出可为 hex 或 url；临时 URL 要及时落地，不作为工程永久依赖。[M1]

中国站当前音乐文档列有 music-3.0 和 music-2.6 等模型；不要继续把旧配置中的 music-2.6 当唯一选项，也不要不经账户和预算检查就切到新模型。[M3] 音乐时长以返回文件实测，匹配视频的裁切、合理循环、淡出交给工程；不编造已经支持的 duration 请求参数。

### 7.3 必须修改的真实调用链

1. 在现有 MiniMax adapter 内实现请求执行、业务错误映射、非空校验、音频接收／解码和元数据归一，而非只声明 configured。
2. 扩展配音 provider 选择，使真实制作和试听路径都能进入 MiniMax；`CodexProvider.speak` 目前的旧分支不能保持原样。[R4]
3. 保持既有返回契约兼容。原 speak 消费者需要 WAV 字节时，进行明确转换或增加兼容的带资产／字幕结果方法，不能把返回类型悄悄改成另一种结构。
4. 把 `creativeVoiceInteraction` 的固定本地音色 schema 改为实际能力目录；前端音色显示、选择、试听和历史已选声一致。[R5]
5. 每段声音成为持久资产，带来源、模型、真实 voiceId、音频哈希、测量时长、字幕与 trace；临时链接不进入最终母工程。
6. 将结果接入已有 audioGraph、字幕时间投影、版本、撤销和导出；不是只开一个孤立音频测试页面。

建议的适配职责为 listVoices、synthesizeSpeech、generateMusic、normalizeAudioResult；这些是待映射到现有代码的职责名，不宣称已有函数。结果应统一为实际音频资产、时长、字幕 cue、provider/model/voiceId/traceId、可取得的用量与状态；缺费用不编金额。

### 7.4 先保证“说到哪里、看到哪里”

对于详情、教程、问答：信息段→批准文案→实际生成／读取旁白→测量时长和有效字幕时间→落到对应证据画面的时间窗→再完成最终版式与动画。

不要先渲染整片，再把一条长声音从零秒铺到底。分段以完整意思和自然语气为单位，不机械逐字或固定一幕一句。已有整条声音可依真实句界切分并重新排程，不必总是重新合成。

源时间／旁白局部时间／工程全局时间分别存储，接口返回单位实测后统一。恒定速率映射：输出时间 = 工程片段起点 +（源时间 − 源截取起点）÷播放速率；字幕还需裁到有效区间并量化到帧。

语音超出画面窗口时，先去重复和精简不必要解释，再选择更充分的同部位片段或调整允许的时长；不能截断声音、牺牲必要动作或擅自加速整片。锁定时长与完整内容无法同时满足时，明确这一冲突。

生成旁白以批准脚本为文字基准，使用实际返回时间；原片原声使用独立 ASR／对齐能力。不能让 ASR 把确认型号改成同音错字；读音错误需修声音，而不是只把字幕改对。中文分行按词组、标点和实际字宽检查，避免型号拆开或单字落行。[D1]

### 7.5 真实接入的最短验证次序

音色查询→一条短句试音→正确落地和完整解码→一段带字幕旁白进入已有工程→最终 MP4 声音与对应画面核对→换音色并重排受影响字幕→改一句文案只更新相关段→纯伴奏音乐生成或换已有音乐→混音导出→刷新重开仍可用。

正常场景不需要每次用户先批准所有试听；仅当用户要求试听或在选声时展示选择。明确默认音色可自动执行，用户选择必须可覆盖。

### 7.6 错误、缓存与付费请求

文档区分超时、频率限制、鉴权和余额等错误；先判断 HTTP，再判断业务码和实际文件。[M4]

缓存键包括账户命名空间（不存明文 Key）、供应商、区域、模型、音色、文本、读音配置、语速、格式和字幕策略。改音色只失效相关声音；改字幕样式不失效 TTS。成功音频先原子落盘校验再登记；任务取消或输出过期不能错误发布。

查询音色可以有限重试；付费生成的请求超时需区分“明确未提交”和“提交结果未知”。后者保留 UNKNOWN 状态，不能盲目重发。同步 TTS 的 trace_id 用于定位记录，不应被冒充可查询异步 task_id。[M1][M4] 本地去重不能保证供应商侧严格恰一次计费，必须如实记录。

## 8. 多轮自然语言再编辑：不是零开始，但必须成为可靠产品能力

当前 `planCreativeEdit` 已有文字、音轨、转场、顺序、素材替换等操作以及受控原生修改路径。[R2] 正确做法是补上下文和验证，不另造“聊天编辑器”。

执行顺序：当前请求→真实基准工程和对象→目标／保持集→现有确定性操作或模型规划→服务器校验→受控 patch→受影响范围失效→预览／导出→保持项检查→发布新版本。

简单操作不需重做整片导演；复杂布局可走既有受控原生适配，但必须绑定场景和对象并通过检查。不能让一个拥有全目录写权限的编码代理直接改母工程后，跳过版本、锁、资源证据和回滚。

### 一条必须实际完成的多轮链

| 轮次 | 用户行为 | 允许变化／必须保持 |
|---|---|---|
| 1 | “把片尾这句话改成我给的文字，其他不动。” | 只改对应文字及必要可读性处理；声音中读了该句时识别关联冲突，不自作主张重配。 |
| 2 | “换成已选的沉稳音色，文案不变。” | 更新相关旁白；测时长并重排关联字幕；商品源片、事实和非相关段保持。 |
| 3 | “音乐再轻一点，结尾自然淡出。” | 只改音乐音量／淡出；不重新生成声音内容和商品素材。 |
| 4 | “字幕再往上移一点。” | 使用当前字幕对象和当前值；不回到原默认字号／位置；不重配音。 |
| 5 | “第三段换成素材库里另一个同部位镜头，别动其他段。” | 只选适合该目的的同商品备选；检查布局和相关原声；无视觉生成。 |
| 6 | “撤销刚才换镜头，但保留前面的音色和字幕。” | 撤销第五轮，不整条重置，也不把“刚才”指向错误工程。 |
| 7 | “基于这一版再出竖屏，原版保留。” | 独立分支、主体重框、字幕重布局；原版和非目标分支不变。 |
| 8 | 刷新／重开，导出工程包到干净目录，改字和音频后再导出 | 资源可访问、历史可追溯、不靠原工作区绝对路径。 |

另测同名文字、过期 revision、并发修改、锁定段、不存在对象和明确取消。后一次迟到响应不能覆盖用户较新修改。单次 patch 成功不等于多轮链完成；新视频字节改变也不能说明全片被重做，应比较原生对象、源区间、声音哈希和修改依赖。

## 9. 场景成片与质量：完成一个，封存一个

八类工作流全部覆盖；已完成那一场景保留合格结果，余下七类逐个交付。S08 至少两个用途明确的派生版本，不能用多个版本数凑场景数。S07/S08 可复用现有母工程和素材，但必须有真实精剪／重布局价值。
