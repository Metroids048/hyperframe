更新：新增、改字字幕默认生成对应旁白，删除字幕同步删除关联旁白；已有讲话字幕复用原声。已知的短旁白台词直接配字幕，无需再次语音识别；同文同音色配音跨项目缓存复用。超出字幕时长或与其他旁白冲突时会提示调整，不截断朗读。验证记录：outputs/caption-voices/report.json。

这份说明对应 2026-09-09 本机运行的对话剪辑 Demo，描述实际代码，不把原实施计划中尚未启用的服务当成现有能力。

当前流程是：导入原视频 → 在唯一聊天框输入要求 → Codex 理解并输出编辑清单 → 程序校验和修改时间轴 → 合成声音、生成 HyperFrames 工程 → 检查后更新预览 → 自动导出对应版本的 MP4。选择样例仅导入原片；点击常见要求仅填入文字，发送后才执行。历史版本是编辑记录，不是预先准备好的答案。

**各部分如何分工**

| 部分 | 当前实际实现 | 模型是否参与 |
| --- | --- | --- |
| 读取视频 | 流式上传，FFprobe 检查时长、尺寸、旋转和音轨；FFmpeg 生成 30fps 工作副本、低分辨率预览、缩略图和波形。原文件保留 | 否 |
| 理解聊天 | 通过本机已登录的 Codex CLI 使用 ChatGPT 订阅，当前配置 gpt-5.6-sol。输入本轮要求、当前版本、素材信息、选中引用及最近对话；输出受 schema 限定的编辑清单 | Codex |
| 理解画面 | 对需要内容判断的请求，联合定时抽帧、镜头变化和真实转写建立场景索引。内容选片会再对候选范围密集抽帧复核；场景必须附已有证据时间 | Codex 看抽帧；本地 Whisper 转写声音 |
| 精确修改 | 校验素材 ID、图层 ID、范围、时长与基础版本，再由固定代码应用操作 | 否；模型不能任意运行命令或改工程 HTML |
| 中文配音 | 本机 Kokoro 生成 WAV，使用 HyperFrames TTS 下载的模型和音色；Misaki 中文前端处理发音，再检测真实长度 | 本地语音模型，不是 Codex 输出音频 |
| 讲话字幕 | 本机 faster-whisper small 识别词级时间戳，按停顿、句长和显示时间分组，映射到当前成片 | 本地识别模型 |
| 声音合成 | FFmpeg 按时间轴裁切、延迟、调音量、淡入淡出和混音，生成一条 master 音轨 | 否 |
| 视频呈现 | 时间轴确定性生成 HyperFrames HTML；Player 播放，HyperFrames check 检查，strict render 导出；FFprobe 核对导出规格 | 否 |

当前默认不需要填写 API Key。代码保留了另外的 OpenAI API 模式，但此 Demo 实测走订阅模式；最初计划里的 whisper-1、gpt-4o-mini-tts 和 marin 云端音色不是当前默认实现。当前本地配音主要支持固定普通话女声/男声，尚不能把任意音色、语速、情绪要求都精确映射到生成参数。

**自然语言如何变成时间轴**

时间轴固定 30fps，所有操作转换为整数帧。视频片段记录素材 ID、源入点 in、源出点 out 和原声音量；片段按顺序拼接，累计长度决定在成片中的位置。字幕和附加音轨记录稳定 ID、成片 start/end；音轨另有素材入点、音量、淡入淡出、旁白/音乐角色等字段。

例如“删掉开头三秒”，模型输出 delete_range，范围为第 0～90 帧。程序保留源第 90 帧以后的画面，原声跟随同一源范围；原来第 5～8 秒的字幕由 150～240 帧映射为 60～150 帧，即新视频的第 2～5 秒。后续旁白也使用同一映射；跨越删除区域的图层会裁切或拆分，并保留关联 ID。

“只保留前十秒，第 2～5 秒写『新品上市』”对应两项操作：keep_ranges 保留 [0,300)，caption_add 在 [60,150) 添加文字。结束边界不显示，所以字幕从第 60 帧显示，到第 150 帧消失。字幕由独立 HTML 图层承载，GSAP 和 HyperFrames 按时间控制显隐；同时出现的字幕按实际文字尺寸分层，避免互相盖住。

同一条请求里的时间都指发送时的基础版本，统一解析后再映射，不能前一个删除做完就改变后一个时间的含义。“原视频第几秒”会通过源入出点映射；无法唯一定位就提问。执行中的后续聊天可以排队，轮到执行时以已完成的前一版为基础；前一任务失败则保留后续要求，等待处理，不越过失败任务乱改。

“剪到十五秒以内”由模型根据内容选择保留范围，执行器验证总长度不能超过 450 帧。程序不擅自加速；内容证据不足或必须保留的内容放不下时要澄清。语义判断仍可能需要修正，整数帧校验不能证明模型理解了用户的全部意图。

每次成功修改写入一个新版本，保留时间轴、编辑清单、素材引用和父版本。旧版下载仍可用；撤销或恢复也创建新版本。重复请求通过幂等键识别，过期基础版本不能覆盖当前结果。明确的“撤销上一步”和“回到第 N 版”直接走版本逻辑，无须调用模型。

**HyperFrames 如何实际参与**

编译器为每个片段生成 video 元素，以 data-start、data-duration 和 data-media-start 指定成片起点、持续时间、原素材入点。字幕生成定时文字图层；工程尺寸和 object-fit 决定横竖屏及完整适配/裁满。HyperFrames Player 负责工程预览，HyperFrames CLI 负责检查及最终画面渲染。

视频元素自身静音，避免原音频重复播放。原声、旁白和音乐由 FFmpeg 按同一时间轴合成为 assets/mix.m4a，然后作为工程中唯一的 audio 引用。预览和导出使用同一混音，所以检查声音必须同时核对混音文件、导出文件和浏览器实际输出。Player 的 Web Audio 接管声音时，内部原生 audio 元素显示 muted 属于正常机制，不能据此判断无声。

配乐压低依据识别到的讲话时间段：进入人声范围时，音乐在设置音量基础上乘 0.22，前后各留少量缓冲；新增旁白按其实际播放范围参与压低。淡入淡出单独处理。这个功能不会把已经混在原片里的音乐和人声拆开。

聊天编辑完成后先发布可播放工程，再排队导出 H.264/AAC MP4。导入、理解、配音、字幕对齐、合成、检查、导出等阶段显示 loading、已用时间和进度；模型阶段的进度是阶段标记，不是假装知道精确剩余时间。失败会保留输入及旧版，不显示为成功。

**聊天框上方每个常见要求的实现**

所有按钮只是自然语言模板，用户可以改写；点击不会直接提交预制编辑清单或切换成片。除明确撤销外，发送后仍调用当前 Codex 规划器，再走同一执行器。

| 预设 | 实际要求和执行路径 |
| --- | --- |
| 剪成 10 秒，加一句字幕（产品样例） | 保留原片前 10 秒；第 2～5 秒添加“清爽一刻，即刻出发”。生成 keep_ranges＋caption_add |
| 配中文旁白并自动加字幕（产品样例） | 第 1 秒开始说“欢迎体验我们的新品”；先生成声音，检测长度，再转写本轮旁白生成字幕；原声降到 15% |
| 按画面自动添加说明字幕（咖啡样例） | 先分析咖啡画面和已有商品信息，再规划 4 条说明字幕，每条 4～6 秒。不改烧录文字 |
| 精简成 15 秒品牌短片（咖啡样例） | 根据画面索引选片，保留开场和产品内容，验证不超过 15 秒；最后 3 秒加“从一杯好咖啡开始” |
| 给讲话自动加中文字幕（讲解样例） | Whisper 识别原视频讲话，时间戳映射到现有片段，生成字幕图层；不把画面说明当成讲话 |
| 加入轻快背景音乐（讲解样例） | 使用内置音乐，覆盖前 15 秒，音量 20%，淡入淡出，人声期间压低 |
| 剪到 10 秒（通用） | 保留当前视频前 10 秒，同步裁掉其后的原声、字幕和附加音轨 |
| 加一句字幕（通用） | 在当前视频第 2～5 秒添加“新品上市” |
| 加一句旁白＋字幕（通用） | 第 1 秒开始生成“欢迎体验我们的新品”，添加对应讲话字幕，原声降到 15%。这是一句短旁白，不代表整条视频都有解说 |
| 加入背景音乐（通用） | 内置音乐覆盖前 10 秒，淡入淡出，人说话时压低；音乐起止受时间轴校验 |
| 撤销上一步（通用） | 复制父版本时间轴建立恢复版，保留全部历史 |

样例会显示对应的 2 项要求，加上通用的 5 项。视频短于预设指定范围等约束冲突不能伪装为执行成功，需缩短范围或调整要求。

**“时间轴与精确工具”中的功能**

精确工具读取用户填写的数值或选中对象，直接生成结构化操作，省去 Codex 理解这一层；它们仍使用相同的校验、执行、版本和 HyperFrames 编译流程。涉及配音/识别时仍调用本地语音模型。当前精确工具完成后更新预览，MP4 用“导出视频”生成；聊天路径则自动安排导出。

| 精确工具 | 如何执行 |
| --- | --- |
| 添加字幕 | 起止秒数乘 30 并取整，文字与上/中/下位置生成 caption_add |
| 从讲话生成完整字幕 | caption_transcript，对当前可听见的原片及旁白转写、分组并对齐 |
| 删除范围 / 仅保留范围 | delete_range / keep_ranges，按源入出点切片，同步重排所有图层 |
| 在起点分割 | split，把当前片段分成两段，视觉和时长不变，方便后续独立处理 |
| 选中片段移到起点 | move，按选中片段 ID 调整顺序，附着于该范围的声音和字幕跟随 |
| 在起点插入素材 | insert，把选定视频插入指定位置，后续内容顺延 |
| 添加音频 | 从所选音频开头取指定长度，放到起止范围，应用音量、淡入淡出和可选人声压低 |
| 生成旁白 | voiceover，合成输入台词，用真实音频长度确定终点；范围放不下会报具体冲突，不偷偷截断 |
| 调整选中原声 | clip_volume，只修改选中视频片段的原声音量 |
| 删除选中图层 | 根据字幕/音轨 ID 执行 caption_remove / audio_remove |
| 调整画幅 | 修改工程真实宽高和 contain/cover；完整适配保留画面，裁满会裁掉边缘 |

移动或插入每轮只执行一次，并与删减分轮处理。现有精确面板只是快捷入口；需要换字幕内容、替换指定旁白、复杂保留范围等，可直接在聊天中提出。

**本次“字幕有、声音没有”的核查结果**

咖啡项目第 4 版的旁白是“欢迎体验我们的新品”，实际放在 1.00～3.27 秒；截图停在 13 秒，那里的宣传字幕不是仍在朗读的旁白字幕。核查发现该版混音、MP4 以及嵌入式浏览器在旁白区间都有实际音频输出，不能把这次情况写成“没有生成声音”，也不能仅凭本机检测断言用户设备上一定听到了。

这次增加了明确的旁白时间和原文、“试听本段旁白”“定位到视频中的旁白”，并让“播放修改处”优先跳到新增旁白。切换工程时重建 Player，避免旧媒体条目残留；试听与视频互斥。浏览器补测了暂停、重播、跳转、静音恢复和版本切换；同时解码导出 MP4 检查声音。

复现测试：node scripts/test-preview-audio.mjs 检查现有咖啡项目，结果在 outputs/preview-audio/report.json；node scripts/test-preset-loading.mjs 在独立测试数据目录通过真实订阅重跑 11 个预设，结果在 outputs/preset-loading/report.json。音频检查包含实际输出信号和语音识别回读，不等同于人工主观听感验收。

对应代码：web/editor.js（聊天、预设、精确工具、loading、试听），lib/edit/codex-provider.mjs（订阅、本地语音模型），lib/edit/provider.mjs（分析和规划），lib/edit/service.mjs（任务、语音字幕准备、版本），lib/edit/timeline.mjs（精确时间轴），lib/edit/media.mjs（素材处理、混音、HyperFrames 编译和渲染）。
