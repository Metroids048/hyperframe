## 1. 唯一终点
用户从日常主WebUI打开自己的真实作品，直接用自然语言编辑；改动准确、反馈可见、等待可解释；八类场景均有符合各自业务目标的完整成片，S08两派生，最少9条；全部保留可重开的原生工程与版本、真实声音和效果，主服务与受验构建相同。

全目标达成必须同时满足：业务、主入口、真实链路、成品检查、性能、版本恢复和源/权限边界。任何独立子项通过不自动关闭总目标。

## 2. 顺序和工作包

W0 发布到正确入口 → W1 成品直接续改 → W2 交互/制作性能 → W3 真实连续编辑与视听 → W4 逐场景闭环 → W5 同构建最终验收。W0的CI修复可与不争用代码的证据整理配合，但生产写入仍单一负责人。前三项不是重做全局架构；每项只修当下断点。

### W0：真实基线、主运行时与Windows阻断

业务结果：用户打开惯用入口就是最新可运行应用，不用在3020/3024/3041猜地址。

修改重点：start.py、server.mjs、已有runtime-build/workspace-context/build-web、isolation.mjs、isolation-protocol.mjs及Windows supervisor脚本和相应测试。

实施要求：核对本地HEAD、dirty tree、监听PID、cwd、数据根、前端与后端已加载指纹。健康检查对比“磁盘当前代码”与“进程启动时加载代码”，不能每次请求现算一个新hash伪装已重载。保留当前活跃run，等待/安全取消并保存后，只重启本任务拥有的服务；不得按端口或进程名杀别人的程序。需要使用测试副本时，最终仍必须在主入口复验。

复现并修复105098942901的ISOLATION_PROTOCOL；覆盖正常、超时、取消、内存限制、子进程回收、重复/缺失回执。保留原失败日志，不跳过安全能力。

通过条件：启动旧进程→更换源码→再次启动可正确识别失配而非ready；主UI显示构建/项目/版本；Win+Linux当前提交CI均无未解释失败；选定实际用户平台完整本地冒烟。

### W2：先测后优化，让低风险编辑走短路

业务结果：简单修改不再等待一轮“重新制作”，复杂任务有明确阶段和预览。

先在同一机器/构建采样：冷启动、热启动、首次素材准备、简单字幕、复杂语义编辑、单段TTS、35秒导出、六镜头首次生成、21版本工程重开。追踪message/run/job/project/revision，记录队列、路由、模型各次调用、素材处理、ASR/TTS、编译、隔离、截图、评审、渲染、打包，以及缓存命中。并行任务按critical path计算墙钟，不把并行耗时简单相加。

不能用CI科幻片的3.5秒当Commerce实测，也不能拿“已写任务状态”的时间当用户看到结果的时间。

优化顺序：
1. 消息先入现有任务/消息存储，迅速返回ack；路由/语义分析异步，前端能显示阶段、取消、状态。控制消息可在忙碌时发出；普通写操作排队并绑定正确基准，不能并发覆盖。
2. 已确定对象、许可字段及范围的字幕/标题样式和音量走现有确定性patch，不调用语义模型、TTS或ASR；不重走素材观察和全片导演。模糊语句仍走真实模型且先绑定scope。
3. 将校验缓存改为场景/资源依赖粒度：源码、原生对象、媒体hash/源窗口、字体、输出、时间映射、转场邻接、校验器版本共同决定有效性。不能只按sceneId缓存；不能复用受字幕布局/画幅/时长变化影响的旧证据。
4. 缩小preview池占用范围，真实浏览器/渲染占用时才持有；网络模型评审期间释放。保留取消与基准冲突检查。
5. 首次制作优先实际适配过的原生组件/组合，原创custom只用于现有组件不足的关键镜头；允许一次规划多个明确依赖的镜头，但不同场景叙事不能变成同模板换字。共用分析/事实/资源检索复用，已批准脚本不为每句重建上下文。
6. 字幕/低风险视觉预览完成后允许用户继续编辑；MP4固定到已提交revision异步导出，完成晚的旧导出不得替换当前新预览。正式导出仍执行必要完整检查、解码和可见验收。
7. 按硬件实测1/2/适配worker，保留内存阈值与限并发。不要直接加满线程，也不提高付费额度冒充提速。
8. 导入历史要保护全部记录与内容hash，但可先校验所有文件和结构、编译当前要打开的revision，历史按需编译。只有在原合同与安全检查允许时实现；必须通过历史选择/恢复/续改测试，不能删历史来换速度。

建议性能验收目标（是新目标，不是现状）：热态已导入工程普通消息ack P95≤1秒；30次低风险修改中可用预览P50≤3秒、P95≤10秒；明确局部字幕/音量操作新增模型/TTS/ASR调用=0；语义局部修改通常只一次规划，必要评审单列；六镜头常规资源路线首次生成在质量不降前提下较修改前墙钟至少降低50%；同一已完成composition的App导出耗时不高于直接HF同参数渲染+相同必需检查的1.25倍。首次生成/导出至少3次并列全部样本，不以小样本P95声称稳定；未达标保留阻断与实测原因，不能自动放宽。

### W3：后三目标的真实主入口验收

业务结果：不是“有12个Skill”，而是用户真的能依次完成操作。

保留全局路由/Skill/transition目录，扩展必要测试，不再重新造五个同名核心文件。确认两条执行后端都真实消费规则，不只是记录selectedSkills。请求目标与保持项在规划前确定，模型返回的操作不能反过来定义被允许改谁；跨轮引用扩展到实际业务里的标题、镜头、字幕、转场和声轨，歧义时只问最小问题。

主工程至少10轮真实自然语言会话：打开S02→字幕小一些→再上移→只改一个标题→仅第一转场指定色散→调低音乐但旁白不动→仅一段换真实所选音色→恢复上一版转场且保持字幕→撤销→重做→固定当前版导出（可按实际素材拆为更多轮）。至少混入同义说法、指代、否定、复合要求和一个失败恢复。不能把这一整组压成预构造operations直传。

声音要区分ASR原文字幕、用户画面说明、合成旁白字幕、烧录字；普通改字不发TTS。换声以真实音频测量和对齐为准，只替换目标段；句级时间不冒充逐词。真实配置了MiniMax且有授权时，至少完成同一主工程局部换声并导出；其他未配置供应商不必全接，但不可声称已验。音乐API410不等于本地音乐入轨失败，分别记录；指定云音色不可静默换Kokoro。

指定效果须从对应真实组件/Shader进入导出；任意seek、转场中点、文字拥挤帧、字幕与手部避让都检查。失败后保留原revision，不能静默换淡化、静态或者别的供应商；允许替代只在用户约束/显式批准允许且标注候选未完成指定项时。

通过条件：当前主入口、同build、同project真实链；每轮target/preserve diff成立；多轮引用来自可追溯历史；真实模型/ASR/TTS测试与替身测试分列；完整导出、刷新、重开继续改成立；无声或坏文件的失败不会报成功。

## 4. 失败后的继续方式

每次中断前记录当前真实任务、项目/版本、最新错误、下一条可执行命令和已耗预算。恢复后只读当前项及其依赖，不再次吞全部历史。一个写入者；相同错误两次无新证据需改变诊断方法。外部模型错误只阻塞相关步骤，输入和上一有效版本保留；停止/取消后不能迟到发布。所有状态变化受实际证据约束，旧通过只对输入/源码依赖未变化部分有效。
