# 对话式视频剪辑续作验收

日期：2026-09-10。基础版本：`cb176bc2dd433760e99221f021fc1ce64edb4f63`。工作分支：`agent/continue-editing-optimization`。本报告区分已有实现、本次修复、自动测试、真实模型运行与人工质量评审。

## 结论边界

本次是接着现有工程修复并验证，不是另建一个演示。主分支和用户 Windows 工作区没有被覆盖。没有从 ChatGPT 直接恢复原 Codex 线程，也没有读取用户本机登录凭据。现有作品、历史导出、素材与本地配置保留。

精确剪辑的受控执行可以不调用模型；理解主题、找精彩片段、语义重排、字幕翻译等仍需要可用的模型连接；转写和配音需要实际安装本地语音依赖或配置可选提供方。本次没有验证用户账号的实时额度，也不会把工程补丁描述为订阅/登录问题的解决证明。

**本次不宣称已达到专家相对 85 分，不宣称原 i5/16GB 机器已达到 p95 20 秒或简单修改提速 50%。** 这些都需要相同硬件与素材条件下的对照，以及专家成片和独立人工评分。

## 本次真正修改了什么

| 问题 | 修复 | 验证方式 |
|---|---|---|
| 路径写死在 Windows，缺失 Python 会中断执行 | 平台识别、显式配置优先、Python 常驻 worker 的启动错误与取消处理；媒体工具从 PATH 解析为绝对路径 | 本地核心回归、Windows/Linux 干净安装与执行 |
| 本地配置加载晚于工具路径解析 | 在媒体模块解析前载入 `config/edit.local.env`，已有进程环境变量优先 | 配置载入与工具路径回归 |
| Codex 请求使用固定私有模型名，提示词易受 Windows 参数长度影响 | 默认不指定模型名；完整要求经标准输入发送；区分模型不可用、CLI 不兼容、登录、额度、超时和网络错误 | 请求契约与错误分类测试；没有实际请求用户账号 |
| 简单操作仍等待模型 | 严格匹配字幕、数字裁切、分割、原声音量、条件允许的倍速、导出；未知条件一律保留给模型 | 否定/附加条件/引用/越界回归，真实十轮聊天脚本 |
| 上传视频依赖内置配乐，配乐缺失会导致导入失败 | 原片导入不再强制准备背景音乐，仅明确用到时加载 | 真实影片导入；缺少可选配乐的服务回归 |
| 第二段素材导入阻塞当前视频编辑 | 分离素材导入与编辑调度；首次导入仍正确等待基础版本 | 服务并发回归，前端交互检查 |
| 缓存索引存在但文件已损坏或被删除 | 校验非空文件和安全相对路径，缺失时重建，合并并发构建，失败允许重试 | 删除/损坏/并发/取消测试 |
| Linux 的 `.zip` 实际可能是 tar | 真正的 UTF-8 ZIP，CRC 校验，流式写入，完成后原子发布；失败保留旧文件 | Python `zipfile` 独立解压、中文路径、取消与尺寸限制 |
| 下载完成状态早于工程包写完 | MP4 检查和 ZIP 都完成后才发布导出成功；旧版导出不替换当前预览 | 导出状态与并发修改检查 |
| 浏览器测试等待网络彻底空闲而被 SSE 持续连接卡住 | 等待页面 DOM、真实播放器 ready 和新版本，不使用 network-idle 作为产品完成条件 | 真实浏览器回归 |

ZIP 当前实现不是 ZIP64；超出 4GiB/65535 个条目会明确失败，不能把超大工程宣称为已支持。缓存文件存在性检查也不等于逐次完整视频解码；最终导出仍执行完整检查。

## 代码与运行入口

服务与界面保留原结构：`server.mjs`、`lib/edit/service.mjs`、`web/editor.js`；`/` 与 `/edit` 是聊天剪辑，`/create` 保留旧生成入口。新模块为 `runtime-tools.mjs`、`local-env.mjs`、`local-edit-intents.mjs`、`codex-command.mjs`、`zip-export.mjs`。没有自动升级 HyperFrames，仍固定 0.8.33。

在 `video-agent` 目录安装锁定依赖、构建界面、检查环境再启动：

```text
npm ci
npm run build:web
npm run doctor:edit
npm start
```

默认本地端口为 3040，监听 127.0.0.1。语义规划默认使用已有 Codex 登录；未另外配置时不会调用付费音视频 API。`doctor:edit` 只检查工具与登录状态，不向模型发送请求，也不证明额度、TTS/ASR 或渲染已经可用。首次素材分析可能需要下载本地模型，不能把 Python 文件存在当作模型已安装。

可重复的验证入口：

```text
node scripts/verify-editor.mjs core
node scripts/verify-editor.mjs browser
npm run test:upgrade:live
npm run quality:status
```

前两个不会调用付费模型。`test:upgrade:live` 是留给实际登录环境的真实语义/语音整体验收，默认连接 3040，并会真实创建隔离测试项目；未连接模型时失败是能力未就绪，不能改成假响应让它通过。

真实闭环使用冻结哈希的 90 秒 Tears of Steel 原片，通过真正的 HTTP 服务与浏览器输入框执行十轮：新增字幕、改字幕、调原声、删开头、保留指定时段、1.25 倍速、分割、再次调原声、再改字幕、撤销。检查实际播放时钟前进与跳转，刷新恢复预览；随后在聊天里导出当前版本，并在渲染未结束时启动下一次修改。断言导出未阻塞新编辑、旧版导出未替换新预览、普通字幕未生成旁白、手机界面无 JavaScript 错误。

Windows 与 Linux 均真实输出 H.264/AAC、1920×800、30fps、9.6 秒 / 288 帧的 MP4，以及有效 ZIP。交付的 `hyperframe-conversation-demo.mp4` 是 Windows 这一轮的实际结果，属于流程验证片，不是专家质量对照片。已查看真实桌面/手机截图与成片抽帧；未把自动响度/像素检查当作人工完整听音。

本地 Linux 另执行同样 105 项核心检查；更新器的 6 组保护测试和一次针对干净基础代码的完整 27 文件应用测试通过，更新后再次通过 105 项核心检查。当前 ChatGPT 沙箱的浏览器导航受管理策略阻止，所以没有标为本地浏览器通过；浏览器与严格渲染证据来自上述 Windows/Linux CI。

核心回归包含服务/provider 的模拟测试；真实媒体套件使用真实 FFmpeg、HyperFrames 和浏览器，但部分低层画面测试故意使用可测量的色块/动态图案，以检查像素、转场和裁切。这些不是首页的“真实示例”，更不等于真实语义模型能力。

当前可访问仓库实际只有这两个主样例；此前日志提到的普通话采访没有随当前仓库提供，不能标成已经验收。本次不要求重新上传完整电影源文件，用户自己的实拍素材可以走相同导入流程。

| 场景 | 可以提出的要求 | 依赖与验收边界 |

| 精确快剪 | 删开头 3 秒；只保留第 0 秒到第 12 秒 | 命中严格语法可本地执行，不等模型 |
| 字幕与画面说明 | 指定时段加文字；只改字幕文字，不改声音 | 普通字幕与配音独立；烧录在原片里的字不是可直接编辑图层 |

## 更新时保护未上传文件

本次不执行 `git reset --hard`、`git clean`，不覆盖本地模型、数据和素材。下载的轻量更新包只含改动代码与文档，没有原片、模型、字体或登录信息。

更新包内 `apply-upgrade.mjs` 默认只检查：核对每个待修改文件与基础版本的内容，允许 Windows CRLF 差异。明确加 `--apply` 才写入，并先把原始文件备份到 `.implementation-backups/`。一个文件冲突会阻止所有写入；已应用则跳过。提示 conflict 时应保留本地改动并人工合并，不提供强制覆盖选项。停止正在运行的编辑服务后使用；更新后重新安装锁定依赖和构建前端。
