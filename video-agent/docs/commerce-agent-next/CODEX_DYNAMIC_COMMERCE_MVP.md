一张图片要求真实开箱动作时，明确不能证明的内容并给可执行选择；不能自动伪造动作，更不能把正常有素材正例错判为这种负例。

这不是统计意义的全面成功率证明，只是当前有限范围的泛化验收。不要声称“任意商品/所有用户需求均已验证”。

8. 工程检查、真实用户测试与视觉内容验收

工程层

实际文件完整解码；规格与请求一致；原生对象、源时间和音轨正确；预览与导出对应；负例、撤销、错误回滚与资源安全不被削弱。重要字幕和商品可见性不能靠机械时长/文件存在替代。

当前平台跑本轮所改函数的定向测试及关联生产测试。最后对候选build做一次现有core/browser关联回归，不每次重渲全量旧片。上游/其他平台已有失败记录如实保留；本轮不因与当前交付无关的远端专项阻塞全部本地作品，也不称全平台通过。

真实用户层

在新的浏览器上下文从首页执行S1—S4，保存原请求、素材、job/run/revision、版本和实际截图。正式提交只用页面；日志/接口用于观察，不注入预制plan、不伪造数据库状态。确认演示/重新生成/自带素材三种入口不会混淆。

B1—B6在本机真实运行，特别是下载ZIP后导入干净测试目录，再编辑和导出。端点存在、刷新页面、拿到ZIP三个现象，不能独立替代工程包可继续编辑。

视频内容层

先看实际导出的成片，再看作者说明。通过实际可视工具审阅所有镜头关键时刻、前后切点与必要连续片段；按最终显示尺寸检查小字。仅有少数截图时如实说明未覆盖范围，不声称逐帧看过。至少做一次完整1倍速播放的机械验证。

每条回答以下五个问题，不要求固定美术风格：

商品和视频目的是否一眼明确，用户指定信息有没有漏或错？

每段是否有信息/动作/合理观看作用，是否重复画面或停留凑时长？

字体、颜色、构图和留白是否适合真实商品与用户方向，文字在出现的时间内是否能看清？

动效/图解是否帮助表达、指向真实细节，是否遮挡关键动作或退化为通用大字卡？

声音策略与原需求是否一致，画面和声音源时间是否对应，编辑有没有改变不该变的内容？

必须根据实际证据评价：写revision、时间段、画面/音频证据、原需求、严重性和修复目标；禁止只写“高级感不够”。

硬问题：错产品/事实、漏明确要求、关键文字不可读、黑帧缺媒体、原声错误、明显裁切、编辑越界——必须修。

主要质量问题：叙事没有推进、信息与画面不对应、持续机械轮播、明显不符合指定风格——定位并在本轮改。

轻微偏好：不同字体/转场偏好但目标已达成——记录取舍，不无限美化。

AI主观评审用于改进，不假扮真人；当前不强制两名真人85分才完成这一阶段。未具备真实听音能力，不把音轨存在、静音播放或ASR文本说成已试听；继续可做的制作/文件/时间检查，并交完整有声文件供用户听感复核。文件或同步实际有错仍是本轮缺陷。

同一镜头重复失败且没有新证据时切换根因诊断，不无穷重试。达到明确质量标准即可封存；未达标准不能为结束自评分通过。超出实际授权预算诚实报告，并继续不依赖该预算的工作。

9. 执行顺序与结束条件

顺序

确认本轮范围覆盖旧完成门槛，封存有效基线；备齐A/B两组素材、预算和当前平台。

先从S1真实输入跑现有主链，定位通用输入/图片资源最小缺口；同时只补本轮需要的适配。不要等所有资源接入才第一次制作其他商品。

完成S2/S3，证明实拍与混合路线；三条通过后登记为可运行示范。

做S4需求变更验证及B1—B6；UI入口与示例准备基于已产生成果收口。

在最终候选build复核四条作品、基础编辑和新用户入口，交实际文件与范围说明。

子项完成就执行下一个满足依赖的子项，不再以“修完一个模块”“通过几项单测”“启动了渲染”“做出一条视频”作为整轮结束。一个主要创作任务串行运行，避免资源竞争；轻量检查可穿插。不要花时间另写第N套方案。

本轮可以宣布完成的条件

S1—S4四条新视频都有实际完整文件和可重开原生工程，满足各自请求，没有已知硬缺陷和未解决主要内容问题。

B1—B6有实际用户流程证据，保留修改前后与版本；工程包真导入过、改过、再次导出过。

选用的本轮资源有真实执行/引用证据；确有新增或补齐的表达能力，均已在相应镜头或生产渲染中验证。已有能力足够时不强制新增，不以仅装插件计完成。

新浏览器从首页能找到三个真实示范并提交自由需求；示例输入可取得，不依赖旧开发机器状态。

最终构建的关联测试完成。旧延期用例、其他平台状态和未知听感/商业权利分别列出，不混入通过。

最终标题用“多商品动态创作与基础编辑：本轮范围验收结果”，不要写“全部项目、所有商品或商用验收通过”。

输出顺序：可打开工作台与三个示范 → 四条新视频及修改前后 → 原生工程 → 本轮逐项结果和未覆盖边界 → 实际资源使用与代码摘要。复用现有结果页和一份简短说明，不再创建多套文件目录让用户自己拼。

确被权限、必需输入、累计预算或宿主限制打断，保存精确检查点、已完成文件和下一动作，明确未完成；不能声称会话结束后会继续后台工作。当前只是少数任务受阻时继续其他可执行任务。

10. 可直接接入产品的运行时提示词增补

以下规则写入应用真正使用的相关R阶段，不只是让开发Codex读到。与现有prompt合并，避免全文在每个阶段重复发送。

R1/R4：需求与分镜

你的任务是为本次真实商品输入制作视频，不是找一个名字相似的预设。先提取有原文依据的硬约束，再根据已观察的素材设计内容。分镜数量和表现方式不是用户硬要求，除非用户明确指定或批准。每幕列出目的、实际资产/时间区间、支持的事实和为什么适合该表达。素材不能支持自拟镜头时，修改自己的计划；不可通过虚构产品事实、生成未获准素材或让用户补自己臆造的镜头来继续。缺少可选品牌/价格不阻断中性展示。相同素材换了目标，应改变有意义的内容取舍，不是只改背景颜色。按合理阅读与动作时间安排，不填空白凑时长。

R3/R5：资源匹配与制作

先按素材、输出、运行时、安全、可编辑性过滤候选；再按镜头的表达目的选资源。优先使用经过验证的组件或参数化布局，现成资源不适合时允许受控组合和原创。模板是结构与视觉语言，不是必须照搬的整片分镜。不要把所有商品统一成底部色块加标题，也不要为了展示技能堆叠无意义动效。布局最清晰状态先合格，再加必要运动。记录真实引用与执行的方法，保留原生文字/媒体/图形对象及可修改参数。

R7：基础编辑

先确定请求对应的当前revision和对象；只输出最小必要操作。准确改文字、素材、颜色/字号、单镜头时长或已有音量。普通文字/样式不生成旁白，不重做整片，不改事实、不解锁其他内容。无关对象保持不变，合法裁剪的后文时间平移及关联声音/字幕同步必须一致。更换素材时验证新素材确为目标商品且可满足原时段；不能满足时说明具体缺口。失败保留上一有效版，成功后给用户简明说明实际改了哪里。

R6/本机视觉复核

先看实际输出，不为制作过程辩护。按用户目标判断商品是否清楚、信息是否推进、画面是否支持文案、动效是否有作用、可读性与声音时序是否正确。只报告证据支持的问题，标实际时间与对象。源码和模型说明不能替代画面；机器参数不能替代内容质量。主要问题定点修复，轻微审美取舍不无限返工。明确你的检查是AI视觉复核、机械播放还是实际音频感知，不冒充真人或未知能力。
