# 同输入质量实验、Demo 与验收

状态：待执行方案，不是测试结果。所有阈值为本项目拟定验收口径，不是行业标准或已证明性能。

## 1. 对照实验：找出并缩小直接调用与应用内调用的差距

### 1.1 三组必需结果

- A / reference-author：直接 Codex 使用 HyperFrames 和已允许资源，从冻结的用户请求与原始素材创作。允许正常工具迭代，人工额外指导单独记录。
- B / baseline-product：改造前工作区指纹下，用户从应用 WebUI 提交相同输入，记录全部失败/修复与输出。
- C / current-product：改造后相同输入通过真实应用入口执行，不额外提供人工分镜、参考成片源码或冻结答案。

A 是可达质量参考，不是天然正确答案；先确认它满足商品事实、用户要求与权利边界。B 不可用时如实记录，不复制历史样片代替。

三组尽量使用同模型、同推理设置、同商品资料、同素材、同运行时/字体/浏览器、同声音策略与相近的实际工作预算。无法对齐的条件单独列出，不用不公平配置得出单一归因。

如研究更新的 HyperFrames 版本，另记 A+ / exploratory-upper-bound，不能混入同版本配对。用户历史好片在本地可读且输入能复原时可作为额外参考；输入不可复原就不能当严格基线。

### 1.2 必须记录的差异

模型 ID/实际回退、推理配置、输入/输出及可得用量；完整用户输入；素材和事实快照；加载技能正文及关键引用哈希；工具表；检索/实际执行资源；工作目录权限；主规划/镜头生成/修复次数；渲染配置；人类额外提示；等待/失败；当前工作区指纹。

不能只记录大模型名称就断言“模型一样，所以一定是模板问题”。

### 1.3 最小定位实验

至少在一项 60 秒任务上分别观察：

| 条件 | 研究问题 |
|---|---|
| B 原应用 | 当前实际短板是什么 |
| B + 完整相关技能/资源上下文 | 资源供给是否改善构图和方法选择 |
| 上项 + 分镜级制作与受控表达扩展 | 一次性生成/表达限制是否是瓶颈 |
| 上项 + 真实视觉复核与局部修复 | 自检能否减少“运行成功但不好看” |
| C 完整工作流 | 质量、成本、稳定性与连续编辑的综合变化 |

这是一组成本受控的诊断，不要求每个 Demo 都全套消融。若分阶段工程状态难以独立重放，明确记录实验可比性不足，不编造因果结论。

### 1.4 防止只挑好结果

每种主要任务至少保留两次独立真实执行（预算/额度允许时），记录全部首稿、修复和失败，不只展示最好的一次。样本不足时按实际样本数报告。

普通短需求与精确 Brief 两条线分开统计。详细 Brief 能做得好不等于 Agent 会自主导演。开发者对参考组的额外指导必须可见。

## 2. 本轮主力 Demo：不再只用 15 秒片证明品质

这些 ID 是测试用例，不是产品固定场景入口。所列时长是该测试明确的输出要求，不是所有用户的默认值。

### Q01 · 45 秒商品图文与真实细节

输入：同款商品至少 4 张清晰、授权适用的不同用途图片，附经确认的参数/配件说明；不得用旧广告截图作为原始商品照。

短请求：“用这些商品图做一条45秒介绍视频，把整体、细节和适用方式讲清楚。风格跟商品匹配，画面有层次，但别花哨。只用我提供的信息。”

检查：Agent 自行选材和叙事；局部放大指向真实细节；可用图解而不是全程图片慢推；没有捏造动作/性能。分别测试横屏和竖屏布局。

续改：“只把中间的参数展示改得更清晰，开头和结尾保持不变。”

### Q02 · 60 秒真实操作与动效包装（第一主门槛）

输入：同一商品多段真实操作视频，总有效内容足以支撑 60 秒；可使用既有素材但必须核实实际动作。保留原素材及源区间。

短请求：“把这些实拍做成一分钟的商品介绍，操作过程要看懂，配一点恰当的文字和动效，不要像图片轮播。保留操作原声，不加配音，不编造参数。”

检查：选镜/trim/重排是实际视频编辑；动作有起止；字幕和图形配合动作；时长是 60 秒，不通过慢放/循环凑长；真实视频不被全屏装饰替代。

续改：“开头更有吸引力，中间步骤别打乱，最后留出看清成品的时间。”

### Q03 · 90 秒混合素材商品解释

输入：商品图片、实拍、确认文案/规格和可用声音（无音轨也可）；至少包含整体、细节和说明资料。

短请求：“用这些材料做90秒的视频，让第一次看的人弄明白产品是什么、怎么用、适合哪些已说明的需求，最后自然收尾。不要机械罗列卖点。”

检查：需求驱动组合图片布局、实拍选镜、图解和字幕，文案与证据相互对应；有段落节奏和全片统一设计；不能只堆九张十秒文字卡。

续改：“把中间解释压缩10秒，把省下来的时间用于已经提供的使用细节，总长不变。”

### Q04 · 120 秒口播/旁白与图形同步

输入：180—600 秒的授权口播，或足够的已批准商品讲解文字加现有可用配音能力，以及对应的商品辅助素材。

短请求：“做成两分钟的商品讲解，关键条件都要保留。字幕跟声音对齐，有重点的时候再出现商品细节和图形，不要整段一直用同一种标题。”

检查：真实转写/音频计时；语义和限定条件完整；字幕、辅助镜头、关键字强调同步；不会因为语音比估计长而截断；支持从母工程输出代表性方向预览。

续改：“只改第二段这句话，其他讲解内容不要改；重新对齐相关字幕。”替换文字来自测试提供的实际原句，不由系统编造。

### Q05 · 180 秒较长叙事与恢复

输入：足量、有清晰步骤或信息结构的真实商品演示及文案；不是将 Q02 素材简单复制三份。

短请求：“做成三分钟的完整介绍，各部分衔接自然，已经重复说过的信息不用再说。”

检查：分层计划、逐镜头制作、全片一致、字幕声音、内存/缓存和任务恢复。中途取消或服务中断后能安全恢复有效产物，不污染上一版本。

说明：用于长任务能力与工程验证，不要求所有电商广告都达到三分钟。

### Q06 · 15 秒精确促销回归

输入：确认的商品图、价格、币种、活动日期和条件。

短请求：“做15秒促销视频，第一秒就让人看到活动价，条件也要看清，结尾不需要重复价格。”

检查：移除“价格只能最后三秒”的通用硬编码；信息准确；短片紧凑。该用例与长片同样重要，但不是旗舰质量证明。

### Q07 · 无模板名称的复杂组合需求

输入：现有 60 秒原生工程、新商品图和确认文案。

请求：“中间改成一边播放操作、一边解释细节，讲到哪里就标到哪里；后面保持原来的剪辑和声音。”

检查：不要求用户选择“画中画/促销/图文”场景；受管多媒体布局与图形标注可执行；仅修改指定范围；资源不适合时受控原创而非拒绝。

### Q08 · 素材不足与不合理时长

输入：一张图片，没有动作视频，也没有足以支持长篇解释的资料。

请求：“做两分钟真实开箱、安装、使用过程，产品从不同角度转一圈。”

检查：识别无法证明的动作/视角；说明素材缺口和可执行的补拍/简化方案；本轮不自动调用生图生视频，不用虚假的 3D 或静帧循环冒充真实过程。正确处理缺口也算 Agent 能力，但不算已经完成该原始视频需求。

### Q09 · 品牌一致与多画幅

输入：已经确认的 Q02/Q03 工程及授权适用的品牌规范。

请求：“保留内容和节奏，再给我竖屏和方屏版本，不能裁掉商品，字体和风格要一样。”

检查：重排而非硬裁；文字/价格/品牌留白一致；对应修复不会修改母版；字体缺失有真实处理记录。

### Q10 · 对话十到十四轮连续编辑

使用 Q02/Q03 的真实工程完成：改标题 → 改强调色 → 指定镜头细节 → 改价（仅当用例有价格）→ 仅撤销动效 → 缩短一段 → 恢复指定版本 → 切画幅 → 只改结尾 → 导出期间继续编辑 → 重开工程 → 比较两版本。

没有价格的工程不要为测试强加价格；使用同等范围的另一项事实更新。每轮记录目标对象、影响范围、锁定项、实际差异和验证结果。

## 3. 未见需求集

在集中调优前冻结至少 10 个未见 Brief 组合，条件允许时扩展到 20。不是枚举 36 个业务菜单，而是交叉素材数量、输入类型、文案长短、目标时长、品牌、声音、目标画幅与修改约束。

至少包括：无任何业务场景词；同目标但不同素材；同素材但不同目标；长中文；不同款混入；图片只有一张但有充分说明资料；一条源片含多个动作；中英文品牌词；要求明确保持静音；只改现有项目一个对象。

不能针对文件名、资产哈希、样例 ID、题目关键词或固定回答硬编码成功路径。holdout 内容不写入成片模板和预设推荐的答案。

## 4. 技术与原生工程硬门槛

- 输出规格符合当前任务的批准合同；准确时长按整数帧验证，30fps 下允许的导出边界误差先定义，建议不超过 1 帧。
- 多场景重叠、片段源入点、播放速度、音频起点和字幕锚点经过计算，不能只求总时长对上。
- 主体、文字和资源缺失时有可定位错误；无无意黑帧、截断声音和无法解释的冻结。
- 商品图片不是伪视频；应用创建的标题、价格、图形、媒体布局、声音和字幕保持可修改性。
- 同工程预览/渲染一致，随机 seek 到边界与中段可复现；不要将 MP4 二进制一致与画面一致混为一谈。
- 原生包能重开与继续编辑，版本快照清楚；已有旧项目回归。
- 工具调用、版本发布有幂等、取消与冲突处理；不能被并发请求覆盖或恢复错误版本。
- 新扩展的 CSS/SVG/视频布局/插件能力有正例和安全负例。静态检查之外，还验证浏览器网络/文件/桥接接口隔离、资源预算与超时。
- 字体缺失和资源版本不匹配不静默漂移；相关依赖哈希进入锁文件。

## 5. 质量评审与拟定指标

### 5.1 分开四种结论

工程正确、视觉/叙事/声音合格、素材与商品事实依据明确、发布者审核完成。缺人审时只声明相应工程/自动检查的真实结果。

### 5.2 100 分内部量表

| 维度 | 权重 | 看什么 |
|---|---:|---|
| 任务与内容完成 | 25 | 用户必需项、真实商品信息、段落信息推进、动作/语义完整 |
| 视觉与排版 | 20 | 商品主次、中文可读、构图、安全裁切、细节指向 |
| 动效与全片节奏 | 20 | 有目的的运动、镜头变化、衔接、没有模板重复和空转 |
| 声音与字幕 | 15 | 指令遵循、真实同步、声音层次、无截断；静音任务评静音与文字时序 |
| 品牌与输出适配 | 10 | 字体/颜色/语气一致、画幅重排与交付格式 |
| 连续修改质量 | 10 | 改准、锁定保持、版本可恢复、对象可编辑 |
| 总分 | 100 | 不替代关键事实/权限硬门槛 |

候选目标：绝对质量至少 85 分，同时与 A 组使用同一量表的分数差不大于 5 分；任何关键事实、严重声音/画面错误不能由总分抵消。这是拟定项目门槛，不能称为统计显著、行业标准或历史“专家相对85分”的既有结果。

开发中先用事实和渲染证据修缺陷，最终由两位独立评审完整观看并检查修改结果。没有评审就保留表格待填；模型可辅助指出问题，但不能冒充真人盲评。

A 组低于绝对质量门槛时，应改善参考或明确其不足，不能因为 C 跟坏参考相近就通过。对短片、长片、复杂原创与未见任务分别报告，避免平均数掩盖失败。

### 5.3 实际运行指标

首稿采纳、自动修复后采纳、关键需求覆盖、首稿/修复/全片耗时、模型调用、可得用量、资源成本、峰值内存、失败恢复、无关修改率和重开成功率。样本少时列原始数据，不虚报 P95；样本足够再报告分位数。

不能由视觉分数推断点击率、销量或投放回报；本轮不自动投放。

## 6. 证据包与真实演示

每次运行保留：case ID、run ID、项目/版本、工作区指纹、输入原文、原始素材哈希与源区间、事实与约束、provider/资源配置、技能与引用、工具调用、规划摘要、镜头源码版本、完整输出、失败/修复、工程检查、实际视觉证据、声音检查、续改日志和发布状态。

浏览器演示必须展示：原始输入 → 发送自然语言 → 实际阶段进度 → 范围/全片预览 → 对话修改 → 新版对照 → 下载 → 工程重开。视频播放证据与请求日志必须是同一任务。

固定预设可用于快速讲解，但页面明确标“已生成样例”；重新生成要新建 run 并从原始素材执行。人工挑选候选镜头、人工改过源码、人工补过文案都要记录，不能称零干预。

每个核心 Demo 至少交付：原始输入包、完整 MP4、原生工程、需求/资源/制作摘要、关键缺陷与修复前后对照、续改和重开证据。未完成任何一项就写实情，不造文件路径。

## 7. 发布范围与边界检查

素材来源可追溯不自动等于适用商业用途；代码许可、示例素材、字体、音乐、肖像/声音使用范围分别处理。未知状态不强行标 licensed。

版本的发布审核包括确切商品事实、价格/条件、授权适用和适用标识要求。实施时根据目标平台及现行规则核对，不在本包中写死会变化的外部规范。不承诺所有平台审核必过。

最高 600 秒的合同验证与边界压力测试保留；其通过不表示三分钟以上所有广告都达到与旗舰作品相同质量。超过本机/应用支持规格时明确提示，不静默降低规格或伪造成功。

## 8. 最终验收决策

先判断产品主入口是否实际执行全部关键能力，再判断技术、全片质量和连续编辑。任何“只在直接 Codex 里好看，应用里仍基础”的结果都不能认为本轮核心目标完成。

完成报告必须能回答：用什么输入、走什么步骤、用了哪些 HyperFrames 真实资源、生成了什么、为何比原版本好、怎样继续改、哪些需求仍受限。这比资源数量、PR 数量或单测通过数更重要。
