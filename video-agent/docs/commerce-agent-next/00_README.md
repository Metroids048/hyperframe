## 本包是什么

这是供本地 Codex 修改现有项目的设计和执行指令，不是已实现的代码、已安装的插件、已运行的产品测试或已完成的视频。

本包更新上一轮方案的四项重点：

1. HyperFrames 从最终渲染依赖，升级为贯穿需求、创意、资源、源码、预览、修改的能力底座。
2. 场景库仅作检索和验收标签，不要求用户选择固定场景，不建立互斥模板漏斗。
3. 主攻“直接 Codex 调用 HyperFrames 好看，而应用成片基础”的差距；用同输入实验、真实技能工具接入、分镜级创作与视觉修复证明改善。
4. 用完整、可恢复的 Agent 制作工作流统一生成、剪辑和连续修改；以 45—120 秒为主力质量验证，并验证 180 秒、保留现有 600 秒边界。

历史约束继续有效：保留浏览器对话 WebUI；不重做传统时间线编辑器；本轮不新增生图、生视频和数字人服务，不更换既有模型登录方案，不自动启用付费 API，不自动投放。原生图形、排版、动效和合成不是生图/生视频模型接口，属于本轮重点。

## 使用方法

把本目录放到本地项目 `video-agent/docs/commerce-agent-next/`。也可将四份正文直接附加到 Codex 图形聊天，并告诉它附件的实际保存位置。不需要你在终端里逐条操作。

向 Codex 发送：

> 读取 video-agent/docs/commerce-agent-next/ 下的 01_SOLUTION.md、02_CODEX_EXECUTION.md、03_RUNTIME_PROMPTS.md、04_BENCHMARK_AND_ACCEPTANCE.md。以本地真实项目为准，按 02_CODEX_EXECUTION.md 的总控和 Loop 00—07 连续实施。这是修改现有产品的执行任务，不是让我再确认方案。先保护已有改动、核对基线，再实现真实主入口的需求理解、HyperFrames 资源调用、分镜创作、视觉修复和连续编辑。不要只改文档、只加 skills 名称、只制作手工样片，或在某个单测通过后宣布完成。先交付一条由应用真实生成并可续改的 60 秒质量样片，再完成 90/120 秒等验证。每轮运行相应测试，证据与当前代码、资源和工程版本绑定；阻塞项记录原因并继续独立工作，不伪造通过。

执行 Codex 应自动创建执行状态账本，不让用户逐项批准 Loop。确实缺授权、账号/额度或必需素材时，只询问无法自行解决的那一项。缺独立真人评审时可完成工程与自动化验证，但发布状态保留待人工审核。
