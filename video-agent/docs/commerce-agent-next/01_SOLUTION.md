# HyperFrames 电商视频 Agent · vNext 解决方案

日期：2026-09-11。状态：待实施设计。以本地真实工作区为最终实施基线。

## 1. 产品目标与这次真正要解决的问题

产品目标：电商用户输入自然语言以及图片、视频、文稿、声音、商品资料，Agent 理解这次要完成的任务，组织合适的制作步骤，交付有内容、有设计、有节奏、可继续修改的视频。业务聚焦电商，底层能力按素材、内容、时间、设计和编辑需求组合。

这次不是再增加几种动效、把 15 秒常量改成 60 秒，或者另写一个更长的系统提示词。核心是把“直接 Codex 使用 HyperFrames 时的观察、找资源、设计、写场景、看预览和修改能力”搬进应用真实运行链路，同时保留稳定工程、安全执行和可恢复性。

成功的区别：开发 Codex 做出好片，只证明技术可行；普通商家从 WebUI 输入简短要求，由应用 Agent 做出好片，才证明产品能力。

### 1.1 不改变的边界

保留现有 WebUI、模型接入、媒体处理、转写/配音、原生文档、对象级修改、版本、工程包、严格导出。不要用大重构替代质量交付。

本轮不新增生图、生视频、数字人、云投放、复杂多租户平台，不自动换用收费模型。已有声音能力按用户要求使用。图片原生进入 HyperFrames，不先转成静止 MP4。真实视频保持真实选镜与动作，不用图片动效冒充视频剪辑。

现有不超过 600 秒、最高 1080p 级画幅、30fps 等边界先按本地合同核对和保留；不因演示主力改为 60—120 秒就缩小已有范围。资源与渲染并发以目标 Windows 机器能力为准，默认保守运行。

## 3. 架构原则：一个主控，一份工程，按需组合能力

建议的逻辑结构：

用户对话与附件 → 当前工程/任务状态 → 需求与证据整理 → 可组合任务计划 → HyperFrames 能力与资源解析 → 创意总稿 → 分镜制作与复核 → 同工程预览 → 局部反馈修复 → 完整渲染/发布检查 → 同工程继续编辑。

不是每次都跑完整生产线。已有作品只改一句字幕，直接走对象定位、影响分析、修改、局部验证；用户只要导出，验证指定版本后导出；新作才走完整创作流程。

一个主控协调多个专业阶段。可以是同一个模型在不同阶段使用不同上下文，不要求部署多个常驻 Agent。纯读取和独立镜头工作可以有限并行，但工程提交、共享合同和版本切换由主控串行处理。

### 3.1 需求模型，不是场景菜单

为每次任务保存需求规格（名称可映射到已有 Brief）：

- 当前操作：新建、续作、修改、变体、导出或检查。
- 业务意图：这条视频希望观众理解什么、采取什么行动；可多标签，也可暂时 unknown。
- 输入情况：商品素材/真人/音轨/批准脚本/参考风格/已有项目。
- 必须满足：时长、画幅、原文、品牌规范、价格条件、保留镜头、不得增加内容。
- 可由 Agent 决定：叙事顺序、视觉布局、合法的文案表达、适度动效和默认输出设置。
- 素材与事实缺口：不能仅凭素材外观证明的卖点、型号关系、动作缺失等。
- 制作优先级：品质优先或快速小改、已有授权预算、可用工具。
- 反馈与锁定：用户已经认可的文字、风格、镜头、配音和固定时长范围。

不要求用户填写全部字段。已有聊天、附件和项目能回答的先读取；风格未指定可基于素材选默认并简要告知。关键价格矛盾、无法确认的商品匹配或必须素材缺失才需要澄清，不把“没有选场景”当成阻塞。

### 3.2 任务计划是可组合图

每个任务节点记录输入、前置条件、工具或阶段、输出、验证条件、重试上限、取消行为和下游失效范围。

示例：“把两分钟口播剪成 60 秒，加商品细节，字幕有层次，结尾放活动价。”

路径：转写与语义分段 → 口播精剪 → 商品素材匹配 → 事实/优惠条件验证 → 字幕与辅助镜头排布 → 局部原生动效 → 混音 → 全片检查。

它同时借鉴 talking-head、product-promo、captions 等工作方法，不需要把用户硬归为一个场景。转写和图片观察可独立完成；镜头定稿依赖剪辑和语义证据；最终导出依赖全部质量检查。

场景地图用于召回制作经验、统计覆盖和构造测试；不能决定能力上限。资源检索无命中时进入通用制作规划和受控原创，而不是拒绝或静默套基础模板。

## 4. HyperFrames 融入的七个位置

### 4.1 入口和工作流

将官方路由和制作流程作为可读、可解释的方法资源。保留本项目用户体验与范围：不因为上游某个 Skill 默认打开新工作台、联网取材或要求新登录，就自动照搬。

### 4.2 技能与依赖

建立项目内版本化能力索引。先发现完整公开目录，再根据本地兼容性决定哪些可运行；每次任务只加载有关技能的正文、被引用的必要规则与蓝图，不能把全部文档一次塞进模型，也不能只注入一句摘要。

技能包依赖可能包括 references、scripts、样式预设、字幕皮肤、素材清单格式和其他技能。缺依赖要显式说明，不能只复制 SKILL.md。

主创作的上下文记录应包含实际加载的 skill ID、版本、源哈希、依赖、裁剪/摘要位置和选择原因。记录可审计的决策摘要与工具输出即可，不要求暴露模型私有思考。

### 4.3 示例与成片源码

起始模板是脚手架，不是成片公式。Showcase 的公开成片源码可用于研究构图、镜头衔接、统一设计、时间组织和素材使用，但网页上的视频不当然附带可用源码，更不代表其中素材可以商用。

每个研究案例要产出：观察到的视觉方法 → 对应源码/时间范围 → 适配需求 → 可复用的场景或规则 → 在自己素材上的应用证据。不能只收藏链接、抄视觉标签或复制现成整片。

### 4.4 Blocks、Components 和品牌资源

分别登记：工作流、完整示例、场景块、小组件、动效蓝图、字体/设计系统、媒体、工具适配器。一个场景可组合多个组件，但由同一个设计与时序合同约束，避免多个动画同时修改同一属性。

优先评估商品展示、细节标注、参数图解、字幕、品牌收尾、排版和克制转场。商品仍是主体，资源调用次数不是质量指标。

### 4.5 运行时与插件适配

官方目前的动画能力地图包含 GSAP 及 Lottie、Three.js、Anime.js、CSS、WAAPI、TypeGPU 等适配方向，但这不证明当前固定版本 0.8.33 全部支持或本项目可直接执行。

将“插件”明确为可选运行时/效果/工具适配器，不设计成任意 npm 包执行入口。默认深度用好 HTML/CSS/SVG/GSAP；对真正有价值且本地可验证的额外能力，走版本固定、依赖审查、性能/seek/对象编辑验证后再启用。没有真实 3D 模型时不承诺从一张照片还原真实商品全角度。

### 4.6 预览、渲染与检查

应用内部使用统一的 HyperFrames 执行桥接层，封装本地已验证的初始化、资源安装、编译、预览、检查、渲染操作。按安装版本发现可用命令，不能假定 inspect/check/validate 在所有版本语义相同。

预览与最终导出使用同一源码与资源锁；15 秒方向预览是当前母工程的范围输出，不是另一条重新创作的短片。

### 4.7 原生编辑

场景来源、节点 ID、参数、文字与素材绑定、时序、品牌 token 都留在工程里。模型原创和引入官方模板，都必须达到可续改要求；不能为了接资源把全部转成不可编辑视频再拼接。

## 5. 资源接入与安全合同

### 5.1 三步而非一个“已安装”

资源运行成熟度独立标记：discovered → compatible → adapted → executable → verified。授权状态另外保存，不能用 verified 替代授权。

资源描述至少包括：来源和固定版本/哈希、类型、依赖、输入前提、能力标签、可编辑参数、支持尺寸/字体、渲染与内存预算、不可用条件、代码许可、示例素材许可、测试证据和已知问题。

允许索引全量可发现资源，但激活范围逐项验证。旧项目读取创建时的 lock，新版本不偷偷改变旧成片。

### 5.2 调用闭环

需求/镜头目的 → 搜索候选 → 检查资源依赖、素材、版本和权限 → 比较构图/节奏适配 → 生成场景计划 → 执行资源适配 → 原生对象映射 → 检查 → 调用记录。

同一画幅、不同商品，可能选择不同资源；同一商品、不同输入，也可能走不同制作步骤。没有合适资源可原创，不以“用了模板”作为目标。

必须有实际调用收据：检索结果、选中/舍弃原因、使用的资源文件哈希、工具实际启动记录、生成对象 ID、验证结果。仅写 registry JSON 或在日志中声称“使用高级动效”不算接入。

### 5.3 兼容性升级决策

先固定当前锁文件与工具版本，建立基线。新资源不兼容时依次判断：可安全适配、值得小版本升级、暂不启用。升级需有分支/隔离目录实验、回滚说明、旧项目重开与输出回归。禁止运行生产流程时自动拉 main/global latest 造成漂移。

### 5.4 创作自由与权限分离

按明确视听需求扩展表达能力，不扩大文件/网络/系统权限。

三档执行配置可渐进实施：项目已审核组件；受管 HTML/CSS/SVG/GSAP 原创；特定已审核运行时插件。第三档不是本輪必须全量接入。

受管原创建议补：可绑定品牌字体和 token 的布局能力；多媒体容器和安全 mask；受管视频 wrapper 的位置、尺寸、裁切及变换；复用图形局部定义时的安全 ID 重写。每项按真实效果需求与负例测试批准。

继续禁止任意 shell、读取工程外文件、任意远程加载、未授权脚本、无界循环、无界内存、随机时钟依赖、视频自行 play/pause/seek。AST 和 CSS 校验本身不是完整隔离边界：浏览器执行需限制网络、文件可见范围、桥接接口、超时和资源占用，按 threat model 验证。

## 6. 为什么更长的视频需要不同制作方法

目标不是“所有视频都长”，而是用户要求 60/90/120 秒时有足够内容和设计，要求 15 秒时又能准确压缩。

### 6.1 分层叙事

采用段落 → 表达节拍 → 镜头 → 画面对象四层。一个段落可以用多个连续镜头解释同一件事；一个镜头内文字、标注和商品可以先后出现。

不再把总时长均分给最多 12 个场景。场景数从内容、动作和可读时间产生，安全上限从本地资源预算产生。不要从“max 12”直接换成“max 100”而缺少分批制作和状态管理。

### 6.2 三种计时依据

- 有旁白：脚本初稿 → 实际声音 → 实测词/句时间 → 调整镜头、字幕和强调时刻。用户锁定总时长时，先精简或重写获准文案，不能悄悄拉快语音或截断句子。
- 有真实操作/口播：动作与语义边界决定入点和出点，再处理段落节奏。
- 无声图文/动效：阅读时间、视觉动作、场景关系和用户总时长共同决定停留。

叙事可在音频产生前粗排，最终 timing 必须回到实测音频。数字、型号、价格等精确信息不为押节奏而变动。

### 6.3 内容充分性

记录每段新增的信息及其证据，检测重复标题、重复画面与没有新信息的空转。重复商品亮相可合理存在，但须有叙事目的；不能重复十次并叫“丰富”。

一张图并不绝对不能做长视频：若有足够的经确认参数、说明和图解，可以采用解释型设计。反过来，只有一张图且没有资料，却要求长时间真实操作演示，应明确素材缺口，不虚构拍摄内容。

### 6.4 60 秒参考叙事（不是固定模板）

0—5 秒：用真实商品或问题建立观看理由。
5—16 秒：展示整体与使用背景。
16—32 秒：用证据解释两三个重点，按内容切镜与标注。
32—46 秒：展示操作、结构细节或适配说明。
46—55 秒：根据用户资料处理选择理由、价格或关键条件。
55—60 秒：清楚收尾。

没有价格、口播或使用视频时，不能强塞对应段落。以上秒数只说明“内容推进”，不是写死的分镜。

## 7. Agent 的完整工作流

| 阶段 | 做什么 | 输入/产物 | 退出条件 |
|---|---|---|---|
| 0 恢复上下文 | 判断新建还是改已有；读取锁定与版本 | ProjectSnapshot、请求原文 | 确认目标项目和 baseRevision |
| 1 理解要求 | 提取目标、硬约束与允许自由发挥处 | Brief/任务规格、假设与缺口 | 关键事实无冲突；缺口有处理策略 |
| 2 观察素材 | 真图、镜头边界、按需加密抽帧、转写/音频分析 | AssetEvidence、候选源区间 | 每个重要镜头有证据，不靠文件名 |
| 3 组织任务 | 组合技能、制作步骤与依赖 | TaskPlan、CapabilityPlan | 任务图可执行、资源预算允许 |
| 4 创意总稿 | 叙事、品牌、脚本和镜头职责 | StoryPlan、DesignSystem | 全文案可追溯；叙事覆盖需求 |
| 5 计时与方向样片 | 实测声音/动作计时，验证关键画面与短范围 | TimingPlan、HeroFrames、PreviewRange | 时长可实现；方向符合任务 |
| 6 分镜制作 | 场景级资源使用/原创；局部合成 | SceneBundle、对象映射 | 每镜头过结构、素材、时序检查 |
| 7 全片质量闭环 | 合成预览，检查画面/声音/动作/故事 | QualityReport、RepairPlan | 阻断缺陷修复；预算耗尽明确保留草稿 |
| 8 导出交付 | 绑定版本渲染，完整播放检查，发布状态 | MP4、工程包、资源/权利清单 | 技术与视觉证据真实；放行状态明确 |
| 9 持续修改 | 定位目标、算影响、局部重做与回归 | PatchPlan、新版本 | 指定修改生效，锁定内容未污染 |

这些是逻辑阶段，不是要求每阶段都单独调用模型或弹出确认。确定性工作交给工具。快速修改绕过不必要的策划和素材分析。

方向预览默认从同工程选 10—15 秒代表片段，并覆盖一处关键复杂效果；复杂长片另看开头、中段、结尾的静态关键帧。之前已选“直接完成”的用户不被强制多次打断；需要创意审批的任务才等待确认。审批绑定 Brief、设计、素材与源码快照，变更后按影响重新确认。

## 8. 分镜制作器与质量修复

### 8.1 镜头工作包

一个镜头收到自己的目的、上下文摘要、前后镜头关系、真实素材区间、批准文案、品牌规则、尺寸、时长、目标效果、候选资源、被选技能/引用、可用工具和允许修改的 ID 范围。不把全部素材与整个工程反复发给每个镜头。

先做最清楚的一帧，再添加入场、强调、保持和衔接。视觉主次来自商品和信息，不从“每幕必须几种 easing”之类模板计数机械产生。

### 8.2 质量评审器

评审实际渲染证据，不根据源码存在多少动画推断质量。输入包含场景起/中/尾帧、转场前后、代表性短片段、全片低成本预览和声音检查结果。

报告问题的严重性、时间、对象、证据、影响与最小修复建议。例如：第 28—31 秒价格条件字号太小；第 42 秒商品被双栏边界裁掉；第 55 秒语音尚未结束但字幕已退出。不能只输出“高级感不足”这样的无法执行评语。

### 8.3 两类修复

工程修复：无效源码、空对象、越界、seek 不一致、源区间错误。
视觉/叙事修复：布局不清、节奏机械、真实动作中断、重复镜头、标注不指向细节、声音压过口播。

一次只改受影响的镜头/字段，重新验证受影响区域及前后衔接。可配置每镜头默认最多两轮视觉修复、整片最多两轮叙事修复；这是成本保护，不是质量达标承诺。仍不合格则保留最佳有效版本与缺陷，不自动退成普通图文卡或无限重试。

小镜头修好不等于全片修好：最终需要核对总时长、声音、全片叙事、重复和用户必需项。

## 9. 单一工程与依赖更新

优先扩展现有 NativeDocument v3、受管 SceneBundle、资源锁和对象地图。必要时进行显式 schema 迁移，但不要仅因方案叫 vNext 就再建一套不可兼容文档。

文字/价格/素材选择/时序的权威来源是原生文档；自定义结构与源码的权威来源是该文档引用的版本化 bundle；资源锁保存外部依赖。compiled HTML/MP4 都是派生物。不允许 Agent 直接手改导出 HTML 却不回写工程。

依赖更新示例：

- 改价：更新价格字段和条件，重排关联节点并重查可读性，不重选素材。
- 改旁白一句：重做该音频段、实测时间、更新字幕与后续锚点；锁定总时长出现矛盾时明确处理。
- 改动效：只更新对应 bundle/参数，保留之后用户确认的文字和价格。
- 改画幅：使用布局适配重排和重新检查，不能硬裁中心。
- 导出期间继续编辑：导出固定 baseRevision/资源锁快照，新编辑产生另一个版本。

缓存键至少由源码/资源/时序/字体/模型或工具配置中相关的输入哈希构成。语义不变不等于 MP4 二进制一定相同；未修改源和节点可要求哈希不变，像素复现需在固定编码环境单独定义。

## 10. 执行状态、预算与恢复

将状态保存到项目中，沿用已有 store 并测试原子性、写入冲突和幂等。任务记录目标版本、完成步骤、实际工具调用、模型调用计数、资源快照、证据路径、失败原因和下个可运行任务。

不要只沿用固定 12 次模型调用作为所有长片预算。按任务规模配置上限，逐次记录实际消耗；也不能把扩容预算当成解决质量的主要手段。纯工具步骤不虚记模型调用，失败和修复都计入。

启动工作进程时确认中断任务是否有可复用产物，不盲重做已完成镜头。重试有幂等键，取消不发布半成品，冲突不覆盖当前版本。对缺真人评审、模型容量、授权素材分别记录 blocked-human/provider/assets，继续无依赖工程工作。

## 11. 本轮实施包与现有代码映射

| 工作包 | 优先查看/扩展位置 | 关键交付 |
|---|---|---|
| 基线与差距实验 | package-lock、模型 provider、creative 主调用、examples | 同输入的直接参考/旧应用记录，不覆盖用户作品 |
| HyperFrames 能力桥 | runner、runtime-tools、skills/effects registry | 版本探测、完整 skill 依赖读取、资源解析和执行收据 |
| 需求与任务主控 | creative service、agent-kernel、tool-registry | 从真实 WebUI 进入任务工作流，不是旁路脚本 |
| 故事与计时 | model-director、director、audio/captions/cuts | 分层叙事、实测时间、动态镜头计划 |
| 镜头表达 | compiler、custom-source、isolation、document | 受管视频布局、品牌规则、可编辑资源适配 |
| 质量闭环 | preview-check、HyperFrames 检查桥、scene worker | 实际渲染评审、有界修复、原始失败证据 |
| 连续编辑 | model-edit、patch、history、branches、portable | 精准影响范围、锁定、重开、快照导出 |
| 交付与演示 | web/commerce、测试与样例目录 | 长短、多输入、未知需求与真实浏览器演示 |

名字是定位指南，新增路径由 Codex 对本地结构决定，不能把建议函数名当成已有能力。

优先顺序：先用同输入找清差距 → 打通资源与主控 → 在应用里做出第一条 60 秒质量片 → 扩展 90/120/180 秒与编辑 → 完整产品验收。安全回归随每个扩展执行，不要将全部时间投入整理文档后仍没有改善成片。
