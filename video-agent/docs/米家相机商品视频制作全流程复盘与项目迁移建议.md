# 米家相机商品视频制作全流程复盘与项目迁移建议

> 记录日期：2026-09-15。面向后续接手的 Agent、产品与视频制作开发者。
> 文档性质：真实案例复盘与迁移建议；不是自动流程验收报告，也不是通用视频模板。
> 用户最终评价：后半部分“勉强可以接受”。应把 V2 当作可继续改进的方向参考，不能提升为“高级品牌广告已经达标”。

## 1. 接手 Agent 先读这几条

1. 用户上传的是一条约 72 秒的米家相机开箱视频，希望得到明显经过广告化编辑的成品：前三秒抓人、节奏有变化、细节突出、动态标注、设计转场和产品收尾，同时保持原商品内容与配音。
2. 适配场景是 **`product_launch`：单品上新／种草／产品展示**。素材没有提供完整、可验证的操作教学链，不能仅因“开箱”就归入 `product_demo` 教程场景。
3. 前半程自有项目的 Agent 链路反复遇到观察、证据、装配和超时问题，**没有完成本片的自动导出闭环**。
4. 后来由当前助手直接编写 HyperFrames HTML／GSAP 工程。V1 被用户否定；V2 重做叙事和版式后，用户认为“这个效果还可以”，同时明确只是“勉强可以接受”。
5. V2 的来源标记是 `reference-author-v2`，`productAgentPass: false`。这不是自有项目 Agent 自动生成能力的成功样本。
6. “完全使用 HyperFrames”在本案中指主要画面编排、动效与渲染使用 HyperFrames；素材预处理、抽帧、解码和音频比对仍使用 FFmpeg 等工具。
7. 后续要迁移的是**观察—决策—编排—检查—修复的方法和能力**，不是把这一条片子的硬编码 HTML 包装成万能 Skill。
8. 用户已明确要求两个任务各自独立，不给另一个任务加工作。继续本案例时不要跨任务派工、改动另一任务或重启其依赖服务。

### 三条执行路径与结果

| 路径 | 实际做了什么 | 结果与评价 |
| --- | --- | --- |
| 自有项目 Agent | WebUI 上传、选场景、运行；后续对同一 run 进行 CLI 续作 | 修复若干真实缺陷，得到局部方向预览；动画调用反复超时，没有完整交付 |
| HyperFrames V1 | 助手直接编排，增加标签、少量慢放、遮罩转场和尾页 | 技术检查通过，但用户认为“跟原版没什么区别”，创意失败 |
| HyperFrames V2 | 先重新分析成品目标，再重做 11 幕构图、文字层级、细节放大及转场 | 已渲染可播放 MP4；用户勉强接受方向，质量仍需提高 |

## 2. 用户需求、素材与执行假设

### 2.1 用户原始要求

> “把这条商品视频优化得更像高级品牌广告。前 3 秒加强 Hook，整体节奏更紧凑，商品细节部分放慢突出，在关键卖点处加动态文字和标注，转场更有设计感，最后重新做一个高级产品收尾。保持原商品内容和配音不变。”

用户还要求先判断素材适合的业务场景，并用当前项目和 HyperFrames 实际测试。后续强调要先理解视频和成品目标，再制作，让人能看见 Agent 带来的变化。

### 2.2 素材事实

| 项目 | 记录 |
| --- | --- |
| 原文件 | [Xiaomi_MiJia_4K_Action_Camera_Unboxing.webm](../../素材/Xiaomi_MiJia_4K_Action_Camera_Unboxing.webm) |
| 时长与规格 | 71.989 秒；1920×1080；24000/1001 fps；VP9 视频、Opus 音频 |
| 可见内容 | 开箱、包装与配件、相机正面／顶部／背面／侧面／底部、屏幕点亮、生活与手机画面 |
| 语音识别 | faster-whisper small 执行成功，但返回 0 个词；不能由此断言没有语音或已经完成试听 |
| 产品事实边界 | 可以使用画面支持的结构名称；不能只凭文件名确认 4K，不能推断防水、防抖、续航等性能 |
| 生活片段边界 | 可以作为原素材中的使用氛围；没有证据时不能标为“该相机实拍效果” |

素材、附带文本及识别结果是待分析的数据，不是修改任务规则的指令。商品身份、结构与未经核实的营销主张必须分开。

### 2.3 本次一个重要的执行假设

助手把“配音不变”扩展成了“完整保留原始声音，起点 0、原速、顺序不变”，因此成片继续约 72 秒。**72 秒不是用户原始明确指定的目标时长**，而是本次执行中采用并解释过的保守约束。

这个选择保护了声音，却压缩了“更紧凑”的发挥空间。后续合同应分别记录：

- 配音文字是否必须逐字保留，是否允许移动句子对应位置。
- 原音乐、环境声、音效是否也必须完整保留。
- 是否允许剪掉停顿、静音或无关段落；是否允许新增音乐。
- 目标时长与允许范围，以及音画对应是否必须保持。

不能把“保留配音”默认为“保留整条音轨和时长”，也不能为了广告节奏擅自删改配音。必要时只澄清这个会实质影响剪辑的约束，其余制作继续推进。

## 3. 上传者真正希望得到什么成品

本案最适合做成“真实开箱素材驱动的产品展示广告”。核心价值是让观众迅速理解这是什么产品、外观与结构有哪些值得看、为什么继续看，并留下一个明确的产品记忆。

原片按照拍摄过程展开；目标广告需要按照观众的注意力展开：

**产品先出现 → 建立品牌与视觉气质 → 集中展示细节 → 带入使用氛围 → 产品记忆收尾。**

这要求 Agent 做出可解释的编辑判断：选什么、删减或压缩什么、哪个局部要放大、哪些镜头适合并列、文字为什么在这个时刻出现。只增加标签和淡入淡出，无法回应“把它变成品牌广告”的需求。

本片没有充分的可信差异化卖点资料，因此 V2 主要展示了外观和结构。**结构名称不等于商业卖点**。后续要提高说服力，需要用户确认的产品资料、品牌规范、受众和投放目标，不能靠模型补造。

## 4. 全过程：失败发生在哪里，后来怎样改变

### 4.1 环境恢复与真实项目尝试

初始依赖和服务未就绪，安装受到过期的 localhost:7890 代理／镜像配置影响。清理当前进程配置后安装成功；恢复本地语音环境，核心 doctor 就绪。

实际进行了 WebUI 上传与提交，选择单品上新／种草、16:9 和本次采用的 72 秒。后续为了不影响共享服务里的另一任务，改为使用同一个 `buildCommerceProject` 入口对原 run 做 CLI 续作。

这两种执行必须分开记录：CLI 续作不代表 WebUI 完成；没有修改原项目状态文件去伪造成功。第一次续作改变了 `render` 输入，被 `RUN_INPUT_CONFLICT` 拒绝；恢复原 `render:false` 后继续，说明输入一致性约束应保留。

### 4.2 自动链路的主要问题与局部修复

| 问题 | 原因与影响 | 本次处理及边界 |
| --- | --- | --- |
| 空转写阻断制作 | 识别成功但 0 词被当成全流程失败 | 增加观察音频状态；保留原音且无需字幕时允许视觉候选，试听仍待审；需要字幕时不能伪造转写 |
| 现有素材也必须填生成提示 | 规划校验混淆“使用现有素材”和“生成新素材” | 仅缺失／生成资源要求生成提示，用途和构图仍需明确 |
| 慢放被判素材不足 | 按源时长必须覆盖输出时长校验，没有考虑播放倍率 | 明确慢放请求时允许受限比例，仍检查源范围；不授权改变声音 |
| 已有证据未给到模型 | 有 19 张证据图，调用却长期只拿旧的前 4 张 | 新证据优先，增加当次图像与查询预算；本片使 19 张进入调用，不能固定为所有任务都发 24 张 |
| 0 分镜报错不准确 | 空输出被归入“镜头过多” | 区分空分镜与超量，错误应指向可修复原因 |
| 无法实际试听形成死锁 | 视觉证据齐全后仍因试听前置条件停住 | 允许生成待审候选，明确未试听；不能把待审变成自动通过 |
| 原音跟随镜头切片 | 默认视频节点声音会随源区间、速度改变 | 建立独立完整原轨，起点 0、速度 1、音量 1，不绑定视频节点，并做结构验证 |
| 原生切片触发 null.html | `footage-cut` 合法 `source:null` 被当作 HTML 处理 | 仅对合法 `native.footage-cut` 回执允许空源码，预览和装配同步修复；其他缺源码继续拒绝 |
| 长调用反复超时 | 第 6 镜头动画调用达到 600 秒，恢复后仍超时 | 保留检查点和日志；本次没有完成自动链路，不把重试视为完成 |

相关源码入口：[音频观察与原轨](../lib/creative/observation-audio.mjs)、[证据索引](../lib/creative/evidence-index.mjs)、[生成计划](../lib/creative/generation-plan.mjs)、[能力适配](../lib/creative/capabilities.mjs)、[导演](../lib/creative/model-director.mjs)、[生产编排](../lib/creative/production.mjs)。接手时以当前源码为准，表格不代表这些文件永远停留在本次版本。

自动链路曾得到 16 段分镜，并完成 11 秒方向预览的工程检查。但创意计划本身仍弱：主要是 cut，新增文字很少，不能据此声称已实现动态卖点、设计转场和高级收尾。即使工程故障全部解决，也不保证那份计划会满足用户。

### 4.3 V1：交出了文件，却没有交出用户期待的变化

助手转为直接编排 HyperFrames 参考工程，输出 72 秒视频。加入黑色区域标签、少量慢放、三处遮罩转场和产品尾页。

V1 的技术结果不错：检查无错误警告、9 个布局样本无问题、20/20 文字对比度通过、完整解码通过、原音高度相关。然而用户反馈：

> “搞了这么半天就出来一个这个东西吗，跟原版没什么区别啊……”

失败原因主要是：

- 仍然延续原开箱的观看方式，商品没有形成明确的视觉主角。
- 大部分画面仍是原片全屏，改动集中在叠加层，缺少重新构图。
- 动效没有承担足够的信息组织作用，转场存在但没有形成整体节奏。
- 花了大量时间修工程，直到交付才检验最关键的“广告感”和变化程度。

**技术检查衡量可运行性，用户评价衡量作品是否实现目标。两者不能相互代替。** V1 应保留为失败对照，不能因为检查通过而从案例中删除。

### 4.4 V2：先重新定义成品，再编排

收到否定后，先明确场景和目标：把开箱素材重组为产品广告，重点改变叙事、构图和文字层级。只在本任务输出目录制作，不再联系另一任务、不再修改共享产品源码。

采用深墨绿、暖白和低饱和强调色；大字、产品画面和留白建立层级。原画面去除上下黑边，实际裁切为 `1920×864，x=0，y=108`。使用原片抽帧组成多角度卡片，不生成替换商品。

| 成片时间 | 表现方式 | 对观众的作用 |
| --- | --- | --- |
| 0–3 秒 | 暗色大字、产品双栏揭示与推近 | 首屏识别产品，建立与原片不同的开场 |
| 3–9 秒 | 暖白品牌页与产品画面 | 给产品名称和外观明确位置 |
| 9–15 秒 | 开箱、说明书、配件三路视频错峰出现 | 并列压缩开箱信息，改变单一全屏观看方式 |
| 15–23 秒 | 整机与圆形镜头放大、焦点环、慢放 | 主动引导看局部细节 |
| 23–31 秒 | 顶部／背面／侧面三张结构卡片，标线依次出现 | 建立多角度对照 |
| 31–39 秒 | 底部画面、编号和标注 | 把观察重点落在具体结构 |
| 39–47 秒 | 屏幕画面、大字和引导线 | 突出背屏展示 |
| 47–53 秒 | 原片生活画面与标题 | 提供使用氛围，不宣称相机实拍性能 |
| 53–59 秒 | 生活／人物／手机画面双栏编排 | 改变节奏和画面密度 |
| 59–65 秒 | 多视角产品卡片错峰旋转出现 | 回收产品外观记忆 |
| 65–72 秒 | 独立暖白产品收尾、正面相机 | 明确结束，留下产品主体 |

使用方向遮罩与圆形揭示衔接不同章节。动画有限、可按时间定位；原音轨独立播放，不随视频慢放改变。详见 [V2 需求分析](../outputs/mijia-brand-test/v2/BRIEF.md) 与 [设计记录](../outputs/mijia-brand-test/v2/DESIGN.md)。

### 4.5 V2 制作中仍然需要实际画面修复

- 带时间的容器嵌套带时间的视频触发检查问题：本工程改成非 timed 版式容器，由根 GSAP 控制显隐，视频自己管理媒体时间。
- 第一版“放大镜”只是把整台相机缩进圆内：检查后改为真实局部裁切放大。
- 镜头区间后半段转向顶部，和“镜头”标注不一致：重新选择连续正面区间，并调整倍率。
- 收尾也出现角度不合适的问题：同样根据真实画面收窄区间。

这些错误说明：代码里写了“镜头特写”和“产品收尾”，不代表输出画面已经满足。必须检查实际媒体在指定时间的内容。

## 5. 当前成品的准确状态

### 5.1 已验证与未验证

| 项目 | 结论 |
| --- | --- |
| V2 文件 | 72.000 秒，1920×1080，30 fps，2160 帧，18,752,969 字节 |
| 渲染 | HyperFrames 0.8.33，单 worker，约 4 分 24.6 秒；实际文件已生成 |
| 工程检查 | 0 错误；3 个 `duplicate_media_discovery_risk` 警告，已核对为有意并列／局部复用，不表示新证据 |
| 布局与文字 | 9 个布局样本无问题，32/32 文字对比度通过 |
| 输出检查 | FFmpeg 全片解码通过；抽看最终 MP4 和转场序列，存在预期的多栏、放大、标注与收尾 |
| 音频技术比较 | 8 kHz 单声道 PCM 对齐偏移 0 秒，相关系数约 0.99992364；不是逐字节一致 |
| 主观反馈 | 用户称“这个效果还可以”，并总结为“勉强可以接受” |
| 未证明的事项 | 助手没有完成连续全片观看、实际完整试听、音画语义审核；没有产品 WebUI 全程导出、局部修改／撤销／重开闭环证据 |

历史 `provenance.json` 中 `humanReview: pending` 和技术报告中的待审信息保留原样。本次用户反馈记录在本复盘中，**不据此修改产品正式审批状态**。报告里的音频峰值也不能单凭相关系数解释成“听感完美”；实际听感仍需检查。

### 5.2 为什么仍然只是勉强可以接受

- 手持开箱的光线、背景、清晰度和拍摄角度限制了品牌广告质感。
- 72 秒整体仍长；完整原轨约束下，视觉更丰富不等于总体更紧凑。
- 多次使用相同相机区间，存在重复感；部分呈现更像动态产品画册。
- 原片约 24 fps，0.3／0.32 倍慢放会增加重复帧，不能把慢放自动视为高级感。
- 有结构展示，但缺少被证实的差异化卖点、品牌策略与转化目标。
- 变化显著与作品成熟是两件事；需要进一步检查动效是否过多、文字是否必要、节奏是否有留白。

因此 V2 证明的是“通过重新编排能让同一素材产生明显不同的结果”，没有证明“一条素材已经变成高水平品牌广告”。

## 6. 可复用的经验与不能照搬的参数

### 应复用

1. **先定义成品目标。** 场景路由必须输出为什么适配、素材支持什么、缺什么，而不只是一个场景 ID。
2. **先做少量代表性画面。** 开头、核心细节、结尾各出一个可播放片段，尽早检验创意方向，再完整渲染。
3. **把变化写进分镜。** 每段写明相较原片改变了什么，以及变化服务于哪个观看目标。
4. **证据要真的进入决策上下文。** 根据镜头相关性选择图像、源区间和观察结论，避免磁盘上有证据但模型看不到。
5. **声音和画面分开建模。** 保留整轨、跟随切片、旁白重排是不同模式，必须有可验证的结构。
6. **检查输出，而不只检查工程。** 预览帧、实际 MP4、连续运动和声音分别提供不同证据。
7. **局部失败局部修复。** 能复用的观察、分镜、已完成镜头与素材不应因续作而全部重算。
8. **诚实记录来源与状态。** 手工参考片、自动候选、正式交付是不同产物。

### 不应照搬

- 不把 72 秒设为 `product_launch` 的默认时长；现有场景建议通常更短，最终仍服从实际音频与用户约束。
- 不把三联画、圆形放大、墨绿色、超大字或固定转场数量设为所有产品的模板。
- 不把本片证据数量、24 张预算、0.3 倍慢放或硬编码时间戳当成通用参数。
- 不把 [create-v2.mjs](../outputs/mijia-brand-test/create-v2.mjs) 直接移入正式生产入口：它是本案例作者脚本，包含专用素材与时间选择。
- 不把测试通过数当成广告质量评分；不把用户一次轻度认可当成以后所有视频的验收标准。

## 7. 迁移到自有项目：建议的职责与流程

本节是**后续设计建议，未在本任务实现或验收**。项目已经存在合同、生产编排、资源目录、Skills、检查和交付等结构，应先对照 [Commerce 实施规范](commerce-focus-v1/03-IMPLEMENTATION_SPEC.zh-CN.md) 与当前源码，补齐能力，不另造一条相互绕开的流水线。

### 7.1 推荐的数据流

`用户需求 → 场景路由与约束合同 → 素材证据 → 导演计划 → 资源选择 → 代表性预览 → HyperFrames 编排渲染 → 实际成片审核 → 局部修复 → 可编辑版本与交付`

| 阶段／职责 | 必须输入 | 应输出 | 关键判断 |
| --- | --- | --- | --- |
| 场景路由 | 用户目标、素材概况、投放背景 | 场景、适配理由、缺失信息、目标成品描述 | 教程需要操作证据；展示不能冒充性能证明 |
| 合同整理 | 原始需求与澄清 | 时长、比例、声音策略、商品保真、允许生成范围 | 用户要求与助手假设分开存储 |
| 素材观察 | 原片、音轨、产品资料 | 时间段、主体位置、角度、动作、可用性、可信事实 | 空 ASR 不等于无语音；重复视图不等于新证据 |
| 导演计划 | 合同、证据、风格参考 | 每段目的、源区间、文字、布局、速度和转场理由 | 前三秒看点、快慢对比、结尾是否具体可执行 |
| 资源选择 | 分镜需求、资源能力与约束 | 可追溯资源回执、适配参数、失败替代方案 | 资源要适配素材与文字，不能只按关键词匹配 |
| 动效编排 | 确定的分镜、媒体与资源 | 可定位时间的合成、可编辑节点、独立音频结构 | 时间所有权清晰，任意时间点渲染稳定 |
| 审核与修复 | 实际 MP4、合同、源证据 | 问题位置、严重性、修复范围与复验记录 | 区分工程问题、事实问题和创意问题 |
| 交付 | 版本、审核结论、来源 | 视频、可编辑工程、待审项、版本记录 | 候选可交付不等于正式审批通过 |

这些是职责边界，不要求部署成多个并行 Agent。可以先由同一个模型分阶段执行，只要输入输出独立、状态可恢复、审核不会被作者自述替代。

### 7.2 让导演计划承载创意，而不是只填时间表

每个镜头建议具有以下语义，并映射到现有对象，不直接照此新增一套 schema：

- **观看目标：** 观众此刻应该理解或注意什么。
- **源证据：** 来自哪个素材、什么时间、实际可见什么。
- **编辑决定：** 为什么选择并列、裁切、慢放或全屏。
- **文字依据：** 结构标签、已确认事实或品牌文案；来源分别记录。
- **动效目的：** 引导视线、解释对应关系、进入下一章节，还是仅装饰。
- **声音关系：** 保持整轨或与该镜头绑定，是否存在语义错位风险。
- **验收画面：** 哪几个时间点应看到什么；需要连续播放验证什么。

例如“镜头细节”不能只写一个标题，应指定正面镜头持续可见的区间、放大区域、文字避让和离开该角度前的切出时间。V2 曾经出现的标注与画面错位就能在这一层被发现。

### 7.3 Skills 与资源如何从本案沉淀

| 可沉淀能力 | 输入／适配条件 | 输出与检查 |
| --- | --- | --- |
| 商品首屏揭示 | 清晰主体、可裁切区域、标题长度、品牌风格 | 三秒内产品与主题明确；不靠遮住商品制造动效 |
| 多画面信息压缩 | 互补的真实源区间、可读最小尺寸 | 并列内容不同；同源复用可追溯；不会误导为多条证据 |
| 局部放大与标注 | 稳定的局部坐标、连续可见时间、结构名称 | 放大的是目标细节；标线随画面内容成立 |
| 多角度结构卡片 | 有来源的角度图、统一裁切和文字 | 名称对应画面；卡片进入有顺序和留白 |
| 产品收尾 | 合适的正面／英雄视角、品牌与允许的 CTA | 明确结束；商品身份不变；没有未经授权的购买信息 |
| 原轨保留 | 唯一明确音源、目标时长覆盖、声音合同 | 独立音轨结构、对齐检查和待试听状态 |

每个资源或 Skill 应声明版本、适用素材类型、比例、文字容量、安全区域、时长范围、可调参数、时间控制方式、许可证／来源和降级方案。资源回执应记录实际选中的版本及参数，不能只保存“使用了某高级模板”。

HyperFrames 继续负责可靠的画面、媒体与动效执行。上游负责选对素材、讲对内容、用对资源；下游负责看真实输出和修正。单独增加模板数量无法补足导演判断。

## 8. 质量门槛：分别验证三个层面

### 工程正确

文件存在、可解码、媒体不越界、字体与布局可用、时间轴稳定、音轨符合合同。HyperFrames 检查和测试属于这一层。

### 内容可信

商品未被替换，结构标签有依据，产品主张有来源，素材使用没有产生错误含义，配音与画面的语义关系可接受。

### 创意有效

前三秒有具体看点；主体足够突出；每段有目的；信息密度和节奏存在变化；细节确实看清；动效有作用；结尾形成记忆。要通过真实播放与对照评价判断，不能用转场数量或截图数量代替。

建议沿用项目已有的候选与正式交付区分：音频待审可以允许视觉候选继续，但不能自动签发正式审批。审核反馈应落到时间段、问题和可执行修复，避免只给“更高级一些”的空泛评价。

## 12. 最终结论

本次最有价值的经验是：**先理解上传者想要的成品，再用素材证据作编辑决定，最后让 HyperFrames 把这些决定稳定地表现出来。**

前半程暴露了自动生产链路的可靠性缺口；V1 暴露了“工程合格但创意无效”；V2 则证明了重新组织叙事、构图与细节展示能带来可见改善，但成品还没有达到可作为高质量品牌广告标准的程度。

下一步应把这些决策和检查接回自有项目的路由、Agent 职责、Skills、资源与版本交付体系，既缩短反馈时间，也提高作品质量。保留失败证据和剩余限制，与保留可用的动效方案同样重要。
