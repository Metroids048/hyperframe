# 场景交付验收：产物、业务、多轮修改三者同时成立

本文件定义门槛，不报告已经通过。不得用一个总百分比覆盖未检查维度。

## 每场景的六个关卡
| 关卡 | 需要的实际结果 | 不算完成 |
|---|---|---|
| A 输入可用 | 完整可解码、实际观察源窗口、身份与事实准确、足够选择空间、用途授权状态明确 | 有文件名、ffprobe头通过、下载页面可打开 |
| B 业务链正确 | 普通需求进入正确业务目的+操作；否定/保持项继承；必要步骤/商品/问题保留 | 人为把正确分镜/节点清单直接塞给被测Agent |
| C 资源真应用 | 实际目录资源或明确标注的受控自实现绑定到真实节点，资源需求与素材兼容 | Prompt列10个组件名字、复制官方示例媒体 |
| D 完整片可看 | 全片MP4、最终预览一致、无阻断/重大视觉或内容问题、字幕与声音可核对 | 分镜、方向预览、无有效音画的文件、exit code=0 |
| E 多轮能改 | 每场景8轮对话，其中第1—5轮有实际编辑差异；引用、保持、恢复、撤销重做成立 | 8个孤立工程、结构化操作单代替自然语言 |
| F 原生能交 | 历史包换目录导入，再自然语言小改并导出；素材与对象/资源仍在 | 只有MP4、把成片当原生分层、包内缺字体依赖/音频 |

## 评价维度分开
技术验证、业务语义、视觉自动检查、完整播放检查、音频信号检查、真人创意判断、真人听感判断、版权/商用放行必须分别保存。无法听音不能自签听感；真人未审不升级为人审通过。没有重大自动/业务问题时可交“待人审候选”，继续下一可执行项，不伪造最终商用验收。

## 片内检查
连续播放完整最终MP4；抽查每个场景最可见帧、密集文字帧、首尾帧、所有切点与转场中间帧；横竖屏分别检查主体、标签、字幕和关键操作保护区。标签不得指向错误部位，步骤不得未做先完结，营销文字不得当作原声转写。片尾声音不截断，音乐不覆盖旁白；实际源时长、音轨范围、生成语音时长必须实测。

每片的个性化视觉机制按业务判断：S01记忆与亮相；S02整体/局部关系；S03动作顺序；S04多件组合身份；S05活动字段可读；S06答案证据；S07删留逻辑；S08分支隔离与画幅重布局。不能以“至少用了三种转场”代替这些目标。

## 多轮保持检查
记录每轮userRequest、projectId、baseRevision、resultRevision、焦点对象、改变字段、必须保持字段和实际diff。删除/移动镜头后的源时码、相应原声/字幕需一起验证；标注跟踪关系不能脱节。样式调整不应生成新商品画面，不应无故再次TTS；音量修改不应重新跑导演。实际未调用需以日志/计数证明，不填写推测值。

选择性恢复和完整undo要分开：用户“声音回到上一版，字幕留在现在”只恢复相关声音；undo恢复上一实际操作语义。存在依赖冲突时给出最小明确问题，不能擅自改全部。某轮失败不发布半成品；旧有效revision保持并保留失败证据。

## S08专门门槛
至少A横屏开头版+B竖屏重新布局版，都来自S02同一有效母版。A第3秒之后的源/文字/音轨/绝对时间保持；B保全部位、事实和声音，不能只改尺寸。兄弟版与母版字节/对象合同受保护。A/B都须有最终实片，并在历史包恢复后可分别编辑。

## 产物回执字段
scenarioId；actualBusinessScenario；taskMode；输入原话；实际源码与配置指纹；project/run/revision；实际工具与模型调用；source ranges与证据；资源来源/版本/执行器/范围；目标与保持diff；视频/工程真实路径与SHA256；本地执行命令、退出码、日志；已覆盖观察维度；失败与未验项；商业发布状态。

## 数量与范围
S01—S07各一条完成片，S08两条，最低九条。旧片、参考片、方向预览和同一MP4重命名都不计新增正例。已有S02可以复用合格成片/工程作为该场景基准；必须完成本轮仍未通过的业务/质量/多轮义务，并在台账中标“复用+修复”而不是“从零新生成”。
