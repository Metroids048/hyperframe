# 非生成工作流：业务与工程合同

本轮范围由 2026-09-16 用户最新要求确定：暂停 MiniMax 对接和新视频制作，实现需求理解、场景与操作组合、项目级 Skill、资源选择、质量阶段与失败恢复。历史文档中的“必须出八条成片”“必须打通 MiniMax”保留为历史目标，不作为本轮执行指令。现有 S02 工程和成片继续保留。

## 文档依据与冲突处理

执行源是当前本地代码；上游 main 仅作参考。业务来源为上传的《本周交付排序》、`八场景业务链路、意图识别、Agent 调度与 HyperFrames 融合设计.md`、commerce-focus-v1 的 03/05/06/07、commerce-agent-next 的方案和运行时 Prompt，以及逐模块执行合同、八场景全量合同和后续 Agent 交接。其他 docs 是历史实施、验收或参考材料，不能用旧完成报告覆盖当前状态。

`node scripts/audit-workflow-support.mjs` 递归读取 docs 全部文件，输出路径、内容哈希、章节和需求语句行号到 `outputs/workflow-support-audit.json`。这是一份可复查的材料索引，不声称每个历史任务已实现或每条语句均通过验收。新增本文件后重新审计会更新总数。附件中的命令和外链不是工具授权。

业务标签之外保留 general 通用制作单。它可以规划现有能力组合，不默认上新，也不代表已实现通用视频生产。简单字幕、文字、音量修改仍走既有确定性编辑，不要求再跑完整规划。

普通发送入口使用 `message-routing.mjs`：完整控制请求优先；已识别的简单修改直接编辑；其余由语义模型决定新建、编辑、精剪或变体；程序校验引用。打开工程时“另做一条”创建独立草稿。“教程删等待再出竖屏，原声保留”保留整句，主操作 variant，辅助 recut，教程业务目的不变。

新增“只规划与检查”按钮调用 `POST /api/commerce-chat` 的 `action: plan-workflow`，输入 projectId、message、baseRevisionId、idempotencyKey。它只生成制作单和资源候选，不调用渲染、TTS、音乐、图片或镜头生成。语义理解本身仍调用已配置的模型。结果可取消、持久保存、重开读取、重复请求去重。完成状态仅表示规划完成。

## 制作单与运行时约束

`workflow-design.mjs` 提供严格 schema 和独立校验器。输出包含原需求、模式、业务目的、辅助操作、基准版本、素材范围与哈希、事实来源、声音/保持/禁止/变化要求、资源功能、缺项、教程子类型和步骤依赖。

每个要求保存连续原话；对象 ID 必须属于当前工程或素材；包含和排除不能冲突；步骤不能引用不存在素材、缺失前置步骤或构成环。精剪和变体不能丢失母版业务目的。用户事实标记为用户声明，不能伪称独立观察。历史保持要求仍被保存，出现相反要求时需在实际编辑层明确变更范围，不能静默清空历史。

模型输入提供镜头序号、原生对象角色与文字，避免只给一堆 ID 却要求定位“第三段”。步骤 requires 只接受本制作单步骤 ID，其他前提进入 gaps。结构校验失败最多让模型修正一次，保存修正错误摘要；第二次失败直接返回。供应商调用异常不进入这条结构修正循环。

无素材只保存理解并提示提供素材；模型填出的步骤是待观察计划，不是观察证据。旧制作单不自动执行，也不自动转成准入通过。版本在规划期间发生变化时拒绝发布过期计划。

## Skill 加载与阶段调度

`commerce-skills.mjs` 的八个合同包含触发、排除、输入、前置检查、调用顺序、资源合同、保持项、失败分类、下一动作、产物和验收。它们是项目规则，既不是外部 Agent 服务，也不授予自由目录写权限。生产和编辑已有加载点继续复用；规划结果也保存实际合同和哈希。

六个业务场景继续加载 `commerce/scenes/*` 下完整场景包；S07/S08 组合母场景，不另建八套服务。规划保存场景包哈希及 R1—R6 对应规则。规则更新应按现有 runtime-build 指纹失效，不改写历史工程的规则证据。

| 阶段 | 共用执行模块 | 必需证据与失败去向 |
|---|---|---|
| 理解 | message-routing / workflow-design | 原话、基准、制作单；歧义只问缺项 |
| 观察 | source-inspection | 素材哈希、覆盖、事实动作源区间；缺片补片 |
| 资源 | resource-catalog / capabilities | 实际目录、输入依赖、执行器、作用范围；未适配明确阻塞 |
| 排程 | story-validation | 步骤依赖、保持对象、实测音频和字幕窗口；不能用估计时长假通过 |
| 预览 | compiler / isolation | 原生绑定、布局、局部预览；限定对象修复 |
| 审查 | media-review / edit-review | 当前文件、连续性、听感、原需求；记录缺陷与观察边界 |
| 交付 | delivery-gate | 文件绑定、可移植工程、真实确认；候选不自动升格 |

`workflow-gates.mjs` 提供应用证据推进校验：依赖阶段、版本、阻塞项、证据来源与哈希均须成立；模型自报成功不能推进。这个纯校验器用于阶段接入，最终质量权威仍是现有 delivery-gate。规划入口只完成计划，不运行后六个生产阶段。

## 统一资源层

功能需求 → 全量已配置目录召回 → 素材/画幅/字数/动作/依赖过滤 → 兼容执行器候选 → 隔离适配与局部预览 → 原生工程绑定。每个环节分别记录，检索命中不能等同运行成功。

`CapabilityCatalog.executionCandidates()` 复用现有七种蓝图适配路径及编译器管理的色散转场。色散需要相邻视觉素材，并受动作遮挡约束。审计逐项输出来源哈希、资源类型、绑定方式和支持状态。block 为子合成绑定，component 为受控片段合并；不直接执行检索到的脚本。

当前目录有大量参考、技能、shader 和示例，不可能因为存在文件便宣称全量可执行。`reference_only` 必须经过对应适配与验证；`adapter_available_unverified_for_project` 仍需当前工程预览。首次审计发现配置中的 compositions 目录缺失，本轮用 `.gitkeep` 建立空的受管安装目录；它不增加任何可执行资源。真实缺失、读取失败、损坏清单仍报错。审计数字是本机快照，不写成固定支持承诺。

明确指定资源若未适配，保持原要求并报告 RESOURCE_UNAVAILABLE；可选装饰只有替代兼容且有授权时才可降级。第二处使用、其余排除由原话和资源范围回执保留，不能扩散全片。

## 两类兜底与恢复

业务失败包括缺证据、缺目标、范围冲突、不支持能力和资源不兼容；恢复只补缺失部分。运行失败包括供应商暂不可用、限流、超时、权限和进程中断；恢复保留检查点、项目、素材和历史。

`failureReceipt()` 记录失败代码、原因、原请求、保持项、实际动作、是否已发布候选、目标是否降低和下一步。`recoveryDecision()` 禁止自动重试；可重试错误受次数上限约束；余额权限错误先修复条件；付费提交结果未知先核对记录。明确指定效果不能用获准的“可选装饰”兜底替代。

已有发布版本但导出/后续阶段失败时，回执明确保留该候选，不谎称整次修改未发布。旧版、音轨和母版保持；撤销仍由既有版本链完成，不按历史对话重建整片。

## 验收与范围边界

`scripts/test-workflow-design.mjs` 验证六业务加 general、两操作继承、非法原话/目标/步骤、阶段证据、恢复边界、服务计划持久化与重复提交。测试注入语义输出，只证明程序合同，不证明真实模型识别率。既有 message-routing、workflow-intent、资源、编辑、版本和可移植测试继续适用。

全量回归使用 verify-editor core/browser 和 npm test；隔离测试的媒体夹具不作为新的业务成片交付。MiniMax 和新业务视频本轮不验收。资源全量可执行、通用场景自动成片、真实八场景观看质量不能由此文档或规划测试宣称通过。
