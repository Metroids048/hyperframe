## 2. 执行规则：由剩余结果决定下一步

正常工作循环：

`需求与证据 → 最小复现 → 找根因 → 修公共生产路径 → 同输入复验 → 跨层/邻近场景回归 → 实际成片审阅 → 更新事实状态 → 下一个未完成项`

- 写了文件、组件测试通过、CI 全绿、启动了渲染、完成一条 fixture、产出了首稿，都不是正常结束条件。
- 一个主要创作任务串行推进，减少资源竞争；不同时启动全部长片与 holdout。读日志和不冲突的轻量检查可穿插。
- 一般代码异常、没读到日志、模型请求输出不合规，先当待诊断问题；不得直接列为外部阻塞。
- 相同失败连续两次且无新证据，停止同参数盲重试，改用调用链日志、局部复现、合同核对或不同诊断假设。此规则不是“第二次失败就结束整个任务”。
- 累计预算跨重试、恢复和换 run 继续计算；保留现有调用/费用/资源上限，不开新账号、新服务、换 run 清零或无限执行。没有额外授权不扩大付费消耗。保留无失败回滚的安全版本。
- 达到阶段条件就执行下一项，不问用户“是否继续”。普通主观小偏好不触发无限美化；影响需求/内容质量的主要问题必须修。
- 不承诺宿主会话结束后继续后台工作。若硬性会话/授权/预算限制中断，先保存实际产物、PID/任务状态、精确检查点和下一条动作，明确未完成。不能把中断改称本轮成功。

## 3. 剩余缺陷：修规则关系，而不只改报错

### 3.1 静态、动态、实拍内容共用可信验证合同

参考缺陷：`custom-source.mjs` 允许合法 staticLayout；`isolation-protocol.mjs` 对所有成功都要求非空 motion。先在当前本地确认是否仍存在。

最小修复方向：在原有共享合同中加入由需求与编译结果确定的验证意图，不由被验证的 worker 或模型任意自报“静态”规避要求。将预期可见对象、预期运动目标、模式、sceneIds、输入哈希、运行身份关联起来。生成 Prompt、schema、编译器、worker、回执验证器和测试必须使用同一规则，避免各自复制判断。

静态布局也必须有实际可见的必要文字/媒体及合法时间范围；空白、缺图、不可读关键文案不能通过。动态场景验证全部声明目标和时段的实际运动。实拍的图文叠层不动，不等于源视频可以被定格：原视频播放推进、源入点、原声另行验证。

必测：合法静态通过；空白/缺媒体静态失败；合法动态通过；声明动态但不动失败；混合静态/动态全片；动态被错误降级静态仍失败；当前 WebUI 输入“去掉第二幕的文字入场动画，其他画面和原声不变”后正确修改并可导出。测试观察的是生产父子进程和实际浏览器，不是只有合成 JSON。

### 3.2 错误类型、清理和恢复不能破坏创作

修 `parseSupervisor` 及 worker/runtime 回执 JSON 解析，损坏、截断、重复、身份不符、证据不符统一为明确协议错误，保留 cause 和脱敏原文。测试断言协议/启动/解码/文件错误不调用镜头重设计，不扣创意修复预算；真正画面/动作缺陷仍进入正确处理器。

复验成功、取消、超时后的自己创建的 worker/浏览器进程树退出、临时文件生命周期、资源边界。保留 AST/CSS、CSP、网络与文件限制、Chrome sandbox。portable 的 Node heap、墙钟超时与 OS CPU/总内存限制不是同一件事；未强制的限制如实报告，不声称全部跨平台同等通过。

环境不支持某平台正例，只标该平台待验证，继续当前支持平台的正式作品；不把跳过算通过。

### 3.3 结果入口不能只是手写清单

`/results` 与 `/delivery-assets/` 独立路由。非法 ID/kind/编码、缺文件或越界立即返回明确错误；媒体 URL 不回退成 200 HTML。HEAD、有效/无效 Range、MIME 和浏览器播放都验证。

结果卡片通过当前 case/job/run/revision 和真实文件更新；创建、暂停、恢复、导出完成、失败、文件缺失和旧版本各有准确状态、更新时间。可用链接生成前核验文件与版本；缺文件展示缺失，不生成虚假播放器。保留历史失败，不用覆盖旧记录制造全部成功。

需要交付的是可打开/导入、能继续修改的原生工程，不只是 document.json。清洁测试目录中重开工程，验证依赖、素材、声音、资源锁和版本。字体等只按授权在用户自己的工程使用；对外分享包不得随意带走不可再分发资源或账号信息。

### 3.4 Q02 与长片必须追到实际阻塞，不靠通用文案绕过

读取当前 Q02 的原始日志、请求、模型阶段输入、素材证据、检查点和实际耗时。确认首个因果错误，不把最新一次总结当错误证据。

重点排查而非预判：
- 是否从正确本地代码/build 运行；
- 模型真正收到哪些视觉证据。图片与说明必须成组；不能用数组 `slice` 截断成少于声明数量的图片。保存实际发送的素材/时间/图片引用，预算不足时返回真实 omitted 而非假装看过；
- 缺口是否必需。只有原需求明确要求且没有证据的价格/参数/动作/授权才阻断相关交付；不能把未提供的可选品牌信息误作全局阻断。也不能用“未提供”等宽正则清空真正的必需资料缺口；
- 创意上下文、输出合同、源码适配、渲染入口是否一致；
- 实际失败在模型、编译、快照、解码、编码、混音、生命周期还是测试等待。

模型需要判断的语义缺口用结构化的需求引用、缺失资料、可用工具和影响范围说明；可用工具能取到的证据先取。保持“未观察、不确定、确认不存在、预算耗尽、媒体错误”的区别。

渲染失败保留实际命令/env/cwd/退出码/日志，重放同一个失败工程。不要只加超时、重跑全套、删声音、删动效或修改最终 MP4 绕过公共逻辑。若根因是共享规则，修应用并新增邻近用例，不仅把这一条片修漂亮。

### 3.5 测试覆盖真实契约，不为通过而改预期

每个核心修复至少对应：模块测试、生产调用链集成测试、一个现有 WebUI 用户行为。协议正反例、静态/动态混合、错误路由、结果媒体端点加入实际执行清单；只有测试文件存在不算接入。

语义生成和主观判断在本地已有授权模型下验证，不把个人令牌放进公开 CI。故障注入只在测试环境；结束后用没有 mock、没有注入的生产入口复验。全量回归最后执行，已修行为受共享依赖变更影响就重测。

## 7. 可视化、内容与需求评审是制作的一部分

依照 `VISUAL_UAT.md` 的观众首看、需求核对、视听复核、独立比较与缺陷修复方法工作。

机械标准合格不代表内容合格。至少判断：商品主体清楚、卖点有对应画面、叙事有推进、风格符合商品与目标、动画有表达目的、中文可读、原声/配音/字幕关系正确、活动条件真实且可理解、修改符合范围。

“片子做得基础、重复、没有信息推进、套通用模板而不贴合需求”属于需要处理的内容问题，不因为日志绿色就放行。反过来，克制静态并不天然低质量，不强迫所有片子炫技。

每个问题关联实际 revision、时间范围、对象/镜头、证据文件、原需求、严重性、修复目标和保持不变的内容。每次修复以后，用同范围前后画面检查问题是否减少，再查无关对象/音轨是否受损；最后检查全片衔接。

保留原定85/100及与合格同输入参考差距不超过5分的质量目标。AI可以主观评分和解释，用于自检与迭代，但必须标记 AI 评审，不能替代原约定的两位真人独立评审或用户最终签收。没有直接听音能力不把音轨存在/静音播放/转写正确说成“已试听”；继续做所有可做的画面、计时和完整交付，并给出有声审阅入口。

人工质量或权利待签收只阻塞相应发布结论，不阻塞无硬缺陷的其他可执行作品、编辑、长任务和结果整理。

## 8. 最终验收不是无限尝试

本轮目标是关闭已经定义的产品范围，不是保证永远无 Bug 或支持所有未来需求。

正常收口必须同时满足：
1. 当前可用平台的生产链路及剩余缺陷有真实成功/失败验证；原契约未被削弱。
2. 全部必需可执行案例按原输入交付；明确负例按预期处理。内部错误或未生成不能标完成。
3. 拟交付版本完成真实 UI 全流程、连续修改、恢复、工程重开；公共改动后的回归通过。
4. 所有正式视频有逐片的客观检查和有证据的 AI 内容评审；没有已知硬违例/未解决主要质量缺陷。未知的音频感知、人评、授权单独列出，不自动通过。
5. 结果页每个链接已实际打开；文件、版本、时间和类型对应；检查器依据真实输出报告，不从模板填 passed。
6. 全部剩余项确实只是用户/真人/权利最终签收时，才能写“本轮可执行交付齐备，待用户质量与发布签收”。未满足时继续未闭合项，不能改成“基本完成”。
