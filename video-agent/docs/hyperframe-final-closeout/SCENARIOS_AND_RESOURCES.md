# 电商需求覆盖与 HyperFrames 资源收口

本文件是最终执行指令的资源/场景附录，不是已安装清单或已通过的商家调研。场景用于理解需求、映射原测试和展示Demo，不把用户限制在互斥菜单里。不会额外要求跑36条无关新片；先将以下36个需求例映射到原冻结Q/I/H，缺口如实列出，原范围内必需项不能删。

## 一、目标不可退回通用渲染器

用户购买/使用的是完成经营任务的能力，不是组件名称。产品应串起：需求与素材理解、事实核对、创意叙事、资源匹配、原生制作、完整视听检查、对话续改和发布前交付。

“丰富”不是模板数或动效数。应由不同需求得到不同但合适的表达：产品亮相、细节解释、动作流程、真实证据、优惠条件、品牌风格、口播包装、重剪和多画幅。单条片不需要全塞；真实素材更适合直接剪辑时，不强行套组件。

## 二、36个需求例的覆盖地图

以下是整理需求的起点，不是市场统计。每行3个例子，可被同一个原case覆盖多个维度；多行也可组合为一次需求。

| 经营/内容任务 | 三类典型输入需求 | 需要证明的能力 |
|---|---|---|
| 新品上架 | 只有主图做上新；图加实拍做介绍；资料齐全做品牌新品片 | 简短输入到自主叙事，不编事实 |
| 商品细节 | 放大材质；解释按钮/结构；展示颜色与尺寸 | 素材清晰度、真实指向、主体保护 |
| 功能与选择 | 多功能说明；不同配置对比；选购/适配建议 | 参数有依据、信息分层、比较不串款 |
| 开箱与使用 | 包装/配件；操作教程；维护/清洁说明 | 真实动作完整、顺序正确、原声对应 |
| 口播与种草 | 精剪口播；加入商品辅助镜头；有授权的评价/反馈整理 | 转写语义、保留限定条件、字幕和辅助素材匹配 |
| 活动促销 | 限时折扣；组合装/赠品；优惠券与门槛 | 价格与条件正确、显著可读、按要求安排时序 |
| 品牌与风格 | 生活方式；高端简洁；年轻活力 | 品牌视觉一致、风格适合商品，不同品牌不是换色模板 |
| 老素材再利用 | 长片重剪；同片换开头；不同受众改卖点次序 | 复用实际素材、结构重组、锁定其余内容 |
| 素材版本管理 | 替换指定图片；切换SKU；改活动价与日期 | 绑定对象/事实、版本安全，不串图串价 |
| 分发适配 | 竖横方重排；语言改版；15/30/60秒同素材重组 | 不是简单裁切、倍速或截断，声音/字幕重新计时 |
| 批量与变体 | 同SKU两个独立创意；多SKU品牌一致；不同开头可比较版本 | 批次信息正确、独立创意与参考分开、可追溯 |
| 连续编辑与缺口 | 锁开头只改中段；只字幕不要配音；素材/事实不足或冲突 | 复合意图、精准变更、正确拒绝/说明/恢复 |

首批演示沿原Q/I/H选择真实同款商品、原素材和原请求。不能把无声中性操作片算作口播营销全覆盖；也不能为了凑促销Demo凭空加价。更广的直播长切片、数字人等可在能力地图列为后续供给，不能临时引入新收费服务绕过当前正式任务。

交付的覆盖表至少有：用户需求例、原case/输入引用、已实际覆盖的步骤、运行/作品/资源证据、通过或缺口。区分“列出了场景”“做过技术样例”“真实用户任务已通过”。

## 三、资源分层，不能混为“插件已安装”

| 层 | 作用 | 进入项目后的合格证据 |
|---|---|---|
| 框架/运行时 | 时间、媒体、原生合成、渲染 | 版本固定、检查/seek/渲染/编辑一致 |
| Skills/引用/蓝图 | 做事方法和制作规则 | 应用阶段实际加载所需正文/依赖、收据关联 |
| 整片示例/模板 | 结构、视觉语言的参考 | 许可/兼容检查，可拆成镜头能力而不是固定整片套用 |
| Blocks | 完整场景或子合成 | 进母工程、时间/尺寸/对象映射正确、可续改 |
| Components | 字幕、标注、图形、效果 | 参数化执行、有真实画面/动作证据和对象ID |
| 品牌规则 | 色彩、字体、留白、语气与运动幅度 | 全片及派生画幅一致，未知字体不静默替换 |
| 插件/适配器 | 本地工具、动画或媒体能力入口 | 有真实可调用实现、依赖、风险和版本验证，不是标签 |
| 媒体 | 用户的图、视频、声与获准素材 | 来源、同款关联、使用范围、哈希、源时间可追溯 |

本轮优先改善已有 CapabilityCatalog/native-recipes/R0—R8 等入口，不重建插件市场。一个模板拆成12个名字不算12个新能力；只把蓝图放入prompt不等于已经参数化执行。

## 四、官方资源盘点的具体入口

### A. 核心技能与任务工作流

HyperFrames官方Prompt Guide列有入口路由、core、animation、creative、CLI、media-use、registry、keyframes和general-video等技能，以及product-launch-video、embedded-captions、talking-head-recut、motion-graphics等任务工作流。[S1]

本地按当前快照核验文件和依赖是否存在；对应实际任务分阶段加载，不一次性将全库堆给模型。技能必要引用、蓝图、样式和脚本分别审查，通用方法和受信任执行能力分开。上游安装指令不自动授权升级、登录、联网传素材或调用付费工具。

建立最小资源记录：来源/版本/许可、kind、可表达目的、所需输入、适用画幅/语言/时长、可编辑参数、限制、调用方式、相应验证。

### B. 起始模板

官方Showcase提供成片和部分公开工程，也列出九个起始模板。[S2] 下列是建议的电商映射，不是它们已在本项目全部通过：

| 名称 | 可借鉴的方向 |
|---|---|
| product-promo | 多场景商品展示 |
| warm-grain | 生活方式与品牌表达 |
| swiss-grid | 参数、功能与结构化内容 |
| kinetic-type | 文字卖点、活动/标题表达 |
| play-mode | 有活力的上新/社交内容 |
| decision-tree | 选购关系、步骤解释 |
| nyt-graph | 有可信数据的图表 |
| vignelli | 竖屏通知/活动信息 |
| blank | 现有模板不适合时的受控原创 |

不要求硬装或硬用九种。先比较本轮任务的需要，再适配最合适资源。广告数据和图表数字必须有事实来源，不能借模板捏造。

### C. 动效与组件的优先表达

重点核验：商品清楚亮相、细节特写/嵌套视图、真实指向标注、参数/双栏比较、配件/步骤、原生字幕强调、视频加图文、多画幅品牌收尾。

先以已有GSAP和受管原生能力完成。官网出现的其他动画运行时或集成，不等于固定0.8.33应用已经支持。若某个表达确实受执行器限制，给出具体输入、预期画面、合同缺口，做最小兼容适配与正反测试，不用放开任意脚本来换效果。

## 五、资源匹配的运行机制

`用户目标/素材 → 事实与缺口 → 叙事和镜头目的 → 候选检索 → 硬条件过滤 → 最合适资源组合 → 可编辑原生执行 → 实际成片与续改验证`

先看输入数量/类型、可读尺寸、同款素材、声音、中文、版本、许可、时钟和可编辑性，再比较风格与节奏；不能只用几个关键词截前三个就封死整片表达。不同镜头可以有不同资源，仍继承同一品牌语言。

保留四种执行选择：实拍精剪、参数化复用、组合适配、必要原创。每次选择都能回答“为什么有助于这次需求”。没有适合资源，不是自动降低目标，也不是临时调用未经授权的外部生成器。

资源能力验证包括：进入真实调用链、实际画面不是占位、对象可修改、暂停/seek/重开可靠、输出和预览一致。成功方法可在现有本地资源/技能机制中沉淀，去除商品私密内容；不能只保存MP4然后下次全部重来。

## 六、三个参考产品分别借鉴什么

**即创：经营任务导向。** 用户给的登录页本次没有可读取的工作台内容；不能声称实测了登录后的全部功能。[S3] 巨量引擎公开商家课程将其用于创意素材制作，[S4] 可将其作为电商任务组织的研究线索，不直接据此写当前功能完成表或转化承诺。

**ChatCut：方法复用与可编辑表达。** 官方把Skill解释为可复用的工作方法，并支持把成功流程保存为个人Skill；效果文档描述优先使用兼容效果，不适合时再生成自定义效果，且保持源素材不被改写。[S5][S6] 本项目借鉴方法/风格/对象/资源的分离和精准续改，不复制闭源模板，也不把竞品收费生成能力列为本轮依赖。

**Vidu Agent / ViduClaw：从目标组织完整制作流程。** 官方页面描述面向电商、营销内容及技能复用的工作流。[S7] 本轮参考其任务表达和流程组合，不接入新的生图、生视频、数字人或收费服务；此类供给能力明确不在当前收口范围内。

**执行机制参考：** OpenAI的工程实践强调给Agent可操作的应用、日志、验证和恢复能力，而不只是更长的指令。[S8] 对本项目只取小型必要反馈链：复现、公共修复、真实页面复验、结果记录。不要照搬大规模工具平台或给自动提交/合并授权。
