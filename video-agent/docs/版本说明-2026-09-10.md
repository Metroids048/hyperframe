# 版本说明：2026-09-10 最终整合版

> “昨天版本”指 9 月 9 日你本机已经在使用的对话剪辑 Demo / 工作状态。这个 GitHub 仓库的提交历史从 9 月 10 日才开始，因此下面不虚构一个不存在的 9 月 9 日 Git commit。本文同时区分“今天已累计并入 main 的能力”和“本轮最后补齐的改动”。

## 一句话变化

昨天更像“已经能用自然语言做一批剪辑操作的 Demo”；现在变成了一个更接近 ChatCut 形态的**聊天 + 预览工作台**：编辑状态、版本、缓存、真实媒体检查、生成素材接入和 HyperFrames 渲染被收进同一套工程规则，同时补齐了连续撤销/重做、中文版本号、大批量操作、工作台启动上下文和 10 个可路由 skills。

## 新增 / 完善的 Skills

项目原来实际注册 5 个结构化执行 skills：`timeline-edit`、`speech-captions`、`visual-composition`、`audio-mix`、`rough-cut`。

本轮再加入 5 个 HyperFrames 创作/规划 skills，总数变为 10：

- `hyperframes`：总路由，约束固定 HyperFrames 0.8.33、原生项目续改、确定性预览/导出；
- `faceless-explainer`：主题/文章/笔记 → 讲解节奏、旁白、句级字幕、场景结构；
- `hyperframes-creative`：可编辑标题、强调、步骤、对比、信息图和品牌开/收尾的创作规则；
- `media-use`：真实截图/图片/视频的使用与取景规则，禁止用无关 B-roll 冒充指定素材；
- `hyperframes-animation`：seek-safe 动画、GSAP 进入/退出和转场规则。

这 5 个新 skill 被真实注册到 `config/skills/registry.json`，并加入 `lib/edit/skills.mjs` 的意图路由，相关请求会把对应说明加载进 Agent prompt。为了不夸大能力，注册表会区分 `project-adapter`（当前执行器可以直接执行的结构化工具）和 `prompt-router` / `composition-guidance`（用于规划和创作约束、不会获得任意 shell/HTML 权限）。

## 对话剪辑核心流程完善

今天累计完成的关键变化包括：

- 工作台收敛到聊天 + 预览，普通用户不需要直接操作复杂时间线；
- 简单裁切、字幕、音量等优先走本地精确意图，减少没必要的模型等待；复杂“按内容剪”才触发模型、转写、抽帧或镜头分析；
- 编辑任务和 MP4 导出分队列：导出旧版本时仍可继续提出下一轮修改；
- 真实素材准备、FFmpeg/FFprobe、HyperFrames preview/full check、严格 render 和项目 ZIP 形成完整验证链；
- ASR/TTS、媒体准备、混音、历史版本媒体尽可能复用缓存；
- Windows/Linux CI、真实浏览器、异常媒体、声音、画面边界和原子保存都进入回归；
- 本地 Codex 登录复用系统代理；模型容量失败会保留输入和项目，不再伪装成功；fallback 只走明确配置的受支持模型路径；
- 普通字幕和配音分离：加字不自动朗读，只有明确配音/绑定旁白才生成声音；
- 本地 Whisper / Kokoro 路径、VAD、人声压低、字幕翻译和多素材处理得到统一工程约束。

## 本轮最后修复的 4 个确定性问题

1. **连续撤销/重做**：之前“撤销”直接追当前 revision 的 parent，恢复版本后再撤销容易走错历史。现在单独保存内容历史导航和 redo stack，连续撤销、连续重做都按内容分支运行。
2. **中文版本号**：`回到第十一版`、`第二十版`、`一百零一版` 统一使用 1～9999 的中文/阿拉伯整数解析，不再用字符串下标推断版本。
3. **大批量原子操作**：规划器和执行器统一为最多 2000 项，解决“模型能规划 150 条字幕更新、执行端却在 100 条拒绝”的契约冲突；任何一项失败仍不发布半成品 revision。
4. **服务与预览稳定性**：静态/案例文件异步异常通过 HTTP handler 正确捕获，不再因为缺一个可选文件把 Node 服务打掉；HyperFrames 预览浏览器关闭/重开增加串行化，避免 close/open race。

## GitHub + 本地工作台融合

新增 `prompts/workbench-agent.md`、`scripts/workspace-context.mjs`、`npm run doctor:workspace` 和启动前 preflight。现在工作台启动时会知道：当前分支/HEAD、`origin/main`、ahead/behind、是否有本地源码改动、HyperFrames 版本、完整 skills 清单以及应该如何融合。

核心原则是**不以 GitHub 覆盖本地，也不以本地覆盖 GitHub**：本地当前文件是真正执行源；GitHub main 是上游参照；dirty + behind 时必须三方融合并复测；网络不可用时仍允许 standalone-local 启动。Claude 入口和仓库 Agent 入口都指向同一个 canonical prompt，避免同一项目被不同 Agent 用不同规则理解。

## 相较昨天，用户能明显感知的差别

| 昨天 | 当前版本 |
|---|---|
| 一次撤销基本可用，多次恢复链容易混乱 | 连续撤销 + 连续重做 + 任意中文/数字版本恢复 |
| 某些大批量字幕/操作会在执行端突然超过 100 条 | 规划/执行统一 2000 条并保持原子提交 |
| 模型/媒体/浏览器异常有些会表现为“页面卡住” | 任务保存、错误边界、预览 session 收尾更明确 |
| 5 个偏传统剪辑 skills | 10 个 skills，增加 explainer/creative/media/animation/HyperFrames 路由 |
| Agent 启动主要依赖当前会话自己理解目录 | 启动即生成 Git/本地上下文，并读取统一 prompt |
| GitHub 与本地冲突主要靠人工临时判断 | 明确 clean/behind/dirty/diverged 四种策略，禁止破坏式同步 |

## 没有伪装成“已经完成”的部分

- 自动化测试通过不等于“专家主观质量 85 分”；没有两位真人完整盲评就不写这个结论。
- 模型容量属于外部运行条件，本轮只能保证失败时保存输入/版本并安全重试，不能保证某个云模型永远有容量。
- 新增的 5 个创作 skills 已进入 Agent 路由，但其中 `prompt-router` / `composition-guidance` 不等于任意自由 HTML 已开放给编辑器执行器；当前执行仍受结构化操作 schema 和已配置媒体 provider 限制。
- 纯零素材“文章直接一键生成最终长片”仍需要继续把自由 HyperFrames composition authoring 安全接入共享编辑工程后，才可以称为完整产品闭环。现在 Agent 已有对应工作流规则，但不能把未接执行器的部分写成已实测功能。
