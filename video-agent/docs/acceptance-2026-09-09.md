# 本地 Demo 验收记录 · 2026-09-09

## 范围与结论口径

本轮验收针对 v0.6 本地商品营销视频 Demo：一段话与商品图片输入、信息整理、镜头编辑、HyperFrames 检查与渲染、MP4 播放下载、历史版本和 Studio 交接。测试使用独立的 3022 端口与 `outputs/acceptance/<时间>/projects`，不覆盖正式项目。正式入口仍为 http://127.0.0.1:3020/ 。

本次包含真实 Chrome 操作和真实视频渲染，不再仅依赖内存界面替身。最终逐项状态以 `outputs/acceptance-latest.json` 为准；正式案例复核见 `outputs/release-smoke.json`。结论仅覆盖当前 Demo，不表示模型接入或生产服务已验收。

## 已修复的问题

1. **Windows 启动失败**：PowerShell 5.1 对无 BOM 的中文脚本解析异常。启动脚本改用兼容的 ASCII 提示，并补建日志目录；已在 Windows PowerShell 实际启动成功。
2. **检查依赖在线字体**：Georgia 被 HyperFrames 映射到 Google Fonts 下载，断网时拖住检查。为 Georgia 和微软雅黑明确声明本机字体，保留既有视觉风格；新工程无需该在线字体下载。检查阶段设置 60 秒上限。
3. **渲染失败仍长时间等待**：底层 Chrome 偶发启动失败后，CLI 可能仍保持进程。捕获明确的 Render failed / Check failed 输出，终止本次子进程并将项目转为失败，保留输入和重试入口。
4. **无效 JSON 返回内部错误**：空值、数组、错误类型和超限请求增加入口校验，分别返回 400 或 413。
5. **断网无限刷新**：状态请求增加超时与退避，连续失败三次后暂停，提供「重新连接」按钮，不自动重新创建或重新生成项目。
6. **界面状态不一致**：视频设置摘要随选择更新；快速切换项目时忽略过期响应；防止重复点击生成；按帧比较分镜时长，避免浮点显示差异产生无意义的新版本。

## 复测方式

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1
npm test
node scripts/check-boundaries.mjs
node scripts/release-smoke.mjs
```

`npm test` 会创建独立测试项目并真正渲染视频，需要本机 Chrome 与现有依赖。测试结束关闭测试服务，保留日志、画面和视频用于追溯。`release-smoke` 用于正式示例与 Studio 交接，会先备份已有 Studio 副本。旧的 `test-v3/v4/v5/v6` 文件是历史验证脚本，当前回归统一使用 `npm test`。

## 已知边界与未验收项

- 当前真实输出为横屏 720p。竖屏、方形、1080p、4K 只保存需求并展示提示。
- 自由描述使用本地规则，案例使用预置文案；没有把它当作实时 GPT、生图或生视频 API 验收。
- 视频上传处理、配音、字幕、单镜头模型生成、镜头级缓存尚未实现。
- Studio 是独立编辑副本，手工修改使用 Studio Export，不自动回写历史 MP4；Studio 内部全部编辑器功能和 Export 未逐项测试。
- HyperFrames 对重复图片与单轨多镜头仍有两类结构警告；完整运行、布局、运动和对比度检查通过。未通过隐藏警告或跳过检查来验收。
- Chrome/HyperFrames 的偶发进程启动失败仍可能发生，本轮补齐快速失败和重试，不宣称任何机器上百分之百出片。持续压测、断电写盘恢复、生产鉴权和并发服务化不在本次范围。
- 长片可播放并不等于营销效果已验证；没有承诺投放收益或专业剪辑质量。
