## 1. 保持范围与兼容性

## 3. 场景 A：单品上新／种草
### 3.1 用户与任务
制作用户假设：中小商家、品牌内容运营，手里有真实拍摄资料，但不擅长剪辑。观看者是假设的首次接触商品人群。触发是新品上线或需要社媒单品介绍；业务目标是快速建立商品形象、呈现一到两个可信重点、引导进一步了解。这些画像需要后续访谈验证，不当成已有调研事实。

### 3.2 输入与输出合同
输入包括真实同款视频、可选辅助图、商品身份、已确认事实、品牌信息、目标观众、发布用途、时长画幅与声音要求。用户不用手工编写全部分镜。商品价格、性能、优惠缺失时不得补造。

默认可建议 20—30 秒主片、竖屏，但不是不可协商的硬编码值。必须服从用户原始要求和素材取景。输出为最终 MP4、来自该文件的封面、原生可编辑工程、来源清单和当前质量状态。

素材内容建议覆盖整体、真实使用、至少两处有效细节和结果／整体回归。同一条连续视频也可能包含足够镜头，不因文件数量少而拒绝；反过来，下载十个无关片段也不能判充分。

### 3.3 完整流程
理解目的 → 生成短任务合同 → 检查同款、权利和信息覆盖 → 观察原片并索引可用区间 → 制定主表达与镜头安排 → 选模板／部件 → 建立静态关键帧 → 制作候选 → 导出实际文件 → 商家／消费者／剪辑视角审查 → 局部修复 → 待真人确认 → 正式交付。

镜头结构是指导而非固定填空：迅速建立主体，展示真实使用，呈现有证据的细节，回到整体，清楚收尾。每幕至少提供新的有效信息或必要的情绪推进。缺内容时减少时长或请求补料，不重复慢推图来凑足秒数。

### 3.4 Agent 与 HyperFrames 的分工
Agent 决定目标、事实、选段、叙事、资源匹配和修复；HyperFrames 呈现媒体、布局、文字、动效和声音并输出原生工程。模板可以复用，但不能固定某商品文件名或直接返回预置 MP4。

### 3.5 用户验收与真实续改
首次观看者能在前段理解是什么商品；细节与文案一致；没有错型号或性能编造；品牌和原色正确；结尾明确。测试至少包含“只改片尾标题、不动声音”“减少动效、保持镜头和事实”“撤销并重开导出”。

## 4. 场景 B：单品使用／操作演示
### 4.1 用户与任务
制作用户假设：电商运营、售前售后或教学内容人员；观看者是第一次使用商品的人。目标是看完能够理解并重复关键操作，不是只做一条漂亮的展示片。

### 4.2 输入与输出合同
输入是同一商品完整操作原片，必要时有同一操作的细节补拍；还包括可信步骤资料、必须保留动作、观看者基础和声音要求。可建议 45—60 秒，时长以关键动作能完整理解为准，横竖屏以保护动作和用户用途共同决定。

输出为可学会的完整操作片、独立可编辑步骤说明、原生工程、步骤到源时间映射、最终质量报告。不得为卡时长删掉前置动作；原片没有某一步就明确缺口，不能用文案、静图、逆放或别的商品补假动作。

### 4.3 完整流程与动作证据
理解观众基础 → 看完整操作 → 建立步骤与先后依赖 → 为每步记录源视频区间 → 判断是否缺步骤 → 删除等待和可删重复 → 保留连续关键动作 → 同步源音频 → 添加不遮挡操作区的步骤条 → 检查能否照做 → 修复／续改／交付。

每个必要步骤记录 stepId、前置步骤、assetId、sourceStart/sourceEnd、动作说明、保护区域、对应成片区间、证据和置信限制。一个视频中的同一动作被不同裁切复用，不算多次独立证据。转写文字能辅助，但不能替代看动作。

### 4.4 分工与验收
Agent 决定哪些能剪、哪些必须保留；HyperFrames 准确呈现选段、步骤、局部提示和对应原声。新手能看见从何处开始、如何完成、完成结果；不能仅凭“步骤字幕都写了”通过。

测试包括“把第二步说明移开手部”“慢放指定动作但同步原声”“缩短等待不删步骤”“只改字幕不生成声音”“撤销、重开、重新导出”。若时长和动作完整性冲突，应说明并记录实际用户选择，禁止悄悄牺牲关键操作。

## 5. 共用数据：不要靠一大段聊天保存全部规则
新增或扩展既有持久对象，优先沿用现有存储方式，不先迁移数据库。

BusinessContract 保存场景、制作者／观看者、目标、商品身份、已确认事实、未知事实、输出、声音、必须内容、禁止项及版本。输入事实要区分用户提供、原片可观察、尚未确认；模型推断不得升级为事实。

AssetManifest 保存来源页、作者、授权范围、文件路径、哈希、媒体元数据、商品身份核对、可用源区间、镜头角色、动作覆盖、审核状态。素材候选不等于准入批准。

ShotPlan 保存每幕目的、源区间、支持事实、动作／文字／音频、保护区、资源和可改对象。ScenarioProfile 保存业务结构、缺料处理和专用验收。ResourceReceipt 保存确实选择并使用的组件／模板／Skill版本。

QualityReport 保存最终文件与证据、独立审查结果、覆盖范围、问题、修复和人评。DeliveryDecision 由后端从这些对象计算，不接受客户端直接传来的 accepted=true。

## 6. 三个不同门禁：先准入，再审候选，最后交付
G1 生产准入：场景已归一、素材真实且充分、关键信息没有不可满足冲突。权利不清的素材不能进入本轮商用制作分支；与商用隔离的内部研究需要按明确用途许可处理，不能混称商用批准。

G2 候选检查：允许导出待审视频；技术检查和自动审查完成后，按实际覆盖给出“待人工”或“需修改”。审查必须读取实际导出文件，不能只看源码、工程预览和封面。

G3 正式交付：当前合同、素材、规则、工程、MP4与审查对象一致；无阻断问题；相应权利范围成立；有本轮要求的真实人工确认；通过原生工程完整性检查。公开发布仍是另一个授权动作，不能因为视频被认可就自动发布。

关键：不得把“必须经过人评才可正式交付”写成“人评之前连候选 MP4 都不能产生”。否则无法观片，会构成流程死锁。候选文件可以供内部和用户审阅，页面、下载命名、响应元数据都明确候选；不能显示正式合格徽标。

## 7. 状态应是多维，不是一个 success 布尔值
计算任务状态与作品质量分开：jobStatus 可 succeeded，deliveryStatus 仍 awaiting_review。建议独立保存 materials、technical、visual、actionContinuity、audioPerception、rights、humanAcceptance、provenance。

每一维使用 pending/pass/fail/not_applicable，并保存依据。not_applicable 仅在合同确实不适用时由确定性规则给出，例如明确静音作品没有听感要求，但仍需技术确认无意外音轨。缺观察能力不是 not_applicable，而是 pending／blocked。

面向用户的摘要可以是“素材不足”“制作中”“技术检查通过，画面待审”“候选片需修改”“等待你确认”“正式交付”。不要让模型直接决定正式状态。缺报告、文件不存在、哈希不符、解析异常、权限不符都对正式交付失败关闭，保留可恢复的项目与解释。

历史产物迁移为 legacy_unverified。历史素材与工程继续使用，认可记录保留其旧作用范围；没有当前证据就不能凭旧的 rendered 字段给新标准通过。

## 8. 最终视频审查必须真实且可追踪
每次报告绑定 projectId、runId/jobId、revisionId、contractHash、assetManifestHash、policyHash、template/resourceHash、documentHash、finalVideoSha256、证据索引和时间。哈希只能证明对象一致，不能证明已经观看，不能单靠哈希变成人评证据。

技术层检查完整解码、时长画幅帧率、媒体缺失、声音存在或必须不存在、音轨边界。黑帧、静止和素材复用只是待解释信号；自然停留、阅读和合理回看可以成立，不能机械删除。

视觉层看实际文件：首尾、每幕最大信息时刻、所有切点、字幕变化、商品细节、关键动作；连续性需要覆盖相关连续片段，不只是九宫格。模型支持视频时才写视频级自动评审；只支持图片时写 keyframes_only，保留未覆盖动作／节奏／听感并交给真实人类复核。

声音层区分技术检查和实际听感、语义、同步。播放按钮被自动化点击、网页走到 ended、音频电平正常，都不是“真人看过／模型听过”的证据。

独立审查上下文只接收用户合同、批准事实、真实媒体和版本，不接收制作模型自夸或“应该给85分”的暗示。可以使用同一现有模型的隔离上下文，无需新增付费供应商；这仍不是真人评价。

## 9. 人工确认的可用与可信设计
沿用现有应用的操作者／会话体系，无需强制新账号服务。人类在明确当前版本的审阅界面提交“认可／需修改”和反馈，记录操作者上下文、版本、提交时间。无账号本地单用户模式，应明确记录“本地操作者确认”，不要假装已核实实名身份。

Agent 的工具集不能包含可代填真人通过的生产操作；后端不信任模型提交的 reviewerType=human。确认路由需与普通模型工具隔离，按既有安全机制校验真实交互上下文。测试夹具仅在隔离测试环境模拟，不得写进用户工程的真实人评记录。该边界防止无意伪报，不声称能防御拥有完整本地磁盘权限的人任意篡改。

缺视频理解能力不应让整个开发停摆：可完成代码、素材、技术和帧级审查；生成候选并列清待人工连续观片／试听项。只有该片正式交付停在相应状态，其他互不依赖工作继续。

## 10. 硬阻断与修复循环
硬阻断包括：错商品／不同型号混用；编造关键事实和价格；必要动作缺失或顺序错误；关键主体／手／结构被遮挡或裁掉；关键字幕错时或标记错指；违反声音要求；权利不符；最终文件未复验；用参考作者片冒充产品 Agent 新制作。

审美分数可以帮助比较，但不能抵消硬阻断。不把“自动评分85”设为客观商用标准；评分阈值需要用实际参考片与人评校准。

每个缺陷记录 requirementId、视频起止秒、证据、用户影响、推定原因、最小修复、必须保持的对象、复验结果。处理优先级：事实与动作 → 主体和可读性 → 叙事节奏 → 声音 → 非关键装饰。两次同类修复失败后诊断素材、裁切、组件、编译或评审本身，不能无限重复“再高级一点”。

## 11. 修改、恢复与并发都必须触发质量规则
文案、图像、裁切、时间、音轨、字体、商品事实、合同变化产生新版本，并使受影响证据失效；正式交付仍需检查新最终文件。未改变内容的技术缓存可以复用，但不能直接搬运“新片已人评”的结论。

导出锁定修订 R1 时用户可继续改成 R2，二者互不混淆；R1 的审查不能给 R2 通过。正式交付在检查和提供文件间需保证版本／文件未变化，使用既有锁或原子版本校验，避免检查完就换文件。重复审查请求应幂等，不丢历史。

导入原生工程或恢复历史必须重算适用状态，验证外部证据的来源和文件一致性，不能因导入JSON写着human=pass而自动信任。原生工程清单包含媒体与对象但不得非法再分发原始图库或字体。

## 12. 资源建设：两套模板、六类部件、一个实际调用链
上新模板需要主体、使用、细节、收尾槽位；教程模板需要步骤依赖、源片段和保护区域。槽位不是固定五幕，允许按有效内容调整。

六类业务部件：主体媒体容器、标题、细节标注、操作步骤、字幕、片尾。组件需通过长短文案、横竖素材、缺Logo/价格、目标移动、局部续改等测试。脚本静态样例仅为参考作者片；真实Agent要能在新素材上选对组件，而不是只播放固定模板。

以本地锁定版本的官方Skills和Registry为准，按需加载 general-video、media-use、核心/动画/声音/CLI/registry 等能力；资源不存在就查当前官方索引或记录替代方案，不根据宣传名凭空调用。新业务审查提示在 05-RUNTIME_PROMPTS.zh-CN.md 提供，需要映射至真实R阶段并更新manifest。

P1：实现两场景合同、素材清单、生产准入及旧任务兼容；负例不能越过API进入生产。

P3：下载／实看素材、建设两套模板与六类部件，接入运行时Prompt和资源选择；留下真实使用记录。
P4：每场景从真实WebUI新建任务，完成候选、独立审查、至少两类续改、撤销、重开、导出；真人确认不伪填。
P5：每场景再测一组未参与模板调试的素材，运行原有回归和新增负例，生成证据驱动报告。

代码工作可先完成门禁，素材下载与基础检查可并行推进；不因一条素材下载失败放弃所有分支。缺关键输入无法出片时记录具体阻断，不能假素材顶替；也不能把任务全部标完成。

## 14. 必须交付的证据

完成定义：两个业务流程真实改变且不能绕过，现有能力不被误伤。代码通过、文件存在、样例上架均不能替代这个定义。
