# 电商视频 Agent 产品整改实施记录

本记录对应用户批准的八场景整改方案。目标仍是用户在既有 WebUI 上传和对话制作、持续编辑高质量视频；参考片、代码制作的组件测试片与产品 Agent 作品分别记录。当前为实施中，不是八场景交付声明。

## 已接入的运行链路

- 素材候选记录主体、动作、清晰度、构图、重复信息、原声证据及观察局限。分镜增加位置理由、切点依据、主体保护、声音关联和转场目的，并保留到原生工程及源选段回执。
- 八类表达策略按实际业务场景和任务模式组合；教程兼容 `product_howto` 与 `product_demo`。策略传给各制作阶段，资源检索在原有兼容性、输入条件和显式排除规则之后增加叙事功能匹配。
- 导演阶段接收本次源素材实际图像，以及本地米家 V2 三张参考抽帧。参考仅用于层级和完成度，不能成为商品事实、待选源媒体或验收通过依据。参考缺失不会伪装为已观看。
- 新增参数化文字节奏、独立步骤条和主次详情对照。媒体、文字及运动装饰保留独立原生对象；不适配时回到原生适配，不能删除内容凑模板。
- 观察预算累计持久化，允许围绕剩余缺口追加小范围观察。4Hz动作观察有实际时间标签，代理片保留真实音轨；抽帧精度与听音限制明确记录。
- 内部对齐、听音能力或观察工具问题与真实缺料分开。旁白优先使用实测时间，粗粒度时尝试转写及强制对齐；能力不可用时保留限制，不能按字符伪造精确时间。
- 最终 MP4 生成带声音的首尾与切点连续回看片段、哈希清单和 WebUI 审阅入口。其状态始终待审，不能代签完整观片或人评。
- 原生工程保存版式、镜头长度、段落结构、动效属性和信息作用签名。跨片对比可提示换文案仍沿用相同结构的情况；语义判断另列待审。

## 素材与来源

运行 `python3 scripts/archive-commerce-materials.py` 可重复生成项目根目录“素材”中的八个场景目录和总索引。原路径和历史文件保留；规范名称包含场景、主题、用途及内容哈希。当前归档25个媒体文件，复制后校验SHA256及ffprobe媒体信息；本批原件均在本地，无下载需求。

参考作品、Agent候选、历史输出分目录。素材扫描排除这些输出类别，防止重选成片。S03/S04辅助作品、S07参考作者片等不会自动升级为首轮自主制作验收。没有新成片的场景继续标为未交付。

## 验证与可复现入口

- `node scripts/test-product-remediation.mjs`：场景路由、功能资源选择、观察预算、缺口分类、实测对齐、原生对象绑定、跨片结构对比和实际带声音切点文件。
- `node scripts/verify-remediation-layouts.mjs`：三种新布局的横竖版真实 HyperFrames 检查与 MP4 导出。结果为代码编写的技术测试片，不是产品自主首轮制作证据。可附单个用例ID复验，历史失败保留在回执中。
- `node scripts/product-remediation-ui.mjs create S02` / `create S03`：普通浏览器上传与对话提交，不注入分镜或原生工程。`REMEDIATION_SPEC_FILE`可提供新输入，`REMEDIATION_BASE_URL`指定隔离测试服务；默认3056。`edit 场景 项目ID`通过输入框发送`REMEDIATION_MESSAGE`。
- `node scripts/compare-commerce-films.mjs document1.json document2.json ...`：比较实际工程签名，输出结构复用提示及语义待审项。
- 核心、浏览器及完整流程回归的实际报告路径、通过状态与实时制作ID见 `outputs/product-remediation-20260918/status.json`。
