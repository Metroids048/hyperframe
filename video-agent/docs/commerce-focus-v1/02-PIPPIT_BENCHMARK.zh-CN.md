# Pippit Marketing Agent 对标与项目转化
## 学习完整业务过程，不复制宣传页与未知内部实现
版本：2026-09-14｜对应用户原始第 5 项需求

## 1. 研究结论与证据边界
本轮对标的核心不是“一句话生成”的按钮，而是把需求、商品、计划、制作、修改和营销管理组织成一个任务。我们的现阶段目标是借鉴这种任务完整性，先在单品上新和操作演示两个场景交付稳定成片。

指定页面 https://www.pippit.ai/marketing-agent 在本环境两次读取失败；以下结论来自可读取的 Pippit 官方 Vibe Marketing、AI Marketing Agent、Video Agent 和官方使用文章。[P1][P2][P3][P4]

本轮没有登录产品做同素材实测，没有访问私有模型、代码、提示词、训练数据或商业指标。官方描述标记为“公开宣称”；产品建议标记为“我们的设计”。不能把官网介绍当作我们验证过的质量与转化率。

## 2. 两层 Agent 应该分别理解
Marketing Agent 围绕营销目标组织多项内容：明确商品和市场、形成品牌与发布计划、生成内容、安排发布及查看表现。Video Agent 面向一条具体视频：提供需求及媒体，选择制作方式，查看结果，继续编辑、下载或发布。[P1][P2][P3]

非技术理解：前者像内容负责人，决定这一批内容为什么做、做哪些；后者像单条视频导演，负责这一条如何做出来。我们先借用前者的需求组织方法，扎实实现后者的两个任务。

不要把“批量发社媒内容”直接理解为“自动投广告、管理广告预算、优化竞价与归因”。这些不是同一件事，公开入口也不能自动证明完整商业闭环。

## 3. 官方公开流程能够确认到哪一步
### 输入与补充信息
官方介绍允许输入想法、商品描述或链接，并上传已有图片、视频等媒体；在营销流程中确认地区、发布目的与素材条件。[P1][P2]

### 计划与制作
官方页面描述了品牌计划与结构化内容计划，再批量生成内容。视频工具允许进一步设置并生成视频。我们能学习“先计划，再产出”，不能据此判断其内部用了几个 Agent 或哪套提示词。[P1][P3]

### 修改与交付
Video Agent 页面提供结果审查、进一步编辑、下载及发布路径；官方文章也展示了快速修改和更深入编辑的区分。[P3][P4]

### 发布与表现
营销页面介绍了日历视图和社媒分析。可读取信息主要涉及发布安排和互动数据入口；本轮不对独立转化提升、盈利或自动投放能力作验证性结论。[P1][P2]

## 4. 为什么这套体验值得学习
以下是我们根据公开流程作出的产品分析，不是其私有架构事实。

用户只需要先描述目标；系统帮助把缺失信息补齐。计划让用户知道它准备做什么，而不是长时间等待后才看到错误视频。结果可继续编辑，意味着用户不用每次重新讲完整需求。发布与管理把视频放回商业任务中，而不只是一个文件。

但这些优势不意味着我们现在必须同时做全部模块。当前真正的短板是素材、制作结果和验收的一致性。先补这三处，才有意义扩张批量能力。

## 5. 能力对照：这一轮做什么，不做什么
| 维度 | Pippit 官方公开描述 | 我们本轮落地 |
|---|---|---|
| 需求输入 | 提示、商品信息和媒体 | 自然语言加真实素材；保留轻量确认 |
| 目标理解 | 地区、发布目的、素材条件 | 明确制作者、观看者、业务结果、事实禁区 |
| 内容计划 | 品牌与发布计划 | 每条视频的结构、镜头目的、证据与缺口 |
| 视频生产 | 不同制作入口与媒体选择 | 只用已有素材，两个场景、原生 HyperFrames |
| 资源复用 | 可编辑模板和素材工具 | 两套业务模板、六类部件、可追溯选择 |
| 持续修改 | 查看结果并继续编辑 | 指定范围修改、撤销、重开、重新导出 |
| 质量保障 | 官方强调可用内容 | 我们增加明确的技术、业务、视听、真人状态 |
| 营销管理 | 排程、发布、分析入口 | 暂缓，保留接口边界，不假装已接入 |

我们的硬性视觉门禁是本项目的设计，不应说成已经逆向查明 Pippit 也采用相同方案。

## 6. 场景 A：从上新目标到一条可信展示片
输入不仅是几段视频，还包括谁观看、商品身份、主要表达和禁区。Agent 把需求写成简短合同；检查同款素材是否覆盖整体、细节与使用；选择开头、内容推进和结尾；调用部件形成完整候选；按首次观看者视角审查。

建议测试需求：使用已有耳机素材制作约 30 秒竖屏上新片，展示真实外观和使用状态，不编造价格、续航、降噪，不加旁白。用户不需要提供分镜，Agent 必须自行选段，但每个商品结论能回溯到素材或批准事实。

我们学习的是“目标驱动”和“可修改”；不调用新镜头生成来掩盖素材不足。

## 7. 场景 B：从冗长操作原片到能照做的教程
先明确是完整操作还是某个子步骤。Agent 应观察动作、建立必要先后关系、把每一步绑定到原片区间，再删等待与重复。说明和标注不能遮挡手部及关键部位。

本轮建议以高质量手冲器具使用素材作为新候选方向；品类不改变“操作演示”这一场景。只有逐段核验同一器具及步骤覆盖后，才能确定制作完整教程。现有领饰教程保留作历史回归，不以旧低清片顶替新质量标杆。

如果素材缺准备、关键操作或结果，必须停在素材缺口状态。不能把“注水片段”包装成“完整手冲教程”，也不能为了满足时长而剪掉关键动作。

## 8. 工作台应该怎样呈现
继续使用现有 WebUI，不重写编辑器。默认创建入口聚焦“上新种草”和“操作演示”，旧项目通过历史入口保留。

用户始终能看到当前任务理解、素材缺口、制作进度、当前版本和具体待审问题。候选视频可以播放、继续修改和下载审阅；正式交付需要通过统一门禁。错误提示要告诉用户哪个时间段有什么问题，而不是只显示一个数字分数。

例如：“00:12—00:15 步骤文字挡住关键动作，正在调整说明位置；商品和原声保持不变。”这比“正在优化高级动效”更能建立可验证的信任。

## 9. 对标研究转成什么项目对象
这是建议架构，不是 Pippit 内部实现：任务合同保存用户目的；素材清单保存真实来源与使用边界；镜头计划保存来源区间、目的和可证事实；工程保存独立对象；审查记录保存问题与观察范围；交付凭证保存用户认可的具体文件和版本。

已有 production.mjs、capabilities.mjs、media-review.mjs、patch.mjs 等应按职责扩展，而不是再造一个全能 Prompt。实际加载的规则与素材应进入缓存指纹，避免改了规范仍取回旧答案。[R1][R2]

## 10. 正式同素材对标怎么做
当前没有完成该实验，不能填入假数据。后续在用户已授权的账户和素材下，由操作者完成相同输入测试，不擅自购买套餐或发送私密素材。

先冻结两组输入和同一输出合同；分别在 Pippit 与本项目制作；保存实际输出、原始需求、模型与设置、修改次数和可观察耗时；按未知来源顺序让评审观看完整视频。

上新片检查商品识别、表达、节奏、事实和下一步行动；教程检查步骤、连续性、可重复操作和遮挡；共同检查声音、局部修改、撤销和工程可追溯性。不能用对方精选广告与我们随手测试直接作公平评分。

## 11. 六个必测对话任务
| 编号 | 相同输入要求 | 观察点 |
|---|---|---|
| P01 | 上新片首次生成 | 是否先理解需求，是否真的选素材 |
| P02 | 只改片尾标题 | 未指明内容与音轨是否保持 |
| P03 | 缩短中段但保留重点 | 是重剪还是机械截断 |
| P04 | 完整操作教程 | 必要步骤及顺序是否正确 |
| P05 | 故意拿走关键步骤片段 | 是否说明缺口，还是伪造完整性 |
| P06 | 把教程改成更克制的风格 | 动作与声音是否仍不受破坏 |

如官方功能受账户或地区限制，记录实际限制，不能填“通过”。不宣称已达到 Pippit 品质，也不把自动模型分数当真人结论。

## 13. 本轮实施结论
把 Pippit 的目标理解、制作计划、可继续修改转为真实工作流；把我们自己的成片审查要求转成后端规则。先交付两个稳定场景，不并行开发营销日历、广告预算、数字人或新的生视频接口。

决定成功的不是文档数量，而是新任务真的经过这些环节，失败会停止正式交付，修复后产生可验证的新版本。
