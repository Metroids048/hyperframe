# HyperFrame 电商视频 Agent：六场景业务设计（文本评审版）

版本：会议后修订，2026-09-15  
适用项目：Metroids048/hyperframe / video-agent  
性质：待评审、待实施的业务设计，不是完成报告，不是可直接加载的机器配置。

## 0. 本轮方向与阅读方式

本轮先暂停新的 AI 视频镜头生成。制作输入采用用户已有且有相应用途权限的商品照片、原始视频、音频和商品事实；继续进行剪辑、文字制作、动效、音频处理、渲染与导出。素材不足时说明缺口，不靠生成镜头、静图假动作或历史成片冒充完成。

本产品要证明的不是“HyperFrames 能做视频”，而是“我们的 Agent 能理解商家目的、看懂素材、选择恰当资源，稳定地制作和修改视频”。米家 V2 保留为用户认可程度有限的视觉参考，不作为 Agent 自动完成的证据。

六个场景全部采用相同的设计深度；实施按场景逐条验收。A、B 优先打通，不表示 C—F 被删除或已通过。本稿中的画像是产品设计假设，尚不是用户访谈所得的统计结论。

### 0.1 业务场景与历史字段的兼容关系

| 本文场景 | 业务含义 | 已有相关字段／兼容方向 |
|---|---|---|
| A 单品上新／种草 | 让初次接触的人认识商品并愿意继续了解 | launch / product_launch |
| B 单品使用／操作演示 | 让新手理解并重复关键操作 | demo / product_howto；当前场景加载器归一到 product_demo |
| C 商品详情／卖点与细节说明 | 用具体证据解释一个或几个购买关注点 | detail |
| D 穿搭／组合／系列展示 | 讲清多款、搭配、组合或系列关系 | style；不能等同于任意视觉风格 |
| E 活动促销／直播预告 | 让用户准确理解活动、条件与行动入口 | promotion |
| F 选购说明／场景问答 | 回答一个具体问题，说明适用范围和限制 | faq |

这里不是重新分配已有 Demo、工程或 revision 的编号。开发时应查实际登记，保留历史 ID，用别名兼容而不是批量重命名。recut、versions、换比例、换音乐、改字幕是跨场景操作，不另建为业务主场景。输入方式 image/video/mixed 也不是业务场景。

### 0.2 所有场景共同的产品原则

用户提供“想达成什么”和必要事实，不需要提供逐秒分镜、组件名或技术参数。Agent 对可逆选择采用明确默认，例如克制风格；对价格、权利、商品身份、必要动作等不可臆造的内容才提出最小补充问题。信息足够时直接制作候选，不要求用户每一步批准分镜。

场景由目标决定，素材决定能否实现。不能因为素材是视频就判成教程，也不能因为素材很酷就把操作需求改成上新片。一个需求可以有主目标和辅助段落，但不能把六套片头、片尾机械拼接。

所有表达应区分：用户确认的事实、画面直接可观察的信息、模型推测、尚未确认的信息。推测不能升级为性能、功效、活动条件或用户体验事实。清楚展示一个动作不等于证明一个长期效果。

所有视频共同交付：当前版本候选／最终 MP4、从实际成片抽取的封面、可重开和继续修改的 HyperFrames 原生工程、资产与版本记录、审查结果。候选可供观看和下载，但不标成已获真人认可；公开发布需要另行授权。

## 场景 A：单品上新／种草短片

### A.1 用户画像与业务目标

制作用户是中小商家或品牌内容运营：有商品照片和拍摄片段，但没有稳定的视频剪辑能力。观看用户是第一次接触商品的人，需要很快看懂这是什么、有什么值得关注、是否继续了解。

目标是在较短时间内建立商品形象，表达一到两个可信重点，让人愿意查看详情。不是压缩全部参数，也不是用一连串大字和强转场替代商品内容。

### A.2 Agent 输入和最终输出

| 项目 | 定义 |
|---|---|
| 输入素材 | 同款商品整体、细节、真实使用、环境片段；少量辅助图片。一个长视频也可以包含全部所需内容。 |
| 输入信息 | 商品事实、目标受众、品牌风格、发布位置、时长、画幅、原声／旁白／音乐要求。 |
| 用户不必提供 | 完整剪辑方案、每秒分镜、组件名、动效参数。 |
| 建议输出 | 约 20—30 秒主片、实际成片封面、原生可编辑工程、审查记录。 |
| 画幅原则 | 优先一个主画幅，常见为竖屏；具体服从发布要求和主体保护。 |
| 不可缺少 | 商品身份可辨、支撑主表达的有效画面、可信文案。用户要求的真实使用段不能由静图替代。 |

### A.3 真实用户需求示例

> 用这组同款耳机素材做一条约 30 秒的竖屏上新片。面向喜欢桌面搭配和数码配件的人，突出外观与真实佩戴场景。整体克制，不加旁白，不虚构降噪和续航。最后引导查看详情，未提供价格就不要添加价格。

### A.4 完整业务链路

上传素材 → 理解上新目标 → 核验同款和事实 → 观察素材并索引可用区间 → 选定主表达 → 编排故事 → 匹配资源 → 制作候选 → 审查 → 对话修改 → 交付。

Agent 需要判断哪段最适合开头，哪段是等待，哪处细节足以支撑文案，整体与局部如何穿插。它不能只把输入顺序当剪辑顺序。

| 段落 | 观众应该获得什么 | 制作重点 |
|---|---|---|
| 开头 | 知道商品及使用语境 | 商品先出现，不被长片头占用。 |
| 中前段 | 理解真实使用状态 | 用对应实拍，不用图片动效伪造使用。 |
| 中段 | 看清一到两处重点 | 文字与细节同屏对应，保留阅读时间。 |
| 后段 | 形成完整商品印象 | 回到整体，避免只有碎片和极近特写。 |
| 结尾 | 知道下一步做什么 | 清楚的行动提示，声音和画面完整收束。 |

这些是信息角色，不是固定秒数模板。素材不足时减少内容和时长，或请求具体补料；不能循环相同画面凑够 30 秒。

### A.5 Agent 与 HyperFrames 的分工及资源策略

Agent 负责主表达、选段、节奏、文字事实、资源选择和修复。HyperFrames 负责把镜头、构图、文字、动效、声音做成可编辑工程和视频。

资源优先选择主体清晰的构图、轻量标题、卖点标注、少量段落转场与 CTA。composition 承载整段结构，component 承载局部说明，typography 建立文字层级，lower third 避免覆盖商品。shader 或强特效只在确实需要时使用，不能改变商品颜色、结构或遮住佩戴动作。

无旁白时不要生成口播字幕轨；屏幕营销文案是独立图文层。用户说克制时，不应因为找到了炫酷资源就强行使用。指定色散转场时，只在适合的镜头边界使用，并绑定真实商品画面。

### A.6 音频、字幕与后续修改

“不加旁白”必须保留为项目约束，不能由模板默认值覆盖。是否保留原声、是否有配乐分别记录。片尾标题、卖点字、字幕样式可独立修改；换音乐不得重新选择商品镜头或调用视频生成。

验收修改示例：“只把片尾改成‘查看产品详情’，不动声音”“把细节镜头提前，其他不变”“减少动效，保留商品文案和镜头”。每次保留当前工程版本链。

### A.7 缺料和验收

缺性能证明时删除该性能主张；缺使用画面而用户必须展示真实使用时请求补片。仅有照片时可以说明能制作图文展示候选，但不能冒充本场景约定的实拍使用片。

合格标准是商品清楚、表达可信、镜头有内容、节奏有变化、结尾完整。用户没给价格时不出现价格；不同镜头不混型号；标题和特效不盖住主体；候选来源必须是自有 Agent 链路而不是预置 MP4。

## 场景 B：单品使用／操作演示短片

### B.1 用户画像与业务目标

制作用户是商家运营、内容人员或售前售后人员：有演示原片，但原片冗长，步骤不突出。观看用户是初次使用商品的人，或想判断商品是否容易操作的潜在消费者。

目标是让没看过原片的人，看完能理解并重复关键操作。与上新片相比，操作片优先保护动作和理解，而不是追求每秒变化和强烈节拍。

### B.2 Agent 输入和最终输出

| 项目 | 定义 |
|---|---|
| 输入素材 | 连续操作原片、必要细节补拍，明确为同一商品；区分同款与同次连续操作。 |
| 输入信息 | 已确认步骤、前置条件、必须保留动作、观众基础、原声和画幅要求。 |
| 用户不必提供 | 精确剪切点、每步时码、手部保护框、字幕定位参数。 |
| 建议输出 | 约 45—60 秒操作片、独立步骤说明、原生工程、步骤与源区间映射、动作检查记录。 |
| 时长原则 | 服从关键动作，不为硬卡时长删掉必要过程。 |
| 画幅原则 | 以看清操作为先，不能机械把横屏裁成竖屏。 |

### B.3 真实用户需求示例

> 把这段操作原片剪成约 45—60 秒中文教程，观众没有经验。删除介绍和等待，但保留全部必要动作。步骤文字随动作出现，不能遮住手和商品关键部位。保留对应原声，不加配乐。原片缺少关键步骤时明确指出，不要补假的动作。

### B.4 完整业务链路

上传原片 → 理解观众基础 → 看懂完整操作 → 建立步骤和先后关系 → 找到各步骤源区间 → 检查动作是否齐全 → 删除可删等待 → 包装说明 → 检查能否照做 → 修改与交付。

每个必要步骤都记录开始状态、完成状态、前置步骤、真实源区间、对应声音和关键保护区域。关键动作需连续观察，不能仅凭稀疏关键帧或转写文本声称看懂了。

| 段落 | 观众应该获得什么 | 制作重点 |
|---|---|---|
| 开始 | 要完成什么、从什么状态开始 | 简短交代准备，不强加上新片头。 |
| 准备 | 必要工具、接口或零件 | 必须能对应真实画面。 |
| 核心步骤 | 动作顺序和操作方法 | 保留进入、进行、完成过程。 |
| 易错处 | 哪里需要注意 | 局部提示不遮住动作；可在完整动作后重放细节。 |
| 完成 | 如何确认已经完成 | 显示真实结果状态，不突然切到营销口号。 |

### B.5 Agent 与 HyperFrames 的分工及资源策略

Agent 决定哪些能剪、哪些不能剪，以及步骤依赖和源时间映射。HyperFrames 准确呈现选段、步骤、原声和局部提示。

优先使用步骤条、数字序列、透明 lower third、局部高亮、指示线和低干扰构图。跨步骤可以轻切换；关键动作内部不使用遮挡或变形转场。信息卡不能替代缺失动作。字幕安全区应跟随动作区域，而不是全片固定在同一位置。

### B.6 音频、字幕与后续修改

“保留对应原声”表示每段操作与其源音频保持对应，不是把整条原声铺在已重排画面上。用户明确要求完整原声独立保留时则建立不同合同，并复核画面改动是否改变声音语义。

“第二步文字移到左上”只改说明位置；“缩短等待”不能削掉必要操作；“慢放穿入动作”需处理对应声画时间。更换旁白音色不能为了匹配新配音时长而暗中加速操作。

### B.7 缺料和验收

素材没有拍到关键穿入动作时，正确反馈是：当前素材没有完整显示该步骤，请补充从开始穿入到完成的连续片段，现有内容只能交付非完整说明候选。不能加一张图并写“然后穿过去”后宣布教程完成。

合格标准是新手能看见每个必要步骤、理解顺序和结果；步骤字幕存在不等于动作存在。保护区无遮挡，源时间不越界，变速后声画对应，必要动作没有被转场盖住。不确定观察范围时保留未审项。

## 场景 C：商品详情／卖点与细节说明

### C.1 用户画像与业务目标

制作用户是商品运营或详情页内容人员；观看用户已经知道是什么商品，正在判断某个具体关注点是否满足自己。目标不是再次喊“新品来了”，而是用证据回答“这个设计有什么、在哪里、怎样使用、对我有什么意义”。

### C.2 Agent 输入和最终输出

| 项目 | 定义 |
|---|---|
| 输入素材 | 商品整体定位、局部细节、可观察的结构或功能展示；允许有参数资料但要注明来源。 |
| 输入信息 | 优先解释的问题、已确认事实、目标使用者、不能声称的内容。 |
| 用户不必提供 | 卖点排序、细节坐标、分屏形式、特写剪点。 |
| 建议输出 | 约 30—45 秒详情片，整体到局部的对应关系、可编辑标注与事实索引。 |
| 不可缺少 | 具体主张与对应画面／资料；看不清的内部结构不能靠图解编造。 |

### C.3 真实用户需求示例

> 用这组背包素材做一条约 35 秒的详情片，给日常通勤的人看。重点解释视频里真实可见的分区和取物位置，先交代整体再展示细节。没有尺寸和容量资料，不写能装几升或能放多大电脑。配乐轻一点，标注不要挡住拉链和开口。

### C.4 完整业务链路

上传资料 → 识别购买关注点 → 核验主张 → 定位整体与细节 → 为每个主张匹配证据 → 编排解释顺序 → 添加图文标注 → 检查能否看懂 → 修改与交付。

| 段落 | 观众应该获得什么 | 制作重点 |
|---|---|---|
| 问题／整体 | 本片解释什么，部位在哪里 | 先建立商品和空间关系。 |
| 细节一 | 某处结构是什么 | 画面、指示线、文字准确对齐。 |
| 细节二 | 如何使用或另一个相关点 | 真实动作或特写，不重复同一描述。 |
| 关系回顾 | 两处细节如何共同服务需求 | 回到整体或清楚的对照。 |
| 结尾 | 适合继续了解哪些信息 | 未知参数明确保留，不扩大主张。 |

### C.5 Agent 与 HyperFrames 的分工及资源策略

Agent 负责把“值得说的话”约束在证据内，决定是特写、放大、分屏还是局部提示。HyperFrames 负责可编辑的 callout、局部构图、文字层级和比较布局。

优先 component、lower third、typography 和清晰的 detail composition。使用 comparison 类资源前，必须有可比较的两项资料；同一素材裁两次不能自动当成独立对照。使用测量图示前必须有已确认数值，不能为了好看编刻度。

### C.6 音频、字幕与后续修改

旁白可以解释画面，但不能加入画面或资料不支持的性能。修改一个卖点说明只影响该说明及相关旁白；普通样式调整不重新合成声音。换背景音乐不应改掉已经核对的标注位置。

修改示例：“把分区二提前，其他细节保留”“删掉容量说法，只留取物位置”“这根指示线指错了，指向拉链开口”。

### C.7 缺料和验收

缺某个细节时明确列为未覆盖，建议补拍对应部位；允许减少主张数量。不能把 unrelated B-roll 当本品细节。

合格标准是主张有证据、观众知道细节在哪里、标注不误指、尺寸参数不虚构、解释顺序清楚。详情片不能只由“品质、精致、高级”等空泛词构成。

## 场景 D：穿搭／组合／系列展示

### D.1 用户画像与业务目标

制作用户是有多个款式、颜色或组合方案的品牌内容人员；观看用户在选择款式、理解搭配或者比较适用场景。目标是让不同款的关系清楚，而不是把多款商品当作同一个商品混剪。

style 在这里表示穿搭、组合、系列展示这一业务意图；“高级、杂志感、活泼”等只是其视觉风格，可以跨其他场景使用。

### D.2 Agent 输入和最终输出

| 项目 | 定义 |
|---|---|
| 输入素材 | 每款商品整体与细节、对应穿搭／组合画面、系列或搭配关系。 |
| 输入信息 | 每款身份、色号／名称、允许的事实、组合逻辑、品牌风格、展示顺序偏好。 |
| 用户不必提供 | 多商品镜头调度、卡片网格、比较版式、连续转场设计。 |
| 建议输出 | 约 25—45 秒系列片；清楚的款式标识，可分别修改的商品层和字幕。 |
| 不可缺少 | 商品之间的身份边界；不能把 A 款的事实写到 B 款。 |

### D.3 真实用户需求示例

> 把这三款运动鞋和对应上脚素材做成约 30 秒的系列展示，整体偏杂志感。每款都要出现整体和上脚状态，名称按我提供的写，不推断缓震性能。用同一套文字系统，最后同屏展示三款，方便观众选择。

### D.4 完整业务链路

上传多款素材 → 识别展示关系 → 分离每款身份与事实 → 检查各款覆盖 → 选定系列叙事 → 分配展示时间 → 统一视觉系统 → 检查款式标识 → 修改与交付。

| 段落 | 观众应该获得什么 | 制作重点 |
|---|---|---|
| 系列建立 | 为什么这些商品放在一起 | 明确系列／搭配主题。 |
| 各款展示 | 每款是什么、怎样呈现 | 名称、画面和事实严格绑定。 |
| 差异／搭配 | 款式之间的可观察差异 | 对比依据一致，不伪造性能排名。 |
| 整体回顾 | 记住系列及选择关系 | 清楚群像，标识可读。 |

### D.5 Agent 与 HyperFrames 的分工及资源策略

Agent 负责分组、识别、排序、曝光分配和事实边界。HyperFrames 负责 grid、split-screen、cards、成组 typography、协调转场和系列收尾。

可以比教程更强调节奏和视觉连续性，但商品必须仍可辨。转场遮罩不能把一款变形为另一款并造成误解；调色不能改变真实色号。统一模板不代表所有款必须有相同镜头数。

### D.6 音频、字幕与后续修改

音乐可以统一情绪；存在用户讲解时优先保证讲解可懂。不同商品名称、文案和旁白段独立绑定。后续“删掉第二款”“把第三款提前”“只换系列标题”应局部修改，而非重建所有素材。

### D.7 缺料和验收

某款缺上脚素材时，不能复用另一款的上脚片；说明缺口，并让用户选择保留纯展示、补片或暂不展示该款。未确认多款属于同一系列时，不凭相似外观宣布同系列。

合格标准是观众能分辨款式、名称和画面一致、搭配逻辑清楚、每款展示符合要求，没有串用事实。好看的拼贴不能替代清楚的商品关系。

## 场景 E：活动促销／直播预告

### E.1 用户画像与业务目标

制作用户是店铺运营或活动负责人；观看用户需要迅速理解活动是否相关、有什么条件、如何参与。目标是准确、清晰地传达活动，不是靠虚假紧迫感或大价格牌制造刺激。

### E.2 Agent 输入和最终输出

| 项目 | 定义 |
|---|---|
| 输入素材 | 活动所涉商品或直播内容素材、合法可用的品牌资产。 |
| 输入信息 | 活动名称、日期时间及适用时区、商品范围、价格／优惠、限制条件、真实行动入口。 |
| 用户不必提供 | 价格卡版式、优惠排版、倒计时技术实现、节拍剪辑。 |
| 建议输出 | 约 15—30 秒促销片或预告；活动信息可独立编辑，关键条件有阅读时间。 |
| 不可缺少 | 实际要宣传的优惠和时间必须有明确来源；未知信息不补造。 |

### E.3 真实用户需求示例

> 用这些咖啡器具素材做一条 20 秒直播预告。只写我给的直播日期和时间，主题是桌面冲煮演示，引导进入店铺直播间。没有确认价格，不写优惠价、不写限量，也不要做会过期的动态倒计时。

### E.4 完整业务链路

上传活动资料 → 识别转化目标 → 核验商品与活动条件 → 选择支撑活动的镜头 → 安排主题、价值、条件和行动 → 制作信息层 → 逐项核对最终文字 → 修改与交付。

| 段落 | 观众应该获得什么 | 制作重点 |
|---|---|---|
| 活动识别 | 这是什么活动 | 简短、清楚，不隐藏主商品。 |
| 参与价值 | 为什么值得关注 | 真实展示或已确认权益。 |
| 关键条件 | 时间、适用范围、价格条件 | 信息可读，不能缩成不可见小字。 |
| 行动 | 到哪里、何时参与 | 不编入口，不出现歧义。 |

### E.5 Agent 与 HyperFrames 的分工及资源策略

Agent 负责活动事实、优先级、条件一致性和过期风险。HyperFrames 负责 promo composition、价格／日期组件、信息层级、轻量强调与 CTA。

模板有价格槽不等于必须填价格；有倒计时组件不等于应该使用。条件无法在目标时长读完时，减少文案、延长停留或与用户协商，不隐藏限制条件。shader 不应干扰数字识别。

### E.6 音频、字幕与后续修改

活动信息的画面文本和朗读文本要建立关联。只改标题样式不重配音；修改已被读出的活动时间，则提示对应旁白也要更新。用户要求暂不改声音时，不得交付前后矛盾的正式活动片。

修改示例：“活动日期往后改一天，其他不变”“移除价格，仅保留直播预告”“背景音乐换轻快一些，商品镜头锁定”。

### E.7 缺料和验收

没有明确价格就做不含价格的预告，不能造原价、到手价或折扣。日期不完整时要求最小补充。内部演示活动必须在作品与记录中清楚标识，不能对外当成真实报价。

合格标准是时间、商品范围、优惠与条件准确一致，可读时间足够，CTA 清晰，未出现过期或虚构紧迫信息。修改一个活动字段后，所有相关显示和旁白都要复验。

## 场景 F：选购说明／场景问答

### F.1 用户画像与业务目标

制作用户是客服、内容运营或售前人员；观看用户有具体疑问，例如是否适合某个场景、某个物品怎样收纳、某个功能如何判断。目标是回答一个明确问题，并交代答案的依据与边界，而非把上新文案换个问号。

### F.2 Agent 输入和最终输出

| 项目 | 定义 |
|---|---|
| 输入素材 | 与问题直接相关的演示、细节、真实测试片段，必要说明资料。 |
| 输入信息 | 用户问题、已确认答案或事实卡、适用人群、限制条件、不能承诺的内容。 |
| 用户不必提供 | 回答结构、证据剪辑顺序、问题卡组件、画面标注。 |
| 建议输出 | 约 20—40 秒单问题回答片，回答与证据可追溯，可编辑问题和说明层。 |
| 不可缺少 | 问题有可核实的回答依据；没有证据时不能给绝对结论。 |

### F.3 真实用户需求示例

> 用这段背包收纳演示回答“通勤时水杯怎样放取更方便”这个问题。只依据画面和我给的事实卡，先直接回答，再展示对应动作，不说任何水杯都能放。不要复用上新口号，结尾说明具体尺寸还需核对。

### F.4 完整业务链路

输入问题 → 判断问题类型和观众 → 找到答案依据 → 确认限制 → 选择最直接的证据 → 先回答再解释 → 检查问题是否真正解决 → 修改与交付。

| 段落 | 观众应该获得什么 | 制作重点 |
|---|---|---|
| 问题 | 本片回答哪一件事 | 保留原问题含义，不偷换成营销主题。 |
| 简答 | 核心结论 | 语气与证据强度相匹配。 |
| 证据 | 为什么这么说 | 对应真实动作／细节／确认资料。 |
| 限制 | 哪些情况不适用或未确认 | 不把个例扩大为普遍承诺。 |
| 收尾 | 需要核对或下一步做什么 | 不用强 CTA 把关键限制挤掉。 |

### F.5 Agent 与 HyperFrames 的分工及资源策略

Agent 负责问题解析、答案证据、适用条件和是否需要进一步澄清。HyperFrames 负责 Q&A composition、问题卡、答案重点、证据标注和条件提示。

问答与教程可以共享步骤组件，但目标不同：问答回答一个问题，教程完整教会一串操作。如果回答需要完整操作，应进入教程子流程并保持问题上下文，不新建无关项目。

### F.6 音频、字幕与后续修改

问题与回答可以旁白，也可以原声加解释文字。区分逐字转写和总结式答案卡；总结不能假装是原话字幕。删除一个结论时，应同步处理关联的画面说明和旁白，不残留误导片段。

修改示例：“回答太长，只保留直接结论和限制”“这个说法没有依据，删除它和对应旁白”“换成更平实的音色，不改证据镜头”。

### F.7 缺料和验收

没有证据时先指出无法确认的部分，可输出问题整理和补料建议，不能编测评结论。需要尺寸对照但没有尺寸数据时，说明必须补充哪些尺寸，不能猜测兼容性。

合格标准是问题被直接回答、证据可对应、结论不过度、限制可见、没有换题或用空泛口号回避问题。

## 7. 六场景共同的资源、音频与修改约定

### 7.1 不强求一条片使用所有资源类型

| 功能资源 | 业务意义 | 使用边界 |
|---|---|---|
| template | 可复用的信息与视觉骨架 | 必须能删掉不适用槽位，不固定某商品。 |
| composition | 一段或整片的组合结构 | 时间线、画幅和项目结构必须兼容。 |
| component | 局部标注、卡片、图表等 | 需要真实数据与素材绑定。 |
| effect | 局部视觉变化 | 不破坏商品身份和信息可读性。 |
| transition | 两段画面的衔接 | 教程关键动作内优先禁用遮挡型转场。 |
| skill | 制作方法、规则和操作知识 | 是指导，不是可直接放上时间线的媒体。 |
| caption | 有时间关系的字幕呈现 | 内容、时间和样式独立；不能伪造口播。 |
| typography | 字体、层级、排版及文字动画 | 以清晰、品牌一致为先。 |
| lower third | 画面下部或局部的信息条 | 可因主体保护移动，不机械固定下方。 |
| shader | 实现某些视觉效果的底层程序 | 需确认运行版本、输入纹理和渲染兼容。 |

这是一套业务功能分类，不宣称 HyperFrames 官方存在十个对应目录。一个资源可以有多个功能标签，避免重复统计；官方 block、component、example 等安装或来源类型另记。

### 7.2 音频与文字分离

至少分别管理现场原声、旁白、背景音乐、音效、转写字幕、营销／步骤文字。声轨和字幕是可独立操作的对象，同时保留必要关联：同一段旁白改变时长，相关转写字幕必须重校；普通字体调整不应调用语音合成。

更换背景音乐可以只重混音并重新封装输出，不必重新生成镜头。字幕改动可能仍需重新渲染画面，这不等于重新生成素材。只提供烧录了字幕和混合声音的最终 MP4 时，不能承诺恢复原本不存在的分层工程或无损分离。

MiniMax 尚未提供账号接口时，先完成上传原声、现有旁白和本地音乐的资源化编辑。待提供 API 后再验证真实语音、音色和可用音乐能力；当前不得记录“MiniMax 真调用通过”。

### 7.3 共同验收状态

六场景分别记录：文档已设计、规则已加载、运行已接通、候选已导出、自动审查已完成、等待／已获真人确认。不能用 A 的成功给 C—F 自动打勾，也不能因为某个资源曾在横屏渲染成功，就认为所有商品、尺寸和镜头都通过。

## 8. 从文本到 Agent 配置的下一步

先确认本稿的业务目标、必须内容、禁止项、缺料响应与验收标准，再将其映射进已有场景包和 Prompt 加载器。不得直接把整份长文塞进每一轮模型上下文。

后续机器化应按阶段提取：理解时加载画像与合同，观察时加载素材政策，策划时加载故事原则，选资源时加载约束，续改时加载保持项，审核时加载该场景的验收规则。规则版本随工程冻结，升级后有可追溯的影响范围。
