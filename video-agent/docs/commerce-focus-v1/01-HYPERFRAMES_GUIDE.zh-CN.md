# HyperFrames 非技术全景教程
## 从理解工具，到理解我们的电商视频 Agent
版本：2026-09-14｜读者：产品、运营、设计、Codex 开发执行者

这份教程讲清产品层需要掌握的完整结构，不要求读者写代码。它不是“全部功能都已在本项目实测”的证明。官方能力、当前代码和本轮设计分别表述。项目核对基线：Metroids048/hyperframe，10542b9ebb385cee115b2641e026cf55fd4012a6。

## 1. 先用一句话建立正确理解
HyperFrames 把可编辑的网页式画面说明，按时间做成视频。Agent 决定“讲什么、用什么素材、怎么安排”，HyperFrames 把这些安排实现出来。它不是天然懂电商的营销总监，也不是凭一句话生成新实拍镜头的视频基础模型。[H1]

把它想成制作团队：商家是客户，Agent 是导演，素材是摄影原料，HyperFrames 是剪辑与图文包装工作间，WebUI 是沟通工作台，验收机制是质检。成片不好，可能是原料、导演、制作或者质检的问题，不能只怪最后负责导出的工具。

本阶段暂停“文本／图片生成新的商品视频镜头”，继续保留文字提需求、脚本、字幕、分镜和对话修改。已有高清照片可以辅助，但不能靠几张图的平移缩放伪造真实操作。

## 2. HTML、CSS、动画时间线各自是什么
HTML 回答画面上有什么：商品片段、标题、价格、Logo、字幕。CSS 回答它们长什么样、摆在哪里：大小、位置、字体、颜色、遮挡关系。动画时间线回答何时出现、怎么移动、停留多久。[H1]

例如“耳机在左，右边出现两行标题，三秒后切到佩戴镜头”：这是画面、排版和时间安排，不需要读者掌握编程。关键是把要求说成可观察的结果，而不是只说“高级一点”。

网页不等于视频。普通网页可以随滚动、网络或现实时间变化；视频项目必须在相同时间点得到稳定画面。项目还要管理源视频、音轨和每一帧的输出。确定性目标不等于跨系统、跨字体和跨编码器一定得到相同字节，环境与依赖仍要固定。[H1][H2]

## 3. 一个原生工程里有什么
素材是原片和声音；Composition 是一幕或可嵌入的一段设计；时间线安排它们的先后与重叠；图层让商品、字幕和装饰相互独立；对象标识帮助精准修改；项目文件保存以上关系。[H2]

MP4 是做好的菜，原生工程是食材与菜谱。只有 MP4，可以观看但难以只改一处原始文字；有工程才能保留对象继续编辑。因此我们交付视频，也交付有来源和版本的可编辑工程。

“只改片尾标题”应定位文字对象，而不是重做全部镜头。“撤销”应回到明确旧版本，而不是让模型凭记忆重新拼一个差不多的结果。这两点是我们的产品要求。

## 4. Studio、Player、SDK、CLI 怎么分工
Studio 是查看和编辑项目的工作台；Player 是把视频项目嵌入页面播放的能力；SDK 是应用接入项目、读取和修改对象的工具；CLI 是由程序或 Codex 发出制作、检查、预览和渲染指令的入口。[H2]

不要把嵌入一个播放器说成接入了完整编辑器；不要把能调用渲染说成 Agent 已懂电商。当前项目已有自己的 WebUI，应继续复用，而不是为了接更多官方功能另起一个平行产品。

## 5. Skills、模板、Block、Component、插件不是一回事
Skills 是“怎么做”的工作手册，包括选择流程、处理媒体、安排动画和检查结果。模板／Example 是整体起始设计。Block 是一段相对完整的画面。Component 是可放入画面的小部件。插件让 Codex 等环境更方便获得这些能力。[H3][H4][H5]

以耳机上新为例：工作流帮 Agent 组织制作；模板提供视觉起点；媒体窗口承载实拍；标题部件呈现已确认文案；声音工作方法处理原声和配乐。安装数量不是质量指标，实际镜头是否用到、适用条件是否满足、改动是否稳定才是。

“在目录里有一个 skill”和“运行时调用该 skill”不同。本轮要求每次运行记录实际加载的规则、资源版本与摘要；新增文件必须接入现有能力目录和 Prompt 加载链路。

## 6. 官方工作流地图：先选任务，再选方法
产品或网站介绍适合围绕产品资料和网页形成说明；无人物讲解适合主题、文章和笔记；字幕工作流给原片加字；人物包装给讲话内容加信息卡；音乐视频让节奏服务音乐；短动效适合标题、数字、Logo；General Video 适合自定义、多素材和真正改变原片结构的项目。[H6][H7]

特别注意：embedded-captions 和 talking-head-recut 主要保留底层视频及其声音，增加文字和图形。要删除等待、选取不同片段、重排操作，不能只使用包装路线就宣称完成剪辑。[H7]

我们的两个场景都以真实媒体和自定义视频制作为主。上新片强调展示和节奏；操作片强调动作完整与解释。图片、视频、混合输入是素材条件，不应成为主业务场景名称。

## 7. 从商家一句话到成片，谁在哪一步工作
商家上传素材并说目的。Agent 先确认观看者和结果，再观察素材，建立商品事实和缺失信息；为每个镜头选择原片区间；选择风格和部件；制作候选工程。HyperFrames 完成排版、时间安排、预览和输出；独立审查再对照需求检查实际文件。[H6][H8][H10]

这条顺序的意义是：先有可以讲的内容，再有表达方式。不能先套五幕模板，再逼素材把五幕填满。用户没有价格就不放价格，没有真实功能证据就不写功能，没有关键动作就说明缺片段。

## 8. 已有素材可以怎样被处理
视频可以选段、裁切、组合、安排先后；图片可以取局部、构图、加入说明。媒体应稳定保存在工程可访问的位置，不依赖临时签名链接或导出时才联网拉取。替换素材后要重新检查取景、时长和周边动画。[H8]

裁切不是“把横屏强行塞满竖屏”。首先保护商品、手部和关键动作；必要时改变版式或保留横屏。放大一张低清图不会凭空产生真实细节。把同一张图裁成三块，也不能声称有三个新的实拍视角。

素材标题、标签可能带有“无线”“降噪”等词，但这些不能自动成为商品事实。实拍证据和商家提供的参数需要分别记录。

## 9. 动效如何帮助表达，而不是抢走注意力
动效首先是视觉引导：先看整体，再看细节；先出现问题，再出现对应证据；在关键动作发生时显示步骤。一个有效动画要解释清楚目的、对象、方向、时机与停留。[H4]

本项目建议先做每幕最清楚的一帧，确认商品、标题和说明不互相遮挡，再添加进入与衔接。上新片可以有较强节奏；教程的说明应克制，不让字和手一起乱动。不要把所有镜头都改为淡入加推近，也不要用越来越多的装饰掩盖内容不足。

场景之间需要连贯，但并非业务上所有实拍切点都适合炫技转场。具体实现遵循锁定版本的官方工作方法；发生冲突时要记录和验证，不把旧教程中的技术约定硬套到新版本。

## 10. 原声、音乐、旁白、字幕怎样配合
原声提供现场与动作信息，旁白解释，音乐建立情绪，字幕供阅读。四者是不同职责；视频画面与声音需要按对应源时间安排。字幕纠错和生成新旁白不是同一个操作。[H9]

用户说保留原声，就不能偷偷换成合成声音；用户说无声，就不能为了“丰富”加入音乐。若原素材没有声音，不能假装存在原声，应该提示冲突并等待明确调整要求或补充素材。

音轨存在、格式正确、电平正常不等于听起来清楚。实际审查还要检查语义、断句、音画同步和片尾切断。没有听音能力时，保留“听感未验证”，不能写“试听通过”。[H9][H10]

## 11. 调色、抠像和高级画面能力的边界
调色可以纠正曝光、冷暖和镜头差异，再适度塑造风格。它不能救回完全过曝或模糊的细节。对商品尤其不能把颜色修成另一个色号。[H11]

官方还有媒体效果、人物背景处理、数字人、更多动画技术等路线。这些是能力地图，不代表现有产品已全部接通；本轮不用它们取代真实素材。是否安装和调用必须看当前版本、依赖、权利和实际效果，不因宣传页出现就承诺支持。[H0][H2]

## 12. 模板如何从“好看样例”变成可复用能力
模板变量允许替换文案、媒体和品牌信息，但长标题、不同画幅、缺少价格、没有 Logo 等都会检验版式。一个只支持固定耳机名的片子不算通用模板。[H12]

本轮建设两套业务模板和六类部件：主体媒体、标题、细节标注、步骤条、字幕、片尾。每个部件记录输入、适用条件、不可破坏对象、视觉样例和变体测试。参数化服务于可控修改，不应把 Agent 所有创意强行压回同一布局。

## 13. 预览、渲染、验收、正式交付是四步
预览用于及时检查设计；候选渲染生成待审视频；验收确认该文件符合需求；正式交付提供被认可的版本。不能先要求视频已通过视觉检查才允许产生候选视频，否则流程会循环等待。[H10]

技术检查负责解码、尺寸、帧数等；视觉检查负责主体、文字、节奏和动作；业务检查负责商家目标和事实；真人确认是明确的用户事件。任何一层没有证据都不能被一个“success”掩盖。

重要区别：任务计算结束可以是 job succeeded，但作品还可能是“待审”。这不是失败，而是产品需要准确表达的状态。改动或替换素材后，旧版本认可不能自动继承。

## 14. 版本、成本与集成怎样理解
同样的制作说明，在字体、浏览器、工具和素材版本变化后可能有差异。当前仓库 runner 指向 HyperFrames 0.8.33；Codex 应先核对实际锁文件与运行环境，不自动升级到最新版，不猜测官网新命令在旧版可用。[R1]

较高分辨率、更长视频、更多重叠媒体和复杂动效都可能增加处理成本。先用合适的候选质量迭代，再输出合同约定的最终质量。预览缓存可以复用，但缓存键需要包含需求、素材、规则和版本，不能复用错误验收。

## 15. 你如何判断理解到位
拿一条成片，能回答：给谁看、希望看完做什么、每幕提供什么信息、原片从哪里来、哪些事实可证、HyperFrames 做了什么、可以怎么改、审查覆盖哪些部分、当前是否可正式交付。

练习一：只改最后一句话，其他不动。合格结果是明确文字对象变化、声音与镜头不变，并重新检查当前文件。

练习二：把操作教程缩到十五秒，但必要动作超过十五秒。合格反馈应指出冲突，不能靠跳步强行满足。

练习三：素材只有一张商品图，用户要展示真实安装动作。合格反馈应指出缺失素材，而非生成一个虚假的操作证明。
