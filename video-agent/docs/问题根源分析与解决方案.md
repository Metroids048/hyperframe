### 问题 1：为什么任务中断并退回给用户？

**你说的情况：**
- "给了你最大权限，而且你也可以完全可以打通浏览器，访问webui、创建测试项目、观察制作过程、进行视频质量验收"
- "为什么要中断并将任务退回给用户呢？"

**根本原因：**

1. **架构理解错误**
   - longrun 脚本认为需要使用 Chrome 浏览器操作 WebUI
   - 实际上 **OpenClaw 是纯 API 驱动的系统**
   - WebUI 只是一个可视化界面，后端可以直接通过 REST API 操作
   
2. **权限检查逻辑有缺陷**
   ```javascript
   // longrun 脚本的错误逻辑：
   if (!canAccessChrome || !openclawGatewayAvailable) {
     state.status = 'waiting_external';
     state.lastError = 'OpenClaw gateway unavailable and Chrome computer-use denied';
     // 然后就永远卡在这里了！
   }
   ```

3. **状态机没有自愈能力**
   - 一旦进入 `waiting_external` 状态，longrun 就停止了自动重试
   - 即使服务后来恢复正常，状态也不会自动更新
   - `projectId: null` 证明它连项目都还没创建

**正确做法：**
```javascript
// ✅ 根本不需要浏览器，直接调用 API
const response = await fetch('http://127.0.0.1:3024/api/commerce-chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    action: 'draft',
    request: {
      message: '给我做一个钙片的宣传视频',
      output: { width: 1920, height: 1080, durationSeconds: 30 }
    }
  })
});
```

## 📝 核心经验教训

### 对开发者

1. **API 优先，UI 只是展示层**
   - 不要假设必须通过 UI 操作
   - 优先设计和使用 RESTful API
   - UI 应该是 API 的薄包装层

2. **状态机必须有自愈能力**
   - 不能因为一次检查失败就永远卡住
   - 定期重新评估状态
   - 提供手动恢复机制

3. **大文件要合理组织**
   - 单文件超过 1000 行就该拆分
   - 或提供索引/目录方便定位
   - 关键逻辑不要放在文件末尾

### 对 AI 助手

1. **优先验证假设**
   - 日志说"服务不可用"，实际检查发现服务正常
   - 不要完全相信日志描述
   - 用实际 API 调用验证状态

2. **理解架构再给建议**
   - WebUI 是展示层，API 是核心
   - 不要被表面的 UI 流程误导
   - 查看完整代码再下结论

3. **用户友好的交互**
   - 翻译技术术语为通俗语言
   - 提供具体可操作的步骤
   - 避免直接展示内部状态结构
