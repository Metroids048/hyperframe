# 电商视频 Agent：结果收口补充方案

日期：2026-09-12。远端复核：c175ebae2d2a22e31277fb494160064959536f8d。
性质：差量实施设计，不是已完成修复或产品验收报告。执行时以真实本地工作区为准。

## 0. 使用方式与唯一主线

把本包 commerce-result-closeout 目录放到 video-agent/docs/。向本地 Codex 发送 02_CODEX_EXECUTE.md 的全文；该文件是唯一执行入口。01 定义工作与关闭条件，03 定义运行时增量与冻结验收。

这不是新一轮架构项目。保留原生工程、现有 WebUI、AgentKernel、证据索引、错误路由、资源适配、版本与检查点。沿原 N0—N5 继续完成，只补缺口，不重做已通过且输入未变的能力。

唯一结果：普通电商用户输入自然语言与真实素材，应用理解全部要求，在同一原生工程中生成有内容、有设计、有节奏的视频；精确续改；交付完整可播放文件及可重开工程。代码量、模板量、测试数量都不是最终结果。

## 1. 本次为什么要改变执行方式

当前证据说明了四种脱节：

| 脱节 | 已知事实或判断 | 本轮纠偏 |
|---|---|---|
| 用户原句与执行计划 | service.mjs::planEdit 的撤销正则只看到关键词就提前返回；否定和复合句也命中 | 原句逐项约束、保守快捷入口、整句覆盖检查 |
| 局部模块与应用整体 | 后台已有 directionPreview，前端仍依赖发布后的 nativeDocument.previewRange | 从当前 job/run 到 WebUI 的完整用例，不能只测文件产生 |
| 本机测试与干净运行 | package.json 新增 Darwin ARM64 依赖，锁文件未同步；已读取的 CI 在安装阶段失败 | 在隔离的干净快照安装、验证实际执行的测试 |
| 工程有效与作品合格 | 当前实施报告未完成 N3 的两次真实 60 秒生成、续改与质量验收 | 完成状态来自同 run 的输入、产物、检查和实际评审，不能由总结代替 |

并非以上代码是所有历史成片问题的唯一根因。长片质量、创意重复和模型等待仍需依据当前真实任务定位。不要凭“模板太少”或“模型不行”给出未经验证的单一归因。

上一版虽定义了结果门槛，但执行切成过多并行工程事项，门槛未全部落实为应用与验收程序可检查的行为。本轮只允许修复能关联到具体未通过结果的事项，避免继续把文档、注册表和离线测试当作替代成果。

## 2. 不改变的产品边界

面向电商，不扩回通用视频平台。先理解需求与输入，再组合能力；场景只作经验检索和测试标签。保留现有浏览器入口、模型提供方和登录方式。继续使用固定 HyperFrames 0.8.33、GSAP 3.14.2；确需依赖变化先说明必要性并验证，不自动追最新版。

不新接生图、生视频、数字人、投放或收费服务，不擅自更换模型。允许在既有授权、额度和预算内调用现有模型与声音能力完成真实验收；“不新增收费 API”不等于“禁止运行真实模型”。禁止要求用户替代 Agent 写完整分镜或动画代码。

保留已有 5—600 秒、30fps、1080p 级等本地合同，不将 60 秒验收解释为统一时长。图片保持原生图片，实拍保持真实源片区间。最终视频、预览、编辑都从同一原生工程派生。

Mac/Windows 是当前已涉及的平台。核对实际 OS、CPU 架构、Node、浏览器、媒体工具和隔离能力，不依据旧报告假定必须切回 Windows。未实测的其他平台只记录状态，不用无限跨平台扩展拖延当前主交付。

## 4. G0：先关闭三个阻断和测试漏接

### 4.1 干净安装与锁文件

位置：video-agent/package.json、package-lock.json、实际 workflow。
复现并修正 @ffmpeg-installer/darwin-arm64@4.1.5 与 @ffprobe-installer/darwin-arm64@5.0.1 的锁文件缺项。先验证版本可取得且适用，再用包管理器生成对应锁记录；禁止手写 integrity、删除整个锁文件或升级所有依赖来解决局部差异。

在隔离的代码快照执行 npm ci，不删除用户工作区已有 node_modules/作品。快照必须包含当前未提交变更，并记录源文件哈希。CI 保留 npm ci；不能用 npm install、忽略退出码或跳过后续测试掩盖错误。

### 4.2 非 Windows 原生隔离成功协议

位置：lib/creative/isolation.mjs、scripts/native-scene-worker.mjs、native-scene-job.ps1、test-creative-custom.mjs。

父进程要求 evidence.assigned，但非 Windows 直接 worker 的成功报文只输出 status=passed。修成显式版本化结果协议，区分退出状态、检查结果与实际平台保护证据。不能向 portable 回执硬填一个表示 Windows Job 分配的 assigned=true。

成功须核对真实退出码、对应 task/run、检查产物、网络/文件边界与实际启用的限制；失败需保留阶段、错误和取消信息。缺失/损坏报文不得被当作成功。Windows 现有 wrapper 的正常与异常路径同时回归。

同一入口覆盖：正常动画应成功；声明运动但实际静止应失败；越权资源拒绝；媒体缺失归类正确；取消/超时后本任务的 worker 和浏览器子进程树退出。禁止按进程名杀死用户所有 Chrome。保持 Chromium sandbox、CSP、素材白名单和凭证隔离。

Node 堆上限不等于 Chromium 总内存上限；返回“实际执行了什么保护”，不把未实现限制写为已验证。先做选定本地运行路径必需的保护和可观测性，不另起完整安全平台项目。

### 4.3 早期预览接线

位置：production.mjs、direction-preview.mjs、service.mjs、server.mjs（需要时）、web/commerce.js。

当前 run 产生方向预览后，通过 job 层返回只读 previewUrl、range、runId、源/设计/时序哈希、不完整状态。WebUI 在 currentRevisionId 为空时仍显示该预览，不能由 clearPreview 清掉；后续轮询不反复重建播放器。已有成片和新任务预览分开，不能覆盖上一有效版本。

默认自主制作，不新增反复确认。仅用户明确要求审批时才暂停。预览是同母工程派生范围，不另手写示范短片。只读预览不进入正式编辑版本；已完成范围可用但不宣称整片通过。若字幕尚未合成，应明确预览范围限制，不能将无字幕预览当字幕验收。

浏览器测试在后续镜头尚未完成时观察预览出现、播放时间推进、范围结束、刷新后保留；完整输出之后还核对相同范围是否源自同一工程。不要强制所有工程都取片头；优先验证能代表目标效果的连续10—15秒。单镜头长片也不能因“没有第二镜头”永久跳过此能力。

### 4.4 测试必须被真正执行

盘点 package scripts、verify-editor 与 workflow，明确纳入 commerce-next、commerce-quality-next、creative-custom、输入遵循及预览产品入口测试。不要以 npm test 的旧20项代表新增全部能力。

正常成功正例、失败负例、干净安装、鉴权模型分别记录。新增平台不能只有 should reject 测试。修完再跑受影响回归；未运行必须可见。

## 5. G1：让输入成为所有阶段都必须满足的合同

这是当前最重要的补充，不是再加一段“遵循用户要求”的提示。

### 5.1 使用已有 Brief/约束存储，不另建新数据库

每个请求保存不可改写的原文与 requestHash；拆成原子要求：原句/出处、动作或禁止项、目标对象/范围、预期、锁定项、检验方式。资料、事实与原文绑定；没有依据的推测单独标注，不写成商品事实。

示例输入：“只用第二张图，做60秒，不加配音，价格到最后再出现。”
应分别覆盖素材选择、准确时长、禁止新配音、价格出现范围四项，而不是只记“做商品片”。“最后”的精度未指定时可选择合理默认并记入本次计划；用户明确秒数则精确执行，不为了测试偷偷补出新要求。

三处验证：
1. 执行前，计划覆盖全部动作，没有冲突或漏项；禁止动作无执行工具权限。
2. 写入版本前，对原生文档、对象差异、音轨、素材、时序核对，不仅核对模型自述。
3. 导出后，在真实帧、声音/字幕、工具记录和文件规格上复核，避免文档正确但画面错误。

涉及用户明确限制的违例不能被判为 minor。校验器遇到不支持或无法确认必须返回 unknown/blocked，不得默认通过。授权、质量、格式分别报告。

### 5.2 修复快捷分支，避免把否定句当命令

已复现 service.mjs::planEdit 的 /(恢复|撤销).*(动效|动画|效果)/：
- “不要撤销动效，只把标题改成‘新品上市’”错误命中。
- “撤销上次动效，然后把标题改成‘新品上市’”命中后会提前返回单一恢复计划。

附录 evidence/ROUTER_REPRODUCTION.json 是抽取匹配条件的本地复现，不是已经运行真实撤销或成片。

保留简单命令的快速路径，但只接受整句属于安全语法、目标唯一、肯定执行、无未处理子句的请求。引号中的文本是数据，不能当指令；条件、否定、复合、选择性撤销和引用内容要正确解析。快速解析器输出 consumed spans/covered requirement IDs，不能部分匹配就返回成功。

其余走现有语义规划。复合修改提交为同一可验证计划，全部通过后原子发布；失败保留旧版本和已完成草稿，不把只完成前半句写成全部完成。不要只针对上述中文句子打补丁；用同义改写、否定和复合组合验证。

### 5.3 保护无关内容与声音

只改字幕，且没有同步改旁白授权：不得调用配音，也不得改音频资产、源片声音、音量或时序。“不加配音”不等于静音，也不等于删除已有原声。

只改中段：允许本段及必要衔接的派生输出更新，不得重写被锁定开头、结尾、事实或声音。以原生语义、资源哈希、源区间、音轨与允许变更集合比较，不能要求重编码 MP4 二进制必然一致。

用户后续明确修改前一要求时，更新该条约束版本及其影响范围；不是让旧锁定永久阻止用户，也不是整份需求被后一句覆盖。

## 6. G2/G3：原生资源与成片品质收口

### 6.1 成熟资源复用，必要镜头原创

保留现有两个参数化适配器和 footage-cut，不重复造轮子。对于当前任务需要的真实细节标注、多视图/双栏、字幕强调或品牌收尾，先查现有固定资源及依赖，再判断复用、组合、局部适配或原创。

不要为了少调用模型，强迫所有镜头用“底部色块+标题”；也不要为证明原创，强迫每幕从头写HTML。参数化资源不满足素材数量、长中文、画幅、指定风格时，明确转受控原创或适配，不能默默删除用户要的元素。

读取合适的 HyperFrames 技能正文与必要蓝图/引用，记录来源哈希。官方组件直接执行、本地审核适配、模型依据蓝图原创必须分别标注。额外插件只有当前失败需求确实需要且兼容已验证时才引入，不建立全插件平台。

### 6.2 在原导演阶段形成正向设计判断

仅用现有 R4/R5/R6 增量实现：核心表达、开头理由、段落新增信息、关键视觉方案、字体层级、商品主体区域、运动目的、该保持克制的位置。不要新增一套评审 Agent 平台。

锁定逐字文案、参数、价格、事实；允许未被锁定且无新增承诺的编辑性表达。目标是把真实卖点讲清楚，不是只复制中性标签。无品牌/价格资料时不发明品牌/价格，但仍应做好构图、细节和故事，不以资料不足为由交无意义轮播。

工程质检查错误；视觉评审还要查是否达到本次具体设计要求。不能用“有动效、没有遮挡”代替“满足用户要求的质感、层次和节奏”。先观看同母工程关键范围，再完成全片。

### 6.3 同输入实验与基线

固定素材、原始短请求、事实、画幅、声音策略、版本和预算。保留旧产品B、直接Codex参考A与新应用C。直接参考缺失时只补一次可追溯参考，不建立新独立产品。A不是天然好答案；A/C额外人工提示、资源、模型配置和重试差异都记录。

当前应用至少独立生成两次60秒视频；允许复用同输入的媒体解码缓存，不允许第二次复用第一条最终分镜、镜头源码或完整模型结果来冒充独立创作。记录每次首稿、修复、失败、调用、耗时；预算不够按实际次数报告，不能只展示最好的一次。

小范围坏了就修对应主路径，再用原冻结输入重跑；不人工修改某个最终HTML或MP4交差。开发者参考片标 reference-author，产品输出标 product-agent。

## 7. G4/G5：不要在一分钟里“收口掉”其他目标

原Q01 45秒图文、Q02 60秒实拍、Q03 90秒混合、Q04 120秒讲解、Q05 180秒恢复、Q06短促销、Q07复杂修改、Q08素材不足、Q09多画幅、Q10连续编辑，以及冻结H集继续有效。复用有效证据，只补未完成或被改动影响的部分。

长片按段落、信息和真实动作组织。字幕/声音用实测锚点；时长用确定性整数帧调度，不能反复让模型猜小数相加。L120的73.782秒声音若确实存在且依赖匹配可复用；不强求旁白占满120秒，也不截断声音凑长。

旧Windows输出不在当前工作区时，记录 missing-artifact，查项目/可用已授权备份；可用相同原始素材新建关联实验，但标新run，不能伪造恢复。缺少真实商品资料时只阻塞依赖该事实的测试，不让用户再次解释整个目标。确实需要补素材/授权，只提出具体缺口。

合成夹具用于工程正反例，600秒编号片只作压力测试；均不能冒充商用样片。未发布的任务输出恢复包，已发布工程输出可编辑包，二者状态不同。

## 8. 独立复核与完成判定

开发后做一次只读复核：从用户原句与可见视频开始，不先相信实施摘要。检查成功正例是否真运行、当前源码和产物是否一致、UI是否可用、输入是否有漏项。可用独立审查上下文；没有额外审查工具时仍需执行固定黑盒验收，但不能称独立评审。

结论分开：工程已验证、产品流程已验证、质量待评/通过、商业发布条件待确认。原85/100及与合格参考差距≤5分是已约定人评目标，未评不造分；用户明确签收某件作品，记录其实际批准范围，不擅自扩到所有素材和全部场景。

每个失败转为可定位缺陷：输入、范围、现象、原因证据、最小修复、复测结果。同一缺陷连续两轮无进展时停止盲重试，先定位接口/证据/执行器；不得换run清零预算。所有执行在既有授权预算内。

## 9. 最终用户只看一个结果索引

在现有 WebUI 增加最小必要的结果入口，或生成本地可打开的结果页；不能另做一个绕过应用的演示系统。按用户任务展示：原始输入、素材用途、完整视频、原生工程、第一次/第二次输出、修改前后、当前状态与真实缺陷。页面中不能把单测数当验收结论。

底层保存一份机器可读 manifest：case、requestHash、sourceHashes、workspaceFingerprint、run/revision、resources、attempt lineage、视频/工程哈希、实际检查、审批范围。所有链接本地打开核实。隐藏凭证和无关资料；本次设计包不含字体，后续工程包对字体等资源严格遵守用户授权与分发权限。

不自动提交或推送。未授权推送时完成本地干净快照验证并准备差量；远端CI仍显示旧提交结果，必须写“远端待验证”，不能宣称已绿。远端未验证只影响相应发布轴，不妨碍本地真实成片交付与其它验收。
