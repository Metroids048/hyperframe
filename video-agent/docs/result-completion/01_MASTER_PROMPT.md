## 2. 持续执行与正常结束条件

单项状态：`not_started → running → needs_fix → verified_machine → awaiting_human → accepted`。真实外部阻塞单列 `blocked_external`；需要补充证据单列 `unverified`。不同证据层次不得合并为一个 passed。

每个循环执行：

> 读取证据 → 定位原因 → 最小有效修改 → 重放同一失败输入 → 检查真实结果 → 跑受影响回归 → 保存状态 → 选择下一个依赖满足的未完成项。

只有以下状态才允许结束执行回合：

- **可执行交付齐备**：所有适用必需任务已形成真实产物或正确的负例行为，当前代码及浏览器回归通过，交付检查无缺项，完整结果入口可打开；只剩明确的人评/权利签收。报告“可执行交付齐备，待用户签收”，不能自动宣称全部商用通过。
- **全部剩余项确被外部条件阻塞**：给出真实日志、已尝试方案、影响的需求 ID、已完成产物、最小所需动作。内部 Bug、渲染失败、只有泛化错误或没读过日志，不是外部阻塞。
- **用户明确停止或宿主强制中断**：尽可能写入精确接力点，明确未完成；不得承诺会话结束后仍会后台继续。

以下不是结束条件：修了三个文件；单测通过；CI 全绿；做完一个阶段；生成了一条 fixture；已导出但没打开；缺人工评分；一句 render failed；模型第一次超时；旧 Windows 目录不在 Mac；认为剩余工作太多。只有仍有合法、预算内、依赖已满足的实质动作，就继续执行它。

不要为了满足“持续”机械耗时。连续两次同签名失败且没有新证据时，停止盲重试，切换定位假设、缩小复现、查调用边界；这不是结束整项任务。不得通过重建 run ID 清零预算。触达真实调用/费用/资源上限，停止受限调用并继续无依赖的工作；不得无限运行。

## 3. N0/N1：修成功回执、平台运行与故障分流

### 3.1 跨平台回执合同

核对 `lib/creative/isolation.mjs`、`scripts/native-scene-worker.mjs`、`scripts/native-scene-job.ps1`。

审查参考中 portable worker 最后一条 stdout 只有 status/error，而父进程需要 protocolVersion；Windows 外层又是 Job 资源结果、嵌套 stdout/stderr。不能只给非 Windows 补一个字段就认定全平台解决。对本地实际版本先复现；已修有效则复用。

方案：定义共享且版本化的成功/失败信封，分离 supervisor 的退出码/限制/超时证据与 worker 的执行结果。使用明确的结果通道或稳定前缀，不能靠“任何最后一条看起来像 JSON 的日志”识别成功。关联 run/scene/输入哈希，核对退出码、协议版本、超时标志、必要运行证据，避免吃到上次残留文件。对旧回执做显式兼容或拒绝，不静默相信。

必须验证正常动画成功、静态违规失败、未知版本、缺字段、截断/夹杂日志、陈旧回执、非零退出、取消和超时。成功测试必须真正经过生产父子进程路径；mock 只证明协议，不代替真实浏览器成功正例。

macOS/Windows/Linux 按实际可用环境分别报告。不能把非 Windows skip 算跨平台通过；可在当前可用平台完成主产品任务，其他平台保持真实待验证，不伪造，也不阻塞所有本地成片工作。

### 3.2 安全和资源回收

保留 Chrome sandbox、CSP、网络请求拦截、独立环境和路径检查。验证外网、跨项目接口、文件访问和越界资源被拒绝。只回收本轮创建的进程，禁止全局 kill Chrome/Node、影响用户日常应用。

取消和超时必须清理本轮 worker 与 Chromium 子进程树、句柄和临时锁，验证进程确实退出；不能以发出 kill 信号代替完成。声明的 CPU/内存/进程数量限制必须有适用平台的真实证据；未经验证不能标成等价隔离。进程限制和浏览器安全边界分开记录，不用去掉限制修通流程。

### 3.3 渲染失败不是交付终点

核对 `lib/workflow.mjs::runHF`（旧创建路线）与 `lib/creative/runner.mjs::runHyperFrames`（电商路线）的现场实现。一个入口成功不替代另一个回归。

读取失败工程的 check/render/server 日志、cwd、args、实际二进制路径、架构、退出码与首个因果错误。日志缺失就在失败边界补最小脱敏日志，再重放同一工程。依次区分：文件/字体、媒体解码、浏览器启动、合成入口、抓帧、编码、混音、API 事件、测试等待层。

CLI 成功但应用失败时对比真实 env/cwd/args/进程生命周期。编码器不支持时可用现有允许且验证过的同规格软件路径，不降时长、声音、分辨率或设计要求。工具有进度时与真正卡死区分，不盲目放大 timeout。不得手改输出 HTML 或 node_modules 掩盖应用缺陷。

协议、环境、解码问题修对应层；构图问题只修布局；动作选错才重选源；文本/事实问题回对应计划。错误分类必须贯穿上层，不能把 CUSTOM_RUNTIME_FAILED 一律交模型重设计。

### 4.3 正向创意与提前方向预览

应用自动建立需求适合的视觉方向：商品主次、字体层级、色彩、留白、信息推进、运动幅度、镜头关系。先清楚的一帧，再动效；避免不分商品都黑金、光扫、统一大字或图片缓慢放大。产品/资料不足不编造参数、价格、功效或评价。

在同一母工程内完成代表性镜头，先出现 10—15 秒方向预览，再完成长片。验证新工程没有 currentRevisionId 时 job/run 预览能在现有 WebUI 显示、打开和播放；不能只验后端文件。绑定母工程、版本/阶段哈希、时间范围、素材和字体依赖；后续修改使预览过期时要明确。

提前预览是输出，不默认暂停等待审批。代理在现有授权内自行检查并继续；用户主动提出修改时遵守。需要字幕的预览不能假装无字幕版本已覆盖字幕质量；尚未完成的声音必须清楚标注。

## 8. 用户只看结果：统一入口与可检查交付

结果入口复用现有 WebUI 或现有服务的一页只读汇总，不另做制作系统。允许在开始建立空骨架，但最终逐项填入真实产物：原请求、实际视频、修改前后、提前预览、可导入工程、当前状态、待人评/授权问题。

URL 取当前真实服务地址，不猜端口、不把源码 HTML 当播放器。验证点击、刷新、Range/HEAD、播放推进、近末尾 seek、完整时长及有声播放能力。未提供音轨的任务按原要求判定；需声音却无音轨硬失败。播放有音轨不自动表示声音内容合格。

复用或生成真实交付清单，关联 case/run/revision、源码文件哈希、素材/资源锁、当前 MP4、原生 Document/工程包、浏览器记录和失败修复记录。不得包含模型登录凭证、令牌、用户无关资料或未经授权的字体文件分享；引用合法本地字体时清楚记录依赖。

使用随包 `verify_delivery.py` 做只读文件/哈希/规格/证据绑定检查；它不评审审美、授权或日志真实性，不是防作弊安全边界，也不驱动应用。可在本地适配现有格式，但不可删除固定的原需求 ID、伪造媒体结果、把其 evidence-only 返回解释成商用签收。

最终全量回归检查受影响的旧入口和主电商入口；本地没有推送授权时只交付本地实测，不擅自推送，也不因远端还不是新版本而拒绝本地结果。

## 9. 执行可见性、接力和最终报告

进展按实质状态变化简短告知：已关闭哪个问题、生成到哪里、真实产物在哪里、当前阻塞和下一动作。不反复复述计划，不以阶段汇报代替继续工具执行。

计划压缩或会话接近强制边界时保存：工作区指纹、未提交修改、当前 case/run/revision、执行命令/进程、最后成功检查点、失败日志、已花预算、下一条确切动作、未完成需求。宿主支持原会话续跑则使用其正常能力；不假装写了文件就能自行后台运行。

最终回复先给可打开结果入口，再给完整视频与工程、原需求逐项结果、相对旧版改善，最后附测试和日志。三个结论严格分开：
1. 可执行交付齐备（必须有完整机器与产品证据）；
2. 质量/权利待签收（只缺人类判断）；
3. 任务未完成（列明真实阻塞和剩余任务，不能写“基本完成”掩盖）。
