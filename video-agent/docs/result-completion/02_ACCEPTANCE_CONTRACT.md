# 结果验收合同：先交结果，再谈完成

本文件规定本轮交付，不代表任何项目用例已经运行通过。以现有原始需求和冻结用例为准；下表补充对交付证据的约束，不把测试任务改成固定商业场景菜单。

## 一、用户应该实际拿到什么

| 结果 | 合格证据 | 不能替代它的东西 |
|---|---|---|
| 正常自定义场景与跨平台回执 | 共享协议测试；当前平台经生产父子进程、真实浏览器的有效动态正例；反例及取消回收结果 | 只测拒绝、其他平台 skip、伪造 passed |
| 30 秒视觉回归 | 原失败工程重新编译与实际 MP4，商品和重要文字可辨认，关键时间前后对照 | 删除警告、只改最终 HTML、旧 MP4 |
| Q01 45 秒 | 原冻结图文请求，经现有 WebUI 的完整输出与工程 | 延长图片停留凑时间 |
| Q02 / N3-A、N3-B | 相同输入、两次独立创意调用，经 WebUI 的两条 60 秒视频、原生工程、早期预览和制作记录 | 不同 run ID 但复用整片模型答案、复制成片 |
| Q03 90 秒 | 原混合素材任务的完整视频，动作、来源及内容连贯 | 73 秒或半成品冒充90秒 |
| Q04 120 秒 | 原讲解任务及所需真实声音/字幕、完整计时与结果 | 音轨存在就说试听通过 |
| Q05 180 秒 | 完整视频、真实中断后续跑、依赖有效检查点和恢复记录 | 只模拟状态切换、重新生成却说恢复 |
| Q06—Q10 | 原短片、复杂修改、画幅、素材不足等定义的实际结果 | 另换简单请求、强行要求负例也输出 MP4 |
| I01—I12 | 原输入/编辑/锁定等测试及10—14轮连续对话，真实文档差异与媒体结果 | 只看意图路由或测试打印 |
| H01—H10 | 原冻结未见输入逐项结果，所有失败及后续修复保留 | 挑最佳、失败用例移出名单 |
| 结果入口 | 同一真实服务中可播放视频、看修改前后、打开/导入工程和状态 | 一堆猜测的本地 URL、裸源码、已过期链接 |

原用例有别名时建一张映射，不重命名丢失原身份。上述义务已被当前版本有效证据覆盖的可以复用，但独立 N3-B 不能靠复用 N3-A 的创意答案完成。

## 二、机器、模型、人类三层不要混淆

### A. 机器与工程

先验证文件、哈希、完整解码、时长/画幅/帧率、声音需求、源引用、稳定对象、资源锁、版本及失败回滚。字体不缺字，路径不跨界，命令与依赖可复现。正式输出采用已约定规格，不能因为机器慢或编码失败降低要求。

目标时长按视频有效帧及容器时长检查，允许必要编码尾差，不能允许实际内容少几秒。30fps 下重要时间编辑以帧精度记录；音画同步范围根据实际合同冻结，不在失败后放宽。预览抽样不足以证明全片无误，最终还需完整解码和播放过程证据。

对比度和可读性检查评估文字真正应该可读的时段，避免把动画瞬时低透明度误判为长期失败。重要价格/条件/字幕长期不可读为硬缺陷；装饰、短暂转场和刻意叠层需实际画面判定。不能靠机器统一亮度阈值宣布商品拍摄效果合格。

### B. 模型辅助复核

依据真实帧/时间/声音能力提供问题定位、依据和局部修复，不空写“高级感”。每次修复确认指定问题减少且无关对象/声音不变。修复无进展转诊断，达到既有预算保留失败，不循环到输出漂亮分数。

自动检查必须明确 unreviewed：无听音能力不能写已试听；无完整动作证据不能写动作连贯；没有权利材料不能说已商用授权。

### C. 用户与独立人评

沿用原目标：85/100，且与合格同输入参考的差距不超过5分；两位独立评审须是真人且实际看过绑定版本。若原冻结量表已有维度/权重，以原量表为准，不能另立宽松标准。没有量表时建议在评审前冻结：商品表达25、叙事20、视觉20、动效15、声音10、续改/交付10，总分100；无声音的合法任务按事前声明重分配，不拿免音轨当满分。

硬违例优先于平均分：错商品/错价/不被支持的功效、漏用户要求、不可读必要条件、意外黑帧/截断、强制静音、错误修改无关内容，不能靠漂亮画面抵消。

用户是最终签收者。正式人评未完成：可以并应该继续制作其他无硬阻塞任务，把全部成片准备好；状态仍是 awaiting_human。不得由 AI 代签，也不得因等待人评提前停在没有成片的位置。

## 三、预算、独立性与失败处理

使用现有 provider、账号、调用/费用/资源限制；安全与账单限制不可绕过。开发者定点重现与正式运行分别记录，既有实际预算不因清空文件或换 run ID 复位。

两次独立生成可共享源媒体解码/转写等确定性分析缓存，但各自的创意规划与镜头决策不能复用另一条最终答案；记录 creative_attempt_id、阶段调用与 cache receipt。仅两个随机 UUID 不构成独立证据。

外部阻塞需要原始错误、范围和最小解除动作。内部 Bug、没找到日志、尚未查过的素材都不是外部阻塞。物理没有某平台时保持其平台待验证，可推进当前支持平台成片；本地未授权推送也不能成为不交付本地产物的理由。

保留全部尝试。冻结未见用例失败后被用于调试，应在报告标记该用例不再是最终版本的严格 holdout，不能隐瞒为从未见过。负例按预期行为判定，不统一要求视频文件。

## 四、交付清单与检查器

优先兼容已有台账，不增加运行平台。附带模板是**未冻结的起点**；`resolve_original`、`from_request`、缺源定义、空输入等必须由 Codex 从原本地资料解析，不能让检查器自动当通过。模板中的源码 `8e3e61a` 仅为审查参考，不要求回退本地。

### 1. 冻结合同

将 `delivery-contract.template.json` 按原定义落到实际合同文件：
- 每个 case 保留原 ID/别名及 definition_source 的真实文件路径、sha256。
- expected_outcome 只能是 video / behavior / engineering；负例通常是 behavior。
- 视频的音频需求为 required / forbidden / optional，必须依据输入选择，不能为过测改成 optional。
- 指定 duration_seconds；width/height 按原需求填写，缺画幅时按产品合法默认而非检查器默认。
- required_checks 是该用例必须具备的机器/产品记录，不能删除难做项。
- 读完原定义后 frozen=true；把 cases 数组按 `json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(',', ':'))` UTF-8 的 sha256 填入 scope_sha256。首次冻结的完整合同哈希另存台账；后续非用户授权不得变更范围。

### 2. 生成实际 manifest

字段格式见 `DELIVERY_MANIFEST.template.json`。所有 path 相对指定的本地 video-agent 根目录，不允许越界或 symlink 指向外部。每个 artifact 是 `{kind, path, sha256}`。源文件 source_files 使用 `{path, sha256}`，至少覆盖实际改动和关键运行入口；workspace_fingerprint 是按路径排序后的 source_files 数组使用上述 canonical JSON 算法计算的 sha256。检查器复核文件内容，防止报告沿用旧代码哈希。复用旧产物时，workspace_fingerprint 表示本次复验所用实现；原生成指纹必须原样保留在 run_evidence，另记依赖影响分析与迁移/复验记录，不能涂改历史让旧片看起来由新代码生成。

每个视频 case 必须有 final_video（实际 MP4）、native_document（JSON）、native_project（包或可携带的工程入口）、input、resource_receipts、run_evidence，以及 required_checks 对应记录。视频不在这里现场重新生成，检查器只核验结果。

checks 中每项格式：`{"name":"browser_playback","path":"...json","sha256":"..."}`。该 JSON 由对应真实测试输出或薄的规范化器从真实日志整理，应至少有：

```json
{
  "check": "browser_playback",
  "status": "passed",
  "case_id": "Q02-A",
  "run_id": "实际run",
  "revision_id": "实际revision",
  "workspace_fingerprint": "源码清单指纹",
  "evidence_paths": ["outputs/真实记录.json"]
}
```

`evidence_paths` 内文件也必须列进该 case.artifacts 以便哈希校验。不能生成空的同结构 JSON 冒充测试。薄规范化器不得把 failed/unreviewed 变为 passed。native_document 的 revisionId 必须与 case 关联。

### 3. 调用方式（由 Codex 执行，不要求用户改用终端）

```text
python <本包目录>/verify_delivery.py --root <实际video-agent目录> \
  --contract <实际冻结合同.json> --manifest <实际DELIVERY_MANIFEST.json> \
  --ffprobe <当前已验证的ffprobe路径>
```

检查器只读，输出 JSON 到标准输出：退出码0只表示 `EVIDENCE_COMPLETE_AWAITING_ACCEPTANCE`；退出码1表示缺失/失配；退出码2是运行参数/环境错误。**退出0不等于人评通过、授权通过、日志真实性证明或项目商用完成。** 它不评审画面美感、不验证人类身份、不保证上传材料真实。其作用是阻止无文件、旧文件、错时长、漏音轨、错版本、缺测试记录仍意外被汇总成完成。

需要新的测试记录由 Codex 在现有测试/结果链中接入，不允许从模板直接填 passed。checklist 不是结果，样例 JSON 不是证据。CI/测试适配完成后还要开真实浏览器，不能只跑本检查器收尾。

## 五、最终交付内容

优先展示一个实际打开验证过的结果入口，然后是全部必需视频、修改前后、原生工程、逐条请求完成情况和明确待人评/授权项。底层日志与测试置后。目标是用户能直接检查而不是自行在几十份文档和目录里找。

“可执行交付齐备，待用户签收”仅在所有必需机器/产品结果已齐备时成立；若任一要求仍有内部错误或无产物，写任务未完成并继续修复。在全部剩余项真正外部受阻或宿主中断时保存接力，不能改口称基本完成。
