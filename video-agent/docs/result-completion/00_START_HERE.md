# 使用方式

这是一套给本地 Codex 的执行包，不是已修改的项目或已制作的视频。

在原项目的 Codex 图形会话中上传整个压缩包，或把这个文件夹放到 `video-agent/docs/result-completion/`。不需要逐份粘贴历史 Prompt，也不要求用户改用命令行。

粘贴下面这段：

```text
在当前本地 hyperframe 项目中执行附件 result-completion/01_MASTER_PROMPT.md，
并以 02_ACCEPTANCE_CONTRACT.md 作为结果验收合同。
若附件已解压到仓库，则读取 video-agent/docs/result-completion/ 下的对应文件。

这是实际继续实施的授权，不是再次整理方案。
先核对当前文件和失败日志，已修有效的复用；保持原 N0—N5 和原冻结任务范围，
连续执行“复现→定位→修复→同输入复验→真实结果检查→下一未完成项”。
不要在修完几处代码、通过单测或生成一个 fixture 后结束。

重点是跨平台成功回执/渲染问题、真实画面可读性、HyperFrames 资源的实际复用，
然后从现有 WebUI 完成两次独立 60 秒、原 45/90/120/180 秒及冻结正负例、
连续对话编辑、原生工程重开和可播放结果入口。
人评只阻塞最终签收，不阻塞没有硬缺陷的其他可执行任务。

保留原生工程、WebUI、现有模型登录、安全边界与未提交工作；
不新增收费/生图/生视频/数字人服务，不擅自升级、提交或推送。
普通报错继续定位，真实权限/素材/预算阻塞如实记录，其他可做工作继续。
会话若被迫中断保存精确接力点，不宣称完成或后台仍在执行。

复用现有台账；把 delivery-contract.template.json 按原冻结定义解析并冻结，
以 verify_delivery.py 检查交付文件和证据绑定。该检查不是人评或商用保证。
现在直接执行，不先复述方案，也不要每个阶段问是否继续。
```

## 文件

- `01_MASTER_PROMPT.md`：一份连续执行总控，已包含 N0—N5 的具体修复方式与停止条件。
- `02_ACCEPTANCE_CONTRACT.md`：逐项成果、机器与人评区分、检查器格式。
- `delivery-contract.template.json`：默认未冻结、不可验收的任务模板；Codex 必须从本地原定义补全，不能改成简单样例。
- `verify_delivery.py`：只读证据检查器，由 Codex 在本地调用。它不会替你运行应用或证明画面好看。
- `99_RESUME.md`：宿主确实中断后的一条接力指令；不是日常需要反复催促的步骤。
- `reference/`：历史 CI 样片、对比帧和日志，方便定点复现；不是本轮商品成片。
- `SOURCES.md`：审查参考、历史证据和规则来源；已修问题不得重复算缺陷。

保留原有文件；有重名目录则改用新目录并同步启动指令，不覆盖。预算及权限以既有授权为限。Prompt 无法解除模型/工具会话限制，因此通过检查点保持连续性，而不是承诺无限单会话执行。
