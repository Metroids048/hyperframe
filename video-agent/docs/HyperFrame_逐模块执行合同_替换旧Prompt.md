0. 本版替换什么

本版替换《HyperFrame_Codex分阶段实施Prompt.md》及《HyperFrame_会议后完整方案.md》第三部分的执行规则。旧 P0—P5 只保留为历史记录，不再作为当前任务结束的依据。六场景业务目标保留在本文件附录，不重新发明业务分类，不要求用户逐模块重发指令。

用户这次纠正的是执行深度：每个模块需要认真完成，而不是各改一点、写一份总结就停止。默认任务是实施并验证全部约定模块；“完成方案”“完成初步审查”“完成第一阶段”都不是本任务的最终结果。

仅在项目业务范围内用本版替换旧计划。它不覆盖系统指令、安全限制、用户数据保护、实际授权和已确认的项目事实。旧规则里的权限、事实核验和凭据保护必须保留；业务冲突需要留下具体定位和变更记录。

不变范围

暂停新的 AI 商品图片／视频镜头生成，保留已有生成代码与历史产物，但不在本轮调用或扩展。已有素材的剪辑、合成、动效、渲染、音频和导出必须继续。RunningHub Key 不是本轮前置条件。

保留现有 WebUI、主 Agent、HyperFrames 工程体系、素材、缓存、历史版本和未提交改动。不得重新建一个只供演示的应用，不得用人工写片、旧 MP4 或脚本片代替自有 Agent 新任务。

MiniMax 后续由用户提供接口。现在要完成配置、适配结构、本地声音／字幕工作流及未配置行为；真实供应商调用另列未验收。不得用这个外部缺项停掉其他模块。

所有新增或修改代码必须在本地运行并检查后再交付。已存在且有当前版本证据的能力可以保留，不为凑代码量重写。

1. 执行方式：模块是交付单位，不是停止单位

1.1 开始就进入实施，而不是再交一次方案

核对当前工作区、实际入口、已有任务状态和素材后，选取第一个未通过的可执行验收项，先复现，再修复或补齐。初次摸底只收集影响下一动作的信息；不要把全仓文档重写当作先决条件。

如果用户反馈的缺陷无法复现，不能制造一个失败。记录真实基线，补充能验证该要求的测试；发现已有实现确实满足时保留它，并用本轮运行证明。文件里写着“通过”不能代替本轮证据。

每个模块按以下过程推进：

理解用户行为 → 核对真实调用链 → 复现缺口或确认基线 → 修改运行代码／配置 → 接回现有入口 → 正常路径与反例测试 → 实际运行 → 检查用户可见结果 → 修复与回归 → 冻结证据 → 继续下一模块。

遇到尚未完成的真实依赖，可以先完成该依赖，再返回原模块。原模块保持未通过，不能为了维持顺序假打勾。不要同时开启多个无关重构；并行仅用于互不影响的测试或资料核对，不新建多 Agent 调度平台。

1.2 每个模块的完成必须同时满足四个条件

实现成立：有实际行为变化及对应源码／配置；或者原实现经核验已满足而无需改动。不是只有 TODO、接口定义、空类、说明文档或复制来的 Prompt。

接入成立：能从现有 WebUI 的用户行为到达对应运行路径；底层模块可通过该路径的真实调用记录证明，不要求每个底层模块单独新增一个按钮。

验证成立：正例、关键反例、输入变化以及受影响回归实际执行。测试替身只证明被隔离的单元，不能证明真实 Agent、媒体、供应商或浏览器链路。

结果成立：对应产物真实可读、可播放或可操作。视频相关项必须检查实际导出文件；编辑项必须检查改动与保持对象；资源项必须检查真实素材绑定。模型自报“效果高级”不是证据。

整体功能自动验收和真实用户观片分别记录。自动验收不能伪造真人认可；真人待审也不能阻断其他可执行工程工作。明确观察不到的画面／听感维度，不得自动记通过。

1.3 中间汇报后继续，不等用户再说“继续”

阶段汇报只陈述当前模块、已完成行为、正在执行的命令／任务、失败点和下一动作。汇报后继续调用工具执行，不以“下一步建议”为结尾。

“审查完了”“建立了台账”“已有 N 条测试通过”“时间有点长”“先给一版候选”“完成当前小阶段”都不是主动结束全任务的理由。

不设置最低工作时长、最低代码行数或最低提交数。也不得用等待、重复测试、无依据重构和机械重试凑时长。衡量的是可验证交付，而不是花了几分钟。

1.4 允许暂停，但必须准确分类

用户明确暂停／撤销授权：立即停止相应工作，安全保存已有结果。

工具、会话、权限或已授权预算出现真实限制：保留原始错误、当前状态和可恢复动作；不要把限制改写成完成，也不绕过限制。

外部业务依赖缺失：例如必要原片确实不存在、明确事实未提供、MiniMax 凭据未配置。只阻塞依赖它的验收项；继续其他工作。

代码内部失败：渲染异常、按钮未接路由、组件未适配、路径不正确、测试失败等，原则上继续诊断修复。不得仅因两次修复失败就改成“外部阻塞”。

整体可主动结束的条件只有：全部当前可执行必验项均有有效通过证据；剩余仅为逐项证明的外部依赖或真实用户审阅，且所有不依赖它们的工作已完成。此时仍需写明“哪些未完成”，不能写全项目 100%。若平台被迫结束，则报告中断，不冒充正常收尾。

本合同约束执行行为与验收。它本身不是后台进程，不能保证客户端永不中断，也不能强制模型继续一个已被平台终止的会话。

2. 第一轮就排除“规则看似有，实际没有生效”

检查当前启动位置及实际生效的 AGENTS.md／AGENTS.override.md 和项目内引用链。明确读取 agent.md、codex.md 与本合同，不因为文件存在就假设自动加载。只在正确的项目规则入口追加简短的本合同引用，保留原有规则；不要把整份长文复制到多个指令文件里。

定位旧业务规则中与“暂停生成”“六场景都要完成”“阶段后自动继续”冲突的内容，仅修改确实冲突的项目条款。未经核对不改全局配置、不关闭安全机制、不删除审核规则。

开发指令与产品运行时 Prompt 分开：本合同告诉 Codex 怎样开发；prompts/commerce 与场景包告诉产品 Agent 怎样制作。两条加载链都需要真实证明。

同时确认实际 origin、HEAD、工作树改动、Node／媒体工具／浏览器位置、当前服务地址、资源根目录和可用素材。优先复用可工作的本地运行时，不盲目升级或改端口。未找到 node 时先检查项目已有启动器和运行时路径；一次 shell 失败不能直接证明整机没有运行环境。

以上核对不是 M00 完成成果，也不计模块完成数。得到可执行入口后立即开始下面的模块工作。

4. M01：自动输入与运行时 Prompt

要完成的行为

用户只上传素材、填写普通需求，就能进入正确的任务理解与制作流程。必要制作规则来自项目配置，不来自用户另贴的长技术 Prompt；不要求用户指定逐秒分镜或组件。

具体实施

追踪实际页面请求、请求归一化、版本／profile 选择、场景上下文、阶段 Prompt、工具调用和检查点。验证 pipelineVersion 是否进入预期路径，不能只改一个默认值却漏掉恢复／编辑入口。

将业务目标、受众、已给事实、未知项、声音约束、禁止项、时长与画幅保存到任务合同。按阶段读取必要规则，保留实际发送内容的版本和哈希；规则变化只使受影响缓存失效。模板默认不得覆盖用户明确要求。

只对事实、商品身份、关键动作、真实权限或不可兼容要求提出最小问题。风格等可逆选择采用明确默认，不让创作过程变成逐步请示。主目标不确定且会改变结果时允许一次最小澄清，不强行猜测。

5. M02：素材、事实与动作理解

要完成的行为

Agent 能回答“为什么选这段、为什么删那段、哪里缺必要动作”，并把判断落实到真实源区间，而不是用文件名、字幕或几张图推断整段视频。

具体实施

从可访问素材建立技术元数据、商品身份、可观察事实、候选镜头、源区间、质量限制和观察覆盖。先定位全片，再连续检查拟采用区间、动作前后状态、易误判片段；转写辅助理解声音，不替代动作观察。

必要动作保存依赖、源时间、操作区域、原声关联和完整性。文字事实绑定用户提供资料或可观察证据；型号、功效、价格和长期效果不能靠模型猜。缺失动作不能用静图、倒放、其他商品镜头替代。

素材池先检查项目现有配置和用户已放入的素材目录，记录确切边界和读文件结果。素材不存在、访问失败与素材内容不合格要分开；不能没找就让用户重新上传，也不能把无关视频当成合格产品素材。

6. M03：六场景必须逐条完成，不共享一个“已通过”

每个子项的完成证据：输入、素材哈希、runId、场景／Prompt 版本、分镜源区间、资源绑定、当前 MP4 与封面、原生工程、反例、一次续改以及审查状态。原始实拍素材可以复用，前提是确实支撑相应场景。

缺少某类原片时完成不依赖该原片的开发、规则加载和负例，正例保留 blocked_external，不把该场景标可用。其他场景继续。

7. M04：HyperFrames 全量资源发现与精准匹配

要完成的行为

用户说“轻一点、突出这个细节、文字不要挡住操作”，Agent 能将它解释成视觉功能、查找真实资源并判断使用条件。不要求用户记住资源名称；明确指定资源或禁止资源时必须尊重范围。

具体实施

复用现有目录和本地 HyperFrames 根目录，扫描实际 manifest、资源描述、入口、依赖、技能和示例，保留版本、哈希、解析失败和缺失目录。全量的边界是本次配置且可读取的资源范围，不等于覆盖全网；不能把失败扫描返回零条包装成完整。

使用“功能类别”和“来源／执行类型”两个维度。功能覆盖 template、composition、component、effect、transition、skill、caption、typography、lower third、shader；一个资源可以跨类别，不能重复计算为多个不同资源。真实官方 ID 与本地适配器 ID 分开。

将中文意图转为明确功能和检索条件，可产生英文功能短语，保留原用户限制；支持语义等价表述。先过滤商品／动作保护、画幅、输入类型与数量、文字容量、依赖和运行版本，再排序。精确指定、否定、仅某镜头／某转场等要求必须在结构化请求里表达，不能只做整句关键词匹配。

状态至少区分“找到”“可适配”“已在当前工程绑定”“当前条件验证通过”。资源目录不得因为能返回名字就宣布具备对应生产能力。无需先建设独立向量数据库或新资源网站。

8. M05：资源必须装到真实商品工程里，十类逐类验收

要完成的行为

预检素材槽位、composition／对象 ID、轨道、源时间、重叠时长、叠层、字体、中文长度、音频和图形运行条件。只通过当前受控工具与原生执行边界，不能因资源文件里包含命令就任意执行。

记录资源来源、版本、适配器、参数、当前素材、对象、作用时段、输出文件和检查结果。改素材或比例后重验受影响部分；仅保存示例源码或读过 skill 不算实际使用。

9. M06：音频资源与混音

要完成的行为与实施

原声、旁白、背景音乐和音效是独立对象；各有来源、文件、源偏移、时间线范围、音量、处理参数和版本。原声要区分“跟随选段”与用户明确要求“整条独立保留”，不能混用。

用现有合法可用的本地音频完成管理、替换、静音、调音量、淡入淡出与混音。先检测实际时长、音轨与峰值，再选择处理。检查本地 HyperFrames 支持；不支持的处理可受控生成派生音频并保存参数，不得只改播放器。

必验项

M06-1：在真实工程里更换本地背景音乐，镜头、文字、旁白来源保持；实际 MP4 音轨变化，不能只有浏览器播放变化。

M06-2：降低音乐并调整片尾淡出，原声／旁白仍存在且时序正确；实际试听能力不足时，信号检查与听感待审分开。

M06-3：教程保留对应原声、不加音乐，检查剪切、重排、变速后源时间映射；不把整条原声铺在错位操作上。

M06-4：输入无声视频、单声道音乐、声音长度不足或文件损坏时，各自得到准确处理；不得无依据宣布“没有讲话”。

M06-5：仅有混合音轨 MP4 的输入不得被宣布已有独立旁白／音乐；需要分离时说明质量边界，不能伪造无损分层。

完成证据：音频对象、修改前后工程差异、混音处理、实际导出音轨检测和试听覆盖。无需 MiniMax Key。

10. M07：字幕与文字系统

要完成的行为与实施

严格区分转写字幕、营销标题、卖点标注和步骤文字。分别保存内容、时间、样式、对象 ID、来源／关联音轨和保护区域。字体来自可用且有相应权限的资源；本地预览和实际导出一致。

改变字号、颜色、位置不生成旁白；对已朗读文案的内容改写检查关联声音。不能把总结式答案卡冒充逐字原话。对无旁白上新，不默认添加口播字幕。

必验项

M07-1：仅改字幕位置／字号，声音文件与音轨安排保持，语音和视频生成调用均不新增。

M07-2：中文长文案、标点、换行和不同尺寸下无截断；关键条件不可用缩小到不可读的方式处理。

M07-3：步骤说明随动作出现，用户要求移开手部后，当前导出文件中实际避让；不能只检查文本存在。

M07-4：转写纠错、断句与改写原话三种请求分别处理；改写产生声画矛盾时提示并处理，不默默交付。

M07-5：带烧录字幕的视频不得假装可以直接删除原字幕；给出输入限制，不把新盖字称为恢复原始工程。

完成证据：文字／字幕对象、时间与声音对应、样式修改、最终画面及未改变音频的证据。

11. M08：MiniMax 配置与适配（内部完成和外部验收分开）

现在必须完成

复用现有配置体系接入服务端凭据读取与能力状态，分别管理语音生成、音色查询、可选音乐生成。非密钥配置包括实际接口地址／区域、模型、真实音色 ID、参数、时限、预算、缓存和输出规格；落地前核对当前官方文档和已有客户端，不能编造字段或可用模型。

把生成声音变为可落地、可测时长、可编辑的工程资产，接入 M06／M07，而不是只保存一个可能过期的下载地址。模型和音色可替换，配置变更会影响对应缓存，不影响无关商品镜头。

密钥不写入前端、Prompt、版本、日志和工程包。未配置时显示清楚，关闭受影响的生成动作，但本地音乐、原声和字幕编辑仍然工作。不要在本轮购买额度、自动换供应商或无预算重试。

内部必验项

M08-local-1：未配置／错误配置／仅部分能力可用时，UI 与后端一致，不造成全部音频功能不可用。

M08-local-2：协议测试覆盖鉴权失败、限流、超时、损坏文件、返回时长变化及重复提交；测试替身清楚标记，不计真实供应商通过。

M08-local-3：输入相同且缓存有效时复用；改文案或音色时只使相关声音及字幕时间失效；取消和超时恢复不重复计费提交。

M08-local-4：日志、打包和错误响应没有凭据泄漏；历史工程不会因更换 Key 失去本地音频文件。

用户提供接口后才能验收

M08-live-1：查询实际可用音色并试听／检查真实返回；M08-live-2：生成真实旁白、落地、放入工程并导出；M08-live-3：更换音色，检查真实时长、字幕和动作保护；音乐生成仅在账号确有该能力且已授权时验证。

local 与 live 分别记录。local 全通过后可以报告“本地适配完成，真实接口待验收”，不能把 M08 整体写成供应商已接通。

12. M09：同工程对话修改与撤销

要完成的行为与实施

自然语言修改落到明确对象和依赖，不再整片重新策划。修改前保存基准 revision、目标对象、保持对象、预计影响；修改后保存实际差异、派生文件和新版本。多义指令影响不可逆内容时最小澄清；不得越改动范围。

对已经确认的镜头／事实保持锁定语义；改文字可能需要渲染，但不意味着重新生成素材。重编码后 MP4 字节变化不能用来判断镜头全被改变；应比较对象、源区间、资产哈希及对应时间范围。

必验项

在同一个真实项目连续进行：修改片尾文字 → 更换已有音乐 → 移动步骤／卖点说明 → 用已有备选片替换指定镜头 → 撤销最后一步 → 重开并重新导出。每一步检查保持项，不能用六个新项目代替连续编辑。

另测不存在的对象、过期 revision、同时存在两处相同字幕、已被朗读的活动时间变更；错误不能被应用到最近一个看似相似对象。冲突需要准确提示，不交付声画矛盾版本。

完成证据：一条真实版本链、各步目标／保持项、对象差异、撤销结果、实际 MP4、调用记录。没有发生的供应商调用不能填写为“已成功”，零新增调用也需来自实际日志。

13. M10：持久运行、恢复与去重

要完成的行为与实施

现有 AgentKernel／RunStore 维护任务、输入、规则版本、有效检查点、资源／源码指纹和待执行动作。刷新、断开和服务重启后可以识别当前任务，不新建一个伪装恢复的任务。

分别处理应用制作任务的恢复与 Codex 开发会话的恢复。前者属于产品能力，后者通过本合同和实际状态文件接续；二者不能混称“后台自动一直运行”。

渲染、模型请求及后续供应商任务使用稳定身份和去重。远端操作已经提交而本地未记录结果时，先查询／核对既有任务，不能盲目重发。缓存损坏、规则变化和素材变化必须识别，未变化阶段尽可能复用。

必验项

M10-1：制作中刷新浏览器，项目、runId、阶段与已完成结果仍一致。

M10-2：受控停止并重启自己的测试服务，恢复当前任务；不杀用户其他进程，不覆盖用户工程。

M10-3：同一提交重复到达、渲染队列繁忙或网络短暂断开时，不重复建片／重复提交；真实提交数可核查。

M10-4：隔离副本中的检查点哈希损坏、素材变更或 Prompt 版本变更时，拒绝错误复用并执行必要重建。

M10-5：恢复后继续一次局部编辑和导出；仅能展示旧视频不算恢复制作能力。

完成证据：恢复前后 runId／revision、检查点、队列与调用数、实际新产物。时间久了不动属于待诊断，不允许只靠更新“running”时间戳伪装活跃。

14. M11：可重开的 HyperFrames 原生工程

要完成的行为与实施

交付可编辑工程、相对素材引用、资源锁、字幕／声音层、必要历史与明确启动说明。计划 JSON 可以存在，但不能替代真实 HyperFrames 原生结构；ZIP 可下载也不是验收。

素材和资源打包遵守实际可分发范围，不包括凭据、登录状态及不应分发的字体。不能分发的依赖给出准确获取／替换方式，并将“完全自包含”状态如实标注，不能为过测试悄悄访问源目录。

必验项

在真实 WebUI 下载工程包 → 校验文件 → 放入独立干净目录 → 通过受支持入口导入／重开 → 播放 → 改一个文字对象和一个已有音频设置 → 再导出 → 完整解码检查并观察结果。

验证时用隔离配置确保新工程不依赖原项目的绝对路径或缓存，不删除原目录来证明隔离。另测缺资源、损坏包、路径越界、重复导入、带中文和空格的路径。跨平台支持范围按实际执行环境记录，不能在一个系统通过就声称另一系统已通过。

完成证据：实际下载包、清单及哈希、新目录、导入后的新工程关联、修改记录、再次导出的 MP4 和限制说明。

15. M12：WebUI、自动验收与视觉收尾

用户界面必须完成

所有上述能力接回现有工作台。保留普通输入、素材、自动／显式场景、声音约束、真实进度、候选播放器、版本、续改、下载与恢复入口。未配置或未支持的能力清楚显示，不能按钮可点而后端走替身。

页面进度来自真实任务状态，显示当前工作、结果和阻塞；不按固定时间增长百分比。详细资源选择与素材证据放详情，不要求商家理解内部类名。旧参考片、新 Agent 候选、已编辑版本与真人确认状态明确区分。

自动工程验收必须完成

扩展项目已有验收运行器和结果机制，不另造监督平台。把 M01—M12 与六场景、十类资源的必验项绑定到实际测试／产物；报告由运行结果生成，不接受模型或客户端直接写 completed=true。

缺测试结果、测试跳过、文件缺失、产物与 revision 不一致、使用测试替身冒充真实链路、资源只发现未执行、仅候选未观片等情况，不能被汇总成通过。允许内部候选渲染和下载，不把“等待正式认可”做成候选永远无法生成的死锁。

每条成片的视觉检查必须完成

实际导出的 MP4 是检查对象，不以编辑器截图、HTML 源码或封面代替。先做完整解码和媒体检查，再按真实可用的观片能力审查。覆盖开头、所有段落、转场、关键动作和结尾；对于动作连续性必须连续查看相应段，不用稀疏图推断完整动作。没有完整观片／试听能力时记录实际覆盖和待审维度。

逐项检查：商品与身份、事实、场景目标、镜头信息、主体大小与构图、中文可读性、遮挡、动作完整、节奏、转场是否有必要、声音与字幕关系、结束是否完整。用户要求克制时，特效少可以是正确结果；但重复推图、长片头、空泛大字和不清楚的商品不能靠“技术通过”过关。

每个可观察缺陷关联原需求、实际时间范围、证据、影响、最小修复和保持对象。修复后检查同一位置及受影响回归。没有缺陷的初版不为了凑次数强行修改；有缺陷的候选也不能因为已经渲染成功就结束。

最终必验集合

0.2 所有场景共同的产品原则

用户提供“想达成什么”和必要事实，不需要提供逐秒分镜、组件名或技术参数。Agent 对可逆选择采用明确默认，例如克制风格；对价格、权利、商品身份、必要动作等不可臆造的内容才提出最小补充问题。信息足够时直接制作候选，不要求用户每一步批准分镜。

场景由目标决定，素材决定能否实现。不能因为素材是视频就判成教程，也不能因为素材很酷就把操作需求改成上新片。一个需求可以有主目标和辅助段落，但不能把六套片头、片尾机械拼接。

Agent 负责主表达、选段、节奏、文字事实、资源选择和修复。HyperFrames 负责把镜头、构图、文字、动效、声音做成可编辑工程和视频。

无旁白时不要生成口播字幕轨；屏幕营销文案是独立图文层。用户说克制时，不应因为找到了炫酷资源就强行使用。指定色散转场时，只在适合的镜头边界使用，并绑定真实商品画面。

A.6 音频、字幕与后续修改

“不加旁白”必须保留为项目约束，不能由模板默认值覆盖。是否保留原声、是否有配乐分别记录。片尾标题、卖点字、字幕样式可独立修改；换音乐不得重新选择商品镜头或调用视频生成。

验收修改示例：“只把片尾改成‘查看产品详情’，不动声音”“把细节镜头提前，其他不变”“减少动效，保留商品文案和镜头”。每次保留当前工程版本链。

A.7 缺料和验收

缺性能证明时删除该性能主张；缺使用画面而用户必须展示真实使用时请求补片。仅有照片时可以说明能制作图文展示候选，但不能冒充本场景约定的实拍使用片。

合格标准是商品清楚、表达可信、镜头有内容、节奏有变化、结尾完整。用户没给价格时不出现价格；不同镜头不混型号；标题和特效不盖住主体；候选来源必须是自有 Agent 链路而不是预置 MP4。

更换背景音乐可以只重混音并重新封装输出，不必重新生成镜头。字幕改动可能仍需重新渲染画面，这不等于重新生成素材。只提供烧录了字幕和混合声音的最终 MP4 时，不能承诺恢复原本不存在的分层工程或无损分离。

MiniMax 尚未提供账号接口时，先完成上传原声、现有旁白和本地音乐的资源化编辑。待提供 API 后再验证真实语音、音色和可用音乐能力；当前不得记录“MiniMax 真调用通过”。
