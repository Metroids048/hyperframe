# 质量、性能和真实交付状态

## 1. 三个不可替代的工程事实
实现存在 ≠ 已经通过真实用户入口；渲染成功 ≠ 视频视觉质量合格；一条排练样片好看 ≠ 新素材也可靠。

每条需求保存独立 gate：implementation、service/model、webui、render/media、semantics/edit-preservation、reopen/reliability、performance（适用时）、human/rights（适用时）。某次无声用例的 audio gate 可不适用，不代表“声音能力”这条需求可删掉。

## 2. 状态与跳过
任务状态继承 PENDING / IN_PROGRESS / IMPLEMENTED / VERIFIED / BLOCKED / FAILED。行动另存 REUSE_VERIFIED / VERIFY_EXISTING / COMPLETE_GAP / IMPLEMENT_OR_FIX / BLOCKED。

一个 requirement 只有本阶段所有适用门槛有证据才能 VERIFIED。早期已有组件渲染可以证明组件本身，不能证明 WebUI 自动创作。跳过实现的证据至少包括 relevantCodeHash、runtime/dependencyHash、schema/source/motion版本、输入/输出/真实入口、原有证据是否适用及本轮必要 smoke。无关文档变化不要求重跑全部；源码、字体、引擎、计划或素材依赖改变则失效对应结果。

同一项目渲染可用固定 seed 做确定性验证；新项目生成计划允许创意差异，不用像素完全一致伪装可靠。对非目标语义/锁定/原素材保持作独立检查。

## 3. 工程关门与最终签收
- `productCapabilityReady`：所有 P00—P10 的 engineering-stage 和本轮继承的 LEGACY 必需工程项通过；R58 为读取这些结果后完成的治理项，不参与自身前置。基础设施/真实模型/UI/安全/功能缺失均不得为真。
- `demoInputsReady`：产品能力关门后，最终真实输入/文本/许可/文件映射已准备并校验。
- `demoReplayReady`：最终文本与文件在现有 WebUI 从空项目复跑通过，预期输出与工程可重开，无幕后人工修片。
- `humanAcceptance`：用户实际完整观片与需要的独立专家审核状态，只能由真实记录更新。
- `fullScopeAccepted`：全部约定工程与演示要求、必须的人审/专家目标/发布许可真实满足。

前三者不自动推出 fullScopeAccepted。缺专家或用户最终签收时可以交“工程已验证、演示可复跑、待人工签收”的包，不写“全部需求全部验收通过”。当前还有功能缺口则不能称演示就绪。

## 4. 必测画面与声音
每幕：入场、最可读时刻、运动极值、结束前一帧。每个转场：前/中/后。补充非预置但可复现采样；比较顺序/乱序 seek 与导出解码帧。

检查主体是否真的被裁切/遮住、要求运动的对象是否有可见轨迹、中文是否溢出/字小/混叠、价格币种/商品型号/卖点是否正确、信息是否读得完、结尾是否稳定完整。背景变化不能证明商品在动；整图有像素变化不能替代目标对象检查。声明的静止停留不应被 frozen-frame启发式误判，需记录目的。

没有素材支持的3D角度、运动跟踪、结构拆解不能伪造；低清图不能靠过度放大掩饰。正常转场/装饰可以有合理允许溢出，但不能放大豁免区域、隐藏文字或关 strict 过关。

音频检查原声唯一、目标音轨、峰值/响度/淡入出/截断、字幕/动作同步。只改视觉时 audioPlan/源声音保持。没有人听过就不写人工听音通过。

## 5. 实际质量与独立评审
开发集与保留集至少继承原24任务的12/12划分，另有原通用要求不得被电商子集取代。冻结输入 hash、要求、规格、事实、must-change/must-preserve、评分和失败条件。保留集失败后修复，转开发集并补新的保留任务，不一边调一边称盲测。

保留旧方案的专家对照：同素材同要求，至少两位评审随机盲评；relativeScore = 100 × AgentScore / ExpertScore，ExpertScore>0。目标平均相对分≥85、任务组均分≥80、单项≥70；具体原始分/比值与计算方法分开报告，不把相对分当原始百分制。既有更严格合同不自动放宽。

电商维度继承：要求与事实25、商品展示与层级20、动效节奏20、版式品牌15、剪辑同步声音10、整体完成度10。连续编辑可靠性、事实错误、素材损坏、关键内容丢失和许可问题为硬门槛，不被审美平均分抵消。

自动模型可提问题和修复建议，不自签专家成绩。用户未提供/执行独立评审时记录待验，不编造评审人、观看记录或分数。

## 6. Windows 性能目标（都是待实测目标）
目标环境 Windows i5-1334U/16GB。当前本机不同则记录 actual，不把别的硬件数据混成同机达标。

继承指标：即时反馈 p95≤1s；缓存撤销预览 p95≤2s；已导入30秒片的暖确定性文字/样式 patch，p50≤5s、p95≤10s；一次模型判断的局部修改 p95目标≤20s；简单修改 p50比同机基线下降≥50%。首创、复杂代码创作、最终导出分别统计，不承诺所有渲染20秒。

至少30暖样本与5冷启动，p95采用 nearest-rank，报告样本数、失败率、内存峰值、缓存命中、模型/ASR/TTS/混音调用。定义起点为用户发起相应动作，终点为新版本可在UI真实播放，而非仅后端返回job ID。反馈指标只测任务被确认/状态可见，不冒充成片返回。

允许正常依赖缓存、浏览器复用、有预算的并发；不隐藏冷启动、不播放预渲染视频冒充实时、不降分辨率/删动效/静音/关检查提速。模型连接异常单列环境失败，不静默排除所有慢样本。

## 7. Demo复跑报告
每个核心创建案例至少3次独立新项目，至少一次冷项目/新会话；日志包含全部尝试和当前版本结果。不把自动修复后成功算first-pass，不把人工修片算自动成功。公开数据样本有限，不能由3/3推断任意输入100%成功。

自然语言改写、新文件名/顺序、不同商品都应测试。显式“第二张图”引用随顺序变化须同步意图，不能把改变目标当保持同一需求。干净项目可以用正常资产缓存，但计划须真实执行，缓存命中披露。

## 8. 证据保存与隐私
实际命令、exitCode、版本、run/project/revision/job、素材/工程/output hash、浏览器trace/录像、编译/导出与画面变化、真实耗时和review状态。哈希为指纹，不代替实际输出。

脱敏命令参数/路径中的凭据，网络trace不得公开Authorization/Cookie。字体文件不分发；私有素材仅在授权范围本机使用，不自动入Git。空模板默认 pending，不存在的证据引用必须报缺失。
