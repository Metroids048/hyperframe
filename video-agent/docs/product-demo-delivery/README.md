# HyperFrames 产品补齐与 WebUI 演示交付包

版本：2026-09-11 / v1.0。性质：给本地 Codex 的执行方案和任务合同，不是项目已完成报告。

## 用户要的最终结果
先补齐既有视频创作与剪辑 Agent 的全部约定能力，再准备真实用户输入样例与对应 Agent 输出。用户只需打开已有 WebUI，上传准备好的图片/视频，粘贴自然语言，便能生成可观看、可继续修改的作品。演示必须展示真能力，不是播放预制成片。

## 使用方法
把本目录放进现有项目的 `docs/product-demo-delivery/`。通常项目位于 `C:\Users\admin\Desktop\hyperframe`；由 Codex 先核对实际工作区。已有同名目录时合并审查，不无差别覆盖。

先把 `START_HERE.txt` 内容发给 Codex。它会读取总控、方案、任务和验收合同，自行审计已完成项，跳过有证据的实现，补齐未完成项。中断后使用 `08_CONTINUE_PROMPT.md`，不要反复从零重建。

## 文件索引
- `01_MASTER_PROMPT.md`：总控、授权边界、跳过规则、持续执行与停止条件。
- `02_PRODUCT_PLAN.md`：工程方案、兼容决策、事实与工程唯一性、分阶段交付。
- `03_EXECUTION_LOOPS.md`：P00—P14 的依赖、实际工作、通过条件和反作弊规则。
- `04_WEBUI_ACCEPTANCE.md`：现有 WebUI 的端到端验收、用户操作合同、连续修改脚本。
- `05_DEMO_KIT_SPEC.md`：功能补齐之后才执行的真实素材、输入和成品交付规范。
- `06_DEMO_PROMPTS_DRAFT.md`：8 组普通用户语言样例，最终必须绑定实际素材并试跑。
- `07_QUALITY_AND_READINESS.md`：质量、性能、专家评审、跳过证据与真实状态。
- `08_CONTINUE_PROMPT.md`：恢复工作或纠正“只完成基础层”的续作指令。
- `09_SOURCES_AND_SCOPE.md`：继承来源、官方参考和本包范围。
- `10_REQUIREMENTS.json`：逐需求映射，所有状态初始为 PENDING。
- `11_STATE.template.json`：运行状态种子，禁止作为真实状态直接报通过。
- `12_EVIDENCE.template.json`：运行、渲染、WebUI、素材和审核证据种子。
- `13_DEMO_MATRIX.json`：公开演示与能力覆盖关系；不代表已经有真实素材。
- `14_LOCAL_PACKAGE_CHECK.md`：本包的本地文件与结构检查，不是应用验收。

## 三类材料务必分开
**开发测试输入**用于补齐能力，可以在开发初期准备。**最终演示输入包**在产品工程闭环后整理、冻结。**预期作品/运行证据**只用于比较和说明，绝不能被重新当作“原始素材”送进 Agent。

本包不包含用户机器上的代码改动、真实商品图片、B-roll、配乐或成片。所有示例文件名都是交付命名合同，最终由 Codex 找到合法真实素材、填入最终文案、在本机 WebUI 试跑后交付。不得把空目录或素材 URL 清单当作完成素材准备。

## 两种结论不能混用
工程功能通过后，可以准备演示输入并交付“待用户验收”版本。独立人审、专家相对分和商业发布审核必须真实取得；缺失就保持待验。不能因为用户稍后会看，伪造现在已人工通过，也不能拿这个原因停止所有可独立推进的工程工作。
