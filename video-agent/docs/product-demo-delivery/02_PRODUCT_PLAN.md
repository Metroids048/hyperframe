# 解决方案：补断点，不重做产品；先关门，再演示

## 1. 明确继承与覆盖
本包是既有 creative-v2 与 commerce 方案的执行补强，不另造一套业务系统。P00 维护 `SCOPE_RECONCILIATION.md`：每条旧要求是继承、被本次明确调整、已验证复用或尚待实现；不得默认删除历史要求。

已明确调整：文字-only 入口允许生成文字/形状/信息图原生动效，旧的“一律 MISSING_MEDIA”不得拦截；真正需要商品照片却没有照片的任务仍不能捏造商品。图片、视频和混合路线独立验收，视频主门槛不抵消图片路线。混合素材不固定视频为主；按内容与目标规划。Agent/UI 最小链路前置，不到最后才接。

已明确继承：稳定对象、原生工程、真实选镜剪辑、基本字幕/音频、精确时间映射、撤销恢复、缓存/任务队列、取消/失败保留版本、受控素材规格、版本锁、Windows 性能、安全隔离、独立评审及历史回归。

## 2. 单一用户路径
现有 WebUI（文本/上传/当前项目/选中范围） → 现有 API 或宿主入口适配 → 共用请求验证/计划/执行服务 → 受控原生工程 → 同源预览与导出。

WebUI、宿主 Agent、provider 模式使用同一业务合同。不得让“调试脚本里可用”与“用户界面里可用”成为两个系统。自动化浏览器驱动现有 UI 只负责用户动作与观察，不从后台修改工程替它过关。

最小 UI 补齐包括：图片/视频/音频上传与失败说明；无附件文本创建；素材缩略图/名称；当前项目与版本；上下文选择/锁定的可见反馈；真实 job 状态、取消/重试；预览来源版本；变化摘要；撤销/恢复；固定版本导出。现有控件能够完成的直接复用，不强制新建一套面板。

## 3. 数据与工程权威
优先沿用已有 Document v3 或现场已验证的等价原生模型，不为了名称另建 schema。EvidencePack 记录素材和事实来源；Brief/Design/Storyboard 是规划与决策视图；持久工程决定对象身份、文案、素材、时间、锁定和版本；受管不可变 source bundle 决定非模板实现。

规划结果必须在一次事务中进入工程，后续 patch 也走工程事务。DESIGN/STORYBOARD/编译 HTML 是可更新的视图或产物，不能各自偷偷保存第二份价格、时长和素材列表。对外暴露的 HyperFrames 工程源码、sidecar 与资源锁必须能重开、能反向定位到对象；外部源码修改未验证时不得自动覆盖主工程。

Root 负责场景放置和全局时间；子场景负责自己的布局与运动。Stable scene/object IDs、objectMap、source refs 和四种时间锚点（scene-local/source-content/project-absolute/project-end）贯通。改变倍速、重排和重叠转场后只计算一次映射。图层使用绘制顺序，不把 track 编号混同 z-index。

## 4. 素材理解不是 metadata 列表
图片：真实传图、主体位置及置信度、全貌/细节/场景角色、可用裁切区、相似/重复、款式/型号对应、清晰度与文字可读性。低置信度保守 contain，不伪造抠图或新角度。
视频：采样画面、真实镜头/动作区间、候选源范围、重复/失焦/黑场、音轨、使用原因与舍弃原因；不以文件名推断镜头内容。必要时复用转写，不要求纯视觉任务强制 ASR。
事实：user-provided、visual-observation、unknown 分开；观察不能自行升级为功效。演示价格作为明确合成数据标注“演示样例”，不是外部真实报价。

## 5. 创作与执行
先决定每幕说什么/看什么，再决定镜头和效果。规划同时考虑目标、受众、画幅、时长、必须出现/禁止出现、阅读时间、素材能力和锁定。默认不让用户填分镜 JSON。

常规层组合商品揭示、细节窗、图文布局、强调标注、价格/片尾、方向/遮罩/尺度匹配等有效能力；所有能力要有 handler、参数 schema、素材前提、可编辑字段、真实样片与当前 runtime 验证。五组词汇（媒体、文字、布局、标注、转场）是组织方式，不是执行证明。

非标准层仅生成限定场景的 HTML/CSS/GSAP/已固定资源代码，经过静态解析、隔离运行、视觉与可编辑性验证；不进入服务进程执行。素材缺前景遮罩不能假装 3D；没有实拍动作不能生成后当真实 B-roll。

先建立最可读静态构图，再运动。预算转场重叠、有限 timeline、中文字宽、主体避让和最后可见帧。生成后核验产品事实、需求覆盖、动效目标、转场过程和结尾完整性；修复仅影响局部。

## 6. 创建与编辑不是一条成本路径
创建/结构改写：读取证据 → 规划 → 原生编译 → 检查 → 发布。
普通局部修改：上下文寻址 → typed patch → 依赖失效范围 → 受影响场景检查 → 发布；不全片重写，不重新做无关 ASR/TTS。
复合要求：拆为有顺序的事务操作，检查锁定和冲突；全部成功才提交对应版本。
选择性恢复：反向补丁只覆盖选中历史修改的属性，保留后来不相关的价格等变动；存在覆盖冲突必须说明。
多开头：基于同一基线建立变体，后文 source/semantics hash 相同；不得污染主版本。
导出：先捕获 immutable revision，再排队渲染；后续编辑产生新 revision，旧导出完成不切 current 指针。

## 7. 声音边界
none / keep_original / supplied BGM / explicit narration 分开。普通字幕不自动发声；更正字幕不改变原音。讲话字幕依 source-content，场景标题依 scene-local；不能随着重排二次偏移。

音乐叠加保持既有镜头 timing；音乐驱动剪辑分析真实音轨的可用段、节拍/乐句/能量，允许在用户许可下调整镜头 timing。不能用固定等间隔冒充分析。关键镜头和文字仍要可读。中文 TTS/试听/声音选择沿用已有原需求与实际能力，不静默用英语或外部收费服务代替；功能缺失按需求 ID 补齐或明确阻塞。

## 8. 产品工程关门后准备演示
开发期真实测试输入不是最终展示包。P11 关门只确认实际功能/工程证据，并独立列出人工/外部审批状态。P12 才整理最终演示素材、事实说明、普通用户提示文本、连续修改步骤；P13 从空项目经现有 WebUI 三次重复运行与变体运行。

演示输入只含真实合法原素材、用户可见事实和需求。EDL、Storyboard、对象图、标准答案、输出成片只放只读 evidence/expected-output，不喂给产品规划器。文件名或素材 hash 不能成为路由特例。

## 9. 验收分层
结构/代码 → 真实模型/工具 → 浏览器用户链路 → 实际视频与音频 → 同工程续改/重开 → Windows 性能 → 人工视觉/专家相对分/发布审核。

各层有独立证据。功能未做完不得用人审待定掩盖；人审未发生不得伪造通过。最终报告分工程能力、演示可复跑、用户待验和完整目标签收，不用一个全绿布尔值吞掉差异。
