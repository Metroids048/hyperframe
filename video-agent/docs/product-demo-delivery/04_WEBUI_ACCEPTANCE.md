# 现有 WebUI 验收合同

## 1. 浏览器是真正的用户入口
只测后端接口不算 WebUI 通过。每个核心用例必须以实际浏览器打开现有应用，使用现有上传/文本框/发送/播放/历史/导出操作。允许自动化工具操作真实表单和文件选择框；不允许先写内部工程或 mock 请求响应。

P00 定位实际 URL、启动器、按钮名称、页面状态与 API；本文件不假设端口或具体 CSS selector。测试优先按当前可见名称/可访问角色定位，必要时补稳定 test ID，不为测试重做 UI。

测试使用隔离的测试项目与受管数据根，保留用户真实作品。不得导出登录凭据、会话 token、未脱敏网络头或其他人的素材。不能绕过登录或把测试路径变成无鉴权后门。

## 2. 用户应能看见什么
| 环节 | 必须可见/可做 | 不合格表现 |
|---|---|---|
| 创建 | 无附件文字创建，图片/视频/音频上传，粘贴或组合输入 | 必须先上传视频才能开始文字/图片任务 |
| 上传 | 实际文件名称/缩略图/可用状态，失败文件具体原因 | 只显示“上传完成”但 Agent 没收到图像 |
| 生成 | 真实阶段、可取消、失败原因、明确重试 | 假百分比进度、一直 loading 或悄悄播放旧成片 |
| 预览 | 当前项目和 revision 对应作品，完整播放/seek | 聊天说已改但播放器仍显示旧版 |
| 修改 | 选中对象/场景或用自然语言定位，变化摘要、锁定反馈 | 必须输入 objectId、JSON 或 CSS selector |
| 版本 | undo/restore、变体区分、关闭后重开 | 重开只剩 MP4，锁定与历史消失 |
| 导出 | 指定版本、真实任务状态、可访问文件 | 导出旧版完成后覆盖新预览，或显示不存在的下载 |

已有 UI 能做的直接复用。缺少必要 UI 连线时局部增加；不要求另建专业时间线面板。

## 3. 12 类以上用户操作验收
每条都有输入原话、baseRevision、目标对象、must-change、must-preserve、允许联动范围、执行输出、工程差异、画面证据与失败处理。

| ID | 用户语言样例 | 必须证明 |
|---|---|---|
| U01 | 用我上传的第二张图开场，其他镜头顺序别改。 | 精确绑定素材，非目标顺序不变；旧开场事实仍匹配或明确必要调整 |
| U02 | 商品大一点，文字不要动。 | 商品层变化，文字位置/文案不变；冲突不能偷偷改字 |
| U03 | 重点展示这张图中的细节，用放大窗说明。 | 用真实可见区域/真实细节图，标注准确、不乱造特征 |
| U04 | 价格只在最后三秒出现。 | 片尾锚点正确；改总时长后仍满足 |
| U05 | 30秒压成15秒，两条指定卖点必须保留。 | 内容与停留重新分配，不是全片2×；无法满足时解释锁定/阅读冲突 |
| U06 | 改成竖版，商品不能被裁掉。 | 布局重排、主体完整、字可读，不是硬裁中间 |
| U07 | 第二段保持现在的内容和段内时长，后面别动它。 | 锁定持久、分清内容/布局/绝对位置，后续泛化修改不越界 |
| U08 | 其他段高级一点，第二段保持不变。 | 只改获准范围，风格变化有构图/节奏依据，不随机堆特效 |
| U09 | 恢复刚才改的动效，但保留现在的价格。 | 选择性逆补丁，不整项目回滚；冲突可解释 |
| U10 | 换这个商品图，其他尽量保持。 | 取景/标注必要联动被报告，无关音频不重新制作 |
| U11 | 按这首音乐的节奏剪，不要解说。 | 真正音轨分析，关键变化落在合理段点；没有 TTS |
| U12 | 给三个不同开头，后面完全保持，主版本别覆盖。 | 独立分支、后文语义/素材一致、主版本保持 |
| U13 | 先导出这一版，再把价格改掉。 | export固定旧revision，之后新revision可继续编辑 |
| U14 | 只修改字幕中的错字，不要重新配音。 | 字幕文字改，音频内容/计划不变，源时间正确 |
| U15 | 把视频这段前面多余的部分剪掉，并加快这一小段。 | 精确源范围/倍速，字幕按源内容映射，未目标片段不变 |
| U16 | 取消这次修改，保留原来的片子。 | 清理本次任务、旧版可用、不会误杀浏览器或丢项目 |

“其他不变”先指语义/内容/锁定；因允许修改导致的必要排版避让或全局时间移动须事先定义并在摘要中说明，不要求有损 MP4 字节相同。已经明确锁死位置时不能以“必要避让”为由改它。

## 4. 同工程连续演示脚本
在 D03 最终已试跑的基线工程上执行下列意图，Codex 必须先绑定真实素材名称、参考字段和可满足的时长，输出最终无占位符 FOLLOWUPS。基线包含明确的演示价 ¥199、两条短且有依据的卖点、至少四幕、无解说；价格为模拟演示信息。

1. 指定另一张真实主图做开场，保持后文顺序。
2. 对真实细节幕添加局部放大窗和短标注。
3. 将演示价 ¥199 改为 ¥179，其他不动。
4. 锁定第二幕的内容与段内时长，但不锁它在全片的绝对起点。
5. 只把未锁定段的动效改得更克制，文案、总时长、声音保持。
6. 选择性恢复第5步动效，保留 ¥179 与第4步锁定。
7. 压缩至15秒，保留两条短卖点与片尾3秒。若实测锁定使此请求不可能，正确报冲突；最终演示包须事先选可满足的短文案/片段，不伪造成功。
8. 改成方版，明确允许布局重排，继续保持第二幕内容和段内时长；不误把布局也锁住。
9. 改回竖版，仍保持上述内容约束，不重新生成配音。
10. 添加已上传的 BGM，明确保持当前镜头时间不变，不配解说。
11. 生成三个不同开头分支，后文不变，主版本不切换。
12. 导出当前主版本，随后把演示价改为 ¥169；旧导出结果仍是 ¥179。
13. 撤销第12步的价格修改，旧导出任务/结果仍保留。
14. 恢复 ¥169 的已存在版本。
15. 关闭/重新打开网页与该项目，再改一句标题并导出；这一步含浏览器动作，不假装一句聊天自动关闭用户页面。

至少前12个有效修改请求连续通过；保留所有中间版本、job、前后变化与失败记录。必要时把选择性恢复/分支等功能分成不冲突的独立测试，但不能删掉它们。

## 5. 独立负例
多款混入、图片太小、不存在的细节、没有价格却要求折扣、锁定总时长与不可缩短内容冲突、无可用声音、越界源时间、旧 baseRevision、重复提交、取消、素材缺失、服务重启。失败应保留旧版并给用户可理解解释。

演示用例成功不覆盖负例；负例返回具体问题才算通过，不能以自动减字/改价/替换效果过关。

## 6. 证据
run ID、初始空项目证据、实际上传事件/素材 hash、原话、provider/工具轨迹、project/revision/job、DOM/UI状态和截图/录屏、当前工程差异、对应 MP4/原生包、真实时间/内存/失败、机器审核与人工审核分别记录。

最终用户说明使用真实按钮名和实际路径。没亲自运行过 UI 的步骤必须标未验证，不能伪造“点击后会出现”的完成陈述。
