# 最终演示输入与输出包规范

## 1. 准备时机与三类数据隔离
只有 P11 产品工程 gate 通过后，才整理本包。之前用于开发的最小真实 fixture 可以继续用，但不能把打磨好的最终工程当原始输入。

- `input/`：用户真正上传的原图、实拍视频、已授权声音、用户可见事实。
- `prompts/`：用户只需粘贴的自然语言，不能含内部对象 ID、分镜 JSON、源码或固定 EDL。
- `expected-output/` 与 `evidence/`：通过产品跑出的参考作品和检验结果；不得由产品按文件路径读取作答案。人工参考片另放 `reference-author/` 并标执行主体。

公开演示集是经过排练的能力展示，不称保留集。独立保留任务不得提前用于调参；失败后转开发集并替换新的保留任务。

## 2. 素材获取责任
由 Codex 自行检查本地已有可用素材和授权记录，再寻找合法公开来源并保存真实文件。优先同一商品的官方明确授权媒体、可再分发图库套组或用户已授权自有素材。公开可浏览不自动等于允许下载再分发。

找不到同款图与视频，就调整选品到材料齐全的真实商品，并同步更新用户可见事实；不得混型号、伪造许可、不声明地改变目标、让用户自己重新搜一遍素材。

允许必要非生成式准备：方向/色彩修正、裁切、清晰缩放、从有授权的真实镜头抽帧作为图片（写明 derivedFrom 和源时间）、从合适 alpha 得到遮罩。抽帧图片不能被宣称独立摄影素材；同一镜头切多段不能冒充五个不同有效镜头。

不调用生图/生视频，不制造不存在的商品角度，不拿全片 MP4 或开发者精修输出当视频输入；不移除水印规避授权。没有可用的商品透明前景就用适合原图的构图，不强行抠坏边缘。

## 3. 至少三个真实商品/素材集
主商品 A：建议材料齐全的桌面/咖啡/小型生活商品，具体按合法素材决定。6 张左右高质量图片（全貌、另一角度、两处细节、两张场景）、2 张候选替换图、5—10 个真实不同 B-roll，供 D03/D04/D05 共享同款证据。

商品 B：不同品类，如数码小配件或包装商品；至少3—6张真实图片，供 D02 纯图未知事实处理和输入迁移验证。

商品 C：第三组未按 A 的构图预调过的商品素材，供 D08 或额外泛化演示。不是 A 的改名/调色版本。

声音集：至少一条合法 BGM；D06 需要真实中文口播或可合法使用的中文语音素材。需要按需 TTS 时使用现有能力，实际试听选择流程单独验证。使用模拟产品名、价格、活动时，在事实文件和输出可见“演示样例”说明，不能让人误以为真实商家报价。

## 4. 每个素材的 manifest
字段至少含 assetId、展示文件名、相对路径、sha256、真实 MIME、尺寸/时长/fps、媒体角色、productId/model/variant 对应、源 URL 或本地所有权记录、licenseId/许可依据快照、允许展示/再分发范围、署名要求、处理记录、derivedFrom 与原素材 hash、包含人像/标识的相关限制、人工/机器核对状态。

版权信息不足时 rights=unknown，不能由模型改为licensed。字体只记录依赖和合法获取说明/哈希；不要随包分发字体文件。

## 5. 最终目录合同
建议放在 `demos/webui-ready/`，也可复用已有等价受管目录；用户说明须写实际位置。

- `START_DEMO.md`：真实启动方式/URL，演示顺序和每组具体步骤。
- `DEMO_REPORT.md`：能力覆盖、三次复跑、耗时、限制、人审状态。
- `MANIFEST.json`：所有输入与输出索引/哈希/来源。
- `D01-text-motion/` 到 `D08-custom-native/`：每组 input/、prompts/、expected-output/、native-project/、evidence/。
- 每组 `INPUTS.md`：明确要上传哪些文件、什么可以不上传。
- 每组 `prompts/PASTE_FIRST.txt`、`FOLLOWUPS.txt`：直接复制内容，无占位符；说明性文字不得夹进复制文本。
- 每组 `expected-output/`：真实产品生成的 baseline.mp4、关键修改版本、contact sheet（辅助，不替代视频）。
- 每组 `native-project/`：可重开工程与必要可再分发素材/源码/锁，不能只有 MP4。
- 每组 `evidence/`：运行记录、WebUI证据、review、timings、diffs；不含凭据。

不必复制巨量相同资源：可用受管公共素材目录加 manifest 引用，但最终新目录重开要真实通过。用户不得手动补绝对路径。

## 6. 8组演示设计
| 案例 | 输入/输出建议 | 重点证明 |
|---|---|---|
| D01 | 一段文字 → 10秒竖版原生动效 | 无素材也能创作，信息层级/图形/文字动效，修改标题 |
| D02 | 商品B仅3—6张图 → 15秒竖版展示 | 真正看图、选图、全貌与细节、无事实不编价 |
| D03 | 商品A图片+已确认/明确模拟文案 → 30秒完整宣传片 | 电商主展示，设计、细节、卖点、完整收尾，15/45秒变体 |
| D04 | 商品A 5—10个真实B-roll → 20秒宣传片 | 真正选镜/裁切/重排/节奏/变速或重构图和包装 |
| D05 | 商品A图+视频+文案+BGM → 30秒混合广告 | 同一工程混排，按目标决定视觉主线，音乐驱动变体 |
| D06 | 中文口播视频/稿件/声音 → 20—30秒样例 | 原声、字幕、错字局改、字幕不改声音，按需试听配音路径 |
| D07 | D03同工程+额外替换素材+连续自然语言 | ≥12轮精准续改，锁定/选择性恢复/三开头/导出中编辑/重开 |
| D08 | 商品C+少量明确视觉限制 → 15—20秒非模板场景片 | 超出已验证组件组合的真实代码创作、可修改、安全边界及新素材迁移 |

D01—D05 是优先展示的成片主线；D06—D08 展示进阶能力。D07 可接着 D03 演示，不要求用户反复建同一工程。8组不应变成8种硬编码产品入口。

## 7. 参考效果与稳定性
每组用户文本提供清楚目的/必要事实/限制，但不写全套分镜替 Agent 思考。最终作品至少有开头、信息递进、读得清的主体与文案、合理节奏和完整结尾；不是把“3种转场”强加给所有片子。

每个核心创建案例至少3次独立新项目预演，含一次冷项目/新会话；同一工程渲染要求确定性，新一轮 Agent 规划允许合理创意变化，不要求像素一样。三次都须满足硬约束，视觉评价分别记录。最终若某次失败，修通用产品并复测；历史失败仍保留，不只挑最好一次。

输出可预期的意思是稳定满足约束和质量基线，不是无条件保证任何随机输入都完美。最终报告列 first-pass、自动修复、人工介入、耗时和可重跑范围。

## 8. 必须完成的最后一步
Codex 用最终文件和最终 prompt，完整通过现有 WebUI 做一遍用户会做的动作。只有这一步通过，才可将文案标为 `READY_FOR_MANUAL_REPLAY`。

这不是让用户代替开发者做首轮测试。用户接手后是验证和演示，不是先帮项目发现最基本的文件缺失、按钮失效、模型没连上或结果仍是旧版。
